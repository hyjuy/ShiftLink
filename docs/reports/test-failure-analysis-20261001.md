- 최종 로컬 확인: PR #125 CI 수정 후 전체 테스트 634개 통과, 실패 0건

## 검토 배경

MES 센서와 시나리오 추가 후 기존 신호 매핑이 갱신되지 않아 검사 2건이 실패했다. 매핑 JSON·MD와 측정 개수를 갱신한 뒤 해당 검사 4개는 통과했다. 이후 전체 검사에서 통합 KB 재생성 누락과 CV 대기열 복구 조건의 잘못된 가정이 추가로 확인됐다. 이 보고서는 후속 실패 2건의 원인과 해결 결과를 기록한다.

매핑 갱신 시 확인한 구성은 고유 신호 48종, 설비별 측정 위치 69개, 시나리오 104개다. 통합 KB는 A 30장, T4 11장, C 19장, D 21장으로 총 81장이다.

## 1. 통합 KB 동기화 검사 실패

### 발생 현상

`tests/test_kb_cards.py::test_kb_cards_json_matches_batches`에서 다음 검사가 실패했다.

```text
AssertionError: rerun build_kb.py
```

검사는 현재 배치 원본으로 다시 만든 통합 데이터와 저장된 `kb_cards.json`이 같은지 비교한다. 실패 당시 배치 해시와 카드 내용에 차이가 있었다.

### 원인

A·D 배치의 `cards.json`이 변경됐지만, 변경 후 통합 파일을 다시 생성하지 않았다. 배치 원본은 최신 상태이고 앱과 평가가 읽는 통합 파일은 이전 상태여서 불일치가 발생했다. 카드 개수가 같더라도 본문이나 원본 해시가 달라지면 이 검사는 실패한다.

### 적용된 해결책

[build_kb.py](../data/knowledge_cards/kb/build_kb.py)를 실행해 현재 배치 원본에서 [kb_cards.json](../data/knowledge_cards/kb/kb_cards.json)을 재생성했다. 카드 본문, 배치 해시, 유형별 집계와 통합 카드 수를 함께 갱신했다. 이후 원본으로 생성한 결과와 저장된 통합본의 일치를 확인했고 해당 검사가 통과했다.

### 재발 방지 제안

배치 카드 수정 후 통합 KB 재생성과 일치 검사를 필수 확인 단계로 유지한다. 통합 파일을 직접 수정하지 않고 배치 원본을 수정한 뒤 생성한다. 아래 두 명령을 순서대로 실행한다.

```powershell
python docs/data/knowledge_cards/kb/build_kb.py
python -m pytest tests/test_kb_cards.py::test_kb_cards_json_matches_batches -q
```

명령은 프로젝트 의존성을 사용할 수 있는 Python 환경에서 실행한다.

## 2. CV 대기열 복구 검사 실패

### 발생 현상

`tests/test_mes_all_sensor_anomalies.py::test_each_installed_sensor_anomaly_reaches_search_and_recovers[CV-01-cv_queue_len]`에서 복구 후 측정값이 정상 범위에 들어오는지 확인하다 실패했다.

```text
AssertionError: assert 100 <= 70.0
```

검사 대상 신호는 `cv_queue_len`이며 단위는 `pct`, 정상 범위는 0–70%다. 실패 시점의 복구 후 측정값은 100%였다.

### 원인

MES에서 `cv_queue_len`을 실제 코일 점유율로 계산하도록 변경했지만, 기존 테스트는 모든 센서가 복구 후 반드시 정상 범위로 돌아온다고 가정했다.

[engine.py](../../shiftlink/mes/engine.py)의 계산은 다음과 같다.

```text
점유율 = min(100, 100 × 현재 설비에 있는 코일 수 ÷ 설비 코일 용량)
```

CV-01의 용량이 1개이고 코일 1개가 남아 있으면 계산 결과는 100%다. 이상 시나리오에서 주입한 값을 해제해도 실제 코일을 제거하는 것은 아니므로, 복구 시점의 점유율이 0–70%로 내려간다고 보장할 수 없다. 복구 완료와 코일 배출 완료를 같은 조건으로 취급한 것이 실패 원인이다.

### 적용된 해결책

[복구 검사](../../tests/test_mes_all_sensor_anomalies.py)를 수정해 `cv_queue_len`은 복구 후 실제 코일 수와 설비 용량으로 계산한 점유율과 일치하는지 확인한다. 다른 센서의 정상 범위 검사는 유지하며, 복구 후 활성 알람이 해제됐는지도 확인한다.

점유율 값을 임의로 낮추거나 정상 상한을 높여 검사를 통과시키지 않았다. 실제 코일 점유 상태를 보존하면서 이상 주입 해제 이후의 측정 의미를 검증한다.

### 재발 방지 제안

센서별 측정 의미에 따라 복구 조건을 정한다. 일반적인 모의 센서값 복구와 실제 재공품 수에서 계산되는 점유율 복구를 구분한다. 공정 요구사항에 점유율 정상화까지 포함된다면, 코일이 배출되는 과정과 최종 점유율을 확인하는 별도 검사를 추가한다. 이 별도 검사는 이번 해결에 포함하지 않았다.

## 판정 범위와 남은 사항

보고서 대상 실패 2건은 해결됐고 최종 전체 검사에서 재현되지 않았다. 카드 원본·통합본의 동기화 및 합성 MES 복구 측정값의 일관성을 확인한 결과다. 현장 센서 정확도나 실제 설비 복구 성능을 검증한 결과는 아니다.

C 카드의 출처 승인·계보·독립 반복 근거 보류는 별도 [L1 승격 기록](../data/knowledge_cards/kb/20260930-C/l1-promotion-20261001.md)에 유지한다. 해당 정책 보류와 라우팅 오답은 이 보고서의 실패 2건을 해결한 것으로 해소되지 않는다.

## PR #125 CI 실패 후속 분석

[CI 실행 36818059850](https://github.com/hyjuy/ShiftLink/actions/runs/36818059850)의 pytest에서 2건 실패·628건 통과를 확인했다. 이전 로컬 검증 이후 PR 브랜치에 main이 병합되면서 A 카드 원본과 통합 검수표의 A 구간이 변경됐다.

| 실패 검사 | 원인 | 수정 |
| --- | --- | --- |
| `test_kb_cards_json_matches_batches` | 병합 결과의 A 원본과 저장된 통합 KB의 본문·해시가 달랐다. | 병합된 원본에서 `build_kb.py`로 통합 KB를 재생성했다. |
| `test_c_promotion_does_not_clear_policy_issues_or_approve_changed_cards` | C 승격 검증이 A·T4·C 전체 검수표의 해시에 묶여 있어, A 구간 변경만으로 C 19장의 승격 기록을 불일치로 처리했다. | C 카드별 검수 구간 해시를 기록하고 해당 구간과 카드 본문을 검증하도록 수정했다. |

승격 당시 커밋 `4ae9d80`과 병합 후 검수표를 비교해 C 19장의 검수 구간은 변경되지 않았음을 확인한 뒤 해시를 추가했다. 최초 전체 파일 해시와 기존 판정·근거·정책 보류는 보존했다. 검증 조건을 제거하거나 출처 승인 상태를 바꾸지 않았다.

새 회귀 검사 4건은 다른 구간 변경 시 승격 유지, C 본문 변경 시 차단, C 판정 변경 시 차단, C 구간 삭제 시 차단을 확인한다. 수정 후 전체 테스트 634개, C 배치 검증과 라우팅 기준 검사가 통과했다. 라우팅 수치는 dev 20/30, T4 7/20, sanity 29/30이다.
