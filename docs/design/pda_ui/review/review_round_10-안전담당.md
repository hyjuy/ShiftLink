## 감점 내역

### B1 안전 카드 최상단 고정 (-2 / 8)
- 근거: `pda.js:1132-1137`, `pda.js:1339`. 질의가 실패하거나(타임아웃 125초, Jetson 오류) 작업자가 취소하면 `show('ask')`로 돌아간다. 이때 대기 화면에서 로컬 `rankCards(eq).safety`로 보여 주던 안전 카드(`pda.js:1091-1097`)가 사라지고, ask 화면(`pda.html:401-425`)에는 안전 관문이 없다.
- 왜 문제인가: 단말에는 이미 해당 설비의 안전 카드가 있다. 그런데 LLM 경로가 실패하면 그 안전 카드를 버린다. 결국 응답이 없을 때, 즉 작업자가 시스템 없이 혼자 조치하게 될 가능성이 가장 높은 순간에 안전 조건이 화면에서 사라진다.

### B2 `safety_basis` 항상 펼침 (-1 / 5)
- 근거: `pda.html:161-162`, `.safety-stack{position:sticky; max-height:50vh; overflow-y:auto}`. 안전 카드 여러 장을 높이 50vh로 제한한 내부 스크롤 상자에 넣었다. 그래서 둘째 카드 이후의 `.basis`(`pda.js:788`)는 상자 안을 따로 스크롤해야 보인다. 데이터상 `safety_flag=true` 카드는 53건이고 그중 T5는 13건뿐이다(`kb_cards.json`). 한 설비 유형에 걸리는 안전 카드가 여러 장이 되는 것이 일반적인 경우다.
- 왜 문제인가: 접힘 버튼은 없다. 하지만 바깥 스크롤 안에 또 스크롤이 있는 구조라서 근거가 화면 밖으로 잘린다. 바깥 pane을 스크롤해도 그 근거는 드러나지 않는다. "생략 없음"이라는 기준을 구조적으로 어긴다.

### B3 미확정 설비 검색 차단 (-2 / 6)
- 근거: `pda.js:228`, `pda.js:250`, `pda.js:260-263`. 스캔 시간 초과와 Jetson 연결 실패 경로에서 `failScan → openManual`을 부르지만 `releaseContext`를 호출하지 않는다. 미등록 code 경로(`pda.js:245`)만 해제한다. 그런데 manual 화면은 무조건 "설비 미확정 · 확정되기 전에는 카드 검색이 수행되지 않습니다"라고 표시한다(`pda.html:357-360`). 「← 이전」(`pda.js:1331`)을 누르면 직전 설비가 확정된 상태 그대로 ctx로 돌아가 바로 검색할 수 있다.
- 왜 문제인가: 작업자는 "설비 변경 (다시 스캔)"(`pda.html:380`)으로 설비를 바꾸려 했다. 그런데 화면에는 미확정이라고 나오면서 실제 상태는 예전 설비로 확정되어 있다. 화면 문구와 상태가 갈라져, 바꾸려던 설비 대신 예전 설비로 검색이 나가는 경로가 생긴다.

### B4 안전이 선택지로 보이지 않음 (-2 / 6)
- 근거: `pda.js:582`. 증상 선택지에서 `tacit_type === 'T5'`만 빼고 `safety_flag`는 보지 않는다. 그래서 `safety_flag=true`인 T6 카드 K-1215(`kb_cards.json:4239`, `:4249`)가 「작업 전 확인」 그룹의 고를 수 있는 한 줄로 나온다(`pda.js:484`, `pda.js:653-658`). 다른 non-T5 안전 카드도 마찬가지다.
- 왜 문제인가: 루브릭 B1/D-26이 지적하는 "T5만 처리" 패턴과 같다. "끼임 비상정지 후 재가동 전" 같은 안전 전제 조건이 여러 선택지 가운데 하나로 보이므로, 작업자는 고르지 않고 넘어가도 되는 항목으로 읽게 된다.

## 감점하지 않은 것 중 위험 신호

- **서버 안전 공지의 설비 적합성을 검증하지 않음**: `pda.js:729-733`, `pda.js:735-739`. 서버가 보낸 `safety_notices`와 인용된 `safety_flag` 카드를 전체 `S.cards`에서 card_id로만 찾아 관문에 올린다. `cardFits(c, S.eq)`로 교차 확인하지 않는다. 카메라 경로의 질의는 `scan_id`로 나가고(`pda.js:707-708`) 서버가 설비를 따로 풀어낸다. `staleResponse`(`pda.js:1083`)는 로컬 `S.eq`끼리만 비교한다. 서버가 다른 설비로 풀면 그 설비의 안전 지침이 현재 설비 화면에 고정된다. 서버 쪽 `tools.py:83`이 해당 설비의 안전 카드를 모두 붙여 준다는 점에 기대고 있어 이번에는 감점하지 않았다. 다음 라운드에서 응답에 equipment_id가 있는지와 그 값을 대조하는지 확인할 것.
- **결과 화면의 안전 카드 집합 = 서버 공지뿐**: `pda.js:1128`. 로컬 `rankCards(S.eq).safety`를 결과에 합치지 않는다. 대기 화면과 결과 화면의 안전 카드가 서로 다를 수 있다.
- **URL 링크로 설비를 묵시적으로 확정**: `pda.js:107-108`. `?equipment_id=`가 붙으면 확인 단계 없이 `manual_selection`으로 확정한다. ctx에 code가 보이기는 한다.
- **「카탈로그에 없는 설비」 차단은 실질적으로 죽은 코드**: `pda.js:1060`. `S.eq`는 항상 `S.equipment`에서 오므로 이 조건은 참이 될 수 없다. `equipmentFrom`(`pda.js:75`)은 카탈로그에 행이 없는 구성 설비도 `row={}`로 받아들인다. D-41의 기준이 구성(config)이라면 문제가 없지만, 루브릭 문면은 "카탈로그 외"다.
- **대기 화면 안전 카드는 고정하지 않음**: `pda.js:1097`이 `safetyEl(c, false)`를 쓴다. sticky가 아니고 진행 단계 아래에 놓인다(`pda.html:431-437`). 안전 카드가 많으면 스크롤 시 관문이 시야에서 사라진다. **실측 필요.**
- **결과 화면 상단 고정 영역의 누적 높이**: #net(min 44px), #alert(최대 3행 × 52px 이상), #ctx, appbar 50px, safety-stack 50vh, disclaimer가 겹친다. 360×760에서 조치 카드와 「이 조치 시도」에 남는 높이가 얼마인지 **실측 필요**. 손으로 더해 판정하지 않았다.
- **안전 관문에 확인 행위가 없음**: `pda.js:904-909`. 「이 조치 시도」는 안전 관문을 확인하지 않아도 바로 누를 수 있다. 관문은 문구(`pda.js:784`)로만 표시된다. B4의 문면은 충족하지만, 실제로 관문 역할을 하는지는 다음 라운드에서 다시 볼 것.
- **일부 `safety_basis`에 조문 번호가 없음**: 예를 들어 K-1215(`kb_cards.json:4250`). UI는 원문을 그대로 보여 주므로 UI 감점은 하지 않았다. 데이터 쪽 확인 대상이다.
