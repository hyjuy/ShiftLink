## 질문

1. MES가 low/high로 판정한 신호를 결정적 문장으로 만들어 임베딩 검색 질의에만 덧붙이면(M1), 지금 S30h(M0)보다 최종 답이 나아지는가?
2. 그 위에 해당 설비의 활성 경보 화면 이름을 한 줄 더하면(M2), M1보다 나아지는가? 이것은 2차 비교이며 탐색용이다.
3. 단계 0: 질문 형태(경보형·알람형·수치형·증상형)에 따라 사건 조각이 정답 카드보다 먼저 잡히는가? M0 기록만으로 분석한다.

## 구성 (단일 변경)

| 구성 | 임베딩 질의 | 판정기 입력 | 답변 입력 |
|---|---|---|---|
| M0 | 원 질문 | 원 질문 + 조각 | 원 질문 + 근거 (S30h 그대로) |
| M1 | 원 질문 + low/high 상태 줄 | 같음 | 같음 |
| M2 | M1 + "MES 경보: <화면 이름>" | 같음 | 같음 |

**상태 줄 만드는 규칙** (`shiftlink/rag2/mes_ctx.py`의 `state_lines`)
- 해당 설비 observations에서 `*_state`가 low 또는 high인 신호만 쓴다.
- 형식: `<신호 이름> <값> <단위> (정상 <최소>–<최대> <단위> 초과|미만)`
- bool 신호 형식: `<이름>: <값> (정상 <값>)`
- normal, 누락, 유효하지 않은 신호는 쓰지 않는다. 시각은 쓰지 않는다.
- 덧붙일 줄이 없으면 질의는 원 질문과 바이트까지 같다.

**그대로 두는 것**
- 판정기·답변 프롬프트 양식, 모델, lo 0.3 / hi 0.9 / t 0.35277185049977805
- 색인·조각·출처 표시, 설비 필터, top 8
- 근거·경로가 달라지는 것은 검색 변경의 후속 효과이며, 별도 개입으로 보지 않는다.

**실행 방식**
- 운영 코드 `S30hPipeline.run`을 그대로 쓴다. 하위 클래스 `Probe`는 `evidence()`에 넘기는 문자열 하나만 바꾼다.
- 반복마다 같은 요청은 한 번만 계산하고 세 구성이 결과를 공유한다. 기준은 임베딩 텍스트, 판정 (질문, 조각 ID, 본문, 모델, ctx), 답변 프롬프트다.

## 기술 관문

- **T1 입력 동일성** (모델 호출 없음, `mes_ctx check`): N 48행에서 세 구성의 임베딩 질의가 원 질문과 바이트까지 같다. 실행 전 확인 결과 0건 불일치.

## 품질 관문 (A 48행, 최종 출력, 탐색적 선별 기준)

**보조 지표 (관문 아님)**
- 정답 카드가 후보·유지·인용에 들었는지
- 사건 조각이 유지·인용됐는지
- 상황별 개선·악화 수
- 질문 형태별 결과

**판정 규칙**
- 사람 판정은 반복 1의 결과로 한다. 반복 2에서 답이 달라진 행은 그 행도 판정한다.
- Q2–Q4는 두 반복 모두 통과해야 한다.
- 어느 관문이든 두 반복의 결론이 엇갈리면 "보류"다. 추가 반복으로 가르지 않는다.
- M2 대 M1은 같은 기준으로 보되 탐색 결과로만 보고한다.
- M0와 M1·M2의 답 요청이 같은 행은 자동으로 "같음"이며, 사람 판정은 요청이 다른 행만 한다.

**결론 문구 제한**
- 사건 오용이 줄어도 "검색 확장으로 사건 노출이 달라졌다"까지만 쓴다.
- 이 셋은 Claude가 만들었고 개발·평가에 한 번 쓴다. 성능 입증이 아니다.
- 통계는 기술 통계와 McNemar 정확 검정만 쓰고, "유의차 미검출"로 적는다.
