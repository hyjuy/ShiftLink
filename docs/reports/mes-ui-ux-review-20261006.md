# ShiftLink MES 화면 개선 요약

2026년 10월 6일 생산라인 대시보드 검토 결과를 반영했다. 이상 설비를 먼저 확인하고, 설비 상세에서 측정값과 복구 이력을 혼동 없이 읽도록 화면과 동작을 정리했다.

## 수정 내용

1. **관계선 클릭 영역**: 연결선의 투명 클릭 폭을 줄이고 장식용 선의 포인터 이벤트를 제거했다. 인접 연결선과 클릭 영역이 겹치는 문제를 줄였다. 연결 목록에도 출발·도착 설비를 명시한 연결 선택 버튼을 추가해 정확한 선택 경로를 제공한다. 키보드 선택은 유지한다.
2. **복구 단계**: 복귀 완료 뒤에도 중간 단계가 대기로 남던 표시를 고쳤다. 실제 완료 기록이 있는 단계만 완료로 표시하며, 기록 없이 복귀한 단계는 조치 기록 없음으로 구분한다.
3. **완료 사건**: 완료된 사건을 진행 중으로 부르지 않는다. 최근 복구 이력으로 접어서 표시한다.
4. **미선택 상세 화면**: 선택을 해제한 뒤 상세에 들어가도 이전 사건 설비를 자동 선택하지 않는다. 확인할 설비 목록을 제공한다.
5. **상세 진입 방식**: 라인 카드, 가동률 막대, 표의 설비명과 알람, 검색 결과, 우선 확인 항목은 해당 설비 상세로 이동한다. 관계도 노드는 연결을 선택하고 별도 상세 보기 버튼으로 이동한다.
6. **정보 배치**: 우선 확인 항목을 상단 요약 옆으로 올렸다. 시뮬레이션 제어와 연결선 범례는 접을 수 있게 하고, 설비 검색은 기본 노출한다.
7. **측정값 가독성**: 측정 위치와 기준 설명은 펼쳐보기로 정리했다. 설정 기준 범위와 데이터 품질을 구분하고, 부품 선택 후에도 측정표는 설비 전체 기준임을 명시한다.
8. **시간과 지표 기준**: 현재 시각과 모의 운전 시각을 구분한다. 누적 배출은 실행 시작 이후, 처리량·가동률·평균 이송 시간은 화면에 표시한 최근 모의 운전 구간 기준이다. 표본 부족 시 필요한 측정 횟수와 집계 안내를 표시한다.
9. **기록 재생**: 실행 목록을 최신순으로 표시하고 재생 위치에 시간을 추가했다. 알람 발생·해제와 복구 시작·완료 시점으로 이동하는 선택 목록을 제공한다. 모드 전환 시 이전 화면의 카드·표·연결 목록을 지워 새 기록과 섞이지 않게 한다.
10. **상태 색과 표**: 정상 가동률은 중립색으로 표시한다. 표에서 이상·대기·정지 설비를 모아 볼 수 있다. 해당 없음, 데이터 부족, 알람 없음도 구분한다.
11. **제어 안내**: 복구 버튼의 비활성화 이유와 새 시뮬레이션 시작 시 재클릭 안내를 표시한다.

## 용어 정리

| 기존 | 변경 |
|---|---|
| 선택 설비·조치 | 설비 상세·조치 |
| 지금 확인할 위치 | 우선 확인 항목 |
| 복구 진행 | 모의 복구 시작 |
| 새 실행 | 새 시뮬레이션 시작 |
| 확인 맥락 내려받기 | 설비 확인 보고서 다운로드 |
| 현재 관측 | 현재 측정값 |
| 관측 근거 | 선택 설비 전체 측정 정보 |
| 구성 범위 내·이탈 | 설정 기준 범위 내·이탈 |
| good | 데이터 품질: 양호 |
| 선 강조 | 연결선 강조 |
| 관측된 영향 대기 | 영향으로 대기 중인 설비 |
| 대기 작업 | 설비 내 코일 |
| 사이클 타임 | 평균 이송 시간 |
| started·paused·alarm_raised | 운전 시작·일시정지·알람 발생 |
| pct·degC·mm_s 등 설명 속 단위 | %·℃·mm/s 등 화면 단위 |

원문 이벤트와 데이터 식별자는 보존한다. 이벤트 화면은 한국어 요약을 먼저 보여주고 원문 기록을 펼쳐볼 수 있다. 보고서 다운로드 형식은 기존 JSON을 유지한다.

## 검증

관련 회귀 테스트 23개가 통과했다. JavaScript 문법 검사와 변경 파일의 공백 검사도 통과했다.

```sh
python -m pytest -q tests/test_mes_web.py tests/test_mes_operator.py tests/test_mes_recovery_web.py tests/test_mes_ui_layout.py tests/test_mes_sensor_semantics_ui.py tests/test_mes_observation_visibility.py
node --check shiftlink/mes/web/app.js
node --check shiftlink/mes/web/operator.js
```

별도 임시 DB를 사용하는 로컬 테스트 서버에서 브라우저로 다음 동작을 확인했다.

- 미선택 상세 진입 시 설비 목록 표시
- 라인 카드에서 해당 설비 상세로 이동
- GR-01 → RT-01 선 자체와 연결 목록 버튼에서 정확한 연결 선택
- 배전반 트립 발생 시 상단 우선 확인 항목 표시와 상세 이동
- 모의 복구 완료 후 이력 접기 및 미기록 단계 구분
- 저장 기록의 알람 발생 시점으로 이동

코드 변경 후 `graphify update .`로 AST 지식 그래프도 갱신했다.

## 적용 범위

대시보드 HTML·CSS·JavaScript와 관련 회귀 테스트를 변경했다. 센서 기준값, 모의 운전 엔진, 복구 판정 로직은 변경하지 않았다. 저장소에 푸시한 코드를 실행 서버에 반영하려면 해당 서버의 배포 절차가 필요하다.
