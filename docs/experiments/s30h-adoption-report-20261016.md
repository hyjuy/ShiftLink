## 결론과 팀 결정 요청

**S30h를 원문 RAG(RAG v2)의 시연·main 구성으로 제안합니다.** 10/13~10/16 실험에서 S30h는 사전등록 성공 기준을 처음으로 seed 3개 모두에서 충족했습니다(개발 셋 평균 답함 102.7/128, 거절 54/73). Jetson에서도 지연·메모리 기준 4개를 모두 통과했습니다(p95 9.78초, 가용 메모리 최저 1.26GiB). 이후 시험한 대안 9종은 S30h를 넘지 못했습니다.

대신 약점이 하나 있습니다. test30에서 현재 시연 구성(hybrid)보다 답 없는 질문을 덜 거절했습니다(11/19 대 17/19, p 0.031). 아래 결정이 필요합니다.

| 결정 | 내용 | 제안 |
| --- | --- | --- |
| 동결 해제 | 10/26까지 main 병합 금지(freeze-20261013) | **동결 해제 완료(사용자 결정, 10/16)** |
| 거절 약점 수용 | 답을 더 많이 하는 대신 거절이 약한 점을 시연에서 받아들일지 | 수용하고, 발표에서 그대로 밝힘 |
| Jetson 서비스 | 판정기 전용 Ollama 서비스 등록(sudo) | 등록 |
| 최종 확인 | 보류 셋 43문항 1회 실행 | 최종 사전등록 뒤 실행 |

모든 개발 셋 수치는 탐색 결과입니다. 차이가 유의하지 않으면 "유의차 미검출"로 적었고, 원인은 가설로 적었습니다.

**결정 기록 — 사용자 결정(10/16, 오케스트레이터 경유)**: 동결 해제, S30h를 시연용으로 main에 넣는 방향. 보류 셋은 Jetson에서 1회 평가하고, 결과를 본 뒤 채택을 다시 결정한다. 성공 기준은 실행 전에 rag-v2-log에 사전등록했다. 통합 PR 생성·push, 판정기 전용 서비스 등록(sudo), vast 인스턴스 정지는 아직 별도 확인 전이다.

## S30h 구성과 성능

S30h는 이미 배포된 v1 판정기가 근거를 걸러 주고, SFT 답 모델은 답만 쓰게 하는 모델 2개 구성입니다. 판정기가 판단의 대부분을 맡아서 SFT 모델의 seed 변동이 결과에 거의 남지 않습니다.

1. 검색: 구성 C(embeddinggemma, 700토큰 조각, 설비 폴더 필터)로 근거 최대 8조각을 고릅니다.
2. 거르기: 판정기(`exaone-sft-judge`)가 조각마다 2점 이상일 확률 P(≥2)를 냅니다. 0.3 미만은 버립니다. 남는 게 없으면 모델 호출 없이 거절합니다.
3. 경로: 남은 조각 중 최댓값이 0.9 이상이면 "답함"으로 고정하고 답만 쓰게 합니다. 그 밖에는 SFT 모델(ck106)이 판단하고, 판단 확률이 t = 0.35277185049977805 이상이면 거절합니다(반올림 금지).

## 비교한 대안과 한계

시험한 대안 중 성공 기준(답함 ≥ 98, 거절 ≥ 54/73, JSON 깨짐 ≤ 2, 근거 밖 숫자 ≤ 1)을 seed 3개에서 만족한 것은 S30h뿐입니다. 수치는 개발 셋(답 있음 128, 답 없음 73) 기준이고, 다른 셋은 표시했습니다.

| 대안 | 결과 (답함 / 정답 인용 / 거절) | 한계 |
| --- | --- | --- |
| 기본 모델만, 판정기 없음 (10/13, 이전 라벨) | 거절 13/78 | 답 없는 질문에도 거의 답함. 거절을 모델 스스로 못 함 |

| SFT 단독 (판단+답변 한 모델, ck106) | seed 평균 85.3 / 58.3 / 54 | seed에 따라 답함 70~98로 흔들림(학습 loss는 같음). 재현성 없음 |

- **판정기 C와 S30h의 차이**는 McNemar로 유의차 미검출입니다(답함 4:10, 인용 8:6). S30h를 고른 근거는 더 높은 점수가 아니라 품질 조건 충족과 seed 안정성입니다.
- **decider 계열의 한계(가설)**: 학습 라벨이 "답에 인용된 조각"입니다. 사람이 무작위 60개를 판정해 보니 관련 조각 26개 중 8개만 양성이었습니다(재현율 0.31). 학습 양성은 매뉴얼 62%인데 개발 셋 정답은 카드 76%이고, 이벤트 조각은 학습에 없었습니다. 라벨을 사람이 다시 만들기 전에는 개선이 어렵습니다.

## S30h의 한계와 위험

가장 큰 위험은 답 없는 질문에 답해 버리는 것입니다. test30에서 거절 실패 8건 중 6건이 판정기 확률 0.9 이상으로 답을 강제한 경로였습니다.

| 위험 | 근거 | 대응 |
| --- | --- | --- |
| 거절이 시연 구성보다 약함 | test30 거절 11/19 대 hybrid 17/19 (6:0, p 0.031). hybrid 재실행은 30/30 재현 | 발표에서 "더 많이 답하는 대신 거절이 약함"을 밝힘. 후속 개선은 보류 셋 뒤 |
| 개발 셋 낙관 | S30h는 개발 셋에서 7개 후보 중 골랐고 t도 개발 셋에서 정함. 교차 검사 반대 절반 거절 32/37, 22/36 | 보류 셋 43문항 1회로 확인(답 없음 8개라 거절 검정력은 낮음) |
| 실행 간 잡음 | 같은 모델·프롬프트도 원문 145~156/201만 같음. Jetson 판정 확률은 실행마다 최대 0.2 흔들림 | 답함 2개, 인용 1~2개 차이는 잡음으로 해석 |
| Jetson 여유 | p95 9.78초(기준 10초), 가용 메모리 최저 1.26GiB(기준 1.0) | 다른 모델을 함께 올리지 않음(VNC·데스크톱 끔) |
| 배포 복잡도 | 판정기 전용 Ollama 서비스가 하나 더 필요(sudo) | 팀이 서비스 등록. 실패 시 hybrid로 되돌림 |
| 아직 확정되지 않은 기준 변경 | lo/hi 격자 검증 기준을 "원문 201/201"에서 "근거·경로 일치 + 잡음 이내"로 바꿈(격자 결과 보기 전) | **기준 변경 — 팀 확인 필요.** 격자 결론(0.3 / 0.9 유지)은 그때까지 잠정 |

원문 RAG는 매뉴얼 페이지도 인용합니다. 그래서 카드 ID로만 채점하는 test30 지표(citation_hit)에서는 매뉴얼로 맞게 답해도 정답으로 잡히지 않습니다(test30에서 1문항).

## hybrid에서 S30h로 전환하는 계획

지금 S30h는 실험 브랜치(`exp/source-rag-20261013`)의 평가 스크립트로만 있고, MES 앱 파이프라인에는 연결돼 있지 않습니다. hybrid는 앱 안의 답변 모드라 환경변수로 바뀌지만, S30h는 앱에 먼저 구현해야 전환할 수 있습니다.

1. 팀 합의: 거절 약점 수용, lo/hi 검증 기준 변경 확인(동결은 10/16 해제 완료).
2. 보류 셋 43문항 1회 실행: 10/15 최종 사전등록 절차 그대로, S30h(Jetson 배포 구성)와 기준선을 비교. 결과와 관계없이 기록합니다.
3. Jetson 준비: 판정기 전용 Ollama 서비스(동시 2, 문맥 2048) 등록. ck106·embeddinggemma는 이미 디스크에 등록돼 있습니다.
4. 통합 PR: origin/main에서 새 브랜치를 만들어 필요한 부분만 옮깁니다. 검색 색인(조각·벡터), 판정 확률 경로, ck106 호출, 답변 모드 스위치입니다. PR은 사용자 확인 뒤에 엽니다.
5. 통합 후 확인: Jetson에서 시연 시나리오 예행(카메라 포함) 지연과 메모리를 다시 재고, 기준(p95 10초, 메모리 1.0GiB)을 다시 확인합니다.

**비상 대책(시연 직전 문제가 생길 때만)**: 답변 모드 환경변수를 hybrid로 돌리고, 판정기 전용 서비스를 멈추면 10/13 동결 상태(판정기 + `exaone-sft-answer` 상주)로 돌아갑니다. 모델은 모두 Jetson 디스크에 남겨 둡니다.

아직 정해지지 않은 것: 통합 작업량과 담당자, PDA 화면에서 매뉴얼 페이지 인용을 어떻게 보여줄지.
