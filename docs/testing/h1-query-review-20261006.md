# H1 연결부 리뷰와 `K-1001` 답 원인 분석 (2026-10-06)

> 작성: Claude(fork) · 기준: origin/main `212417a` · 대상: `POST /api/query`(질문 + 인식 설비 + MES 관측값 → FixedPipeline), #187의 남은 일 "Claude 연결부 리뷰"와 "answer가 `K-1001`뿐"
> 방법: 코드 읽기. 추가로 **로컬에서 질의 프롬프트를 모델 호출 없이 재구성해 길이만 쟀다**(Jetson·Ollama 접속 없음, 파일 변경 없음, 스크립트 `scratchpad/prompt_probe.py`). 코드는 수정하지 않았다.

## 요약

1. **연결의 정확성은 대체로 맞다.** 정답·시나리오 ID는 응답에 나가지 않고, 시뮬레이터 락은 모델 호출 전에 풀린다. 고칠 점은 인식 결과 만료 없음, 예외 처리 구멍, 첫 호출 때 락 안에서 KB를 읽는 것이다.
2. **`K-1001`만 나온 가장 유력한 원인은 프롬프트 구성이다.** 평가 질문은 관측값이 0~2개인데 시연 경로는 34개(JSON 2,385자)를 그대로 넣어, 프롬프트가 4,477자(토큰 추정 1.6k~2.6k)로 컨텍스트 상한 2048에 닿거나 넘는다. 여기에 질문이 카드 제목 그대로였고, 답 검증이 "비어 있지 않음"만 본다. 잘림은 아직 **증명되지 않았다**(기록에 `prompt_eval_count`가 없다).
3. **확인은 Jetson 1회(입회 필요)로 끝난다.** `prompt_eval_count` 기록 추가 → 같은 질의를 관측값 포함/제외로 2번 → 문장이 돌아오면 확정. 고치는 건 별도 PR 두 개(프롬프트 축소, 짧은 답 거절)이고 이 문서는 구현하지 않는다.

## 2. 인수 시험의 `answer = "K-1001"` 원인

### 2.1 사실

- 기록: `answer "K-1001"`, `cited ["K-1001"]`, `eval_count 31`, `latency_s 2.456`, `load_duration_s 0.004`(`artifacts/mes-h1-h2-20261002/jetson-acceptance.json`). 생성 토큰 31개는 `{"answer":"K-1001","cited_card_ids":["K-1001"]}` 정도 크기다. 모델이 문장을 쓰려다 실패한 것이 아니라 **처음부터 짧게 끝냈다**.
- 질문은 K-1001 카드의 **제목 문자열**이다: "기어·베인 펌프 출구 압력이 없을 때 확인 순서 — Algo A.1 좌측 분기"(`acceptance_smoke.py:43-44`). 자연어 질문이 아니다.
- 평소 Jetson 실행에서는 이런 답이 없다. 저장된 답 304건(final1002·guards1002·judge1002·blind3·T6) 중 **최단 71자, 중앙값 160자, ID만 있는 답 0건**이다. 모델이 늘 이렇게 구는 게 아니다.

### 2.2 가설

| # | 가설 | 근거 | 반증·한계 | 가능성 |
|---|---|---|---|---|
| A | **프롬프트가 너무 길어 컨텍스트에서 잘림** | 오프라인 재구성: 시스템 620자 + 사용자 3,857자 = **4,477자**. 그중 `관측값:` JSON이 **2,385자(62%)**, 관측값 34개(값 17개 + `_state` 17개). 평가 질문은 관측값 0~2개(dev 30문항 중 3개만, 최대 2개)라 평소 이 부분은 0~130자. 토큰 추정(한글 0.5~1.0, ASCII 0.30~0.45 토큰/자): **1,578~2,608**. `NUM_CTX = 2048`(`ollama.py:31`)에 닿거나 넘는다. 넘으면 프롬프트 일부가 잘려 규칙·답 형식 지시를 잃을 수 있다 | 토큰 수를 직접 못 쟀다. `last_call`에 `prompt_eval_count`가 없다(`ollama.py:317-326`). 추정 범위가 2048 아래일 수도 있다 | **높음** |
| B | 질문이 카드 제목 그대로라 답을 ID로 짧게 때움 | 입력과 "답변 후보 색인"의 제목이 같다(`ollama.py:247`, `:254-258`). 모델이 색인의 ID를 베끼는 가장 쉬운 완성이다 | 질문 모양이 평가 질문과 다르다는 것뿐 다른 증거는 없다 | 중간 |
| C | **문법·검증이 짧은 답을 막지 않음** | 출력 스키마가 `answer`에 `minLength 1`만 건다(`ollama.py:64`). 어댑터는 비어 있지 않으면 통과(`ollama.py:398-399`), 검증기도 같다(`response.py:216-217`). "한국어 두세 문장"은 프롬프트 지시일 뿐 강제가 아니다(`ollama.py:80`) | 이것만으로는 모델이 왜 짧게 냈는지 설명이 안 된다. **통과시킨 이유**는 설명한다 | 높음(통과 원인) |
| D | 안전 카드·관측값 블록이 모델 주의를 분산 | 안전 참고 카드 3장 제목이 프롬프트에 들어간다(재구성에서 K-1003·K-1006·K-1218, `ollama.py:260-263`) | 평소 실행에도 같은 블록이 있다 | 낮음 |
| E | 재시도 문구·판정기 영향 | `model_call.retry false`, 판정기는 점수만 낸다 | 직접 관련 없음 | 낮음 |

### 2.3 결론

가장 유력한 것은 **A(프롬프트 과대)가 원인이고, C(검증 부재)가 그것을 통과시켰으며, B(제목을 질문으로 쓴 시험)가 계기**라는 조합이다. 시연 경로는 평가 때와 입력 모양이 완전히 달라서(관측값 0~2개 → 34개) **지금까지의 Jetson 평가 수치가 시연 경로의 품질을 대표하지 않는다**는 점이 더 중요하다.
