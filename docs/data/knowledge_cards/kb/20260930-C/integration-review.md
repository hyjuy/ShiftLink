# 배치 C — 프로젝트 통합 전 충돌 검증

2026-09-30. **판정: 런타임 기본 호환, KB 편입 준비 미완료.**

후속 반영: 출처 52개는 기준 ID로 등록됐고 계보 7개는 후보로 기록됐다.
중복 dev 5건은 활성 평가에서 격리했다. 승인·활성 그룹 배정·독립 반복 근거는 아직 보완 대기다.
아래 충돌 표는 반영 전 발견 기록이다. 현재 카드·검증 동작은 [상위 계약 반영](policy-alignment.md)과
[독립 재검증](policy-alignment-review.md)을 기준으로 확인한다.

서로 다른 서브에이전트 3명이 런타임, 출처·분할 정책, 사람 검수·승격 도구를 독립 검증했다.
현재 mes/develop 기준이며 운영 코드·기존 KB·출처 승인·사건 배정은 변경하지 않았다.
스키마 검증 통과와 프로젝트 출처·분할 계약 준수는 별도이다.

## 통합을 막는 항목

| 항목 | 확인한 충돌 | 필요한 조치 |
|---|---|---|
| 출처 승인 | PDF 7개와 사건/기록 45개의 source_id가 현재 등록부의 기준 ID에 없고 승인된 절·발췌 해시가 연결되지 않음 | 실제 문서 식별 후 기준 ID와 승인 범위·검토 이력을 연결. 기존 다른 판본 ID를 임의 재사용하지 않음 |
| 분할 계보 | 사건 누출 그룹 등록 없이 KB15/dev5를 사건별로 배정 | 합성 원형·템플릿 계보를 확정하고 상위 계약에 맞춰 그룹 단위로 배정 |
| 평가 중복 | KB/dev work_note 정확 동일 8쌍, 정규화 후 인계 포함 16쌍. dev 5건 모두 KB 템플릿 파생 | EV-0416~0420을 독립 평가로 사용하지 않음. 원형이 독립적인 새 평가 기록 또는 계약에 맞는 재분할 필요 |
| 반복 근거 | KB 사건 6쌍의 work_note가 동일 | 서로 다른 ID를 독립 현장 경험으로 계산하지 않음. 근거 추가 또는 적용 주장 제한/보류 |

현재 파일은 보완 대기 자료로 유지한다. 사람의 카드 내용 승인만으로 이 정책 충돌이 자동 해소되지는 않는다.
출처 승인이나 그룹 ID를 임의로 만들고 승인 처리하지 않았다. 기존 KB에는 여전히 C가 포함되지 않는다.

## 통과한 호환 검사

- 19장 모두 KnowledgeCard 스키마 및 실제 로더에서 파싱. 기본 로드 0장, draft 포함 19장.
- accepted/L1 메모리 복제 19장도 실제 로더에서 정상 처리. 운영 파일의 승인 상태는 바꾸지 않음.
- 기존 accepted KB 41장과 메모리 결합 시 60장, 카드 ID 중복 없음.
- T2 10장 MES 신호·설치 위치·good/bad 품질·일치/불일치/미관측 조건 동작 확인.
- 조회한 기존 docs/data JSON 156개에서 Event/Artifact 정의 ID 충돌 없음. 평가·봉인된 자료는 의미 내용을 열지 않아 전역 무충돌 보증은 하지 않음.
- 원본 프롬프트 3개 해시, KB 관측 투영의 정답 제외, dev 직접 인용 0.
- 기존 관련 테스트 **175 passed in 3.54s**: schemas, card_lint, card_loader, kb_cards, mes_card_adapter, retrieval_response, generation.

Python 3.10.21 / Pydantic 2.9.2 / pydantic-core 2.23.4에서 확인했다. 기존 의존성 파일은 변경하지 않았다.

## 수정한 배치 도구

1. `build_docs.py`: 재생성할 때 사람이 입력한 판정 근거를 보존한다.
2. `verify.py`: draft/L0와 accepted/L1을 구분해 허용하고, KB 관측·기록 투영의 내용이 원장과 정확히 일치하는지 검사한다.
3. `merge.py`: 스키마, 19개 계획 슬롯, 유형·설비, 원본 프롬프트 해시와 고정 인덱스를 먼저 검사한 뒤 파일을 쓴다. 훼손된 출력이나 변경된 프롬프트를 새 인덱스로 덮어 감추지 않는다.

각 수정의 실패 재현·재검증은 [워크플로 검증](integration-workflow-review.md)에 기록한다.
위 도구의 PASS는 출처 승인·그룹 계약·독립 평가 승인을 뜻하지 않는다.

## 사람 검수에 추가할 검색 제약

T6 9장은 조건이 비어 있고 safety_flag=true여서 재가동 이외 질문에도 안전 검색으로 병합된다.
HPU 필터 질문에서도 K-1211·K-1218의 실패 기록 4건이 표시됐다.
`verified`는 검색 조건을 통과했다는 뜻이며 실제 정비 완료·기동 허가 확인이 아니다.
`safety_review=null`도 로더의 차단 조건은 아니다. 표시 범위를 수용할지, 별도 응답 경로 변경이 필요한지 검토해야 한다.
안전 표시를 제거하거나 관측할 수 없는 재가동 신호를 지어내어 이 동작을 숨기지 않았다.

RT 카드는 RT-03(EQ-0008) 범위다. RT 별칭은 RT-01을 선택하므로 검수 시 RT-03을 명시해야 한다.
T2의 표시기·소음·실제 차단 등 수동 분기는 MES가 자동 검증하지 않는다.
기존 card_lint는 스키마 위반 0건과 검토 경고 2건을 반환했다: K-1201의 안전 표현/표시,
K-1210의 재가동 표현/T2 경계다. 이 도구는 키워드 기반 자문이므로 임의로 safety_flag나 유형을 바꾸지 않았다.
