# 운전·부하 정상 기준 보완 — Pi 검증·적용 기록

2026-10-23. 기존 v14c 원본 core/settings, 과거 평가와 r1/r2/r3 릴리스를 보존하고 별도 정상 기준 후보를 만든다. 생성·적합·회귀·재생·부하 검사는 Raspberry Pi에서 실행한다. PC는 편집·Git·전송에만 사용한다. 운영 MES에 고장을 주입하거나 기존 경보를 확인·해제하지 않는다.

## 확인된 원인과 수정

기존 연구 정상 분포와 운영 합성 MES 정상 분포가 달랐다. 원인 분석용 2,902프레임에서 정상 상태인데 HPU와 두 CV에 통지가 반복됐다. 예를 들어 냉각기 오일 출구 41.513℃·냉각수 출구 27.123℃·빈 CV 대기율 0%는 구성상 정상 범위 안이지만, 연구 중심값 46.4395℃·29.9715℃·약 35%와 달랐다. 40개 선행 프레임도 good 품질·운전 중·normal 상태·해당 MES 경보 없음이었다. 생성기와 실제 물리 설비의 정상 여부를 동등하게 보지는 않는다.

## 자료 분리와 평가의 범위

[사전 계획](../research/mes-context-v1-prereg-20261023.md)의 통과 기준을 유지한다. 정상 학습은 9조건 × MesEngine/SignalDynamics 정상 경로 × 4실행 × 224프레임 = 16,128프레임이다. 9개 속도·부하 조건과 속도 미상 3조건의 기준을 계산하되, 속도 미상 자료는 같은 정상 학습을 합친 것으로 독립 표본 수에 더하지 않는다.

고장은 별도 additive/hold/독립 코일 개입으로 만들며 탐지기의 PATTERNS/FaultSchedule을 사용하지 않는다. 오일/냉각수 냉각 이상, 누설, 마찰, 진동 고착, 보정 대상 출구 온도 고착, 대기율 불일치, 실제 코일 정체를 비교한다. 라벨·active_alarms를 정상 부하 선택에 사용하지 않는다. 정상 생성 일부와 구성은 공유하므로 현장 일반화의 증거로 설명하지 않는다.

개발 자료는 알려진 속도 24고장+6정상, 속도 없는 replay 24고장+6정상, 정상 전환 6실행이다. 후보와 평가 코드를 SHA256으로 고정한 뒤 12조건의 새 96고장·24정상·6정상 전환, 총 126실행·28,224프레임을 생성한다. train/개발/전환/replay개발/test의 run_id·seed·nonce 비중복을 검사한다.

정상 오통지는 별도 정상 실행의 통지 수다. 비매칭은 고장 실행에서 목표 설비·고장 시작~종료 구간에 매칭되지 않은 통지이며, 고장 전 정상 구간과 다른 설비의 통지도 포함한다. 이번 단독 개입 자료의 비매칭을 실제 파급 반응으로 단정하지 않는다. 두 수치를 합치지 않고 모두 보고한다. 지연은 합성 개입 시작 기준이며 통신·대기·PDA 렌더를 포함하지 않는다. 동일 검출 사건의 지연 차이와 전체 검출 사건의 p95는 구분한다.

## 실패 보존

첫 후보는 개발 24고장 중 5건·정상 통지 59건으로 실패했다. 조건별 통계가 추가된 v2는 21/24·정상 통지 21건이었다. 정상 자료 확장·정체값·온도 상승 보정 v3는 21/24·정상 통지 0건이었지만 CV 정상 정체값 예외가 실제 정체도 가렸고 기존 검출 사건의 지연 기준을 통과하지 못했다. v4에서 CV 독립 코일 근거와 정상 진동의 고착 창을 보완했다. 이후 1~2프레임 코일 불일치의 즉시 통지 RED를 재현하고 최종 후보에서 지속 여부를 확인하도록 고쳤다. 각 후보의 코드·profile·결과를 별도 경로에 보존한다. 미사용 평가를 만들기 전 수행한 개발 과정이다.

## 배포와 운영 경계

운영 기준은 r3-c6c8872다. PR #343이 병합된 것을 확인한 뒤 최신 main의 POSIX fsync 및 기존 동작을 통합했다. 새 후속 PR의 변경은 정상 기준 후보·profile·검증과 worker 연결이다. 기존 PDA 디자인·버튼·용어·active_alarms·확인·배지·진동은 변경하지 않는다. 같은 알람창의 무음 AI 참고 정보 계약과 정지 전 감지 이력 계약을 유지한다.

새 worker는 기존 출력 `/run/shiftlink-analytics/latest.json`과 별도 `/var/lib/shiftlink-analytics-normal-v1`을 사용한다. 기존 `/var/lib/shiftlink-analytics`와 STOP 스위치를 보존한다. 새 profile 해시가 맞아야 시작한다. 릴리스 manifest의 파일과 기존 worker unit 해시를 검사해 동시 수정 덮어쓰기를 차단한다. PDA 파일이 같으면 교체·재시작하지 않는다. 이전 unit과 state로 되돌릴 수 있도록 영구 백업을 남긴다.

실측 센서 정확도와 실제 물리 고장의 미탐 여부는 이 검증으로 확정할 수 없다. 정상 조절 상태와 같은 값으로 고착된 센서는 추가 기준 센서나 운전 변화 없이 구분하기 어렵다. 전체 경로 1초 완료와 고장→PDA 표시 p95도 별도 미검증이다.
