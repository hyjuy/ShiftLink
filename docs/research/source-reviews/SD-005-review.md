# SD-005 원문 범위 검토 — B. 보완 대기

## 1. 검토 요약

**판정은 B. 보완 대기다.** 로컬 원문의 관련 절과 요약의 내용 대응은 확인했으나 공식 원본 계보, 2026년 개정 자료와의 대조, 정확한 텍스트 이용 범위를 확정하지 못했다. A. 초안 생성용 승인 가능으로 판정한 범위는 없다.

| 항목 | 결과 |
| --- | --- |
| 대상 | `SD-005` (별칭 `S-02`) |
| 문서 | 한국산업안전보건공단, 「컨베이어의 안전에 관한 기술지침」, `KOSHA GUIDE M-101-2012` |
| 판본 표시 | 표지 `2012. 6.`, 개요 공표일 `2012년 6월 20일`. 작성자 김건남, 개정자 안전연구실 |
| 로컬 원문 | `docs/sources/safety/M-101-2012 컨베이어의 안전에 관한 기술지침.pdf` |
| 생성 목적 | CV·RT 관련 카드의 초안 생성 근거 후보 검토. 주로 T5·T6, T4는 일부 배경만 검토 |
| 선정 범위 | §2; §4.3(1)(7)(9)(10)(11)(13)(14); §5.1(8); §5.9(2)(3) |
| 선정 이유 | 사용 조건, 위험 우려 정비, 비상·사고정지 후 확인, 테이크업 방호, 롤러 복귀 안내가 이전 탐색의 CV·RT 공백과 직접 연결됨 |
| 검토 전용 모드 | `registry_change=null`. `review_status=pending_review`, `approved_scope=[]` 유지 |
| 실제 원문 검토자 | 서브에이전트 `/root/sd005_source_review` |
| 원문·공식 출처 검토 시각 | `2026-09-22T15:45:13+09:00` |
| 요약 대응·코드 계약·해시 검사 | 상위 에이전트 `/root`, `2026-09-22T16:04:56+09:00` |

이번 판정은 **초안 생성 입력의 사용 가능 여부**에 관한 것이다. 현장 작업 허가, 법적 적합성 판단, 안전 절차 최종 승인, 카드의 accepted/L1 또는 safety_review 승격과 별개다. 사람·현장 전문가·안전 담당자가 검토했다고 기록하지 않았다.

요청의 옛 경로는 실제 파일로 대조했다. 계약은 [현재 출처·분할 계약](../../data/policies/source-and-split-contract.md), 원문은 위 `docs/sources/safety/` 경로에 있다. [생성 가이드](../../guides/card-generation.md), [등록부](../../../seeds/source_registry.json), [배정표](../../../splits/prototype_split.json), [작성 가이드](../../../seeds/카드_작성_가이드_초안.md), [생성기](../../../shiftlink/data/generation.py), [스키마](../../../shiftlink/agent/schemas.py)를 관련 범위에서 확인했다. 사건·정답·holdout 파일은 열람하지 않았다.

## 3. 허용 주장 후보와 제외 범위

아래는 **본문이 뒷받침하는 내용 후보**다. `allowed_claims` 후보를 작성했지만 사용 승인은 아니다. 원문 요약, 프로젝트 합성 설정, 검토자의 제한 판단을 분리했다. 요약에는 프로젝트의 수치·인터록·사건 사실을 섞지 않았다.

| 항목 | 원문 위치와 내용 후보 | 적용·제외 조건 |
| --- | --- | --- |
| C01 | §2, 인쇄 p.1/PDF p.3; §4.3(1), 인쇄 p.5/PDF p.7. 적용 범위와 설계·취급설명서의 용도/조건 준수 | 특정 설치 모델·운전 수치를 제공하지 않음. 조건이 언급되었다는 이유만으로 T2로 분류하지 않음 |
| C02 | §4.3(7), 인쇄 p.5/PDF p.7. 비상·사고정지 후 기동 전 원인과 보수상황 확인 | 정상정지 전체에 확대하지 않음. 확인 완료가 재가동 허가·성공을 뜻하지 않음 |
| C03 | §4.3(9), 인쇄 p.6/PDF p.8. 위험 우려 정비 시 정지와 작동 방지 | 위험 우려 조건 보존. 비상정지와 격리 구분. 차단·잠금·방압 지점/순서·검증 수치 창작 금지 |
| C04 | §4.3(10)(11), 인쇄 p.6/PDF p.8. 덮개 개방·올라가기 제한과 단서 | ‘부득이’를 임의 접근 허가로 축약하지 않음. 필요한 안전조치를 추정하지 않음 |
| C05 | §4.3(13)(14), 인쇄 p.6/PDF p.8. 작업 전 교육과 업무일지 비치·작성 | T4의 수신 역할·인계 시점·채널·확인 방법 전체를 채울 근거는 없음. 기록 항목·보존기간 창작 금지 |
| C06 | §5.1(8), 인쇄 p.7/PDF p.9. 위험 우려 테이크업 장치 및 중력식 추의 방호 | 벨트/중력식 조건을 보존. 유압식 텐셔너에 동일 적용하거나 장력 설정값·정비 순서를 생성하지 않음 |
| C07 | §5.9(2), 인쇄 p.13/PDF p.15. 분기·상승 중 해당 롤러 직전의 화물 정지 구조 | 현장 인터록 시험 절차·걸림 제거 순서가 아님 |
| C08 | §5.9(3), 인쇄 p.13/PDF p.15. 사용 전 상태 복귀 필요의 표시·주지 | 복귀 대상·순서·허용치·정지 유형·성공 결과는 제시되지 않음. 실제 실패 경험을 만들지 않음 |

본문·단서를 확인했지만 **이번 생성 입력 후보에서 제외한 범위**:

- **§4.3(12)**: 인쇄 p.6의 `4.2항(11)호의 통로` 참조를 확인했다. 참조 대상 §4.2(11), 인쇄 p.4는 통로 위 컨베이어의 낙하 방지 설비를 다룬다. 이를 오기로 확정하거나 다른 번호로 바꾸지 않는다. 허용 통로의 완전한 요건으로 해석하려면 공식본과 추가 검토가 필요하다.
- **§5.9(1)**: 인쇄 p.13의 `1.8 m 초과` 또는 낙하 위험 조건, 적재·반출장소 예외를 이미지로 확인했다. 현재 설비의 설치 면제·법적 임계값으로 전용할 근거가 없어 이번 요약에서는 수치와 해당 주장을 제외했다.
- **전 문서의 나머지 절**: 해당 범위를 승인한 것으로 확대하지 않는다. T1 징후 해석, T3 원인 구분 절차, T6 실제 시도·실패 기록은 이번 범위로 새로 만들지 않는다.

검토자의 제한 판단은 “현재 적용성·권리 확인이 부족하므로 생성에 사용하지 않는다”이다. 이는 원문이 그 자체로 생성 정책이나 ShiftLink의 작업 절차를 규정한다는 뜻이 아니다.

## 4. 생성 입력 자료 — 사용 보류된 후보

정확한 텍스트·문장별 원문 대응·메타데이터는 [SD-005-review.json](SD-005-review.json)에 저장했다. **원문 전문을 복제하지 않고 검토 요약 후보를 기록**했다. 이 요약은 생성된 카드나 모델 답변을 별도 원문으로 등록한 것이 아니며, 원문 `SD-005`와 위치에 연결된다.

| JSON 위치 | 의미 |
| --- | --- |
| `excerpts_candidate[0].text` | 실제 전달 후보 텍스트. 원문 발췌가 아닌 검토 요약 8개 문장군. 현재 생성 전달은 보류 |
| `text_kind` | `reviewer_summary`. 현재 `Excerpt`에는 없는 설명 메타데이터이므로 excerpts 항목 안에 넣지 않음 |
| `claim_to_source` | C01~C08과 원문 절·인쇄/PDF 페이지의 대응 |
| `scope_candidate_not_approved` | 현재 생성기의 `ApprovedScope` 키를 사용한 **미완성 후보**. `use_scope=null`이므로 유효한 승인 범위가 아님 |
| `registry_change` | `null`. 실제 등록부 변경 없음 |
| `observed_registry_state` | `pending_review`, `approved_scope=[]` |
| `generation_request` | `null`. 카드 ID·버전·생성 그룹·작성자·모델·confidence/근거를 임의 생성하지 않음 |

후보의 `source_id=SD-005`, `scope_id=sd005-m101-2012-cvrt-review-20260922`, `evidence_id=E1`이다. `scope_id`는 보고서용 후보 식별자이며 등록부에 존재하는 승인 범위가 아니다.

**후보 텍스트 SHA-256**:

```text
da2683d4d6b2b615b963007fccc3c82f8a79cceb2fbf3874bc655cab5d420fcb
```

계산 대상은 JSON을 파싱한 뒤 얻는 `excerpts_candidate[0].text`의 **UTF-8 1,885 bytes**다. 문장군 사이는 LF, BOM 없음, 마지막 개행 없음. JSON 파일의 들여쓰기·인코딩된 `\n` 표현·파일 끝 개행은 계산 대상이 아니다. PDF 전체 해시와도 다르다. 마지막 개행을 추가하면 해시가 달라지는 것을 확인했다.

`reviewed_by=/root/sd005_source_review`, `reviewed_at=2026-09-22T15:45:13+09:00`은 실제 서브에이전트의 본문 검토 기록이다. **사람의 승인 기록이 아니며 `use_scope`를 확인했다는 뜻도 아니다.** `allowed_claims`·`exclusions`에 내용 판단은 기록하되, 불명확한 사용권한을 그럴듯한 문자열로 채워 승인 형식을 통과시키지 않았다.

**approved_scope 변경안은 현상 유지다.** 보완 이후에도 `use_scope` 하나만 채우고 자동 적용하지 않는다. 공식 원본·판본 선택·본문 대응·사용권한·계보·텍스트 해시 및 승인 반영 권한을 다시 확인해야 한다. 새 판본을 선택하거나 요약을 수정하면 위치·주장·제외 조건·해시도 재검토한다.

추후 정식 승인을 별도로 받은 경우에만 `excerpts_candidate`의 항목을 생성 요청의 `excerpts`에 옮길 수 있다. 전체 검토 JSON은 생성기 요청 형식이 아니므로 그대로 전달하면 안 된다. 일반 배경 범위의 `group_id=null`과 최종 `DraftRequest.group_id` 필수 요건은 서로 다른 위치의 계약이다.

| 판본 선택 미확정 | 포털의 B-M-33-2026은 확인했으나 전문·개정 연계표 미확보 | KOSHA 공식 원문 확보 후 선택 절을 대조. 현재 생성 목적에 구판이 필요한지 검토 담당자가 결정 |
| 이용조건 미확정 | 정확한 요약·발췌의 저장, 생성 입력 전달, 재배포 범위 | KOSHA 정책/대상 문서의 표시 또는 권리 담당 확인. 공개 열람·공공기관 발행만으로 허용 판정하지 않음 |
| 현장 규칙 미확정 | 실제 장치 유형·격리점·기계적 지지·승인권자·정상 복귀 조건 | 기계/전기 보전, 설비기술, 안전 담당의 적용 매뉴얼·SOP·설비 식별 자료 필요. 공개 문헌으로 현장 사실 대체 불가 |
| 인계 규칙 미확정 | 수신 역할·시점·전달/확인 방식 | 생산·보전 인계 SOP 필요. 업무일지 조항만으로 T4 필수값을 창작하지 않음 |
| 실패 근거 부족 | 실제 시도·관측 결과·실패 원인 | 사용 허가된 별도 사건 원문 필요. sealed/holdout 정답을 보완 자료로 사용하지 않음 |
| 원문 참조 불명확 | §4.3(12)의 통로 참조 해석 | 원문 담당/전문가 확인 전 입력 제외. 임의 정정 금지 |
| 코드·계약 대조 | 계약의 구현 전 설명과 현재 생성기의 상태 | 계약 첫머리가 후속 구현 및 과거 설명임을 명시함. 현재 입력은 코드·생성 가이드가 일치하며, 이번 범위에서 임의 해결이 필요한 실행 계약 충돌은 발견하지 못함 |
| 코드 검증의 한계 | `use_scope`는 문자열, 해시는 바이트 동일성만 검사 | 권리·판본·문장의 의미·검토자 신원을 코드 통과로 증명하지 않음. 승인 범위의 사실 검토를 별도로 유지 |

`B`는 보고서 판정값이다. 등록부·스키마에 새 상태를 추가하지 않았다. PDF가 존재한다는 사실, 요약 내용이 대응한다는 사실, 초안 입력 사용 승인, 현장 작업 승인 사이의 경계를 유지했다.

## 6. 검증 결과와 변경 파일

| 검사 | 결과 |
| --- | --- |
| JSON | 현재 생성기의 `_read_json`으로 엄격 파싱 통과 |
| Excerpt 필수 필드 | `Excerpt.model_validate` 통과. E1/SD-005/후보 scope_id 및 공백 아닌 text 일치 |
| 원문 위치·예외 | 서브에이전트가 선택 절과 페이지 이미지 대조. C05의 업무일지 **비치**를 보완했고 C06의 위험 우려·방호 수단을 명확히 함 |
| 텍스트 해시 | `hashlib.sha256(text.encode('utf-8'))`와 생성기 `_hash` 모두 위 해시와 일치. 개행 변경 시 불일치 확인 |
| ApprovedScope | **예상된 거부**: `use_scope`가 미확정 null이라 `string_type / Input should be a valid string`. 다른 필드 형식 오류는 발생하지 않음. 따라서 ‘생성 계약 전체 통과’ 아님 |
| 전체 DraftRequest | **예상된 거부**: excerpts만으로 검사했을 때 `card_id`, `version`, `group_id`, `persona_id`, `model_version`, `confidence`, `confidence_basis` 누락. 완전한 요청을 만들지 않음 |
| 계보·split | background/null/[] 확인. 배정표의 버전과 그룹 ID 중복 부재 확인. 최종 생성 그룹 미제공·미배정. sealed 사건 및 정답 미열람 |
| 현재 출처 차단 | 등록부 SD-005는 pending_review. `_prepare`의 출처 승인 검사(생성기 126~130행)에 의해 차단되는 상태임을 코드로 확인. `_prepare`나 생성 파이프라인은 실행하지 않음 |
| 변경 방지 | 등록부·배정표·계약·가이드·스키마·생성기·PDF의 작업 전후 SHA-256 불변 확인. 각 해시는 JSON의 `input_file_sha256`에 기록 |
| 실행 환경 한계 | 묶음 Python의 **Pydantic 2.13.5**로 현재 소스의 모델 검증 수행. requirements의 고정값 **2.9.2** 환경은 확인하지 못함. 프로젝트 venv 없음, 시스템 python3는 `ModuleNotFoundError: No module named 'pydantic'`. 의존성 설치/수정 안 함 |
| 미실행 | 카드 생성, `generate_draft`, 생성 요청 전송, DB 기록, 외부 모델 호출, 승인 반영 모두 수행하지 않음 |

실제 실행한 검증은 pypdf 본문 추출, pdftoppm 렌더/페이지 보기, SHA-256·파일 크기 대조, 공식 웹 문서·포털의 일반 검색/열람, 위 Pydantic 모델 및 해시 검사다. 검사에는 묶음 Python 실행 파일과 `PYTHONDONTWRITEBYTECODE=1`을 사용했다. 원문 모델의 일부만 검증했으므로 카드 생성·출력 검증까지 성공했다고 주장하지 않는다.
