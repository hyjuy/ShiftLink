1. 실험 계획

9/29 벤치마크에서 exaone에 후보 5장을 주면 모델 1순위 인용 정답이 8/30, 검색 1위는 27/30이었다. 모델의 고르기를 프롬프트로 살릴 수 있는지, 아니면 빼야 하는지 확인했다.

2. 진행

오전에 Jetson이 두 번 다운됐다 (원인: llama-server RAM 프롬프트 캐시, 장애 보고서). 다운 뒤의 요청은 "인용 없음"으로 잘못 세져 exaone v2~v4를 무효 처리하고 다시 돌렸다. 실행 스크립트는 방식마다 앞뒤로 Jetson 연결을 확인하게 고쳤다. 10:35 설정 적용 후에는 우회 없이 돌렸다.

검색 1위가 틀렸는데 모델이 맞힌 문항은 Q-019 하나뿐이다 (검색 K-1012, K-1013, K-1010 중 3위 K-1010을 고름). 반대로 검색 1위가 맞았는데 다른 카드를 고른 문항은 실행마다 6~26개였다 (exaone 6~23, qwen 19~26).

4. 해석

  • 모델은 고르기를 잘하지 못한다. 가장 좋은 exaone v3도 검색 1위보다 5~6문항 낮다.
  • 좋아진 방식은 사실상 "1위를 고르게 만든" 방식이다. v2·v3에서 늘어난 정답만큼 1위 선택이 늘었다.
  • 카드 ID로 보여 주면 4번째 후보로 쏠린다 (base·v1, 두 모델 공통). 원인은 확인하지 않았다.
  • qwen은 모든 방식에서 exaone보다 낮고 대체로 느리다. 답변 문장 품질은 따로 본다.

5. 결정과 반영

  • shiftlink/edge/ollama.py: QUERY_MAX_CANDIDATES = 1. 질의 모드에서 검색 상위 1장만 후보로, 인용 enum도 그 1장. 안전 참고 카드는 그대로.
  • 검색(k=5)과 평가용 ranked_cards는 그대로라 route_score는 바뀌지 않는다.
  • 테스트: 여러 장 경로 3개는 상한 5로 계속 확인, 1장 테스트 추가. pytest 552 통과.
  • 실제 모델 확인 (exaone, 같은 31문항): sel@1 28/29, p50 4.2초, p95 4.7초, 검토 대기열 0.
  • 브랜치 feat/query-single-candidate (31e28dd)는 별도 PR.

6. 한계

  • 문항 31개 중 20개는 카드에서 만든 벤치마크 문항이다. 블라인드 질문으로 다시 볼 필요가 있다.
  • 카드 62장 기준이다. #115(배치 C) 이후 검색 1위 정확도가 바뀔 수 있다.
  • 답변 문장 품질은 보지 않았다. 인계 모드는 범위 밖이다.

7. 후속 실험: T4 근거 검색 실측 (인계 모드)

#114의 근거 문장 가중치 0.5는 오프라인에서 인계 질문 16개 중 상위 5장 정답을 8 → 11개로 늘렸고 1위는 4개 그대로였다. 실제 모델이 늘어난 후보에서 정답을 인용하는지 본다.

항목계획

모델exaone3.5:2.4b

7-2. 해석

  • 근거 문장 가중치는 검색에서만 효과가 있다. 상위 5 정답 8 → 11이지만 모델 인용 정답은 ①·② 모두 2.
  • 인계 모드에서 모델은 5번째 후보로 쏠린다 (① 13/16). 질의 모드의 4번째 쏠림과 같은 순서 편향.
  • 후보 1장이 가장 낫다 (③ 4/16 = 검색 1위). 남은 문제는 검색 1위 정확도(4/16)다.
  • 답 없는 4문항을 하나도 "모름"으로 처리하지 못했다. 3개는 검색 결과가 비었는데 인계 안전 카드 K-1103을 인용했다. 질의 모드와 달리 인계 모드에는 "검색 결과 없음 → 모델 호출 없이 해당 지식 없음" 처리가 없다.

7-3. 판정과 후속

판정 기준결과결정
①이 ②보다 인용 정답이 같거나 많고 답 없는 처리가 나빠지지 않음2 = 2, 0/4 = 0/4가중치 0.5 유지
③이 ①보다 인용 정답이 많음4 > 2인계 모드도 후보 1장
  1. 인계 모드 후보 1장 — #119에 함께 반영 (승인 후)
  2. 인계 모드에서 검색 결과가 비면 모델 호출 없이 "해당 지식 없음" (질의 모드와 같게)
  3. 인계 모드 검색 1위 정확도(4/16) 개선 — 카드 문구(허재원)와 검색 쪽을 함께
