# 근무일지 작성 중 설비 선택 손실과 후보 근거 누락
## Summary

작업 중인 근무일지를 다시 열면 이전에 고른 설비가 선택 목록에서 사라졌다. 저장 전 확인 화면은 입력한 내용과 지식카드 후보의 부족 근거를 보여주지 않아, 작업자가 저장 후에야 보완 필요 여부를 알 수 있었다. 기록이 없는 일지도 정상 근무인지 누락인지 확인 없이 저장할 수 있었다.

## Root Cause

작성 초안의 설비 ID를 읽은 뒤 화면 상태에서 다시 비웠다. 저장 전 대화상자는 공통 확인 문장만 사용했고, 후보 판정에 필요한 필드와 인계 누락을 요약하지 않았다.

## Prevention

- `tests/pda_report_save_preview.cjs`에서 한 기록의 여러 후보 예상, 부족 근거, 미해결 인계 및 해결 확인 경고를 확인한다.
- `tests/pda_report_form.cjs`, `tests/pda_report_flow.cjs`, `tests/pda_report_auto_candidates.cjs`로 기존 저장 계약과 자동 후보 전달을 확인한다.
- 배포 전 브라우저에서 초안을 작성하고 화면을 떠났다가 재진입해 설비 선택이 유지되는지, 기록 0건 저장 전 확인이 필요한지, 후보 예상이 상세 내용보다 먼저 보이는지 직접 확인한다. 이 배치와 초점 이동은 DOM 함수 테스트만으로 판단하기 어렵다.
- PDA 화면을 바꿀 때 `shiftlink/mes/web/AGENTS.md`의 센서·네트워크 회귀 검사를 함께 실행한다.

## Evidence

2026-10-20 로컬 Edge 작성 시험: 기록 1건을 화면에서 입력·저장하여 T1·T2·T3·T5 후보를 확인했다. 기록 0건 확인과 초안 설비 복원도 브라우저에서 확인했다. 같은 날 Pi의 `/pda.html`과 `/static/pda.js`가 갱신된 파일을 제공하는지 SHA-256으로 확인했다.

## 센서 근거와 삭제 동작 점검

원인 항목의 센서를 선택해도 현재 측정값 표시에는 테두리가 없어 빈 공간처럼 보였고, 원인·조치 단계 삭제는 `−` 아이콘만 보여 찾기 어려웠다. 선택 당시의 측정값도 원인 항목에 남지 않았다. 관련 센서 옆에 읽기 전용 측정값 칸을 두고 선택 당시 값·단위·측정시각을 원인 근거에 저장한다. 삭제 버튼에는 `삭제`를 표시하며 저장 화면의 중복 안내 문구는 제거한다.

설비가 여러 대인 기록에서 원인 추가를 한 번 누르면 설비 수만큼 입력 칸이 생겼다. 기록 유형을 고장 대응으로 바꿨다가 일반 기록으로 되돌리면, 보이지 않던 결과 필드가 빈 값으로 먼저 생성되어 `결과·인계 추가` 버튼이 사라졌다. 원인은 한 번에 하나만 추가하고, 구조화 기록의 유형 전환에서는 숨은 결과 필드를 만들지 않는다. MES 운전·계측 기록은 새 일지 작성 시 공통 영역에 한 번 첨부하고, 이후에는 작업자의 새로고침 요청으로 갱신한다.

- `tests/test_work_report_capture.py`에서 센서 측정값의 저장·후보 전달과 잘못된 값 거부를 확인한다.
- 로컬 Edge에서 센서 선택 후 값 채움, 초안 값 유지, 원인·조치 단계 삭제, 좁은 화면 배치를 확인한다. 유형 전환 뒤 `결과·인계 추가`와 삭제를 확인하고, 설비가 여러 대여도 원인 버튼 한 번에 한 항목만 생기는지 확인한다.
- 센서 선택 뒤 MES 측정값과 측정시각이 갱신되어도 원인 항목의 값·단위·측정시각이 선택 당시 값으로 유지되는지 `artifacts/live-device-test/verify_cause_ui.py`로 확인한다. MES 가져오기 내용은 같은 측정시각을 설비 간에도 한 번만 표시하는지 `tests/pda_report_sensor_context.cjs`로 확인한다. 새 일지는 선택 설비의 최신 MES 값을 한 번 자동 첨부하며, 초안 복원과 화면 재진입에서는 저장된 값을 유지한다.
- 인계 사항의 `이어서 기록`은 작성 중인 일지가 있으면 유지·삭제·취소를 먼저 선택하게 한다. 작성 화면의 `이전 기록 보기`는 화면 이동 없이 팝업으로 열어 초안과 입력 위치를 유지한다. `artifacts/live-device-test/verify_followup_ui.py`에서 세 선택과 팝업 닫기 뒤 초안 유지를 확인한다.
- MES 첨부 표시에서는 설비명을 설비별로 한 번만 쓰고, 공통 측정시각을 한 번만 표시한다. 유효한 값에 불필요한 `품질 good`을 붙이지 않고 측정값과 정상 범위는 소수점 두 자리로 표시한다. 원본 측정 숫자는 그대로 저장한다. `tests/pda_report_sensor_context.cjs`에서 표시와 원본 보존을 함께 확인한다.
- 지식카드 후보 항목을 별도 조치 내역처럼 반복 입력하지 않는다. 이상 징후 분석은 이상 징후 기록에서만 새로 보이고, 기존 입력은 유형 변경 후에도 보존한다. 조치 적용 기준은 하단 선택 근거로 두며 MES 신호 선택은 신호 ID·등록 단위만 채운다. 순간 측정값을 적용 기준값으로 자동 복사하지 않는다. T2 후보는 동일 기록의 성공한 조치 단계와 확인 결과를 재사용한다. `tests/pda_report_condition.cjs`와 `tests/test_work_report_auto_candidates.py`로 선택·비교·후보 흐름을 확인한다.
- 현장 용어를 바꿀 때 데이터 필드 이름과 후보 종류 코드는 유지하고, 입력 화면·저장 전 확인·저장 일지의 표시 문구를 함께 맞춘다.
- 이상 징후 기록의 MES 신호는 `정상 상태 대비 근거`에 선택 시점 값·등록 정상범위·측정시각을 고정한다. 조치 적용 기준 입력은 선택 사항이며 일반 징후 기록에 요구하지 않는다.
- PDA 설비·채팅 화면은 센서 표시 개선 요청의 대상을 잘못 해석해 변경했던 영역이므로 이전 배치로 복구했다. #317의 조치 기록·근무일지 연결은 유지한다. `tests/pda_sensor_display.cjs`에서 질의 당시 센서 근거와 실시간 관측의 분리, 새로고침 전 값 고정, 연결 실패 처리를 확인한다. `tests/pda_resolution.cjs`에서 #317의 조치 결과·질의 ID·세션 ID 전달을 확인한다.

## 새 일지의 MES 기록 재표시 방지

초안이 없는 상태에서 작성 화면을 다시 열면 이전 화면의 `S.reportContext`가 메모리에 남아 MES 기록 표를 채울 수 있었다. 새 작성 진입은 메모리의 이전 값까지 지운다. 이후 사용자 요청에 따라 새 일지는 선택 설비의 최신 MES 측정값·이벤트를 한 번 자동 첨부한다. 저장된 초안은 원래 첨부를 복원하고 전송 대기 기록은 바꾸지 않는다. 새 수신이 실패하면 이전 첨부를 재사용하지 않는다.

- `tests/pda_report_empty_mes.cjs`: 초안 없음은 이전 MES 값을 비우고, 저장된 초안은 복원하는지 확인한다.
- 로컬 브라우저: 새로 작성하면 최신 값·측정시각을 가져오고 이후 폴링에 고정되는지 확인한다. `artifacts/live-device-test/verify_auto_report_mes.py`에서 새 작성·새로 작성 버튼·초안 복원·수신 실패를 검증한다. 이 동작 변경은 로컬 Windows에서만 적용한다.
- 새 작성으로 이전 요청을 무효화하고, 현재 요청만 첨부 내용·실패 문구·버튼 상태를 바꾼다. `tests/pda_report_empty_mes.cjs`에서 이전 요청의 지연 실패와 역순 응답이 최신 첨부를 덮어쓰지 않는지 확인한다.
- 근무일지 MES 표는 정상 항목의 반복 정상 범위를 생략하고, 실제 상한·하한 이탈 항목에만 정상 범위를 붙인다. 판정 기준이 없는 항목은 `기준 없음`을 유지한다. `tests/pda_report_sensor_context.cjs`에서 정상·양쪽 범위 이탈·경계값·기준 미등록을 확인한다.

## PDA 설비·채팅 화면 복구와 #317 유지

화면 복구는 `32ef95d`의 설비 센서 목록·채팅의 질의 당시 근거 표시를 기준으로 한다. #317의 `조치하며 작성`, 단계 추가·취소, 원인 제안, `sessionRecord`의 조치·질의 ID·세션 ID 전달은 유지한다. 화면 표시를 바꿔도 근무일지 저장과 서버 후보 판정은 그대로 사용한다.

- 회귀 검사: `node tests/pda_sensor_display.cjs`, `node tests/pda_report_empty_mes.cjs`, `node tests/pda_resolution.cjs`. CI에서도 실행한다.
- 후보·DB 검사: `tests/test_work_report_reuse_harness.py`, `tests/test_work_report_auto_candidates.py`, `tests/test_work_report_t4.py` 62건 통과. #317 관련 `tests/test_field_draft.py`, `tests/test_check_upload_recon.py`, `tests/test_mes_analytics.py` 64건 통과.
- `artifacts/live-device-test/verify_restored_workspace.py`로 로컬·Pi의 1280px·390px 화면, 질의 당시 근거, 바로 작성과 조치 세션의 근무일지 전달을 확인했다.
- 기존 제한: `HOLD_RESOLUTION_UPLOAD=True`이므로 `source_session_id`가 있는 근무일지는 중앙 업로드를 보류한다. 로컬 후보 생성 검증을 중앙 승격 완료로 표현하지 않는다.

## 로컬 모의 MES의 동시 관측 (2026-10-21)

같은 응답 안에서 연속 계측과 모의 시료의 생성 주기가 달라 근무일지에 `측정시각 1·2`가 나왔다. 사용자가 함께 받아오도록 요청해 기본 엔진과 랜덤 모의 운전 모두 매 관측 회차에 값·시각을 함께 생성한다. 수집 설명도 같은 규칙으로 맞춘다. 이미 저장한 기록과 외부에서 받은 시료의 실제 시각은 바꾸지 않으며, 오래된 시료의 카드 조건 사용을 거부하는 검사는 유지한다.

- `tests/test_mes_sensor_meaning.py`: 두 엔진에서 모든 측정시각이 스냅샷과 일치하고 모의 시료 값도 새로 생성되는지 확인한다.
- `artifacts/live-device-test/verify_synced_mes.py`: 로컬 API의 69개 측정값을 연속 세 회 확인하고 근무일지의 공통 측정시각이 한 번만 나오는지 확인한다.
- 로컬의 이전 수집 설명은 구성 적용 API로 새 버전을 만들어 갱신했다. 과거 실행의 구성·기록은 덮어쓰지 않는다.

## 네 기록 유형의 실제 입력 검토 (2026-10-21)

두 서브에이전트가 Windows Edge의 추가 기록·이상 징후·고장 대응·수리·정기 예방정비 양식을 직접 입력했다. 사용 중인 일지와 분리된 `18001` 테스트 서버·SQLite에서 저장 요청과 저장된 일지·센서 근거·후보를 확인했다. 수정 후 네 유형 모두 저장 성공, 1280px 데스크톱·390px 모바일에서 가로 넘침 없음. 증거는 `artifacts/worklog-ux-20261021/critic/`와 `conditions/`에 있다.

- 저장 후 성공 알림 함수가 브라우저 초기화 블록 안에 있어 DB 저장 뒤 예외가 났다. 함수를 저장 함수와 같은 범위로 옮겼다. `node tests/pda_report_save_success.cjs`는 성공 표시·초안 삭제·버튼 복구를 확인한다.
- 일반 추가 기록에는 구조화된 고장 조치 필드가 없는데 미리보기가 고장 근거 보완과 `조치하지 않음`·`인계 미기재`를 표시했다. 작성한 상황·조치와 선택 결과·인계만 표시한다. 해결 기록의 정상 운전 근거는 미완료 인계로 표시하지 않는다. `node tests/pda_report_save_preview.cjs`로 확인한다.
- 정기 예방정비의 첫 설명은 정비 대상·점검 목적이고 실제 수행 내용은 조치 단계에 한 번 쓴다. 인계는 남은 문제·다음 확인·시점에 기록하며 별도 조건별 조치 입력은 만들지 않는다.
- 조치 적용 기준은 일반 조치에 필요하지 않다. 조건별로 방법이 달라지고 적용 범위를 확인한 경우에만 작성한다. 비교는 조회 시 신호 측정값과 작업자가 작성한 기준값 사이에 수행된다. MES 정상범위와의 이상 판정과 구분한다.
- 신호 변경 시 기존 기준값·비교식·단위를 지우고 다시 확인하게 한다. 동일 신호 재선택·기준값 입력은 선택과 수동 기준을 보존한다. MES 미수신 상태에도 등록 신호 선택은 가능하다. `node tests/pda_report_condition.cjs`로 확인한다.
- 후보 조건의 숫자가 문자열로 남아 서버 비교가 불가능했던 문제를 수정했다. 등록 MES 신호의 유한한 숫자 기준만 후보에서 숫자로 변환하며 원본 일지 문자열과 분류형 조건은 보존한다. `tests/test_work_report_auto_candidates.py::test_mes_condition_threshold_is_numeric_in_saved_candidate`는 실제 저장된 후보로 초과·미달·같음 비교를 확인한다. 기존 후보를 소급 수정하지 않는다.
- 최종 브라우저 저장 후보 `K-7007`에서 기준값 `145.0` 숫자·원본 일지 `"145"` 문자열을 DB 읽기로 확인했다. 실제 저장 후보로 `155 > 145` 참, `140 > 145` 거짓을 확인했고, 새로고침 후 이전 기록 불러오기로 신호·비교식·기준값 복원도 확인했다. 후보 관련 Python 검사 56건과 PDA Node 검사가 통과했다. 조건·저장 성공·미리보기 회귀 검사를 기존 CI 단계에 추가했으나 원격 CI를 실행한 결과는 아니다.

## 안내 메모·발생일시·MES 이력 표현 (2026-10-21 후속)

- 작성 안내는 도움말 아이콘과 연결하고 칸·제목에 마우스를 올리거나 입력에 초점을 두면 메모로 표시한다. 터치는 아이콘으로 열고, 바깥 누르기·Escape·스크롤로 닫는다. 메모로 마우스를 옮길 수 있도록 닫기를 180ms 지연하고 메모 진입 시 취소한다. 오류·저장 상태와 실제 기록 내용은 숨기지 않는다.
- 안전 제목과 아이콘의 시각 간격은 4px, 터치 영역은 44px로 유지한다. `조치 내역에서 선택` 라벨과 MES 자동 수집 안내는 삭제했다. 실제 조치의 선택 복사, 위험요인·안전 기준의 별도 입력은 유지한다.
- 발생시각은 날짜·시간 입력으로 나누고 `occurred_at`의 기존 `YYYY-MM-DDTHH:mm` 저장 계약은 유지한다. 부분 입력을 현재 시각으로 보완하지 않으며 초안에 유지하고 기존 저장 검증으로 거절한다. 후속 기록의 발생일시는 읽기 전용이다. `tests/pda_report_date.cjs`를 CI에 포함한다.
- 근무일지의 MES 이벤트는 `코일 투입 · COIL-481`처럼 작업 의미와 식별자로 표시한다. `coil_entered`가 라인 입구의 신규 코일 투입이라는 근거는 `engine.py`의 `_advance_coils` 경로다. 반복 접두어와 이벤트 시각은 생략한다. 기존 초안 표시도 같은 규칙을 적용하고 MES 원본 이벤트 객체와 센서 측정시각은 바꾸지 않는다. 알 수 없는 관측 내용은 원문을 보존한다. `tests/pda_report_sensor_context.cjs`에서 원본 불변·투입/배출/경보 해제·기존 초안을 확인한다.
- `artifacts/worklog-ux-20261021/concise/verify_ui.py`로 Edge 1280×800·390×844의 날짜 입력·초안 유지, 메모의 마우스/키보드/합성 터치, Escape·외부 누르기, 안전 조치 복사, 아이콘 정렬과 이벤트 문구를 확인했다. 실제 PDA 하드웨어 검증·배포는 하지 않았다.

### 도움말이 작성 공간을 늘리지 않도록 배치

안내 버튼을 입력칸 아래에 일반 요소로 추가하면 줄과 행 높이가 늘어난다. 입력칸의 안내는 해당 행의 항목명으로 옮기고, 버튼은 제목을 감싼 span을 기준으로 절대 배치한다. 제목과 아이콘은 4px 간격, 누르는 영역은 44px이며 버튼 자체가 문서 흐름에 차지하는 공간은 없다. `추가 정보`·`이상증상 분석`·`안전 조치 기록`의 셀 여백과 펼침 제목 높이도 통일한다. 위 브라우저 검증은 두 해상도에서 버튼을 숨기기 전후 모든 행 높이 차이가 0이고, 세 제목의 시작 좌표와 높이가 일치하는지 확인한다.
