HPU 경계의 원인은 카드 내용, 송신 메시지의 생략, 수신자 추론, 평가 기준 중 어디인지 확정되지 않았다. 수신자는 카드 자체를 읽지 않았다. “측정 대상 명칭도 실제 전달 범위로 제한”은 검토할 가설로 유지한다. 장비 카드 20개를 이번에 수정하지 않는다. 합성 개발 파일럿이 현장 효과나 모든 카드의 효과를 입증하지 않았다는 결론도 유지한다.

## 이번 COMMON 개정의 근거

M07/M08/M13/M16/M18의 수정은 [기존 문서 검토의 보완 의견](../20260925-t4-synthetic/README.md)과 연결 대본 사이의 불일치를 해소하는 작업이다. 실제 파일럿에서 해당 COMMON 카드의 실패가 관측되어 고쳤다는 뜻이 아니다. [변경 전후](changes.json)와 [후속 카드](cards.md), [검토용 경계 사례](boundary-cases.json)를 별도 보존한다. B01~B09는 저자가 쓴 대조 예시이며 독립 역할의 성공 실행으로 세지 않는다. 원래 94.9점이나 과거 pass를 후속 버전으로 승계하지 않는다.

## 실행 뒤의 의사결정 규칙

1. 새 실험의 실제 입력·송수신 출력·실행 ID와 항목별 독립 판정을 먼저 보존한다. 같은 상황의 조건별 성공/실패 인용과 정보가 사라지거나 추가된 단계를 확인한다.
2. 카드 결함, 송신 누락, 수신 추론, 판정 모호성을 구분한다. 차이가 없거나 원인이 불명확하면 미수정 결정과 이유를 남긴다. 실패나 개선 효과를 만들어내지 않는다.
3. 수정이 필요하면 실패 ID와 변경 필드를 연결한 새 버전을 작성하고 비작성자 내용 검토·스키마·참조 검증을 수행한다. 옛 결과나 평가 정답을 덮어쓰지 않는다.
4. 원상황 재실행은 회귀 확인이다. 일반화 확인은 생성·수정에 쓰지 않은 별도 합성 사건으로 세 조건을 다시 사전 고정해 실행한다. 장비명·숫자·문체만 바꾼 파생본은 같은 사건 그룹으로 센다. 별도 상황의 원장·역할 정보·판정 기준·계보를 결과 열람 전에 동결한다.

현재 완료 범위는 기존 경험의 비교와 수정/미수정 결정, COMMON 표현 정합화다. 후속 역할 실행·효과 판정·실행 경험에 따른 카드 개선·별도 새 상황 평가는 미실행이다.
