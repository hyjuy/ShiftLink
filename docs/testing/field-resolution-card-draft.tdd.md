# 현장 해결 기록 → 카드 초안 검증 (2026-10-13)

[검증 문서 안내](README.md) · 구현 PR #268 · 고도화 검토: [현장해결기록_고도화_검토_20261013.md](../planning/현장해결기록_고도화_검토_20261013.md)

PDA 질의가 "해당 지식 없음"일 때 작업자가 남긴 해결 기록이 검수 대기 카드 초안(L0/draft)이 되는지,
같은 고장은 묶이고 다른 원인은 갈리는지, '해결'을 MES로 확인하는지, 업로드가 보류되는지를 확인한 기록이다.

## 2. 공통 상황

모든 시나리오의 출발점은 MES 시나리오 **유압유 과열**(`hydraulic_overheat`, MES 화면 시나리오 칸의 "주요 고장" 묶음)이다.
HPU-01 유압유 온도 78 degC(정상 35~58), 경보 `AL-HYD-HOT`, 라인 고장 정지. 조치 3단계(유면·냉각·밸브 점검 → 냉각 성능 복구 → 유온·공급 정상 확인) 뒤 "모의 복구 시작"을 누르면 정상 운전으로 돌아오고 경보가 꺼진다.

시뮬레이터는 현장 모습(팬이 도는지, 핀이 막혔는지)을 보여 주지 못하므로 상황지가 "현장에서 본 것"을 준다. 작업자는 기록을 자기 말로 적는다.

- 질문은 직접 입력한다. 아래 질문은 모두 "해당 지식 없음"이 나오는 것으로 확인했다(추천 질문 칩은 기존 카드가 답한다).
- 조치는 한 줄에 하나, 결과는 그 줄 아래 "이 조치 후 결과" 칸에 적는다.

## 4. 결과

### 4.1 로컬(노트북 MES + PDA 화면)

A~F 모두 기대대로. PDA 화면에서 직접 눌러 진행했다(일부는 테스트 담당자, 일부는 브라우저 자동화).
진행 중 실제로 찾아 고친 문제는 PR #268 커밋에 반영돼 있다.

- 단계 결과 오매칭: '확인' 같은 공통어만 겹쳐도 다른 단계 결과가 들어갔다 → 공통어 제외, 가장 많이 겹치는 조치 하나에만 사용.
- 같은 원인 다른 표현이 갈라짐: 한 글자 핵심어('팬')를 비교에서 빼고 있었다 → 포함, 기준 0.4(같은 원인 0.43 / 다른 원인 0.25 이하 실측).
- 고장 정지로 0이 된 유량·펌프 전류가 이상 조건에 섞임 → `zero_when_stopped` 신호 제외.
- "새 시뮬레이션 시작"으로 초기화된 정상 값을 복구로 인정 → 질의 뒤 같은 실행의 복구/경보 해제 기록 필수.
- 해결 기록 화면에서 조치 입력칸이 좁고 삭제 버튼이 줄 전체로 늘어남 → 배치 수정.

### 4.2 실장비(Jetson MES + 라즈베리파이 PDA 서버)

PR #268 코드를 Jetson(`field_draft.py`·`server.py`·`storage.py`·`uploader.py`)과 파이(`pda.html`·`pda.js`)에 올린 뒤,
노트북에서 SSH 터널로 **파이의 PDA 서버**를 통해 PDA 화면과 같은 본문으로 질의·인계를 보내고 MES 조치는 Jetson에 직접 실행했다.
(파이 키오스크는 원격 조작이 안 되고, 원격 브라우저는 카메라가 없어 얼굴 인증을 넘지 못해 화면 클릭 대신 이 경로를 썼다.)

| --- | --- | --- | --- | --- |
| A1 | 유온 78, 경보 | 정상 운전, 유온 46 | 새 초안, MES 정상 복귀 | ✓ |

업로드 보류: 해결 기록이 실린 인계 7건이 업로더 여러 주기 동안 모두 `pending`으로 남음(클라우드 미업로드).

### 4.3 시험 승격(K-7000을 Jetson 카드 묶음에 임시 추가 → 되돌림)

초안이 승격되면 실제로 쓸모가 있는지 보려고 K-7000을 L1로 표시해 Jetson `kb_cards.json`에 임시로 넣고 MES를 재시작했다.

| 질문(유압유 과열 중) | 결과 | 시간 |
| --- | --- | --- |
| 쿨러 팬이 안 돌아요 | K-7000 인용(판정기 통과) | 5.8초 |
| 작동유 온도가 너무 높아요 | K-7000 인용 — 기존에는 "해당 지식 없음" | 5.5초 |
| 팬 차단기가 떨어져 있어요 | K-7000 인용 | 4.9초 |

- 답: "현재 온도 78 degC — 정상 범위 35–58보다 높음 / 팬 차단기 트립 원인 확인 후 재투입 팬 회전 방향과 소리 확인 / (K-7000 참조)".
  같은 설비의 기존 안전 카드(K-1003·K-1006·K-1211·K-1218)가 안전 알림으로 붙었다.
- 부족: 3번째 조치와 단계별 결과가 답에서 빠졌다(`compose.py` E1이 `know_how` 앞 두 문장만 씀). 차단기 재투입 전 잠금 등 안전 근거가 카드에 없다.
- 시험 뒤 원본 카드 묶음(86장, md5 `d6923708`)으로 되돌리고 재시작, "쿨러 팬이 안 돌아요" → 다시 "해당 지식 없음" 확인.

### 4.4 정리

시험 뒤 Jetson DB에서 초안 3건, 초안–인계 연결 7건, 해결 기록 인계 7건을 지웠다(백업 `~/shiftlink/app/backup-20261013-fielddraft/mock-mes-before-cleanup.sqlite3`).
테스트 질의 기록은 업로드 보류 대상이 아니라 이미 클라우드에 올라가 있어 그대로 두었다(`is_synthetic`).

## 5. 다시 해 보는 법

- 로컬: 저장소 루트에서 `python -m shiftlink.mes --port 8010 --db <임시 DB>` → MES `http://127.0.0.1:8010/`, PDA `/pda.html`.
  노트북에는 판정 모델(`exaone-sft-judge`)이 없어 기존 카드가 걸리는 질문은 "잠시 후 다시 시도"로 끝난다. 위 표의 질문만 쓴다.
- 초안 확인: `GET /api/card-drafts`(읽기 전용). 검수 대기 초안은 PDA·검색에 나오지 않는 것이 정상이다.
- 실장비: Jetson MES 화면에서 주요 고장 → 유압유 과열을 걸고, 파이 PDA에서 HPU-01 → 증상 질의로 같은 순서를 따른다.
