# MES 인과 합성 자료 v8 — 구현 요청과 사전 고정 설계

사용자 요청을 다음 실행 명세로 재작성한다. 원본 MES·모델·기존 결과를 보존하고 별도 로컬 센서 MES를 실행한다. 정상 시계열, 공정 원인에 의한 다중 센서 반응, 계측기 자체의 단일 센서 오류를 구분해 자료를 생성하고 Timestral 예측 헤드를 원본 공개 체크포인트에서 다시 학습한다. 기존 학습 체크포인트에 평가 결과를 되먹이지 않는다. Pi·운영 서비스·사용자 경보는 변경하지 않는다.

## 검증 질문과 독립성의 범위

1. 공정 상태에 개입했을 때 관련 센서가 서로 다른 관성·지연으로 반응하는가?
2. 계측기 bias/stuck은 출력 측정만 바꾸고 공정 상태·다른 센서에는 영향을 주지 않는가?
3. 모델 선정에 쓰지 않은 정상 동역학과 고장 기전에서 성능이 어떻게 바뀌는가?

학습용 정상 생성기 A와 도전용 정상 생성기 B를 서로 다른 상태 갱신식으로 별도 파일에 구현한다. B는 A를 import하지 않는다. 두 구현 모두 기존 detector PATTERNS, 고장 목표값 테이블, CHALLENGE_MECHANISMS를 읽지 않는다. 공유 요소는 설비·신호·단위 카탈로그, 출력 계약, 정성적인 공정 가정, 개발자다. 현장 보정 물리 모델·외부 기관의 독립 시험이라고 주장하지 않는다. 같은 코드의 seed만 바꾼 시험을 동역학 독립성으로 부르지 않는다.

## 고정 자료 계획

| 역할 | 정상 생성식 | 실행 수 × 프레임 | 용도 |
|---|---|---|---|
| fit | A | 8 × 320 | 정상 통계·유효 채널 선정·예측 헤드 학습 |
| selection | A | 4 × 320 | 정상 loss로 epoch 선택 |
| calibration | A | 4 × 320 | 방법별 정상 score .995 분위수로 임계값 고정 |
| development | A | 4 × 320 | 기존 통지 함수 연결·계약 확인. 고장 지표로 재선정하지 않음 |
| test ID | A / 개발에서 본 기전 | 6 × 384 | 동일 생성식 내 실행 분리 |
| test dynamics | B / 개발에서 본 기전 | 6 × 384 | 정상 동역학 구현 변화 |
| test mechanism | A / 미사용 기전 | 6 × 384 | 고장 기전 변화 |
| test joint | B / 미사용 기전 | 6 × 384 | 두 변화의 조합 |

각 시험군에는 고장이 전혀 없는 실행, 정지·재개, 가까운 사건, 동시 사건을 포함한다. 개발 기전은 friction/leak/sensor_bias, 시험 전용 기전은 cooling_loss/blockage/sensor_stuck이다. 이들은 보정되지 않은 정성적 개입 가정이며 고장 종류를 모델이 분류한다는 뜻은 아니다. 단일 센서 고장이 실제 센서에만 발생한다고 단정하지 않는다.

프레임·중첩 창을 임의로 섞지 않는다. run·seed·nonce와 파일을 역할별로 분리한다. test는 후보·학습 결과·임계값·소스 해시 고정 이후에 처음 생성한다. 사후 결과로 seed·고장 강도·임계값·모델·통지 규칙을 바꾸지 않는다. 새로운 시행이 필요하면 별도 버전으로 보고한다.

일부 정상값의 범위 이탈과 부하 변경·측정 잡음을 허용한다. 신호별 독립 잡음으로 완전 복제 채널을 만들지 않는다. 수동 시료는 비동기 관측으로, 이벤트 신호는 이벤트 부재 시 unavailable로 저장한다. 모델 입력은 fit의 가동·최신·good 관측 비율 95% 이상인 신호만 선정한다. 69개 구성과 입력 차원을 구분하며 기존 68개를 억지로 유지하지 않는다.

학습 전 첫 생성본 감사에서 bool 신호의 연속값과 정상 연속값 범위 이탈 0건을 확인했다. 첫 생성본 `data/`는 학습·시험에 쓰지 않고 보존한다. 수정본 `data-v2/`에서는 bool을 0/1로 유지하고, A는 측정당 .002 확률·표준편차 .8 band, B는 .0015 확률·.9 band의 추가 관측 잡음을 허용한다. 이는 현장 빈도 추정이 아닌 명시한 스트레스 가정이다. 모델 학습·선정·시험 결과를 보기 전에 고정했다.

계측 의미 재검토에서 `fluid_viscosity`는 40°C로 조건화한 시료이므로 운전 온도의 순간 변화와 연동하면 안 됨을 확인했다(`signal_semantics.py:23`). 수동 시료·형상·기타 미모델링 신호에는 임의의 공정 인과식을 추가하지 않는다. 명시한 가정은 (a) 마찰→전류/진동 및 느린 온도, (b) 누설/막힘→압력·유량, (c) HPU 공급→지연된 RT 클램프 압력이다. 전체 69신호의 물리 법칙을 보정한 모델은 아니다. 계측 정의 교정 전 시작한 특징 추출은 중단하고 `training/`과 `data-v2/`를 보존한다. 최종 학습은 `data-v3/`와 `run-final/`에서 원본 가중치로 새로 시작한다. 시험 자료는 이 시점에도 미생성이다.

고장 원인 설비를 한 곳에 고정하지 않도록 GR-01/02, HPU/CAU, 여러 단일 계측 위치를 실행별로 순환한다. 시험의 seen/held-out 기전은 동일한 원인 설비 집합에 배정한다. 모든 설비·모든 고장 종류의 균등 표본을 보장하는 것은 아니며 실행별·기전별 지원 수를 결과에 함께 기록한다.

## 학습·비교·채점

원본 Timestral-28M backbone은 동결, QuantileHead만 5 epochs/AdamW lr1e-4/seed20261021로 학습한다. 정상 selection loss로만 checkpoint를 고른다. fit/selection의 인과 64→1 창을 8개마다 선택하며 창 수를 독립 사건 수로 세지 않는다. 모든 비교법은 같은 유효 채널·64프레임 준비·시각·품질 조건을 사용한다.

비교군은 EWMA(alpha .4), persistence(직전값 예측 잔차), 기존 결합 정책의 Timestral 수치 제거, 새 학습 Timestral+EWMA다. 정상 calibration 자료와 .995 분위수 보정 예산은 동일하며 고장 정답으로 최적 임계값을 찾지 않는다. 결합·재무장·통지 파라미터는 기존 고정 후보를 재사용한다. 표시와 통지 지표를 각각 기록한다.

새 채점기는 생성기 코드를 import하지 않는다. 사건 시작은 private 개입 장부의 실제 개입 시각이며, 생성기별 관측 지연표를 참조하지 않는다. 1사건에 첫 통지 1개만 매칭하고 미탐·중복·정상 운전 노출시간의 오통지·실패 지속시간·지연을 함께 보고한다. 원인 설비와 하류 반응을 혼동하지 않도록 원인 위치 채점과 정상 전용 실행 오통지를 별도로 보여준다. p95는 성공 건의 합성 시각 지연이며 실제 장비 끝단 시간과 구분한다.

오통지의 주 지표는 고장이 전혀 없는 정상 전용 실행에서 공통 64프레임 준비를 마친 가동 시간당 통지 시작 수다. 개입이 끝난 직후의 잔류 반응이나 하류 반응을 곧바로 현장 오경보로 부르지 않는다. 모든 사건은 미탐 분모에 남기며, 지연은 과거 55건의 관측 가능 onset 대신 개입 시점으로 계산하므로 두 자료의 p95를 직접 전후 개선량으로 비교하지 않는다.

새 자료에서의 고장 정답 기반 탐색 예산은 모든 방법 0이다. 결합 정책은 과거 개발에서 선택된 상태로 고정해 재사용하므로, 같은 .995 정상 보정 예산이 역사적인 전체 개발 비용까지 동등하게 만든다는 뜻은 아니다. 시험 전용 기전은 모델 학습·개발 고장 평가에 미사용이며 구현자의 기전 지식·단위 테스트까지 블라인드라는 뜻도 아니다.

## 검증·보존

새 생성·평가 코드는 분할 중복, 역할 접근 차단, 센서 단독 개입의 비전파, 공정 개입의 지연 반응, 재현성, 과거 64프레임만 사용, 생성 규칙 미참조 채점 테스트를 먼저 작성한다. 원본 stage5·기존 55건 기록·체크포인트·고정 runtime 파일을 해시로 보호한다. 모든 산출물은 새 폴더에 쓰고 기존 경로가 있으면 실패한다. 실제 수행 후 결과와 한계를 별도 보고한다.
