# Pi 분석을 질의 참고 문맥으로 연결

2026-10-24, 운영 미배포. 기준은 검증·배포된 Jetson 통합 커밋 `eea5b1101feeda74a68ad59f4a8debb3eb01b099`와
직전 읽기 전용 감사에서 수집한 Pi `normal-context-v1-pda-20261024-r4` 결과 계약이다.
분석기·가중치·프로필·환경 변수·포트·UI 파일·DB 스키마는 바꾸지 않는다.

## 경로

1. 기존 Pi 분석기가 기존 `latest.json`을 갱신한다.
2. Pi `pda/__main__.py:make_handler`가 `POST /api/query`마다 현재 `--ai-insights` 파일을 읽고
   `pi_analysis` 필드를 추가한다. 브라우저가 보낸 동일 필드는 제거한다. 웹 UI 수정은 필요 없다.
3. Jetson `mes/query.py:query_service`가 잠금 안에서 현재 MES 스냅샷을 한 번 캡처한다.
   `agent/pi_analysis.py:validate_context`는 그 스냅샷과 결과를 대조한다.
4. 선택한 장비의 유효한 결과만 내부 `analysis_context`에 넣는다.
   S30h 생성과 하이브리드 Ollama 메시지에 `[Pi 분석 참고]`를 별도로 추가한다.
   원질문, 검색 임베딩, judge 입력, 인용 소스와 근거 부족 판단은 그대로다.
5. 기존 `query_context.pi_analysis`에 질의 당시 분석 근거를 저장한다. 모델 호출 중 MES가 바뀌어도
   새로운 상태로 덮어쓰지 않는다. 기존 근무일지·검토·승격·지식그래프에는 자동 입력하지 않는다.

## 허용 범위

- 분석 전송은 최대 16 KiB이며, 파일 부재·잘못된 JSON·초과 크기는 분석만 생략한다.
- schema 1, `operational_notifications=false`, 같은 실행 ID·설정 ID가 필요하다.
- `generated_at`은 시간대가 있는 실제 생성 시각이다. 실제 시각 기준 -5~10초 범위만 허용한다.
- `input_at`은 MES 시뮬레이션 시각이다. 현재 센서와 0~3틱 차이이고 시각 차이도 그 틱 수와 같아야 한다.
  실제 시계와 시뮬레이션 시계를 서로 비교하지 않는다.
- 장비의 현재 운전 상태·라인 상태와 분석 상태를 함께 전달한다. 준비 중/오류/비활성 결과는 징후를 전달하지 않는다.
- 해당 장비만 포함한다. 이벤트 ID·관측 시각·순번을 대조하며 최근 징후는 30틱 이내로 제한한다.
  정지 전 징후는 정지 시각·정지 순번과 현재 고장 정지 상태까지 일치해야 한다.
- 센서 이름과 low/high 방향만 허용한다. 임의 설명·지시문·추가 속성은 프롬프트에 넣지 않는다.
- 명확한 과거 원문 조회에는 이 문맥을 넣지 않는다. S30h에서 다른 장비를 질문하면 선택 장비의 분석을 넣지 않는다.
- 분석 없음은 정상의 증거가 아니다. Pi 결과는 고장 확정·작업 승인·지식카드·추가 인용 소스가 아니다.
  기존 judge 거절·숫자 근거 검사·보류 규칙을 통과시키는 우회로로 사용하지 않는다.

## 검증과 한계

`tests/test_pi_analysis_query.py`는 시간·장비·실행·설정 경계와 HTTP 프록시→실제 서비스→모델 fixture,
분석 파일 갱신/소실, 현재/미래 판단·과거 원문·저장 답변 보존, 검토→게시→반려 경계를 검사한다.
기존 게시·그래프·PDA·이력 테스트도 별도 회귀 게이트로 실행한다. 세부 결과는
[증거 보고서](../testing/pi-analysis-llm-context-20261024.tdd.md)를 따른다.

직접 MES API를 호출한 데이터의 생성 주체를 암호학적으로 인증하는 기능은 추가하지 않았다.
시각·실행·설정·형식 검증은 사실성·발신자 인증을 뜻하지 않으며, 분석은 제한된 보조 입력이다.
로컬 모델 fixture 검증은 실제 LLM 답변 품질이나 실제 장비의 결함 탐지 정확도를 보장하지 않는다.

향후 배포 시 Jetson의 수신·검증 코드를 먼저 적용하고 Pi 프록시를 이어서 적용해야 한다.
새 Jetson은 기존 Pi의 분석 없는 질문도 받는다. 구 Jetson은 추가 필드를 거절하므로 Pi만 먼저 배포하면 안 된다.
이번 작업에서는 두 장비 모두 배포하지 않는다.
