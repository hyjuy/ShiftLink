# 실행 전 고정할 T4 후속 프로토콜

작성자 `/root/experiment_design_fresh`. 버전 `t4-followup-design-v1`. 작성일 2026-09-26. **작성 시점에는 초안이며 독립 설계 검토·동결·실행 모두 대기**였다. 이후 독립 검토·동결의 최종 상태는 상위 `../README.md` 및 별도 담당자가 작성하는 `../freeze.json`을 확인한다. 이 문서의 명령형은 후속 실행 절차이고 실행 완료 기록이 아니다.

## 목적과 비교 범위

기존 4상황 파일럿에서 필수 사실·미확인이 세 조건 모두 보존되어 추가효과가 미입증이었다. 입력 자체의 안내가 풍부했던 한계를 줄여, 체크리스트·정답성 안내를 넣지 않은 새로운 메모 조각으로 전달 보존과 입력 밖 주장 차이를 조사한다. 실패 유도나 개선 성공을 목표로 정답·원자료를 사후 바꾸지 않는다. 기존 HPU 부정형 대상명 전제는 0~1 경계로 보존하고 이번 기준은 아래 평가 문서에서 미리 구체화한다.

6상황 × 3조건 × 3반복이다. 54개 쌍의 역할은 각 2개로 총108회 계획한다. 추론 단위는 6개 개발 사건 그룹이며 54개 독립 상황이나 원자 사실 수만큼의 표본이 아니다. 반복은 모델 출력 변동을 살피는 목적이다. 같은 장비군 모든 카드에 일반화하지 않는다. PDP와 CAU 카드의 스키마 `equipment=COMMON`은 기존 상태를 그대로 보존한다.

## 조건과 사실의 동일성

각 상황의 세 송신 packet은 `task`, `access_rule`, `notes`가 JSON 값 수준에서 완전히 같고 `support`만 다르다. `none`은 빈 문자열, `checklist`는 무엇/누구/언제/채널/수신 확인의 일반 5문장, `t4`는 선택 카드의 **know_how 단일 필드만 원문 그대로**다. 카드 ID/제목/required_context/acknowledgement/rationale/예시 등 나머지 필드는 노출하지 않는다. 조건명은 packet 본문에 없으며 경로에서는 드러날 수 있으므로 송신자 맹검을 주장하지 않는다.

선택은 실행 전 고정한다: HPU K-0037, GR K-0033, RT K-0048, CV K-0028, PDP K-0042, CAU K-0026. `card-selection.json`의 버전·원본 SHA256·노출 텍스트를 검사한다. 메모에 없는 사건 측정값·승인·완료 상태는 지원에 추가하지 않는다. 같은 사건 사실을 제공하되 지원 방법과 그 길이는 차이가 난다. 수신자는 카드·조건명·원자료·평가 원장 없이 동일 initial과 **해당 실행에서 실제 작성된 송신문**만 받는다.

지원 원문에 있는 카탈로그 참조는 가용성 제약으로 남긴다. 특히 HPU know_how는 카탈로그 공급 관계를 참조하지만 그 카탈로그는 역할 packet에 없으며 추가 조회도 금지다. 참조 표현만으로 미노출 관계의 열람·기억 기반 보완을 허용하지 않는다. 지원 문장 자체가 명시한 일반 관계는 그 범위만 근거로 인정하고 이번 사건 관측 여부와 분리한다. 평가자는 `evaluation-only/rubric.md`의 입력 경계·일반 단위 예시를 적용한다. 역할 packet이나 카드 원문에 평가용 설명을 덧붙이지 않는다.

원자료 `source-memos/*.txt`와 송신 packet의 `notes`에는 메모 발췌만 있으며 평가용 항목 ID나 모범 인계문을 넣지 않는다. 과업 공통 지시는 메시지 작성 역할·서면 채널·출력 상한만 지정하고 정답성 체크리스트를 추가하지 않는다. 평가 사실을 풍부한 설명문으로 packet에 다시 포장하지 않는다. 평가 원장의 미확인 뒤에 숨은 실제 값을 만들어 두지 않으며 서로 충돌하는 출처는 충돌한 상태가 정답이다.

## 역할 입력 생성과 컨텍스트

독립 검토가 끝나고 동결된 다음에만 다음 절차를 실행한다.

1. 운영자는 `run-plan.json` 순서를 그대로 따른다. 각 쌍에서 송신을 끝낸 후 수신을 시작하며 다른 쌍과 역할 호출을 겹치지 않는다. 반복별 조건 순서는 none→checklist→t4 / checklist→t4→none / t4→none→checklist다. 반복별 상황 시작점은 HPU / RT / PDP로 두 칸 순환한다. 무작위 추출이라고 쓰지 않는다.
2. 각 **상황·조건·반복·역할**마다 새 역할 에이전트를 `fork_turns=none`으로 만든다. 배치 호출·기존 역할 재사용·기존 대화 fork를 금지한다. 송신자는 지정된 송신 packet 하나만 한 번 읽고 종료한다. 도구 호출은 그 packet 한 번 읽기뿐이며 추가 조회·글자수 계산 도구·다른 역할 메시지·파일 쓰기 등은 금지한다. 외부 운영자가 입출력을 저장·측정한다.
3. 역할을 시작하는 정확한 외부 메시지는 `지정된 UTF-8 JSON packet {absolute_packet_path} 하나를 도구로 한 번 읽고 그 안의 과업을 수행하라. 그 읽기 외에는 도구를 사용하지 말라. 최종 메시지만 반환하라.`이다. 이 메시지 외에 평가 예시·힌트·다른 실행 정보를 추가하지 않는다. 역할별 실제 외부 메시지와 SHA256도 저장한다.
4. 송신문 원문을 그대로 저장한다. 운영자는 해당 수신 template의 `handoff: null`에 **실제 송신문 전체**를 문자열로 대입해 `execution/actual-inputs/{run_id}-receiver.json` 같은 새 파일로 저장한다. 템플릿의 다른 값은 변경하지 않는다. 송신문 요약·문구 보정·누락 보완·평가 필드 추가·조건 라벨 삽입을 하지 않는다. `null`인 템플릿을 직접 역할에게 주지 않는다.
5. 수신자를 별도 새 컨텍스트로 시작하고 해당 실파일만 한 번 읽게 한다. 수신 역할이 송신 packet이나 원자료를 다시 읽지 않게 지시한다. 외부 운영자가 실제 입력과 원문 송신문 동일성을 검사한다. 지시만으로 파일시스템 접근이 차단된다고 주장하지 않는다. 이 방식은 컨텍스트 분리와 도구 사용 규칙이며 **OS 보안격리 보장이 아니다**.
6. 송신 1편·수신 1편으로 끝낸다. 수신자가 질문해도 추가 송신 답변이나 상황 수리를 하지 않는다. 2개 실제 대화 턴이다. 새 컨텍스트 수·도구 호출 수·질문 답변 단위 수를 턴 수와 섞지 않는다.

사실 원장·평가 항목·F8·모범답안·평가 예시·숨김표식은 외부 시작 메시지와 역할 packet 어디에도 넣지 않는다. 이번 설계는 숨김표식을 만들지 않는다. 단순 키워드 검사와 실제 의미 누출 검토를 함께 사용하며 키워드 부재만으로 누출 부재를 입증하지 않는다.

## 길이·모델 설정

송신과 수신 모두 공백·줄바꿈 포함 Unicode code point 1800자 이하를 요청한다. 출력 JSON이나 코드블록을 사용했다면 원문 전체를 센다. 외부 운영자는 Python `len(text)` 등 같은 정의를 쓴다. 역할이 출력한 설명·자기보고도 원문에 포함하고 임의로 잘라낸 뒤 충족으로 기록하지 않는다. 최소 글자수나 목표 글자수는 없다.

토큰 상한·temperature·top_p·seed·모델 스냅샷·실제 사용 토큰이 노출되지 않으면 **unavailable**로 남긴다. 1800자를 토큰 수로 환산하거나 API 상한을 강제했다고 쓰지 않는다. `run-plan.json`은 현재 호스트 기본 모델을 상속하도록 지정하며 실행 전에 실제 노출 식별자를 기록한다. 노출 모델/설정이 도중에 바뀌면 이 버전은 중단한다. 검토·동결 담당자는 확인 가능한 실행 환경을 고정하고 비노출 설정의 재현성 한계를 남긴다.

총 호출 예산은 기본108역할 호출이며 각 역할의 인프라 재시도1회를 포함해 **최대216시도**다. 기본108출력의 요청 문자 상한 합계는108×1800=**194400자**다. 실패/재시도에서 이미 생성된 원문은 별도로 모두 보존하며 이 합계에 맞춰 삭제·절삭하지 않는다. 총 입력/출력 토큰 및 총 비용 예산은 **unavailable**이며 임의 환산치를 쓰지 않는다. 역할별600초 제한은 운영자가 감시하는 제한이고 API가 제공하는 강제 시간 예산으로 보장하지 않는다. 총 벽시계 상한도 강제할 수 없어 **unavailable**이다. 최대216시도×600초의 산술값36시간에는 운영·검토·대기 간격이 빠지므로36시간 안에 완료된다고 보장하지 않는다.

`input-lengths.json`의 지원 Unicode 글자수·UTF-8 byte수를 보고한다. none의 길이를 맞추려는 무의미 패딩이나 카드 요약은 사용하지 않는다. 따라서 차이는 **지원 내용과 입력 길이가 함께 달라진 패키지 효과**이며 길이로 통제된 순수 T4 효과로 해석하지 않는다. 수신 입력 길이는 실제 송신문에 따라 달라지므로 실행 시 전체 packet bytes·출력 글자수·노출되는 토큰 수를 별도 기록한다.

## 중단·부적격·누락·재시도

- 독립 설계 검토 미완료, 동결 해시 불일치, packet에 평가 내용 혼입 발견: 역할 호출을 시작하지 않는다. 수정본은 새 버전으로 다시 검토·동결한다.
- 각 역할은 최대600초를 기다린다. 운영자가 최대60초 간격으로 상태를 확인할 수 있으나 역할에게 후속 힌트를 보내지 않는다. 명시적 호스트 오류·600초 시간 초과·빈 응답이 발생하면 해당 시도는 누락으로 원문 오류와 시각을 보존한다.
- 역할이 추가 도구를 썼거나 packet을 두 번 읽거나 다른 문맥/평가자료를 접했다면 그 시도는 부적격이다. 도구 기록이 관측 불가하면 `tool_observation_coverage=unavailable`과 `eligibility=unverifiable`로 남기고 검증된 집계와 분리한다. 자기보고만으로 도구 미사용 확정이라고 쓰지 않는다.
- 단순 내용 오류·질문 과다·표현 불만족·조건 차이 없음은 유효 결과이며 재시도하지 않는다. 1800자 초과는 원문 그대로 보존하여 길이 편차·주분석 부적격으로 표시하고 비준수 포함 보조표에서 내용 평가를 별도 보고한다. 길이 초과를 잘라서 적합하게 만들거나 원하는 답을 얻도록 다시 호출하지 않는다.
- 인프라 오류로 **유효한 원문 응답이 하나도 없는 경우만** 같은 packet/새 컨텍스트로 1회 재시도한다. 실행 순서상 바로 이어서 수행하며 최대2시도다. 첫 시도·재시도 모두 로그에 남긴다. 유효한 첫 응답이 이미 도착했는데 운영자가 놓친 경우 뒤늦게 발견한 첫 응답을 보존하고 중복 호출을 편차로 기록한다.
- 송신이 최종 누락·부적격이면 그 수신은 실행하지 않고 `upstream_missing_or_ineligible`로 남긴다. 수신만 실패하면 유효한 송신문은 유지하고 수신만 위 인프라 기준에 따라1회 재시도한다. 송신 내용은 바꾸지 않는다. 누락을 성능0점이나 성공으로 대체하지 않는다.
- 평가자료 노출·다른 상황/조건 정보 접근·템플릿 오염 등 정보 분리 위반이 확인되거나 노출 모델 설정이 바뀌면 **전체 실행을 중단**해 원인·범위를 기록한다. 같은 인프라 오류가 세 역할 연속 발생해도 전체를 중단한다. 영향 없는 완료 결과는 삭제하지 않는다. 수정 후 재개는 새 버전·새 동결·새 run ID로 분리한다.
- 예정54쌍 전부를 로그와 대응한다. 미실행·누락·불가검증·부적격·재시도 사유 및 조건별 분모를 공개한다. 세 조건이 모두 적합한 동일 상황·반복 묶음의 짝 비교를 주표에 쓰고, 빠진 짝과 나머지 유효 출력은 보조표에 보존한다. 특정 조건이 자주 제외되어 생기는 선택 편향을 함께 설명한다.

## 사전 독립 검토·동결 인계

저자와 다른 설계 검토자는 실제 18개 sender packet 및6개 receiver template, 원장 항목, 범위·계보·지원 복제·예산·편차 정책을 확인한다. 특히 단위 미첨부와 태그의 일반 지식, 전송 완료와 수신/내용 해결, GR 무응답과 답장 미첨부를 구별해 평가 가능한지 확인한다. 검토 의견·변경·재검토 대상 해시를 보존한다. 검토자가 작성한 독립 검토 기록과 실제 동결 manifest가 존재하기 전에는 `ready_to_execute`라고 하지 않는다.

동결 대상은 이 프로토콜, 원자료6개, 송신18개, 수신 template6개, 카드 선택·원본 카드 해시, 범위·계보, 입력 길이, 실행 순서·예산·모델 정책, 원장·평가기준·판정 양식·로그 양식 및 생성/검증 코드다. 동결 해시는 별도 검토·동결 담당자가 산출한다. 실제 수신 packet은 미래 송신문에 의존하므로 현재 존재·동결한다고 주장하지 않으며 템플릿과 치환 규칙을 먼저 동결하고 실행 시 실파일/입출력 해시를 기록한다.

## 실패 경험과 이후 별도 상황

독립 판정 후 실제 입력·송신문·수신문·원자 판정·실행ID를 나란히 비교해 누락 위치를 찾는다. 카드 내용 문제인지, 송신자 선택·수신자 추론·입력 자료 공백·평가 모호성인지 구별한다. 카드 조건이 동률이거나 더 나쁘면 그대로 기록하며 개선을 위해 반드시 수정하지 않는다. 반복되는 카드 문구 관련 실패와 수정이 이를 줄일 구체 근거가 있어야 최소 수정 후보를 만든다. 근거가 부족하면 미수정 이유를 남긴다. confidence 값을 효과 점수로 바꾸지 않는다.

이후 카드를 수정한다면 구버전/신버전·실패ID·변경 필드·작성자 외 검토를 보존한다. 원래6상황 재실행은 회귀 확인이다. 별도 평가 상황은 수정·경험 추출에 쓰지 않은 새 사건 구조·관측 출처/접근 구조·누락 또는 충돌 원인을 갖도록 다른 작성자가 만들고, 작성 계보·유사성 검토·원장·기준을 역할 실행 전에 다시 검토·동결한다. 새 상황 생성자는 과거 역할 발화·정답을 복사하지 않는다. 장비명/숫자/시각/문체만 바꾼 파생은 같은 사건 그룹이며 독립 일반화 사례로 세지 않는다.

후속 별도 상황 평가에서는 수정 전·후 카드의 노출 필드·예산·순서를 고정하고, 기존 none/checklist 기준선을 유지한다. 그 평가 전 원자료를 카드 개선에 사용하면 개발 세트로 재분류하고 독립 평가용 상황을 다시 마련한다. 개선이 확인되지 않아도 결과를 보존한다. 이번 설계에는 그 후속 실행 결과·카드 수정·일반화 효과가 없다.
