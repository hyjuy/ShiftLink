## 감점 내역

### A1 터치 타깃 (-1 / 8)
- 근거: `pda.html:265`. 관측 목록의 접기 `summary`가 `min-height:44px`여서 보조 기준 48에 못 미친다.
- 왜 문제인가: 장갑을 낀 손으로는 「나머지 N개 보기」를 놓친다. 범위 안 관측값을 확인하는 경로가 좁아진다.

### A2 대비 (-1 / 7)
- 근거: `pda.html:260`. `.obs small`의 `--tx-3 #7C8792`를 `--surface #161B22` 위에 놓으면 계산한 대비가 약 4.7:1이다. 이 요소는 범위 안 관측 행에서 값의 출처(「MES」/「직접 입력」)를 보이는 본문이다(`pda.js:382-383`).
- 왜 문제인가: 7:1에 못 미친다. 관측값이 어디서 왔는지가 데이터 판단에 쓰이는 정보인데, 그것이 흐리게 보인다.

### C1 순위 근거가 이유로 표시 (-2 / 6)
- 근거: `pda.js:705-706`. 실제 결과 경로(`runSearch`, `pda.js:1105`)에서는 모든 조치 카드의 이유가 `'Jetson 답변 인용'` 한 문구로 같다. 그런데 화면 머리에는 「관련도 순」이라고 적는다(`pda.js:911`). 「조건 일치」류 이유를 만드는 `rankCards`(`pda.js:740-742`)는 대기 화면 안전 카드에만 쓰이고 결과 화면에는 쓰이지 않는다.
- 왜 문제인가: 1위가 왜 1위인지 화면 어디에도 나오지 않는다.

### C2 조건 3상태 구분 (-3 / 6)
- 근거: `pda.js:723`은 서버의 `unverified_card_ids`를 `excluded`로 받는다. 그 항목의 원래 이유는 「MES 관측값으로 조건을 확인하지 못했습니다」(`pda.js:706`), 즉 미평가다. 그런데 `pda.js:811`이 이 문구를 「조건 불일치 — 이 카드는 지금 쓰면 안 된다」로 덮어쓴다. 실제 결과 경로에서는 `conds: []`(`pda.js:705`)이어서 일치·불일치·미평가 알약도 하나도 나오지 않는다.
- 왜 문제인가: 관측이 없어 판정하지 못한 카드를 "판정했더니 불일치"라고 표시한다. 데이터가 말하지 않은 판정을 화면이 만들어 내는 셈이다.

### D1 실값 사용 (-1 / 6)
- 근거: `pda.js:1158`. 인계 화면은 `basis_ids`를 그대로 보인다. 표본(`EV-0031_upstream_cause.json:1197`, `:1207`)에는 「근거 K-0101 · AC-0101」, 「근거 K-0104」가 들어 있다. K-0101과 K-0104는 정본 `kb_cards.json`에 없는 카드 ID다. 시나리오 파일 안에만 있다(`:711`, `:942`). 이 카드들은 `/api/kb/cards`의 C-102 필터(`server.py:41`)를 거치지 않는다.
- 왜 문제인가: 화면에 나온 카드 ID를 단말에서 열어 볼 수 없다. 검색 정본 밖의 ID가 근거처럼 표시된다.

### D2 ID 혼용 없음 (-1 / 5)
- 근거: `pda.js:1120-1123`. 인계 기록을 설비와 묶을 때 서버 키 `equipment_id`를 쓰지 않는다. 대신 `open_items[].text`라는 자유 문장 안에 `S.eq.code`가 들어 있는지로 찾는다. 하나도 맞지 않으면 전체 인계를 보인다(`mine.length ? mine : S.handovers`). 그러면 머리띠에는 HPU-01이 떠 있는데 GR-01·RT-03 인계(HO-0101)가 아무 표시 없이 나온다.
- 왜 문제인가: 라벨용 `code`를 조회 키로 쓰고 있고, 다른 설비의 기록을 선택한 설비의 기록처럼 보이게 한다.

### D3 지어내지 않음 (-2 / 4)
- 근거 1: `pda.html:486-488`. `RECIPIENT_ROLE`·`TIMING`·`CHANNEL`에 「야간조 정비 담당」·「교대 직후 최초 기동 전」·「구두 인계 + 인계서 기록」이 미리 채워져 있다. `docs/data`에는 이 값의 원천이 없다(표본 인계는 A/B/C조 체계다. `EV-0031:1174-1175`). 검사(`pda.js:1215`)는 빈칸만 막으므로 그대로 저장된다(`pda.js:1335-1336`). (-1)
- 근거 2: `pda.js:953-956`. 「이 조치 시도」를 한 번 누르면 바로 `failure_reason: '조치 후에도 증상이 유지됨'`이 기록되고, `observed_result`에는 조치 전 관측값 전체가 들어간다. 작업자가 결과를 입력하는 단계가 없다. 이 기록은 「효과 없음」으로 표시되고(`pda.js:976`) 서버 인계의 `attempts`로 올라간다(`pda.js:1337`). (-1)
- 왜 문제인가: 작업자가 말하지 않은 결과와 수신자가 다음 교대 인계 기록에 사실처럼 남는다.

## 감점하지 않은 것 중 위험 신호

- `SYMPTOM_LABELS`(`pda.js:425-510`)는 카드 `symptom`의 임계값(58·62·1.2·16)을 문자열로 복사해 두었다. 머리 주석(`pda.html:15-16`)의 "값을 복사해 두지 않으므로"와 맞지 않는다. 카드나 MES 구성이 바뀌면 조용히 어긋난다. 지금은 모두 일치한다.
- K-1201 라벨 「차압 1.2 bar 초과 · 막힘 표시」(`pda.js:452`)는 막힘 표시가 보이는 상태로 읽힐 수 있다. 원문은 "막힘 표시 확인이 필요하다"(kb_cards.json:3068)다. 원문은 선택했을 때만 나온다(`pda.js:624`).
- 인계 표본 항목에 「온도 72 ℃」(`EV-0031:1193`)가 있다. GR 베어링 정상 상한 62 ℃(K-1025, K-1210)와 다른 수치가 같은 화면 흐름에 함께 나온다. 원천 데이터 쪽의 불일치다.
- 설비 유형을 `code` 접두어에서 뽑는다(`pda.js:79`). 정본에는 `equipment_type_id`가 있다(plant:236). 카드 적합 판정(`pda.js:46`)이 라벨 문자열 형식에 묶여 있다.
- `outboxItemView`(`pda.js:1265`)는 설비를 찾지 못하면 `code` 자리에 `equipment_id`를 표시 없이 넣는다.
- T5 안전 카드 K-1309·K-1319가 증상 선택지(「⚠」, `pda.js:577`, `:612`)로 나온다. 안전 렌즈에서 볼 일이다.
- 결과 화면의 순서는 서버 `cited_card_ids` 순서 그대로다(`pda.js:722`). 「관련도 순」(`pda.js:911`)이라는 문구가 실제로 맞는지는 서버 계약을 확인해야 한다.
