# #212 · #214 리뷰 후속 검증

2026-10-07. 리뷰 메시지에서 요구한 버그 수정, 실행 환경 이식성, 공용 HTTP 도우미, PDA 진입 출처, 씬 저장 정책을 반영했다. 별도 계획 파일 없이 리뷰 항목을 검증 기준으로 삼았다.

## 변경과 실행 방법

- `check_unity_live.py`는 Unity 실행 직전에 `play-check-result.txt`를 삭제한다. 이번 실행이 결과를 만들지 않으면 종료 코드가 0이어도 실패한다.
- 두 실행 스크립트는 `--editor` 또는 `UNITY_EDITOR`로 Editor를 지정한다. 지정하지 않으면 실행 전에 설정 오류를 안내한다.
- `--temp-dir` 또는 `UNITY_TEMP_DIR`가 있을 때만 TEMP/TMP를 덮어쓴다. 지정하지 않으면 시스템 설정을 유지한다. `--upm-cache`는 `UPM_CACHE_ROOT`보다 우선한다.
- `demo_servers`, `request`와 공통 실행 설정은 `shiftlink/unity_demo.py`에서 제공한다. 실행 스크립트가 테스트 모듈을 import하지 않는다.
- PDA 링크 진입은 `unity_link`, 직접 선택은 기존 `manual_selection`으로 기록한다.
- `FactoryChecks.Run`은 메모리의 임시 씬에서 검증하고 `Factory.unity`, 빌드 설정, 에셋을 저장하지 않는다. 씬 변경은 별도의 의도적인 제작 작업에서만 커밋한다. `OpenDemo`의 최초 씬 생성 동작은 유지한다.
- `unity-monitor.tdd.md`의 모델 제외 문구는 디스플레이 체크포인트 당시 기준임을 명시했다.

실행 예: `python -B scripts/check_unity_live.py --editor <Unity 실행 파일>`.

## 바이너리 관리와 후속 점검

현재 추적 중인 `unity/` 파일 합계는 41,584,052바이트다. 가장 큰 원본은 `ShiftLink_ConnectedLine.blend` (5,423,155바이트)다. 이번 후속 수정에서는 모델을 재내보내거나 Git 이력을 변경하지 않았다.

현재 모델은 기존 Git 관리 방식을 유지한다. `.blend`·`.fbx`의 반복 수정이 시작되면 다음 모델 변경에서 Git LFS 도입을 결정한다. 원본을 외부 보관할 경우 팀원이 접근할 수 있는 위치와 버전을 문서화하고 Unity 재현에 필요한 출력물은 함께 관리한다. 이번 리뷰 후속 브랜치는 `fix/unity-review-212-214-20261007`이다.
