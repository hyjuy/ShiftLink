# D15 결과 — 정상 학습 출처만 맞춘 IF는 보류

2026-10-21. **결정: Isolation Forest 후보 보류, 기존 EWMA 연구 기준 유지.** 정상 학습의 생성 경로만 바꾸는 실험을 새 시드에서 한 번 수행했다. 정상 라벨 창의 경보는 48→46설비·프레임으로 소폭 줄었지만 **최초 고장 전 경보는 46→46**이었다. 전체 반응 탐지는 35→34/49건으로 줄었다. 정상 분포 차이를 맞추는 것만으로 기존 모델을 교체할 근거를 얻지 못했다.

[사전 등록과 실행 전 정정](mes-training-source-prereg-20261021.md), [비교 코드](../../scripts/mes_training_source.py), [원본 JSON](../../output/mes-training-source-validation-20261021.json), [TDD 근거](../testing/mes-training-source-20261021.tdd.md)를 보존한다. 모든 수치는 합성 생성기 내부 개발 검증이며 실제 설비 원인 진단 정확도가 아니다.

## 변경한 변수와 비교 계약

- v4 train에서 구한 평균/scale, D12 센서 마스크 63/69개 위치, 8프레임의 현재값/평균/표준편차/기울기, IF 200 trees, seed20261020, 임계값 .65를 고정했다. EWMA3과 robust z6도 같은 v4 train 통계와 기존 설정을 사용했다.
- 정상 창의 출처만 pattern v4 train → independent v7 train으로 바꿨다. 원래 run으로 창을 먼저 만들고 8프레임 모두 faults=[]인 창만 골랐다. intensity0도 고장 라벨이 있으면 제외했다.
- v4 가용 1,332창과 새 v7 가용 1,282창 중 **설비별 각각 1,282창**으로 수를 맞췄다. v4도 50창을 줄인 대조군이므로 D12의 원래 IF와 동일한 적합이라고 부르지 않는다. SHA256 표집과 선택 순서/키를 원본에 남겼다. 양쪽 모두 8개 run이며 가용 정상 창의 연속 구간은 v4 34개, v7 23개다. 중첩 창 1,282개는 독립 고장 사례 1,282건이 아니다.
- 새 seed1371..1394, 각 분할 8run×300초, hazard .003, warmup60. full/weak validation은 각 2,400프레임, **짝지은 같은 49개 사건**이다. 두 조건을 합쳐 독립 98건이라고 세지 않는다. 학습과 검증 run/seed는 분리됐다.
- 새 데이터셋은 `output/mes-fault-coherent-v7-seed1371-frozen-20261021/`, `output/mes-fault-weak-v7-seed1371-frozen-20261021/`다. 기존 생성기가 test도 생성하므로 시험 행 4,800개는 파일에 존재하지만 **읽거나 평가한 시험 행은 0개**다. 별도 최종 시험과 배포는 하지 않았다.

## 같은 구성·코드를 고정한 이유

첫 실행은 모델 적합 전에 `ValueError: dataset equipment contract differs`로 중단됐다. 공유 폴더의 다른 작업이 시료 신호 수집을 매 프레임 방식으로 바꾸면서 구성과 생성 동작이 달라졌다. 처음 만든 두 `*-seed1371-20261021` 폴더는 구성 불일치로 **미평가**이며 남겨 두었다. 결과를 본 뒤 시드를 재선정한 것이 아니다.

운영 파일을 수정/되돌리지 않았다. 관련 코드 45개를 [고정 연구 환경](../../output/mes-training-source-runtime-20261021/provenance.json)에 복사하고 engine.py/signal_dynamics.py/signal_semantics.py의 이전 수집 동작만 Git HEAD로 고정했다. 기존 구성 ID `3713bf5f3e0f9ef808ff264ea1fa12dee6ded2b97ac4b549816c275c7f568900`을 복원했다. 독립 감사자가 45개 해시와 세 파일의 HEAD 바이트 일치, 해당 환경에서 기존 v7 검증 **2,400프레임 factual/662프레임 prefault twin 동등성**을 확인했다.

새 두 조건도 **모델 적합 전에** 각각 factual 2,400프레임과 prefault 765프레임의 동등성을 통과했다. 원본 JSON에 읽은 feature/label prefix·참조·전처리·코드·카탈로그 해시를 기록했다. source test 본문은 해시 계산에도 읽지 않았다. 현재 작업 중인 새로운 수집 방식의 성능을 시험한 결과로 해석하지 않는다.

## 정상 관계와 배경 경보

가용 정상 학습 창의 RT/CV 속도–전류 Pearson r은 v4 약 .998에서 v7 −.042..+.072로 달라졌다. v4 통계로 정규화한 속도 std8 중앙값은 약 .067에서 .353.. .386으로 달라졌다. GR의 정상 상관은 양쪽 모두 약 .997.. .998이다. 출처 간 차이는 유지된 상태에서 IF의 적합 자료를 바꾼 것이며, 생성기의 물리 관계를 수리한 것이 아니다. 이 표의 관계 기술 통계는 표집 전 가용 정상 창에서 계산했다.

| 같은 평가 창 | 평가 가능한 설비·창 | v4 정상 학습 IF | v7 정상 학습 IF |
| --- | ---: | ---: | ---: |
| 최근 8프레임 모두 faults=[] | 13,040 | 경보 48 | 경보 46 |
| 각 run 최초 고장 이전 | 7,090 | 경보 46 | 경보 46 |

full/weak에서 이 배경 집계는 정확히 같아 하나의 짝지은 근거다. 48→46의 순감소는 고장 후 정상 라벨 창의 2→0에서 발생했다. 더 오래된 고장이 코일/상태에 남을 수 있으므로 **순수 정상 분포의 오경보가 개선됐다는 근거는 얻지 못했다.** 또한 고장 전 총계가 같다는 것은 경보 위치가 같다는 뜻이 아니다. 정상 창의 PDP 경보는 10→19설비·프레임, HPU는 0→4로 악화했고 RT-03은 10→5, CV-01은 8→1로 줄었다.

사전의 기계 판정은 엄격한 순감소 2프레임 때문에 `supported_on_label_free_windows`다. 이 명칭은 **정상 라벨 창이라는 좁은 조건의 기술적 결과**에 한정한다. 통계적 유의성, 속도 변동 하나의 인과 효과, 실제 정상 운전 개선이나 후보 승격을 뜻하지 않는다. 표집한 창 수는 같아도 독립 run 수·연속 구간·정상 내용의 다양성을 같게 만들지는 못한다.

## 전체 고장 탐지와 경보 부담

탐지는 주입 원인 설비에서 새로운 유효 경보가 발생한 사건이다. IF가 고장 유형을 맞힌 점수가 아니다. 미일치 시작에는 중복·조기 시작도 들어간다. 오진 초는 잘못된 설비 경보 시간의 합집합, 설비·초는 설비별 시간 합이다. 지연 p95는 탐지 성공 사건만 계산하므로 미탐과 함께 읽는다.

| 조건 | 방법 | 탐지/49 | 미탐 | 미일치 시작 | 오진 초 | 오진 설비·초 | 성공건 지연 p95초 |

| full | 수량 맞춘 v4 학습 IF | 35 | 14 | 85 | 194 | 288 | 25 |

| full | EWMA3 | 48 | 1 | 26 | 223 | 251 | 3 |

v7 학습 IF의 full 주입 F1은 .414→.463으로 올랐지만 탐지는 1건 줄었다. weak는 .353→.417이며 2건을 더 찾았지만, 잘못된 경보가 하나 이상 켜진 합집합 시간은 88→90초로 늘었다. 한 점수의 상승이 전반적인 개선을 뜻하지 않는다.

## 검증·비용·다음 결정

관련 36개 회귀가 통과했고, 새 코드 7개 테스트를 고정 환경에서 재실행했다. 줄 커버리지는 91.2%이며 branch는 측정하지 않았다. 독립 연구자가 실행 전 누출/정상 창/표집 반례를 검토했고 별도 감사자가 데이터·factual 재현을 확인했다. 독립 결과 검토자가 저장 지표로 관문 실패 123개(full70/weak53), 표집 키·합계·해시를 재확인했다. 고장 전 총계와 경보 위치 동일성을 혼동하지 말라는 비판을 보고서에 반영했다. [상세 근거](../testing/mes-training-source-20261021.tdd.md).

IF 적합은 v4 대조군 8.753초, v7 학습 후보 9.777초, 전체 비교 295.015초였다. 전체 시간에는 두 조건의 factual/개입 재생 검사가 포함된다. 단일 PC 연구 실행이며 장치 추론 벤치마크가 아니다.

재현은 공유 폴더의 수집 변경을 섞지 않도록 보존한 runtime을 사용한다. 기존 결과를 덮어쓰지 않게 새로운 출력 경로를 지정해야 한다.
