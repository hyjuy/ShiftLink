# v10b: 개발 정상 통지 예산 보정 — 새 test 생성 전

v10 최초 개발 후보는 누설2/2·전체12/12를 매칭했으나 정상 통지19/2688초로 목표를 크게 초과했다. 이 결과·소스·frozen lock은 보존하고 test는 생성하지 않았다. 원래 계획의 미사용 시험을 이 후보에 적용하지 않고 개발 단계에서 기각한다. v10 개발 자료는 계속 개발에만 사용한다. v9 시험은 원인 진단 자료로만 사용한다.

19건은 robust EWMA 점수가 채널 정상 보정을1.004~1.260배 넘어선 정상 부하 구간들이다. 많은 센서의 개별 quantile을 동시에 감시할 때 전체 통지 예산이 보장되지 않고, 짧은 calibration의 정상 부하 범위도 충분하지 않았다. 새로운 고장 규칙을 추가하지 않고 개발 정상 노출의 통지 예산으로 임계 여유를 선택한다. 이것은 현장 운전분포 보정이나 오통지율 보장의 증거가 아니다.

v10의 fit/calibration/development와 고정 checkpoint·예측을 그대로 복사해 별도 v10b 경로에서 사용한다. 원본 파일은 덮어쓰지 않는다. 모델 재학습과 추가 모델 추론은 개발에서 하지 않는다. 입력·모델이 같아 예측 재사용이 가능하다. 역할별 분할과 test의 새 seed 영역도 v10 사전 명세를 그대로 따른다. 아직 test 프레임은 없다.

모든5방법에 같은32개 설정(width5/9 × q.98/.995 × patience4/8 × multiplier1/1.5/2/3)을 허용한다. 정상 calibration의 채널별 임계값에 multiplier를 곱한다. 정상 통지 ≤1/line-hour 우선, 그 안에서 paired background 제외 매칭 최대→중복 최소→10초 내 매칭 최대→patience,width,q,multiplier 단순 순으로 고른다. 실패하면 최저 정상 통지율 fallback을 쓰고 실패로 표시한다. 누설에 별도 가중을 주지 않는다. full 동일 설정 TS제거 대조와 gate_only/gate_channel 고정 대조는 v10과 같고, 후자는 선택된 no_timestral의 multiplier까지 공유한다.

개발 선택 후 새 소스·설정·시험 명세·보호 파일·복사한 개발 자료·예측 SHA를 고정하고 그 뒤 처음 test를 생성한다. 모든 예측 저장 뒤 장부를 열어 채점한다. 테스트를 본 뒤 수정하지 않는다. 기존 v9를 같은 새 입력에 적용해 전후 비교하고 과거55·30건과 새36건 수치를 직접 비교하지 않는다.

v10에서 정한 품질 시간·전체 사건 분모·고착 보존·종류별 성적·조건부 p95·10초 내 탐지·정상 통지 불확실성 보고를 유지한다. 정상 노출이 약1.74시간이면0건이어도 독립 포아송 가정 단측95%상한은1건/시간보다 높다. 실제 센서 검증·Pi·운영 연결은 하지 않는다. 개발 탐색을 늘린 데 따른 과적합 가능성과 동일 A/B 계열·고장 유형 공유를 한계로 기록한다.
