# T4 후속 비교 실험 사전 설계

작성자: `/root/experiment_design_fresh`, 2026-09-26. 작성 시점 상태: **초안 작성·정적 확인 대상. 독립 사전 설계 검토 및 동결 대기. 역할 실험 미실행.** 이후 최종 검토·동결 상태는 상위 `../README.md`와 별도 담당자가 작성하는 `../freeze.json`을 확인한다.

기존 COMMON 25개와 장비 20개, 합계 45개는 모두 개발용 `dev/draft/L0`다. 개수는 목표나 상한이 아니다. 이 폴더는 기존 카드를 수정하거나 새 카드를 등록하지 않는다. 기존 파일럿은 카드의 추가효과를 입증하지 않았으며 HPU의 입력 밖 대상명 전제는 엄격 판정 1 / 대안 판정 0의 경계 사례였다.

여섯 장비군의 새 메모 조각을 이용해 상황 6 × 조건 3 × 반복 3 = **54 송수신 쌍, 108 역할 호출**을 계획한다. 송신자에게만 `카드 없음 / 일반 5항목 체크리스트 / 선택 T4의 know_how 원문`을 다르게 제공한다. 카드 전문이나 전체20개 카드의 효과 시험이 아니다. 덜 정리된 원자료를 사용한다는 설계이며 실제 난도 상승이나 조건 차이가 확인됐다는 뜻은 아니다.

| 파일·폴더 | 용도·접근 |
|---|---|
| `protocol.md` | 실행 전 절차·예산·중단·재시도·동결 조건, 운영자용 |
| `coverage-and-lineage.json` | 장비/카드/실패 요인·사건 계보·미포함 범위, 평가·설계용 |
| `card-selection.json` | 선택 버전·노출 필드·실제 복제 텍스트, 운영자용 |
| `input-lengths.json` | 지원 길이 차이, 운영자용 |
| `source-memos/` | 이번 작성자가 새로 쓴 메모 조각 원자료 |
| `sender-packets/` | 상황·조건별 **실제 송신 역할 입력**, 반복 간 동일 파일 사용 |
| `receiver-templates/` | 상황별 수신 입력 틀. 실제 송신문을 넣은 별도 실파일을 실행 때 생성 |
| `evaluation-only/fact-ledger.json` | 원자 사실·미확인 항목과 분모, 역할 노출 금지 |
| `evaluation-only/rubric.md` | 엄격/대안 판정·정상/오류 예시·분석 계획, 역할 노출 금지 |
| `evaluation-only/judgment-template.json` | 독립 판정 양식, 결과 아님 |
| `run-plan.json` | 고정 실행 순서 54개, 전부 `not_run` |
| `execution-log-template.json` | 실행·누락·재시도 기록 양식, 실행 증거 아님 |
| `assemble-design.py` | 이번 파일들을 생성한 stdlib 저자 도구. 정답 포함하므로 역할 접근 금지. 기존 산출물 덮어쓰기 거부 |
| `verify-design.py` | 이 설계 파일의 최소 정적 확인. 역할 호출·동결·등록을 하지 않음 |

저자는 허용된 핸드오프, 장비 카드 보고서·파일럿 결과·연구 문서·장비 맵·카드 JSON, `catalog-projection.json`만 참고했다. 원본 카탈로그와 기존 대본·sealed/holdout은 열람하지 않았다. 새 메모는 카드 방법과 공개된 파일럿 한계를 아는 작성자가 구성했으므로 독립 일반화 평가자료가 아니다. 장비·숫자·문체 치환을 독립 상황으로 세지 않는다.

독립 검토자는 설계·역할 입력·평가 원장을 함께 읽고 의미 누출, 카드 노출 일치, 분모와 예산을 확인한 뒤 수정 필요 여부를 기록해야 한다. 그 검토와 실제 동결 파일·해시는 별도 담당자가 남긴다. 저자 정적 검사 통과는 독립 검토 통과나 동결 완료를 대신하지 않는다.

운영 DB, 출처 등록부, split 정책, 검색 코드, KB 채택, 현장 운전·정비 작업은 범위 밖이다. 역할 실험과 카드 수정·별도 새 상황 평가 역시 이번 설계 작성에서는 실행하지 않았다.
