# 관측 표현 변경 독립 검토 — 2026-09-30

변경 담당 2명(A, T4/C)과 별도 검토자가 카드 변경 전후를 검토했다. 카드 60장 중 21장(A 7장, T4 2장, C 12장)의 관측 표현을 수정했다.

- C의 수치 경계를 `docs/data/reference/00_plant_and_relations.json`의 설비별 `normal_min`·`normal_max`·단위와 대조했다. 정상 범위 경계와 경보 임계값을 혼동하지 않았으며, 가상 MES 수치가 제조사 고장 판정이나 작업 허가 기준이 아님을 본문에 명시했다.
- A의 매뉴얼에 없는 절대 온도·유량·프리차지·냉각 가능 온도 수치는 만들지 않았다. 현장/모델 기준과 계측값을 비교하도록 바꾸고 기준 미확인 시 미판정 또는 보류를 표시했다. 냉각기 입출구와 단일 MES 유온, 현장 베어링부 온도와 가상 신호를 구별했다.
- 소음 성격, 우유빛 거품 등 정성 관측은 유지했다. A K-1025의 표면 온도 측정·점검 가능 온도 대조는 원문의 냉각 대기를 구체화한 관리 표현이며, 원문에 절대 수치가 있다는 주장이 아니다.
- 1차 검토에서 발견한 K-1005 본문/단계 분기 불일치와 C 제목·증상에 남은 상태 표현은 변경 담당자가 보완했고 재검토했다. 검색 조건의 `high`·`low`·`normal` enum은 기존 실행 계약을 유지한다.
- 사건·아티팩트 원장과 출처 식별자, provenance, 카드 ID·개수·상태·등급·조건은 변경하지 않았다. A/C의 `out` 본문과 현재 카드를 대조했다. A의 기존 provenance 차이는 보존했다. 과거 생성 프롬프트와 검수 기록은 당시 기록으로 유지한다.

검증 결과: KB 안의 JSON 47개 구문 통과, 전체 카드 ID 60개 중복 없음, A/T4/C 카드 수 30/11/19 유지, 변경 카드 21장의 식별·스키마·근거 필드 유지, A/C 원본 출력 본문 동기화 통과. `build_kb.py` 결과와 `kb_cards.json`의 구조가 같으며 통합 목록은 A/T4의 41장이다. C는 기존 검수 대기 상태로 별도 보존한다.

환경 한계: T4/C `verify.py`는 실행했으나 스키마 import 단계에서 중단됐다. 기본 Python 3.14와 `.test-deps/pydantic_core/_pydantic_core.cp312-win_amd64.pyd`의 ABI가 맞지 않아 `ModuleNotFoundError: No module named 'pydantic_core._pydantic_core'`가 발생했다. 위 JSON·필드·동기화 검증은 의존성 없이 별도로 통과했으며, 전체 스키마 검증 통과를 주장하지 않는다.

## 후속 검토 — C 초안 19장 전수 적용

사용자 후속 요청에 따라 C의 T2 10장과 T6 9장을 모두 다시 검토했다. T6 9장에 사건별 실측·가상 정상 범위 또는 수치 미기록 상태를 추가했다. 이전 작업에서 수치화한 T2 10장의 경계도 재확인했다.

- K-1211의 152 bar·34 L_min은 EV-0401의 D0 시험기동 AT-4001 및 EV-0402 AT-4004의 관측 결과다. EV-0401의 D1 최종 measurements 133 bar·32 L_min·28 degC와 혼동하지 않는다.
- K-1213의 420 kPa, K-1214의 104 bar, K-1215의 415 kPa·65 pct, K-1216의 정지 전 75 degC→냉각 후 49 degC, K-1217의 106 bar, K-1218의 28 degC·133 bar·32 L_min을 각각 지원 사건의 원장과 대조했다.
- 전원 투입 전 준비 단계의 속도·전류 0은 운전 이상으로 판정하지 않는다. K-1212의 실제 유면과 K-1219의 30일 전 시험운전 수치는 미기록으로 명시했다. 추가한 `gr_oil_level` 가상 정상 70–100 pct는 `shiftlink/mes/scenarios/priority.py`의 SignalSpec과 일치하며 미측정 유면의 대체 판정에 쓰지 않는다. 인터록·방호·승인 확인에 숫자 0/1을 임의 부여하지 않았다.
- C 19장의 카드 ID·개수·상태·등급·검색 조건·provenance·구조화 payload가 기존 저장본과 같음을 검사했다. T6의 `tried_and_failed` 18건은 지원 사건의 restart_attempts와 완전히 일치한다. C 19장의 `out` 카드와 현행 cards.json 완전 일치도 통과했다.

C는 초안 상태로 유지하며 통합 accepted 목록에 추가하지 않았다. 원문·사건에 없는 절대값이 필요한 유면·편주·과거 시험운전은 수치 미확인 상태로 남긴다. 전체 스키마 검증의 위 환경 한계도 그대로다.
