# 전혜민 ShiftLink 시연 대본 초안

2026-10-07 M2 검토용. 발표는 전혜민, PDA 시연은 유현준, 모델·채점 설명은 최재영을 맡는 기존 역할안에 맞췄다. 본 흐름은 **Unity 장면 촬영→설비 식별→질의와 안전 카드→인계 저장→클라우드와 다음 조 확인**이다. 시연 질문의 실제 검색 결과와 장치 검증을 마친 뒤 사용할 질문을 확정한다.

## 시연 전에 확인할 것

- 선택 설비 ID와 Unity 이름표·PDA 표시가 일치한다.
- 학습 CNN이 준비됐으면 모델 식별값·클래스명·설비 ID 연결 기록을 확인한다.
- 시연은 hybrid, 판정 모델은 `exaone-sft-judge`, 답변 모델은 `exaone-sft-answer`로 준비한다. 두 모델 예열과 응답 준비를 확인한다.
- 안전 카드가 적용되는 질문에서 안전 카드 맨 앞·근거 카드 ID를 사전에 실제 화면으로 확인한다.
- 인계 테스트 데이터와 업로더 서비스·접속 준비 상태를 확인한다.
- 화면 녹화·로그 경로를 정하고 접속 정보·키가 화면에 나오지 않게 한다.

## 본 흐름 대사 초안

### 1 문제와 시연 범위 소개

전혜민: “설비에 이상이 생기면 어떤 자료를 먼저 봐야 하는지, 다음 조에 무엇을 남겨야 하는지 찾는 데 시간이 걸립니다. ShiftLink는 설비를 식별한 뒤 지식 카드에 근거한 점검 안내와 안전 정보를 보여주고, 작업자가 남긴 내용을 인계 기록으로 이어줍니다. 지금은 Unity 가상 공장 장면으로 이 흐름을 보여드리겠습니다.”

화면: Unity 공장과 PDA. 설비 직접 제어 기능이 아니라 조회·안내·기록 흐름임을 설명한다.

### 2 촬영과 설비 식별

유현준: “화면 속 설비를 카메라로 촬영합니다. 인식된 설비가 PDA에 표시되면 이름표와 설비 ID가 일치하는지 확인합니다.”

동작: Unity 대상 설비를 웹캠으로 촬영→파이 클래스명 출력→Jetson 전달→PDA 설비 표시 확인.

증거: 입력 이미지·모델 식별값·클래스명·설비 ID·응답 로그·PDA 화면. 실제 흐름이 성공한 경우에만 이 단계의 성공을 설명한다.

### 3 질문과 근거 답변

유현준: “HPU 베인펌프 운전 중인데 출구 압력계에 압력이 안 잡혀요. 뭐부터 확인해요?”

동작: 질문 전송 후 답변 문장·근거 카드 ID·안전 카드 순서를 보여준다. 기대 진단 카드 `K-1001`과 실제 응답을 대조한다.

전혜민: “답변 옆의 카드 ID로 안내의 근거를 확인할 수 있습니다. 적용되는 안전 카드는 앞에서 확인하고, 원인을 단정하기보다 카드에 있는 점검 순서를 살펴봅니다.”

검토: 답변이 ID 문자열만 나오지 않는지, 질문·MES 등 확인된 입력에 없는 측정값을 관측 사실처럼 말하지 않는지 확인한다. 적용 안전 카드 ID는 실제 결과로 기록한다.

### 4 안전 질문 확인

유현준: “유압 유닛 정비 들어가려는데, 설비만 멈추면 돼요? 압력도 빼야 해요?”

동작: 기대 카드 `K-1006`의 운전 중 정비 금지·해당 계통 감압 안내와 실제 답변을 대조하고, 안전 카드가 맨 앞에 있는지 보여준다.

전혜민: “정비 전에는 해당 안전 절차를 먼저 확인합니다. 실제 작업은 현장 작업 절차와 담당자의 판단에 따라 진행합니다.”

G2 판정에는 이 질문이 실제로 적용 안전 카드를 반환한 화면 또는 로그가 필요하다. 대본에 적힌 기대 카드만으로 통과를 선언하지 않는다.

### 5 인계 메모 저장

유현준: “다음 조가 이어서 볼 수 있도록 지금 확인한 상태와 아직 해야 할 일을 남기겠습니다.”

메모 예시: “시연 질문: 출구 압력 미표시. 원인 미확정. K-1006 안내: 정비 전 해당 계통 감압 필요. 정지·감압 이행 여부 미확인. 담당자 확인 전 정비 보류.”

동작: 실제 확인한 내용으로 메모를 수정하고 저장→인계 ID·생성 시각·본문·로컬 저장 결과 확인. 수행하지 않은 점검·감압을 완료로 적지 않는다.

전혜민: “인계에는 확인한 사실과 남은 일을 구분해 남깁니다. 이 기록을 기준으로 다음 조가 작업을 이어갑니다.”

G3 확인은 시험 가능한 시간에 저장→프로세스 재시작→동일 ID와 본문 재표시를 별도로 수행한다.

### 6 클라우드와 다음 조 확인

유현준: “저장한 인계가 업로드되면 클라우드 기록과 같은 ID인지 확인하고, 다음 조 목록에서도 내용을 살펴보겠습니다.”

동작: 로컬 인계 ID→업로드 상태→클라우드 같은 ID·본문→다음 조 목록을 확인한다. 다음 조 화면만으로 클라우드 업로드 성공을 판정하지 않는다.

전혜민: “로컬 기록과 클라우드 기록을 같은 ID로 확인합니다. 통신이 끊겼다가 복구된 경우의 누락과 중복은 별도 시험 결과로 설명하겠습니다.”

업로드가 대기 중이면: “인계는 로컬에 저장되어 있고 클라우드 전송은 대기 중입니다. 연결 복구 후 같은 ID로 올라왔는지 확인하겠습니다.”

### 7 마무리와 평가 설명

전혜민: “설비 식별에서 카드 근거 안내, 안전 정보, 인계 기록까지 이어지는 흐름을 확인했습니다.”

위 대사는 모든 단계를 실제로 보여줬을 때 사용한다. 일부 단계가 미검증이면 “오늘은 [확인한 단계]까지 확인했고, [남은 단계]는 추가 검증할 예정입니다.”로 바꾼다.

오늘 검토용 — 최재영: “최종 답변 평가는 10/14에 사전 등록한 E1·hybrid 두 구성을 각각 유효 1회 실행하고 두 결과를 함께 보고할 계획입니다. 카메라를 포함한 지연 측정과 CNN 클래스별 정확도는 별도로 기록합니다.”

10/26 발표용 — 최재영: “[실제 실행일]에 E1·hybrid 두 구성을 평가했습니다. 구성별 표본 수는 [표본 수], 결과는 [실제 결과]입니다. 카메라 포함 지연 측정은 [측정일·표본 수·p95·성공률], CNN 클래스별 정확도는 [클래스별 정확도·표본 수]입니다.” 실제 기록이 확보된 항목만 채워 사용한다.

최종 평가 뒤에는 실제 결과·표본 수·환경·측정 날짜로 대사를 교체한다. 현재 기준 진척률 71%·게이트 0/7이나 카메라 없는 시험 수치를 최종 성능으로 말하지 않는다.

## 오늘 카메라 모델이 준비되지 않은 경우

전혜민: “오늘은 Unity에서 선택한 설비와 실물 PDA 화면이 일치하는지, 답변의 안전 카드와 근거 ID, 인계 저장 상태를 점검하겠습니다. 카메라 인식 흐름은 모델 확보 뒤 별도로 검증할 예정입니다.”

2단계를 Unity 설비 선택→PDA 같은 설비 ID 확인으로 바꾸고, 나머지는 실제 준비된 범위에서 진행한다. 수동 선택·클래스명 주입 결과는 W2-1/G1이나 카메라 포함 20건 측정에 넣지 않는다.
