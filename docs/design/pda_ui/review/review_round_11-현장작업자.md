## 감점 내역

### A1 터치 타깃 (-2 / 8)
- 근거: `pda.html:483`. `#hoPending` 버튼이 appbar(`pda.html:47-48`, min-height 50px, `.ic` 48px) 바로 밑에 margin 0으로 붙어 있다(`pda.html:93`). 「← 이전」 버튼과의 세로 간격은 CSS 수치상 약 2px로, 8px에 못 미친다.
- 왜 문제인가: 장갑 낀 손으로 「이전」을 누르면 업로드 대기 화면이 열리고, 반대 경우도 생긴다.
- 근거: `pda.html:146`, `#alert`의 padding이 `4px 0`이고 아래 테두리가 2px다. 설비 칸(`#ctx`)이 숨는 스캔·직접 선택·알림 확인 화면(`pda.js:129`)에서는 마지막 알림 행(`pda.html:148`)이 appbar 「← 이전」 바로 위에 온다. 간격은 약 7px로 8px에 못 미친다.
- 왜 문제인가: 이 알림 행을 누르면 설비 변경 화면이 열린다. 「이전」을 누르려다 이 행이 눌릴 수 있다.

### A2 대비 (-2 / 7)
- 근거: `pda.html:185` `.card .body`, `pda.html:204-205` `.steps`. 조치 카드 본문(know_how)과 단계 목록 기본색이 회색 `--tx-2`다. 7:1은 넘지만 루브릭은 회색 사용 자체를 감점한다.
- 왜 문제인가: 작업자가 실제로 따라 할 지침 본문이 화면에서 가장 흐린 글자색으로 나온다. 더러운 화면에서 가장 먼저 안 읽힌다.
- 근거: 운용 정보 글자가 10.5~11.5px다. `pda.html:96`(`.lbl` 11px, 대문자·자간 적용), `pda.html:173`(`.safety .basis` 11.5px, 조문 근거), `pda.html:174`(`.safety .gate` 11.5px), `pda.html:194`(`.why` 11.5px, 순위 이유), `pda.html:199`(`.pill` 11px, 조건 판정), `pda.html:242`(`.t4 .k` 10.5px)
- 왜 문제인가: PDA를 팔 길이에서 볼 때 안전 근거 조문과 조건 일치·불일치 판정이 가장 작은 글자로 나온다. 대비 수치가 좋아도 획이 너무 가늘다.

### A4 엄지 도달 (-2 / 5)
- 근거: `pda.html:301`·`pda.js:1405-1414`. 고장 알림 행은 모든 화면 최상단에 놓인 탭 가능한 버튼이다. `pda.html:483`의 `#hoPending`도 최상단에 있는 탭 대상이다.
- 왜 문제인가: 루브릭은 상단을 표시 전용으로 정했다. 설비를 바꾸는 진입점이 한 손 엄지가 가장 닿기 어려운 자리에 있다.
- 근거: `pda.html:342,355,370,387,403,447,455,462,481,490,497`. 「← 이전」과 「⌂ 홈」이 모두 상단 appbar에만 있다. 결과·시도·인계 화면에서는 하단에 되돌아가는 경로가 없다.
- 왜 문제인가: 한 손으로 화면을 오갈 때마다 손을 다시 쥐어야 한다.

### C3 실패 후 다음 동선 (-2 / 4)

- 왜 문제인가: 버튼 문구는 "시도"인데 실제 동작은 "실패 확정"이다. 젖은 화면을 스크롤하다 잘못 눌러도 거짓 실패 기록이 남고, 그 기록이 다음 조치 순위와 인계로 넘어간다.

## 감점하지 않은 것 중 위험 신호

- **실측 필요 — A4 홈 화면 「설비 스캔」 위치.** `pda.html:324-327`에서 큰 버튼이 두 `.grow` 사이, 즉 화면 중앙 부근에 놓인다. 하단 40% 안에 드는지는 브라우저로 실제 렌더 위치를 재야 한다.
- **실측 필요 — A1 간격 2건(위 감점 근거).** CSS 수치로는 2px, 7px이다. 실기기 렌더에서 다시 확인한다.
- **실측 필요 — 증상 질의 화면 길이.** 안전 카드 여러 장과 증상 목록, 관측값이 쌓이면 「검색」(`pda.html:425`)이 스크롤 끝으로 밀린다. 실제 스크롤 길이와 안전 띠가 덮는 높이(`pda.html:162`)를 잰다.
- **비활성 버튼 대비.** `pda.html:85` `.btn[disabled]{opacity:.4}`. 비활성 「검색」·「저장」(primary)은 글자와 배경 대비가 약 3.6:1까지 떨어진다. 이유 문구(`askBlock`, `hoWarn`)가 함께 나오지만, 더러운 화면에서는 버튼 문구가 안 읽힌다.
- **응답 도착 시 화면 강제 전환.** `pda.js:1101-1110`. 대기 중 고장 알림을 눌러 알림 확인 화면으로 갔다가(`pda.js:1429`) 취소하면 `waitAbort`가 설정되지 않는다. 그 뒤 응답이 오면 `show('result')`로 화면이 바뀐다. 손가락 아래에서 화면이 바뀌어 「이 조치 시도」가 잘못 눌릴 수 있다. 위 C3 결함과 겹치면 거짓 실패 기록으로 이어진다.
- **인계 입력칸 기본값.** `pda.html:505-507`, 「야간조 정비 담당」「교대 직후 최초 기동 전」「구두 인계 + 인계서 기록」이 미리 채워져 있다. 확인 없이 저장하면 사실과 다른 수신자·시점이 기록된다. 원천 확인은 데이터 정합 렌즈 몫이다.
- **증상 표시 이름 하드코딩.** `pda.js:439-470`, 카드 ID별 짧은 이름을 손으로 적었고 수치(58℃, 1.2 bar, 80%)가 포함돼 있다. 정본 대조는 데이터 정합 렌즈 몫이다.
- **고장 알림 4대째부터 탭 불가.** `pda.js:1416-1420`, 넷째 설비부터는 코드만 문장으로 나열하고 누를 수 없다. 동시 고장이 나면 직접 선택 목록으로 돌아가야 한다.
