# 기존 페르소나를 적용한 카드 읽기

2026-09-24. [기존 페르소나 정의](../../../../../../seeds/personas_v0.1.yaml)의 V-01·V-02·V-03을 카드 3건에 각각 적용했다. 아래 설명은 **합성 페르소나에 따른 AI 표현·검토 결과**이며 실제 인물의 발언이나 경험이 아니다. 문헌의 사실은 [원본 카드 JSON](../cards.json)에 유지한다. 3개의 지식을 9개의 독립 지식카드로 늘리지 않았다.

| 페르소나 | 정의된 역할 | 이번 적용 |
|---|---|---|
| V-01 박 반장 · 28년 경력 설정 | HPU·GR 운전 지원·현장 점검, 감각 우선 | 타 설비 협업 관점. 간결하게 설명하되 감각·경험으로 CV 안전을 확정하지 않음 |
| V-02 김 기장 · 19년 경력 설정 | RT·CV 운전·이송 점검, 계측 우선 | 직접 담당 관점. 표시값·체크 기록과 실제 확인을 구분 |
| V-03 이 주임 · 12년 경력 설정 | 공용 설비 상태 취합·교대 인계 | 인계 관점. 미확인 사항과 완료·승인을 구분 |

모든 원문 설명은 SD-005 M-101-2012 문헌의 해당 조항을 요약한 것이다. 현행 현장 절차의 적합성은 확인하지 않았다. **역할별 검토 메모는 페르소나 설정에서 나온 보조 설명이며 원문에 추가된 의무나 조치 순서가 아니다.**

## K-0301 · 정지스위치 주변 장애물 금지

원문: PDF p.7 / 인쇄 p.5 / §4.3(3). 유형 T5.

| 관점 | 원문을 읽는 설명 | 역할별 검토 메모 |
|---|---|---|
| 박 반장 | 정지스위치 주위에 장애물을 두지 말라는 내용이다. 장애물을 치우러 접근하는 방법까지 적힌 조항은 아니다. | 짧게 설명해도 “주변만 비우면 괜찮다”라는 안전 판정으로 축약하지 않는다. CV의 실제 상태는 미확인이다. |
| 김 기장 | CV 정지스위치 주변 장애물 금지로 읽는다. 담당 범위에 RT가 있어도 이 원문을 RT 작업 허가로 넓히지 않는다. | 계측값 정상이나 빈 체크는 장애물 없음의 확인 기록이 아니다. 기록이 제공되지 않은 항목은 미확인으로 구분한다. |
| 이 주임 | 금지 규칙을 설명한 카드이며 현재 장애물 유무나 제거 완료를 보고한 문장은 아니다. | 규칙을 인계받았다는 기록과 현장 조치 완료를 구분한다. 인계 수락만으로 미해결 사항이 해결됐다고 표시하지 않는다. |

추가 확인 질문: 실제 주변 상태를 확인한 기록이 있는가? 장애물이 있을 때 적용할 작업 조건은 어떤 현장 문서에 있는가? 답은 이번 원문·카드에 제공되지 않았다.

## K-0302 · 비상·사고 정지 후 재기동 전 확인

원문: PDF p.7 / 인쇄 p.5 / §4.3(7). 유형 T6, `abnormal_stop_restart`.

| 관점 | 원문을 읽는 설명 | 역할별 검토 메모 |
|---|---|---|
| 박 반장 | 비상·사고로 멈춘 CV를 다시 기동하기 전에 정지 원인과 고장 장소의 보수상황 등을 확인하라는 내용이다. | 경험을 근거로 “확인했으니 돌려라”로 줄이지 않는다. 원문에 없는 HPU·GR 원인 추정도 더하지 않는다. |
| 김 기장 | 정지 원인과 보수상황은 재기동 전에 확인할 대상이다. 카드에는 실제 확인 결과가 없다. | 정상 표시나 알람 해제를 보수 완료·재기동 승인과 동일시하지 않는다. 확인 대상과 확인 완료를 구별해 읽는다. |
| 이 주임 | 재기동 전 확인 요구를 전달하는 문헌 요약이며, 보수 완료 보고나 재기동 허가 자체가 아니다. | 확인된 내용·미확인 항목·승인 여부를 혼합하지 않는다. 인계 수락이나 조장 직책이 승인 근거를 대신하지 않는다. |

추가 확인 질문: 정지 원인과 보수상황 각각의 확인 기록이 있는가? 현장 작업표준의 재기동 조건과 승인 기록은 무엇인가? 현재 담당자·시각·결과를 임의로 채우지 않았다.

## K-0303 · 올라가기 금지와 원문 예외

원문: PDF p.8 / 인쇄 p.6 / §4.3(11). 유형 T5.

| 관점 | 원문을 읽는 설명 | 역할별 검토 메모 |
|---|---|---|
| 박 반장 | 작업상 부득이한 경우에도 사업주가 안전상 필요한 조치를 한 경우를 제외하고는 컨베이어에 올라가지 말라는 내용이다. | “잠깐이면 된다”거나 “멈췄으니 된다”로 예외를 넓히지 않는다. 반장이라는 설정도 예외 충족의 근거가 아니다. |
| 김 기장 | 올라가기 금지와 사업주 안전조치에 관한 예외를 함께 읽는다. 이 조항에는 충분한 조치의 구체 목록이 없다. | 정지 표시·정상 수치·빈 체크 하나로 예외를 충족했다고 판단하지 않는다. 금지와 예외를 함께 표시한다. |
| 이 주임 | 예외 문구가 있다는 사실과 실제 예외 조건이 확인됐다는 사실은 다르다. | 조장 확인이나 인계 수락을 작업 허가로 바꾸지 않는다. 보수적 성향만으로 원문의 예외를 삭제하지도 않는다. |

추가 확인 질문: 해당 현장에서 필요한 안전조치와 확인 기준을 정한 문서는 무엇인가? 실제 조건 충족을 뒷받침하는 기록이 있는가? 원문에 없는 조치 목록·승인자는 추가하지 않았다.

## 적용 결과와 근거

3명의 검토 모두 문헌 사실 본문 유지를 제안했다. 따라서 이번 반영은 **역할별 설명 9개, 오해 방지 메모 9개, 미확인 질문**으로 구성했다. 카드 ID·분류·분할·생성자 이력은 유지하며 페르소나를 원문 출처나 실제 생성자로 덮어쓰지 않았다. 인계 관점이 추가됐다는 이유로 T4 카드를 만들지 않았다. 상태는 계속 `draft/L0`다.

개별 근거와 판단: [V-01 검토](V-01.json) · [V-02 검토](V-02.json) · [V-03 검토](V-03.json). 적용 기록과 파일 해시는 [application.json](application.json)에 있다. 원문 주장과 역할별 제안 사이에 사실 충돌은 발견하지 못했으며, 전체 현장 타당성을 확인했다는 뜻은 아니다.
