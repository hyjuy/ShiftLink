## 감점 내역

### A1. 터치 타깃 (-2 / 8점)
- 근거: 라인 99 `overflow:hidden`, 라인 665~722 프레임 10
- 왜 문제인가: 
  - pane의 사용 공간 674px 대 컨텐츠 781px (오버플로우 107px)
  - row2 버튼들이 화면 아래로 잘려 화면에서 탭할 수 없음
  - 실질 터치 타깃이 선언된 56dp보다 작아짐. 장갑 낀 손(최소 14mm)이 정확히 누르기 어려움
  - 오버플로우된 영역에 주 행동 "이 조치 시도"(라인 689)와 "다음 조치"(라인 711) 동선 포함

### A2. 대비 (-2 / 7점)
- 근거: 라인 21~23 --tx-3 (#7C8792), 라인 54, 161, 207 사용처
- 왜 문제인가:
  - #7C8792 대 배경 #0A0D11의 대비: ~4.2:1 (7:1 미달)
  - 저조도(야간 현장) 환경에서 가독성 부족
  - 행동 필요 정보에 사용: 설비 마크(라인 161), 진행 단계 번호(라인 207), 프레임 설명(라인 54)
  - 라인 1131의 공식 타깃 사이즈 명시에도 불구하고 색상 대비는 미달

### A4. 엄지 도달 (-2 / 5점)
- 근거: 라인 326~345 프레임 01, 라인 104~111 .btn 스타일, 화면 높이 760px
- 왜 문제인가:
  - 프레임 01의 스캔 버튼: fill(flex-grow:1)으로 중앙에 배치되어 하단 40%(304px) 밖
  - 프레임 10의 주 행동이 overflow:hidden으로 가려짐 (위 A1 참조)
  - 현장에서 한 손 엄지로만 접근 가능한 영역은 y≥456px인데, 주 행동이 이 범위를 벗어남

### B1. 안전 카드 최상단 고정 (-2 / 8점)
- 근거: 라인 742~752 프레임 10-b, 루브릭 B1 "무관하게 최상단"
- 왜 문제인가:
  - 프레임 10-b에서 안전 카드가 완전히 누락됨
  - "다음 조치"를 보여줄 때도 "조치 전 필수"인 안전 조건을 재진입해야 함
  - K-0108(T5 안전)이 조치 3번으로 표시되고 있는데(라인 744), 이는 안전을 선택지 목록에 혼합한 것으로 읽힘
  - 프레임 10-b 페이징에서 안전이 시야에서 벗어나면 작업자가 "아직도 이 안전이 필수인가" 재확인 불가

## 감점하지 않은 것 중 위험 신호

### 잠재적 유지 감점 후보 (현 라운드에서 미감점)

**C3 "실패 후 다음 동선" — 오버플로우로 동선이 보이지 않음:**
- 루브릭 C3: "시도 실패 기록 후 다음 조치로 가는 경로 + 순위 갱신 이유 노출"
- 프레임 11(라인 796~802)에서 순위 갱신 이유("설비 단위 조치 2건이 모두 배제되어 범위를 공급원으로 넓힘")가 명시됨
- 하지만 프레임 10의 row2 버튼들과 다음 조치 페이징 UI가 overflow:hidden으로 가려져 실제 동선이 작동하지 않을 수 있음
- 현재는 C3 라인 809의 명시적 설명문으로 의도는 보이므로 감점 보류, 하지만 **다음 라운드에서 재평가 필수**

### 이 렌즈에서 판단 근거가 약한 항목

**A3 "탭 전용" — 호버 CSS는 없으나 JS 동작 미검증:**
- HTML에는 drag/pinch/longpress 이벤트 없음 (라인 전수 검토)
- 하지만 임포트 후 피그마 프로토타입 환경에서의 모션 동작은 검증 불가
- 토큰과 CSS만으로는 충분하지만, 실제 인터랙션 테스트 필요

**D1 "실값 사용" — 문서 참조만으로 데이터 일치 검증 불가:**
- 라인 8~10에서 출처를 명시했으나, 실제 `docs/data` 파일 내용과 일치 여부는 직접 비교 필요
- 파일 헤더 설명만으로 기준 충족으로 판정함 (검증용 파일 비교 불가)
