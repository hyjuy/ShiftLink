# 운전·부하 정상 기준 보완 후보 — 사전 고정 검증 계획

2026-10-23. 기존 v14c settings/core·r1/r2·평가 결과는 보존한다. 모든 생성·보정·회귀·평가는 Raspberry Pi에서 실행하고 운영 MES·경보에는 시험 고장을 주입하지 않는다.

문제는 HPU 냉각기 입출구 정상 관계와 CV 대기율 0% 등 실제 MES 운전 분포가 연구 정상 분포와 다른 것이다. 새 후보는 기존 core의 별도 subclass/정상 profile로 구현한다. 감지 대상 값으로 부하를 분류하거나, 실시간 오경보를 정상으로 자동 학습하지 않는다.

컨텍스트는 승인 config와 유효한 MES 코일 ID·위치·설비 및 운전 속도 명령으로 empty/moving/queued × slow/nominal/fast를 구분한다. 정상 자료에서 HPU 입출구 온도 차이를 보정하고 CV 대기율은 독립 코일 위치·구성 용량과 비교한다. 원시 고착·동시 온도 상승 근거를 유지하고, 정상 범위 밖의 센서를 정상화로 덮지 않는다. 부하 정보가 없거나 범위를 벗어나면 기존 모델로 되돌아간다. 코일이 없는 대기율 0%는 고착 근거로 쓰지 않되 실제 코일이 있는 정체·측정 불일치는 보호한다.

1. 기존 2,902프레임 진단은 개발용 소비 자료다. 새 검증으로 포장하지 않는다.
2. 정상 profile 적합은 정상만 생성한 별도 train run/seed/nonce로 수행한다. MesEngine 정상 및 SignalDynamics 정상 두 경로를 사용하며 고장 PATTERNS/FaultSchedule을 평가 고장 생성에 쓰지 않는다. 정상 생성 일부를 공유하므로 현장 독립 검증으로 설명하지 않는다.
3. 개발셋으로 정상·부하 전환·고장·품질·재시작 회귀를 확인한다. 실패 시 개발 결과/후보를 보존하고 개발셋에서만 수정한다.
4. 후보 코드·profile·평가 규칙 SHA256을 고정한 뒤 새로운 test run/seed/nonce를 생성한다. 시험 자료를 보고 문턱을 수정하지 않는다.
5. 온도 상승(오일/냉각수), 누설, 마찰, 비컨텍스트 센서 고착, 보정 대상 온도 고착, CV 센서 불일치·실제 정체를 별도 개입 장부로 채점한다. normal/abnormal 관측값을 같은 곳에서 만들더라도 고장 개입은 검출 코드와 분리한다. 라벨·active_alarms는 모델의 부하 선택 입력으로 쓰지 않는다.
6. 통과 기준: 새 정상 실행 오통지 0, 개발/새 시험에서 기존 모델이 감지한 사건을 새 후보가 잃지 않음, 새 사건 탐지 ≥95%, 중복 통지 0, 동일 검출 사건 p95 지연 악화 ≤2초. 사전의 작은 합성 개입이 실제 장비 고장을 모두 대표하지는 않는다.
7. 기존 소비 평가의 행별 통지 일치를 별도로 확인해 v14c 회귀를 보존한다. 신규 profile을 모르는 원본 스키마/부하 정보 없는 자료는 기존 모델 경로 그대로다.
8. Pi 1초 처리·기존 PDA 경보/고장 정지 이력 회귀·현재 MES 독립 shadow 결과·원본 해시·systemd/롤백을 확인하고 통과 후보만 새 state directory로 배포한다. 실측 센서 정확도 및 고장→화면 p95는 별도 미검증으로 남긴다.


## 개발 중 발견한 계약 차이와 평가 확장 (미사용 평가 생성 전)

실제 replay에는 코일 위치가 보존되지만 속도 명령은 없다. 현재 `/api/state.speed`를 과거 replay에 대입하지 않는다. 속도를 모르는 경로는 정상 학습 자료의 세 속도 조건을 합친 unknown:empty/moving/queued 기준을 사용한다. 속도가 주어지면 기존 9개 조건을 사용하고, 잘못된 속도·코일 정보는 원본 경로로 되돌아간다. 실제 replay 2,902프레임은 계속 개발 소비 자료로 분류한다.

정상 학습은 9조건 × 2정상 생성 경로 × 4실행 × 224프레임 = 16,128프레임으로 확장했다. 고장 자료를 정상 기준 적합에 사용하지 않는다. 조건별 중심·최대 정상 편차의 2배(원래 scale 하한), 정상 온도 상승 최대의 1.5배(원래 thermal limit 하한), 정상으로 관측한 조절 전압·압력의 정체값을 보존한다. 잡음이 있는 진동 센서의 고착 창은 학습 정상 고정 구간보다 2프레임 길게 정하며 5~16프레임 범위다. 정상 정체값만으로 실제 센서 고장을 식별할 수 없는 한계가 있다. CV는 정상 정체값 예외보다 독립 코일의 위치·움직임을 우선해 실제 정체를 보호한다.

개발 비교는 기존 24고장+6정상, 정상 전환 6실행, 속도 없는 replay 조건의 별도 24고장+6정상으로 확장한다. 미사용 시험은 12조건 × 8고장 = 96고장, 12조건 × 2정상 경로 = 24정상, 정상 전환 6실행으로 총 126실행·28,224프레임이다. 새 test role nonce는 후보 lock에서 먼저 만들고, 코드·profile·평가 규칙의 SHA256을 고정한 뒤 생성한다. run_id·seed·nonce가 train/개발/전환/replay개발/test 사이에 겹치지 않는지 모두 검사한다. 앞의 통과 기준은 유지한다. 전체 탐지 지연 p95와 동일 검출 사건의 지연 차이는 함께 보고하며, 서로 다른 평가셋의 수치를 직접 성능 개선률로 계산하지 않는다.

기존 PR #343이 병합되고 운영이 r3-c6c8872로 갱신된 사실을 작업 중 확인했다. 최신 main을 별도 후보 브랜치에 통합하고 POSIX 디렉터리 fsync와 기존 PDA 동작을 보존한다. 이번 정상 기준 후보는 별도 후속 PR과 새 체크포인트 경로로 적용한다.
