# Jetson 모델 후보 선택 실험 (2026-10-01)

작성: 최재영·Claude · 같은 내용 HTML: [model-selection-20261001.html](model-selection-20261001.html) · 같은 날 장애 보고서: [jetson-ollama-memory-20261001.md](jetson-ollama-memory-20261001.md)

## 요약

- **질문**: 질의 모드에서 검색 상위 카드 5장을 모델에 주면, 모델이 그중 정답 카드를 골라 인용하는가?
- **답**: 아니다. 방식 5가지 × 모델 2개 모두 검색 1위(28/29)보다 낮았다. 가장 좋은 exaone v3도 22~23/29였다.
- **결정**: 질의 모드는 검색 1위 카드 1장만 모델에 넘긴다 (`QUERY_MAX_CANDIDATES = 1`, 브랜치 `feat/query-single-candidate`).
- **확인**: 실제 Jetson에서 exaone 인용 정답 28/29 (검색 1위와 같음), p50 4.9초 → 4.2초.
- **인계 모드 (T4 실측, 7절)**: 근거 문장 가중치 0.5는 검색 상위 5 정답을 8 → 11/16으로 늘렸지만 모델 인용 정답은 그대로(2/16)였다. 후보 1장일 때 4/16로 가장 높아 인계 모드도 1장으로 한다. 답 없는 인계 질문 4개는 어느 조건에서도 "모름"으로 처리되지 않았다.

## 1. 실험 계획

### 1-1. 배경

9/29 벤치마크에서 exaone에 후보 5장을 주면 모델이 1순위로 인용한 카드가 정답인 경우가 8/30이었다. 같은 문항에서 검색 1위는 27/30이 정답이었다. 모델이 고르는 단계가 정확도를 깎는다는 신호였다. 그래서 프롬프트와 출력 형식을 바꿔 모델의 고르기를 살릴 수 있는지, 아니면 고르기를 빼야 하는지 확인하기로 했다 (autoresearch 루프 B, `docs/autoresearch/program.md`).

### 1-2. 가설

| 가설 | 대응 방식 |
|---|---|
| H1 모델이 답을 먼저 쓰고 인용을 나중에 붙여서, 답에 끌려 인용이 흐트러진다 | v1 인용을 먼저 출력 |
| H2 `K-1004` 같은 ID가 비슷해 헷갈린다 | v2 후보를 1~5 번호로 표시 |
| H3 카드 본문 JSON이 길어 핵심(제목·증상)을 놓친다 | v3 번호 + 한 줄 색인만 |
| H4 고르기와 답 쓰기를 한 번에 하면 둘 다 나빠진다 | v4 2단계 (색인에서 번호 고르기 → 고른 카드로 답 쓰기) |

### 1-3. 고정한 조건

| 항목 | 값 |
|---|---|
| 문항 | 31개 = dev 답 있는 11개 (`eval/qa/20260929/qa_dev.json`) + 9/29 벤치마크 20개. 시험셋(`qa_test.json`)은 쓰지 않음 |
| 채점 대상 | 정답 카드가 검색 상위 5장 안에 든 29문항 |
| 카드 | main `kb_cards.json` 62장 (#115 배치 C 머지 전) |
| 모델 | `exaone3.5:2.4b-instruct-q4_K_M`, `qwen2.5:3b-instruct-q4_K_M` (한 번에 하나만 적재, 끝나면 `ollama stop`) |
| 장비 | Jetson Orin Nano Super, 15W, ollama 0.34.1, SSH 터널 |
| 생성 | temperature 0, num_ctx 2048, num_predict 256, 출력 형식은 JSON 스키마(후보 enum) |

### 1-4. 지표와 판정

- **주 지표 sel@1**: 모델이 1순위로 인용한 카드가 정답(primary)인 문항 수 / 29
- 보조: 인용한 카드 중 하나라도 정답 (hit_any), 응답 시간 p50·p95 (첫 문항 제외)
- **판정**: sel@1이 검색 1위(retrieval_top1)를 넘는 방식이 있으면 그 방식을 채택한다. 없으면 질의 모드 후보를 1장으로 줄인다.

### 검색 1위가 틀렸는데 모델이 맞힌 문항

Q-019 한 문항뿐이다. 검색 순위 K-1012, K-1013, K-1010 중 모델이 3위 K-1010(정답)을 골랐다 (exaone v1~v4, qwen v2~v4). 반대로 검색 1위가 맞았는데 모델이 다른 카드를 고른 문항은 실행마다 6~26개였다 (exaone 6~23, qwen 19~26).

## 4. 해석

- **모델은 고르기를 잘하지 못한다.** 가장 좋은 exaone v3도 검색 1위보다 5~6문항 낮다. 모델이 더 맞힌 경우는 29문항 중 1문항이다.
- **좋아진 방식은 사실상 "1위를 고르게 만든" 방식이다.** v2·v3에서 정답이 늘어난 만큼 1위 선택이 늘었다. 번호로 표시하면 모델이 1번을 고르는 경향이 커지고, 1번이 대부분 정답이라 점수가 올랐다.
- **카드 ID로 보여 주면 4번째 후보로 쏠린다** (base·v1, 두 모델 공통). 원인은 확인하지 않았다. 후보 순서나 ID 모양에 끌리는 편향으로 보인다.
- **qwen이 exaone보다 전 방식에서 낮고 느리다.** 고르기 실험만으로 모델을 확정하지는 않는다 (답변 문장 품질은 따로 본다).
- 가설 H1(인용 먼저)은 exaone에서 조금 나아졌고(5→9) qwen에서는 나빠졌다(5→2). H2·H3은 1위 쏠림을 늘려 점수를 올렸다. H4(2단계)는 v3보다 낮고 호출이 두 번이다.

## 5. 결정과 반영

판정 기준대로, 검색 1위를 넘는 방식이 없으므로 **질의 모드는 검색 1위 카드만 모델에 넘긴다.**

- `shiftlink/edge/ollama.py`: `QUERY_MAX_CANDIDATES = 1`. `split_context()`가 질의 모드에서 검색 상위 1장만 후보로 둔다. 출력 스키마의 인용 enum도 그 1장이다. 안전 참고 카드는 그대로 나간다.
- 검색(`search_cards`의 k=5)과 평가용 `ranked_cards`는 그대로라 오프라인 지표(`route_score`)는 바뀌지 않는다.
- 테스트: 후보 여러 장 경로를 확인하던 3개는 상한을 5로 올려 그대로 확인하고, 1장만 넘기는 테스트를 하나 더했다. pytest 552 통과.
- **실제 모델 확인** (exaone, 같은 31문항, 후보 1장): sel@1 **28/29** (검색 1위와 같음), p50 **4.2초** (base 4.9초), p95 4.7초, 검토 대기열 0.
- 브랜치 `feat/query-single-candidate` (커밋 31e28dd)는 이 보고서와 별도 PR로 올린다.

### 7-1. 결과 (같은 날 12시경 실행)

답 있는 16문항 기준. 답 없는 4문항은 "모름" 처리(abstain) 수.

|---|---|---|---|---|---|---|---|---|
| ① 가중치 0.5 + 후보 5장 (main) | 1 | 2 | 4 | **11** | 0/4 | 0.83 | 3.8초 | 5.7초 |
| ② 가중치 0 + 후보 5장 | 0 | 2 | 4 | 8 | 0/4 | 0.85 | 3.8초 | 7.0초 |
| ③ 가중치 0.5 + 후보 1장 | **4** | **4** | 4 | 11 | 0/4 | 0.63 | 4.6초 | 5.4초 |

|---|---|---|---|---|---|---|

### 7-2. 해석

- **근거 문장 가중치는 검색에서만 효과가 있다.** 상위 5장 정답이 8 → 11로 늘었지만(오프라인과 같음), 모델이 그 후보에서 정답을 인용한 수는 ①·② 모두 2개다.
- **인계 모드에서 모델은 마지막(5번째) 후보로 크게 쏠린다** (① 13/16). 질의 모드에서 4번째로 쏠린 것과 같은 종류의 순서 편향이다.
- **후보 1장이 가장 낫다** (③ 4/16 = 검색 1위 정답 수). 다만 검색 1위 정답 자체가 4/16로 낮아, 인계 모드의 남은 문제는 모델이 아니라 검색 순위다.
- **답 없는 4문항을 하나도 "모름"으로 처리하지 못했다** (세 조건 모두). 4개 중 3개는 검색 결과가 비었는데도 모델이 인계 안전 카드 K-1103을 인용했다. 질의 모드는 검색 결과가 없으면 모델을 부르지 않고 "해당 지식 없음"을 내지만, 인계 모드에는 이 처리가 없다. 후보가 없을 때 인용 enum이 걸리지 않아(`minItems` 0, ID 패턴만) 안전 참고 카드 ID를 인용할 수 있다.

### 7-3. 판정과 후속

| 판정 기준 | 결과 | 결정 |
|---|---|---|
| ①이 ②보다 인용 정답이 같거나 많고 답 없는 처리가 나빠지지 않음 | 2 = 2, 0/4 = 0/4 | **가중치 0.5 유지** (검색 상위 5 정답이 늘고, 모델 쪽 손해 없음) |
| ③이 ①보다 인용 정답이 많음 | 4 > 2 | **인계 모드도 후보 1장** |

후속 과제:
1. 인계 모드 후보 1장 — #119에 함께 반영 (승인 후)
2. 인계 모드에서 검색 결과가 비면 모델을 부르지 않고 "해당 지식 없음"으로 처리 (질의 모드와 같게). 답 없는 처리 0/4의 직접 원인
3. 인계 모드 검색 1위 정확도(4/16) 개선 — 카드 쪽 문구(T4 담당 허재원)와 검색 쪽을 함께 본다
