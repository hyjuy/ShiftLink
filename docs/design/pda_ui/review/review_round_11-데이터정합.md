## 감점 내역

### D1 실값 사용 (-1 / 6)
- 근거: `pda.js:1160`이 인계 미종료 항목의 근거로 `basis_ids`를 그대로 보인다. 그 값 `K-0101`·`K-0104`(`EV-0031_upstream_cause.json:1197`, `:1207`)는 정본 `kb_cards.json`에 없는 카드 ID다. 시나리오 파일에만 있다(`EV-0031_upstream_cause.json:711`, `:942`).
- 왜 문제인가: 검색 대상 카드 집합에 없는 카드 ID가 근거로 화면에 나온다. 작업자가 그 카드를 PDA에서 열거나 찾을 수 없다.

### D2 ID 혼용 없음 (-2 / 5)
- 근거 1 (-1): `pda.js:79`는 `type: String(e.code).split('-')[0]`로 설비 유형을 표시용 `code` 문자열에서 잘라 낸다. 이 값이 카드 대조 키로 쓰인다(`cardFits`, `pda.js:46`). 정본에는 `equipment_type_id`가 따로 있다(`00_plant_and_relations.json:236`).
- 왜 문제인가: 라벨 표기 규칙이 바뀌면 카드 대조가 조용히 틀어진다. 라벨용 code를 데이터 키로 쓰고 있다.
- 근거 2 (-1): `pda.js:1122-1124`는 인계 기록을 고를 때 `open_items[].text` 자유 문장에 `S.eq.code` 부분 문자열이 있는지만 본다.
- 왜 문제인가: `equipment_id` 키가 아니라 문장 속 code 언급으로 설비를 엮는다. 예를 들어 RT-03(EQ-0008)이 EV-0031의 실제 대상 설비인데도 문장에 "RT-03"이 없으면 걸리지 않는다.

### D3 지어내지 않음 (-4 / 4, 하한 0에서 멈춤)
- 근거 1 (-2): `pda.js:946-956`의 「이 조치 시도」는 버튼 한 번에 `failure_reason: '조치 후에도 증상이 유지됨'`을 고정 문자열로 기록한다. 화면에도 「효과 없음」·「시도함 · 효과 없음」이 붙는다(`pda.js:975`, `pda.js:800`). 성공을 고를 경로가 없다. `observed_result`는 조치 후 관측이 아니라 누른 시점의 기존 관측값이다(`pda.js:949-951`).
- 왜 문제인가: 작업자가 입력하지 않은 실패 결과가 기록으로 만들어진다. 이 기록은 인계 `attempts`로 MES 저장소까지 간다(`pda.js:1339`). 원천 없는 사실이 저장되는 경로다.
- 근거 2 (-1): `pda.html:505-507`이 인계 RECIPIENT_ROLE·TIMING·CHANNEL을 「야간조 정비 담당」·「교대 직후 최초 기동 전」·「구두 인계 + 인계서 기록」으로 미리 채운다. 데이터의 교대 체계는 A/B/C조다(`EV-0031_upstream_cause.json:1174-1175`). 「야간조」 같은 원천은 없다.
- 왜 문제인가: 수정하지 않고 저장하면 지어낸 값이 `required_context`로 저장된다(`pda.js:1337-1338`).
- 근거 3 (-1): `pda.js:457`의 K-1203 라벨은 「출구 압력 정상 · 압력/유량 부족」이다. 원천 symptom은 "펌프 출구 압력은 **읽히지만** 작업에 필요한 압력 또는 유량이 **부족**하다"(`kb_cards.json:3188`)이고, 압력이 정상이라고 하지 않는다. 원문은 선택한 뒤에만 보인다(`pda.js:586`).
- 왜 문제인가: 압력 부족 증상인데 목록에서는 "압력 정상"으로 읽힌다. 원천과 반대인 표기다.
- 근거 4 (한도 초과로 점수 반영 없음): `pda.js:1125`는 설비에 맞는 인계가 없으면 `S.handovers` 전체를 표시한다. 상단에는 현재 설비 code가 그대로 보이고(`pda.js:187`), 「다른 설비 기록」이라는 표시가 없다. 인계 카드에는 행동 카드의 「출처: 합성 데이터」(`pda.js:880`) 같은 표기도 없다(`pda.js:1138-1161`).
- 왜 문제인가: CAU-01을 선택해도 HO-0101(라인 속도·GR-01)이 그 설비의 인계처럼 보인다.

## 감점하지 않은 것 중 위험 신호

- `pda.js:647-657`: `queryPayload()`는 호출되지 않는 코드인데 `line_id: 'LN-0001'`, `k: 5`가 고정값으로 남아 있다. 나중에 다시 쓰이면 라인 하드코딩이 된다.
- `pda.js:247`: 스캔 결과에 code가 없으면 `scan.class`(분류 클래스명)를 「현재 구성에 없는 설비 code」 문구 앞에 보인다. 클래스명이 code처럼 표기될 수 있다.
- `pda.js:439-470`: `SYMPTOM_LABELS`는 카드 내용을 코드에 복사해 둔 것이다. HTML 주석은 "값을 복사해 두지 않는다"고 하지만(`pda.html:15-16`) 실제로는 복사본이다. kb가 갱신되면 라벨이 원천과 어긋날 수 있다. 지금은 K-1203을 빼고 원천과 맞는다.
- `pda.js:948`, `pda.js:1081`: `AT-0001` 시도 ID가 검색할 때와 설비를 바꿀 때마다 다시 1부터 시작한다. 인계 `attempts`에서 서로 다른 세션의 ID가 겹칠 수 있다.
- `pda.js:1073`: 「이 설비 유형의 안전 카드 없음」이라고 쓰지만, 실제 판정(`cardFits`)은 유형 + COMMON + 설치 지정(`mes_equipment_id`)이다. 문구가 판정 범위와 다르다.
- `pda.js:991`, `pda.js:1003`: 「순위가 갱신되었습니다」·「순위가 올라감」이라고 하지만 실제로는 다시 산정하지 않고 시도한 카드만 걸러 낸다. C3 심사자가 확인할 것.
