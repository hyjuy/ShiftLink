# ShiftLink 설비 흐름·현장 확인 화면

2026-09-20 구현 및 독립 평가 기록.

## 추천 구조

현재 ShiftLink에는 **Python MES 상태·이력 계층 + 웹 2D 설비 관계도 + 선택 설비의 근거·부품·조치 패널**이 적합하다. 관계도는 구성의 `route`, `relations`, `branches`를 사용하고, 상태·조치 가능 여부는 서버가 결정한다. 화면은 센서값만으로 고장 원인을 확정하지 않는다.

```mermaid
flowchart LR
  A[MES 상태·관측·구성] --> B[2D 본선·분기·공급 관계도]
  B --> C[설비와 관계 선택]
  C --> D[부품 가정·측정 근거]
  D --> E[근거 매뉴얼·다음 확인]
  E --> F[조치 기록·안정화·정상 복귀]
  D --> G[관측·가정·미확인 인계 초안]
  F --> H[SQLite 이력·기록 재생]
```

Unreal 도입은 현재 화면의 선행 조건으로 두지 않는다. 실제 조립 위치·분해 순서를 보여주는 3D 교육이 필요해지면 같은 관측 API를 읽는 별도 상세 뷰로 추가할 수 있다. 실제 설비 CAD·부품-센서 매핑이 없는 상태에서 3D 외관으로 원인 위치가 확정된 것처럼 보이게 해서는 안 된다.

## 구현된 사용자 흐름

- 상단 사건에서 자체 이상·주의 설비와 제품 보류를 구별한다. 사건·검색·알람 선택은 상세로 이동한다.
- 본선과 CV-02 물류 분기를 보존한다. 공급·구동은 코일 통과 경로와 구분한다. 실제 시나리오 및 대기 상태가 맞는 관계만 영향선으로 표시한다.
- 관계선을 선택하면 정확한 출발→도착, 관계 종류와 영향 여부를 확인한다. 구성상 연결은 원인 확정이 아니다.
- 선택한 설비에서 시연 가정 부품, 측정값·단위·정상 범위·품질·시각, 다음 조치, 복귀 조건을 확인한다. 부품 위치는 기능별 개념도다.
- 복구 관찰·소재 대기·일반 대기와 영향 대기를 구분한다. 신호 기준이 없으면 판정 불가로 표시한다.
- 신입은 ‘흐름 배우기’로 설명을 읽고, 숙련자는 ‘빠른 점검’과 설비 검색·관계 필터를 사용한다. 두 모드는 같은 관측 사실과 복귀 제약을 사용한다.
- 부품 건전도·운전시간·정비 횟수는 모의 값이다. 실제 잔여수명이나 고장 확률을 뜻하지 않는다.
- 순서대로 조치 완료 → 복귀 진행 → 2 tick 안정화 → 정상 복귀를 표시한다. 제품 보류 ID와 해제 조건을 함께 확인한다.
- 재생은 조회 전용이다. 연결 실패·데이터 진행 지연 때 움직임과 시연 조치를 잠근다. 관측·가정·미확인·다음 확인을 구별한 JSON 인계 초안을 내려받는다.

## 독립 전문가 피드백

동일한 고정 루브릭으로 각 항목 20점, 총 100점. 점수는 **정적 설계·구현 준비도**이며 브라우저 실측 사용성, 현장 진단 정확도, 생산 운영 준비도 점수가 아니다.

| 평가자 / 기준 | 1차 구현 | 수정 후 |
| --- | ---: | ---: |
| UI: 위계·탐색 | 17 | 18 |
| UI: 가독성·대비 | 17 | 19 |
| UI: 상태·접근성 | 17 | 18 |
| UI: 조작 효율 | 14 | 18 |
| UI: 반응형·움직임 | 17 | 18 |
| **UI 합계** | **82** | **91** |
| 설비: 물류·공급 관계와 방향 | 18 | 19 |
| 설비: 관측 이상과 파급 대기 진실성 | 17 | 19 |
| 설비: 문제 부품 위치·근거 | 17 | 18 |
| 설비: 조치·복귀·제품 추적 | 18 | 18 |
| 설비: 학습자·전문가 이해와 불확실성 | 17 | 18 |
| **설비 합계** | **87** | **92** |

UI 평가자 `evaluate_usability`, 설비 평가자 `evaluate_response`가 읽기 전용으로 평가했다. 점수 요청에 맞춰 기준을 낮추지 않았다. UI의 관계별 선택 누락·포커스 유실·축소 글씨·모바일 상세 접근, 설비의 대기 오표기·기준 없는 신호 판정·활성 원인 선택을 수정한 뒤 재평가했다.

## 성능과 검증 범위

독립 `performance_check` 측정: Windows 11 / Intel i5-8265U / Node v24.19.0. 실제 서비스의 정상 포함 8개 시나리오, 각 10대, 워밍업 30회와 측정 200회.

| 항목 | 결과 |
| --- | --- |
| 모델 + 관계도/사건/근거/부품 HTML 생성 p50 | 0.262–0.437 ms |
| 같은 작업 p95 | 0.391–1.124 ms |
| 전체 단일 최대 | 5.847 ms |
| 생성 HTML 크기 | 12,078–15,245 bytes |
| 엔진 tick + JSON 스냅샷 p95, 3개 대표 시나리오 | 5.177–6.176 ms |
| 명시된 핵심 텍스트 색상 16쌍 대비 | 최소 6.561:1 |
| MES 회귀 테스트 | 97 passed |
| MES Python coverage | 92% |

원시 측정: `artifacts/mes-operator-review/ui-render-benchmark.json`, `engine-benchmark.json`, `contrast-check.json`. 해당 폴더에 재현 스크립트도 있다. 위 UI 성능은 브라우저 DOM·레이아웃·GPU·HTTP를 제외한 문자열 생성 비용이다. 엔진 측정은 HTTP·SQLite·브라우저를 제외한다. 텍스트 대비는 명시 색상쌍 계산이며 실제 computed style 검사나 접근성 인증이 아니다.

브라우저 연결이 없어 화면 스크린샷·실제 키보드/스크린리더·터치·초보자 과업 실험은 수행하지 못했다. 전체 관계 표시의 교차선과 긴 레이블, 좁은 화면 지도 이동은 후속 실사용 검증 대상이다. 실제 물리 위치를 확인하려면 설비 배치도·부품 목록·센서 매핑을 추가해야 한다.

테스트 절차와 RED/GREEN 근거는 [검증 기록](testing/mes-operator.tdd.md)에 정리했다.

## 애니메이션 복원 후 재확인

사용자가 이전 장비 애니메이션을 선호하여 롤러·감속기·컨베이어·공급장치 그림과 움직임을 복원했다. 코일 위치만 바뀌면 그림 DOM은 유지하고 위치를 갱신한다. 고장·대기·복구 관찰·데이터 지연 시 움직임 차단과 애니메이션 끄기, reduced-motion을 유지한다.

동일 평가자의 변경 후 정적 재검토는 UI **91점**, 설비 **92점**으로 유지됐다. 확대된 장비 카드로 세로 길이가 늘어난 점은 남은 검증 항목이다. 실제 브라우저에서 이전보다 한눈에 이해되는지 여부는 사용자 확인이 필요하다. 위 성능 측정은 복원 전 리비전이며 변경 후 FPS나 브라우저 성능으로 인용하지 않는다.
