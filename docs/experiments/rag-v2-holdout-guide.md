# RAG v2 보류 셋 작성 안내 (최재영용, 2026-10-13)

보류 셋은 v2 최종 평가에 **한 번만** 쓰는 질문 묶음이다. Claude는 색인·프롬프트를 만드는 쪽이라 이 파일을 열지 않는다. 사전 등록을 마친 뒤 채점 스크립트만 읽는다.

## 2. 몇 개를, 어떻게 나누나 — 40문항 이상
| 유형 | `type` | 개수 | 무엇을 묻나 |
|---|---|---|---|
| 수치·기준값 | `value` | 10 | 압력·온도·토크·주기·간격 같은 숫자 |
| 절차·순서 | `procedure` | 8 | 정비·교체·점검을 어떤 순서로 하나 |
| 원인·점검 | `cause` | 8 | 이 증상이면 무엇을 의심하고 무엇부터 보나 |
| 안전 조건 | `safety` | 6 | 정지·감압·잠금·전원 차단 같은 작업 전 조건 |
| 코드·이름 | `code` | 3 | 알람 코드·부품명·모델명으로 정확히 찾아야 하는 것 |
| **답 없음** | `none` | 8 이상 | 원문·카드 어디에도 답이 없는 현장 질문 |

설비는 HPU·GR·CV·RT·PDP·CAU를 고루, 한 설비에 몰리지 않게 한다.

## 3. 한 문항의 형식
```json
{
  "qid": "H2-001",
  "question": "현장 말투 그대로의 질문",
  "eq_id": "EQ-0001",
  "type": "value",
  "answerable": true,
  "reference_answer": "정답을 한두 문장으로",
  "key_facts": ["채점할 때 답에 꼭 있어야 하는 사실 1", "사실 2"],
  "relevant_sources": ["HY29-0022-UK.pdf:page_14"],
  "note": "자유 메모(어디서 찾았는지 등)"
}
```
| 필드 | 쓰는 법 |
|---|---|
| `qid` | `H2-001`부터 차례로 |
| `question` | 작업자가 PDA에 칠 법한 말 그대로. 문서 표현을 베끼지 않는다(베끼면 검색이 쉬워져 점수가 부풀려진다) |
| `eq_id` | 스캔한 설비. HPU-01=`EQ-0001` 등은 MES 설비 목록 기준. 모르면 `""` |
| `answerable` | 원문이나 카드에 답이 있으면 `true`, 없으면 `false` |
| `reference_answer` | 원문을 보고 쓴 정답. `answerable:false`면 `""` |
| `key_facts` | 채점 기준이 되는 짧은 사실 1~3개. 숫자는 단위까지 |
| `relevant_sources` | 답이 있는 곳. 원문은 `파일명.pdf:page_N`(PDF 뷰어의 쪽 번호), 카드는 `card:K-1008`. 여러 곳이면 모두 |
| `note` | 선택 |

## 4. 원문에서 질문을 만드는 순서 (권장)
1. 설비 폴더(`ShiftLink\docs\data\sources\HPU` 등)나 `docs\sources\safety`의 PDF를 연다.
2. 현장에서 실제로 물을 만한 내용이 있는 쪽을 찾는다(표·절차·주의 문구가 좋다).
3. 그 내용을 **보지 않고도 물을 수 있는 말**로 질문을 쓴다. 예: 문서에 "Relief valve setting 210 bar"가 있으면 → "유압 릴리프 밸브는 얼마에 맞춰져 있어야 해요?"
4. 정답·핵심 사실·쪽 번호를 적는다.
5. 답 없음 문항은 그 설비 폴더를 훑어보고 **정말 없는 것**만 쓴다(예: 우리 공장 고유의 근무 규칙, 다른 설비의 사양).

## 5. 예시 (형식 참고용 — 이 두 문항은 보류 셋에 넣지 않는다)
```json
[
  {"qid": "EX-1", "question": "펌프 돌리기 전에 케이스에 기름 채워야 돼요?", "eq_id": "EQ-0001", "type": "procedure",
   "answerable": true, "reference_answer": "처음 기동 전 펌프 케이스를 작동유로 채운다.",
   "key_facts": ["기동 전 케이스 충유"], "relevant_sources": ["예시.pdf:page_9"], "note": "형식 예시"},
  {"qid": "EX-2", "question": "우리 라인 야간조 HPU 점검표 양식 어디 있어요?", "eq_id": "EQ-0001", "type": "none",
   "answerable": false, "reference_answer": "", "key_facts": [], "relevant_sources": [], "note": "공장 고유 문서 — 원문에 없음"}
]
```

## 6. 지킬 것
- 다 쓴 뒤에는 고치지 않는다. 고쳐야 하면 사전 등록 전에만.
- Claude에게 문항 내용을 보여 주거나 말하지 않는다(개발 중에 보면 보류 셋이 아니게 된다).
- 개발 중 확인용 질문이 필요하면 보류 셋과 별개로 따로 말해 준다.
- 파일은 UTF-8 JSON 배열 하나. 쉼표·따옴표 오류는 채점 전에 Claude가 형식만 검사한다(내용은 보지 않는다).
