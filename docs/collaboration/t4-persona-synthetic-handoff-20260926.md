## 5. 아직 안 한 일과 다음 작업

후속 우선순위는 제안이며 아직 구현·실험한 결과가 아니다.

1. **카드와 새 대본의 표현 정합성부터 맞춘다.** 기존 카드 M07/M08/M13에는 ‘정보 미해결이면 인계도 미완료’로 읽힐 수 있는 표현이 남아 있다. 새 대본은 미해결 상태를 정확하게 인수했으면 수신 확인은 완료될 수 있도록 분리했다. M16의 새 증빙 도착 처리, M18의 명시적 미회신과 회신 기록 누락 구분 등 기존 검토 의견도 확인한다. 이전 카드를 자동으로 수정 완료했다고 가정하지 않는다.
2. **소규모로 송수신 실행을 분리한다.** 송신자는 페르소나와 자기에게 보이는 원장만 받는다. 수신자는 자기 초기 정보와 실제 전달된 대화만 받는다. F8 예시 답변과 평가 정답은 둘 다 보지 못하게 한다. 독립 판정자는 원장과 실행 기록을 대조한다.
3. **카드 유무를 비교한다.** 같은 가상 상황에 `카드 없음 / 일반 5항목 체크리스트 / 해당 T4 카드`를 비교하는 설계를 권장한다. 모델·입력·예산을 맞추고 조건·평가 기준을 실행 전에 고정한다. 단순 전후 대본 작성은 비교 실험이 아니다.
4. **판정 가능한 항목을 측정한다.** 필수 정보 보존, 미확인 상태 보존, 잘못된 승인 추론, 미응답/부분 회신의 완료 오판, 정보 누출, 재질문 수 등을 각각 기록한다. 품질을 임의의 종합점수 하나로 압축하지 않는다.
5. **새 상황에서 일반화한다.** 카드 작성·개선에 쓰지 않은 별도 상황을 만들고 적용한다. 같은 사건의 이름·문체 변형은 같은 그룹으로 취급한다. 기존 sealed/holdout 내용을 읽어 생성 재료로 사용하지 않는다.
6. **실험에서 얻은 경험으로 카드 재작성·검토한다.** 기존에는 `카드 방법 → 후행 대본` 순이었다. 다음 단계의 `고정 상황 → 실제 모의 실행 → 실패/성공 비교 → 카드 개선 → 별도 상황 평가`와 구분해 계보를 남긴다.

새 실험의 생성·평가 지표는 별도 메타데이터로 두고 기존 `confidence` 의미를 몰래 바꾸지 않는다. 검토되지 않은 출처 승인·사람 안전 검토·카드 채택은 기록하지 않는다. 운영 DB·등록부·split 정책 변경은 이번 작업에 포함하지 않았다.
