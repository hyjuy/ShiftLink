# HPU 분류·조건 보류·검색 지연 후속 검증

모델 학습 없이 `field_history.py`와 `S30hPipeline.run`의 결정적 처리만 수정한다.
HPU 관계 검색은 기본 off인 별도 비교 실험으로 유지한다. 운영 배포는 하지 않는다.
이전 결과는 [최초 실제 모델 검증](hpu-retrieval-live-20261025.md)에 보존한다.

## 변경 계약

- `기록`을 과거 조회의 목적어로 인정하되, 현재/미래 판단·독립 실행 요청 검사는 그대로 적용한다.
- 명시적인 일지 조회는 검수·게시된 현장 카드의 설비·출처·기간·날짜 조건을 만족해야 한다.
  적합한 카드 자체가 없으면 임베딩 검색을 생략한다. 이 검사는 답변을 허용하는 검사가 아니다.
- 적합한 카드가 있으면 명시적 일지 조회의 벡터 순위 범위를 그 일지 청크로 한정한다.
  일반 매뉴얼이 일지 조회의 후보 예산을 소모하지 않으며 기존 top/chunk/token 예산은 유지한다.
  그중 적합한 현장 카드 청크만 기존 judge에 전달하며, 판정이 거절되면 보류한다.
  통과한 카드만 기존 `record_sources`로 원문을 복원한다.
- 현장 일지가 없을 때 정적 매뉴얼·교대 이벤트를 대체 일지로 생성하지 않는다.
  일반 현재 상태·작업 판단의 검색·judge·생성 경로와 조건 임계값은 변경하지 않는다.
- 저장 원문·게시 상태·인덱스·모델 가중치를 변경하지 않는다. 새 캐시나 서버 훅도 추가하지 않는다.

## 실제 모델 비교 방법

대표 질문 16개×2, 이전 탐색 질문 4개×2를 각각 유지한다.
질문·기대 인용·보류·관계 허용 라벨은 원래 JSON 그대로이며 대표/탐색 결과를 합쳐 성공률을 부풀리지 않는다.
ck176·embeddinggemma·SFT judge와 같은 인덱스 사본·합성 검수 카드·관찰을 사용한다.
모델 가중치·프롬프트·샘플링 옵션은 변경하지 않는다.

수정 전 대조군은 `SHIFTLINK_HPU_LIVE_REFERENCE=7a52b517e58c66e1a385b0a78aceaddfe37c587b`로
고정 커밋의 S30h 실행 함수와 이력 분류를 검증 프로세스 안에서만 사용한다.
작업 트리나 운영 파일을 교체하지 않는다. 수정 후는 현재 소스를 사용한다.
각 버전에서 관계 off 기준 경로와 관계 보완 실험 경로를 번갈아 먼저 실행한다.
전체 지연은 기존대로 임베딩·검색·judge·필요한 생성·복사 비용을 포함하며,
실험 지연에는 관계 준비와 최종 게시 재검증 비용도 포함한다.

첫 수정 전 수집은 SSH `Connection reset`으로 32쌍 중 18쌍이 오류였다.
오류 수집은 보존하되 품질/속도 개선 근거에서 제외하고, keepalive 터널로 전체 재수집한다.
하니스도 완료 쌍이 모자라면 수집 실패로 끝내도록 보강했다.
정상 수집 PASS는 모델 품질이나 운영 적용 통과를 뜻하지 않는다.

정상 재수집은 수정 전 대표 32쌍·탐색 8쌍, 수정 후 대표 32쌍·탐색 8쌍, 총 80쌍 모두 완료했다.
완료 수 부족·오류·invalidated는 0이었다. 모델 digest, KB/인덱스 해시,
전후 질문/라벨과 코호트 해시가 같고 모든 원문 응답 해시를 검증했다.
각 쌍의 업무 DB dump·원본 KB·인덱스 불변 검사도 통과했다.
수집 하니스 실행은 각각 1 passed: 수정 전 대표 362.55s, 탐색 80.50s,
수정 후 대표 211.20s, 탐색 39.78s. 이는 setup·게시·witness를 포함하는 실행 시간이며
아래 질문별 평균 지연과 구분한다.

같은 질문으로 문제가 해결됐다는 회귀 근거다.

수정 후 관계 실험을 켜도 대표 인용 12/12·보류 4/4, 탐색 인용 8/8로 동일했고

off보다 각각 **80.9ms, 137.0ms** 더 걸렸다.
실험 p95는 대표 9.455초, 탐색 2.241초이며 소표본 변동으로 해석한다.

수정 전 탐색 재측정에서는 관계 실험 평균이 off보다 약 202ms 짧았다.
최초 평가의 +1.278초와 부호가 다른 점도 모델/통신 지연의 변동을 보여 준다.
어느 한 번의 차이를 관계 알고리즘의 고유 속도 이득으로 간주하지 않는다.
동일 버전 안의 off/on 실행 순서는 교차했지만 수정 전후 버전은 순차 실행했으므로,
서버 부하·예열·전송 지연을 완전히 통제한 통계적 실험은 아니다.
판정 호출 수 감소·조건 불일치 시 네트워크 생략은 결정적 테스트로도 확인했고,
보고한 지연 비율은 이번 수집에서 관찰한 값이다.

판단: **기본 검색 수정은 이 유한 회귀 범위에서 개선됐으나, 관계 검색은 기본 off를 유지한다.**

## 제한

실측 설비 원문 대신 격리된 합성 검수 카드 하나를 사용한다.
16+4개 질문·각 2회 반복만으로 다양한 일지나 동시 부하의 성능을 보장할 수 없다.
PC 파이프라인과 SSH를 경유한 Jetson 모델 API 측정이므로 PDA 전체 지연도 아니다.
명시적으로 검증하는 조건은 기존 설비·검수 출처·분 단위 기간·날짜이며,
임의 자연어 조건 전체의 논리적 일치를 증명하는 온톨로지 추론기는 아니다.
운영 배포와 모델 학습은 수행하지 않았다.
