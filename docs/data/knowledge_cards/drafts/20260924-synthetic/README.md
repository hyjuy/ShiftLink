# 페르소나 기반 합성 원문 지식카드 초안 — 2026-09-24

합성 사건 원장에서 만든 작업일지 원문을 근거로 생성한 `draft/L0` 카드 5건이다.
문헌 원문에서 만든 [같은 날짜의 다른 묶음](../20260924/README.md)과 근거의 성격이
다르므로 폴더를 나눴다.

**이 묶음의 원문은 실제 현장 기록이 아니다.** `shiftlink.data.narrative`가 생성했고
등록부에 `is_synthetic=true`, `reviewed_by`가 사람이 아님으로 기록돼 있다.

## 파일

- [카드 5건](cards.json) — K-9001~9005, `draft/L0`
- [필드별 근거 연결](evidence-map.json) — 값이 있는 말단 필드의 JSON Pointer
- [원문 12건](narratives/) 과 [목록·해시](narratives/index.json)
- [검토 기록](review.json) — 무엇을 확인했고 무엇을 고쳤는지
- [보완 대기](pending.json) — 근거가 없어 채우지 못한 항목

## 생성 경로

```
사건 명세 ──shiftlink.data.scenario──▶ 사건·관측·split·카나리
사건+페르소나 ─shiftlink.data.narrative─▶ 합성 작업일지 원문 (SD-901~912)
승인된 발췌 ──shiftlink.data.generation──▶ 이 카드들
```

사건은 [`docs/data/scenarios/`](../../../scenarios/)의 EV-0031·0032·0034·0035·0036이다.
EV-0033은 `sealed`라 생성에 쓰지 않았다.

| K-9001 | T3 | kb | EV-0031 | 하류 전류 상승에 상류 저음·진동이 겹치면 상류 구동부터 |

([같은 원칙](../20260924/persona-review/cards-by-persona.md)).

## 이번 승인의 범위

**보관 위치 승인이다.** `accepted/L1`로 올리지 않았다. 가이드 §3에 따라 생성 모델은
승격하지 않으며, 승격은 도메인 타당성을 확인한 사람이 한다.

확인하지 않은 것:

- 공정 적합성과 실제 설비 수치의 타당성
- 현장 안전 검토
- 합성 원문이 실제 현장 기록을 대표하는지
- 조치 순서의 현장 적용 가능성

## 검토에서 고친 것

기계 검증(스키마·린터)을 통과한 뒤에도 내용 검토에서 4건이 나왔다.

**유형 판정 1건.** K-9005를 T3에서 T6로 재분류했다. 증상과 단계를 갖춰 스키마는
통과했지만, 재가동 지식은 상태 복귀가 목적이므로 T6이며 `steps`를 쓸 수 없다
(가이드 §2·§4, 선례 K-0302).

**인용 수치 3건.** 카드의 임계값이 인용 원문에 실제로 있는지 대조해 3건을 제거했다.
작성자가 관측값(94 %, 78 ℃, 158 bar)은 일지에 적었지만 그 값을 판정한 **기준값**은
적지 않았는데, 카드가 사건 원장과 다른 카드에서 기준값을 끌어다 쓰고 있었다.

`generation.py`는 근거 포인터의 **존재**를 검사하고 인용문이 주장을 뒷받침하는지는
검사하지 않으므로, 이 오류는 자동 검증을 그대로 통과한다. 대조 결과는
[review.json](review.json)에 남겼다.

## 미해결

[pending.json](pending.json)에 4건이 있다. 모두 근거 문헌이 필요하고, 가이드 §3의
"값을 창작하지 않는다"에 따라 채우지 않았다.

- 안전 근거 (K-9002, K-9005) — `safety_basis`에 법령·지침 조항이 필요하다
- 판정 기준값 출처 (K-9002, K-9003) — 설비 인터록·정상 범위 문서가 필요하다
