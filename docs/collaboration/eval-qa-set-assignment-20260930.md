## 한 줄 요약
카드를 보지 않고 쓴 현장 질문 **70건**에 KB 카드 기준 정답을 붙이고, **60건**을 골라 **개발용 30 / 평가용 30**으로 나눈다. **평가용 30건이 계획서의 "평가셋 30건"**이고, 개발용 30건은 조정용으로 추가한 것이다(검수는 평가용만 정식으로).

## 왜 필요한가
- 기존 `eval/fixtures/`(A~F)는 스키마·계약 검사다. **질문에 맞는 카드를 인용하고 맞는 답을 하는지**는 재지 않는다.
- 9/30 Jetson 측정은 카드를 보고 만든 20문항이라 과대평가 가능성이 있고, 20건으로는 모델 간 차이(±2건)를 가릴 수 없었다.
- 검색 규칙·프롬프트를 조정한 문항으로 최종 점수를 내면 점수가 부풀려진다 → 조정용(개발)과 채점용(평가)을 나눈다.

## 채점 항목

| 항목 | 방식 | 계산 |
|---|---|---|
| 인용 적중 | 자동 | 인용 ID에 `primary` 포함 = 적중. `acceptable`만 있으면 부분 |
| 오인용 | 자동 | 인용 중 `primary`·`acceptable` 밖 ID 비율 |
| 안전 카드 노출 | 자동 | `safety_card_ids`가 응답 안전 표시에 모두 있음 |
| 모름 처리 | 자동 | answerable=false 문항에서 `no_knowledge` 또는 인용 없음 |
| 핵심 사실 | 수동 | `key_facts`가 답에 담겼는지 (전부 / 일부 / 없음) |
| 지어낸 내용 | 수동 | 카드에 없는 수치·절차가 있으면 실패 |
| 속도 | 자동 | p50·p95 (Jetson, 데모 설정) |

## 규칙
- **평가용 30건은 조정에 쓰지 않는다.** 실패 사례를 보고 검색 규칙·프롬프트·카드를 고치는 건 개발용으로만 한다. 해시 봉인은 하지 않는다(경량 계획서).
- 평가 문항·정답을 KB 카드나 SFT 학습 데이터에 넣지 않는다.
- 질문 작성자는 카드를 보지 않는다. 질문 문구는 라벨 단계에서 고치지 않는다(검수에서 제외만).
- KB가 바뀌면(카드 배치 B·T4) `labels.json`만 다시 붙이고 질문은 그대로 둔다.

## Q7 (c) 결정의 영향 (2026-09-30)

카드 설비 유형에 PDP·CAU가 들어가(PR #84) **정답지 형식과 커버리지 매트릭스를 설비 6종 기준으로 전면 개정**한다 — **유현준**. 개정안이 나오면:
- 평가셋 문항 필드(`eq_id` 등)와 `labels.json`을 개정된 정답지 형식에 맞춘다 (질문 문구·split은 고정).
- 현재 평가셋 70문항에는 CAU·PDP 질문이 없다. 추가 여부와 방법(카드 비공개 작성)은 개정된 커버리지 매트릭스를 보고 정한다.
- 전혜민의 검수 기준(`RUBRIC.md`)도 개정된 형식을 따른다.
