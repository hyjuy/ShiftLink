# 업무 분장: T4 인계 카드 생성 (허재원)

> 작성 2026-09-30 최재영 · 기간 2주차 **10/5(월) ~ 10/8(목)** · 작업 지시 프롬프트: [`t4-handover-cards-prompt-20260930.md`](t4-handover-cards-prompt-20260930.md)

## 한 줄 요약
근무일지·정비기록 **30건**(KB용 20 + 평가용 10)을 합성하고, KB용 기록에서 **2건 이상 반복된 인계 요령**만 뽑아 **T4 카드 10~15장**을 만든다. 사람 검수를 거쳐 `accepted/L1`로 올린다.

## 왜 허재원인가
T4는 교대 인계 요령이다. 교대 운영·Jetson 현장 흐름·안전 잠금(LOTO) 인계를 가장 잘 아는 역할이 쓰는 게 맞다. KB 검색 연결(Cursor)과 MES 필드 스키마(유현준)와 겹치지 않는다.

## 대응표로 정한 설계 규칙 (단계 3)
| 대응표 결과 | 기록 설계에 반영 |
|---|---|
| MES 신호와 **직접** 연결된 카드는 6장뿐 (K-1001·1002·1004·1024·1025·1027) | 측정값이 이상으로 나오는 사건은 이 조합 위주로 만든다. 측정값 → 인계 → 카드가 한 줄로 이어져야 평가에 쓸 수 있다 |
| **소음**은 MES 신호가 없다 (카드 7장이 소음 성질로 판별) | 소음은 측정값이 아니라 **작업자 관측**으로 일지·인계 메모 문장에 쓴다 ("감속기 쪽 갈리는 소리") |
| 알람은 시나리오가 걸릴 때만 난다 / HPU 정지해도 압력은 정상값 | 알람 없이 신호만 벗어난 사건, 정지 중 감압 여부를 **사람이 확인해 적는** 사건을 섞는다 (MES만으로 알 수 없는 인계 정보) |
| RT: 카드는 코일카 승강부, MES는 반송 속도·클램프·모터 전류 — 구조 불일치 | RT 사건은 **유현준 결정 전까지 MES 신호(클램프·속도)만** 쓰고 승강부 구조를 가정하지 않는다 |
| 카드가 없는 설비·신호: HPU 필터(`hpu_filter_dp`), CV 벨트 장력·속도, PDP-01, CAU-01, 출측 정체 시나리오 | 이 영역 사건도 넣는다. T4 요령은 뽑되, 조치 내용은 **카드 없음 → "정비 담당 확인"**으로 두고 절차를 지어내지 않는다 |

## 하지 않는 것
- 매뉴얼만 보고 T4 카드 만들기 (요령은 기록에서 나온다)
- 기존 평가용 T4 50장(`drafts/*t4*`, `split=dev`)을 KB로 옮기거나 근거로 쓰기
- 인계 메모에 주입 원인(`true_cause`)을 그대로 쓰기
- 검수 전 `accepted` 올리기, `.env`·접속 정보·권한 없는 PDF 커밋
