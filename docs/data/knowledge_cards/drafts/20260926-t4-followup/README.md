# T4 후속 연구 · COMMON 표현 정합화와 비교 실험 사전 설계

2026-09-26. 이전 [장비별 인계 문서](../../../../collaboration/t4-equipment-synthetic-handoff-20260926.md)와 연결 보고서를 이어받았다. 이번 폴더는 후속 버전이며 원본 카드·검토·파일럿 기록을 덮어쓰지 않는다.

## 완료 범위와 남은 범위

COMMON M07/M08/M13의 수신 확인과 정보 해결 표현을 정합화하고 M16의 새 증빙, M18의 명시적 무응답·기록 미첨부 경계를 보완했다. 카드 ID는 유지하고 후속 버전 `synthetic-followup-7f44e65733f0`으로 저장했다. 다섯 카드 모두 T4 / COMMON / draft / L0 / dev, confidence=0이다. 이는 직접 원문 지지 0/5라는 뜻이며 효과 점수가 아니다. 다른 기존 COMMON 카드의 confidence를 0으로 바꾸지 않았다.

논리 카드 수는 기존 COMMON25 중 다섯 버전의 교체와 기존 장비20을 합친 45개다. 원본과 개정본을 서로 다른 새 카드로 세지 않는다. 개수는 목표·상한이 아니다. 운영 DB·출처 등록부·split 정책·검색 구현·KB 채택은 변경하지 않았다. 사람 검토·현장 검증·안전 승인도 수행하지 않았다.

이번 후속 비교 실험은 **비작성자 사전 설계 검토를 통과하고 입력 해시를 동결한 단계**다. [동결 기록](freeze.json)이 최종 상태의 기준이며, 하위 저자 작성본·원장의 초안/검토 대기 표기는 작성 당시 이력으로 보존한다. 새 송수신 역할 실행, 독립 실행 판정, 카드 추가효과 측정, 실행 경험에 따른 후속 카드 수정과 별도 새 상황 평가는 아직 수행하지 않았다. 현재 기존 파일럿이 카드 추가효과를 입증하지 않았다는 결론과 HPU 측정 대상 명칭의 경계 사례 1건(민감도 0~1)을 유지한다.

## 후속 비교 실험의 고정 범위

[실험 안내](experiment/README.md), [실행 전 프로토콜](experiment/protocol.md), [원자 판정 기준](experiment/evaluation-only/rubric.md), [장비·카드·실패 요인·계보](experiment/coverage-and-lineage.json)를 구분했다. HPU/GR/RT/CV/PDP/CAU 각 1개 개발 상황 × 3조건 × 3반복, 총 54 송수신 쌍과 기본 108 역할 호출 계획이다. 54개 독립 사건이 아니다. 반복별 순서는 고정 순환이며 무작위화라고 주장하지 않는다.

조건은 카드 없음, 일반 5항목 체크리스트, 선택 T4의 **know_how 원문 단일 필드**다. 선택 카드는 K-0037/K-0033/K-0048/K-0028/K-0042/K-0026이며 새 COMMON 5개 개정의 효과 시험과도 구분한다. 카드 전문이나 장비 카드 20개 전체 효과를 평가하지 않는다. 조건별 원자료와 공통 과업은 같고 지원과 그 길이가 다르므로 길이를 통제한 순수 카드 효과가 아닌 지원 묶음의 차이를 관찰한다.

원자료 6개, 실제 송신 packet 18개, 수신 template 6개, 평가 전용 사실 원장과 판정 기준을 별도 파일로 만들었다. 수신 실입력은 아직 없는 실제 송신문을 넣어 실행 때 생성해야 한다. 역할별 새 컨텍스트·packet 한 번 읽기 외 도구 금지·송신 1편/수신 1편·각 1800자 요청·역할당 600초와 인프라 재시도 1회를 사전 지정했다. API 토큰 상한·총 토큰·비용·모델 스냅샷 등 비노출 값은 unavailable이며 계측·강제했다고 주장하지 않는다.

이번 6상황은 알려진 카드 방법과 기존 파일럿의 한계를 보고 만든 개발 자료다. 새 문장으로 작성됐다는 이유로 독립 일반화 평가자료라고 부르지 않는다. 필요한 카드 수정은 실제 후속 실행 뒤 근거를 확인해 결정하고, 수정하지 않은 새 사건 구조에서 평가할 때 일반화 여부를 별도로 검토한다.

[최종 독립 설계 검토](experiment/review-design.json)는 pass다. [초기 revise](experiment/review-design-initial.json), [수정 이력·7개 원본 snapshot 연결](experiment/review-revisions.json)을 보존했다. 실제 수신 입력 원자의 별도 분모, 복합 사실 분리, 미노출 카탈로그를 요구하는 카드 문구의 한계, 지원에만 있는 용어를 기준선 필수 답변으로 요구하던 공정성 문제를 수정했다. 로그 필드도 보완했다. 원자료·역할 입력 30개는 수정하지 않았다.

[설계 정적 검사](experiment/validation-design.json)는 사실 원자 69개·미확인 원자 27개, 선택 카드와 장비 매핑·버전, 카탈로그 참조 21개, 조건 간 공통 입력, 54개 실행 순서를 확인했다. 최종 설계 검토의 입력 해시 55개와 초기 snapshot 7개를 대조했다. 역할 실행 0회다. 송신 지원은 체크리스트 91자, T4 400~463자이며 이 차이는 분석의 한계다.

## 검증 재실행

카드 스키마 5/5, 다섯 필드별 누락·공백 거부 50/50, dev 적재 거부 5/5, 메모리상 draft/L0 제외 5/5, 원본 파일 해시 67/67 유지, 연결 대본 5/5 동일, 대본 사실 참조 74건을 확인했다. 비작성자 내용 검토는 초기 revise와 최종 pass를 별도로 보존하고 최종 검토 해시 일치를 확인했다. 경계 사례 9건의 구조 검사와 의미 검토는 실제 역할 실행 결과와 구분한다.

프로젝트 루트에서 `python -X utf8 docs/data/knowledge_cards/drafts/20260926-t4-followup/verify.py`를 실행한다. 현재 폴더의 validation.json만 갱신한다. 기존 배치 build.py/verify.py/pilot.py를 실행할 필요가 없다. revise.py는 이미 생성한 카드가 있으면 덮어쓰기를 거부한다. 카드 변경은 새 버전과 검토가 필요하며 과거 리뷰의 해시를 바꾸어 새 리뷰처럼 처리하지 않는다.

정적 검증 통과는 수신자의 실제 행동이나 카드 효과를 증명하지 않는다. 과거 문서 설계 점수 94.9를 승계하지 않는다. 실험 설계의 카드 노출·정보 접근·반복·오류 기준은 실행 전에 고정하며 실행 편차와 불리한 결과도 보존한다.

설계만 다시 검사하려면 `python -X utf8 docs/data/knowledge_cards/drafts/20260926-t4-followup/experiment/verify-design.py`를 실행한다. 동결 입력 변경은 첫 검증 명령에서 거부된다. 새 실제 발화·실입력·판정은 별도 execution 폴더에 저장한다. 이 동결은 연구 입력 보존이며 운영 채택이나 작업 승인이 아니다.
