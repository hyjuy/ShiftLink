# 모의 MES 개발팀 작업 지시 템플릿

이 문서는 `codex/mock-mes` 브랜치에서 사용할 개발 실행 지시서다. 아래 설계는 구현 제안이며, 기존 문서의 미결 사항을 승인·확정 처리하지 않는다.

## 복사해서 사용하는 시작 지시

> `docs/mock-mes-development-template.md`를 읽고 `codex/mock-mes`에서 모의 MES를 구현해줘. 메인이 공통 규격을 먼저 작성하고 시뮬레이션, MES 화면, 데이터·연동 서브에이전트를 생성해 병렬 작업해줘. 구현 담당의 작업이 끝나 자리가 생기면 통합 검증 에이전트를 투입해줘. 기존 변경을 보존하고, 정상 가동·이상 전파·복구·기록 재생을 실제로 확인한 후 실행 방법과 검증 결과를 보고해줘. 커밋·푸시·PR 생성은 별도 요청이 있을 때 수행해줘.

## 1. 목표와 범위

- 가상 냉연 코일 이송·공급 보조설비의 정상·이상 상태를 2D 화면으로 보여준다.
- 화면, 센서값, 코일 이동, 알람, 저장 데이터는 동일한 시뮬레이션 상태를 사용한다.
- ShiftLink의 신입 지원(S1), 저년차 문제 해결(S2), 교대 인수인계(S3)에 필요한 관측·이력 데이터를 생성한다.
- 정상, 구동부 이상, 출측 정체, 유압 공급 이상을 지원하고 각 이상에서 복구·재가동까지 연결한다.
- 생성 데이터를 기록·재생하고 JSONL/CSV로 내보낸다.
- 모든 화면·출력에 합성 데이터임을 표시한다. 물리 검증이나 실제 MES 연동을 완료한 것으로 표현하지 않는다.
- 이번 범위에서 3D, 실제 PLC 제어, 생산계획·ERP 연동, RAG 전체 구현은 제외한다.

## 2. 시작 전 확인과 기존 계약

1. 현재 브랜치와 작업 트리를 확인한다. 다른 브랜치라면 기존 변경을 보존하면서 작업 위치를 먼저 해결한다.
2. 적용되는 AGENTS.md와 관련 코드만 읽는다. 기존 테스트를 실행해 기준 상태를 기록한다.
3. 실제 구현 경로는 `shiftlink/`, 테스트는 `tests/`다. README의 `src/` 표기만 보고 새 구조를 만들지 않는다.
4. 기존 `shiftlink/agent/schemas.py`의 Event, KnowledgeCard, Artifact 계약과 `S1/S2/S3` 값을 유지한다.
5. `shiftlink/agent/tools.py`는 저장소 연동 전의 스텁이다. 선언된 인터페이스를 실제 동작으로 오인하지 않는다.
6. `shiftlink/data/`의 현재 CLI와 산출물 계약을 읽고 재사용 가능 지점을 확인한다.

참조 자료:

- `docs/00_plant_and_relations.json`: 기준정보·설비 ID·연결 관계
- `docs/B_data.md`: 운전 컨텍스트·데이터 생성 규칙 제안
- `docs/A_domain.md`: 도메인 범위와 관계 해석
- `docs/01_고도화_초안.md`: 사용자 시나리오와 기존 미결 사항
- `docs/branching.md`: 브랜치·데이터 관리 규칙

현재 자료에는 6대 구성안과 10대 샘플이 혼재한다. 초기 구현은 기존 JSON의 10대 구성을 **시연용 가정**으로 사용하고 설비 목록을 설정에서 읽는다. 형상·소재 이동 경로가 부족하면 별도 데모 레이아웃에 가정을 기록한다. 유틸리티·구동 연결을 소재 이동 경로로 해석하지 않는다. 기존 기준정보를 임의로 확정하거나 덮어쓰지 않는다.

## 3. 팀 구성과 파일 소유권

메인 포함 동시 실행 한도는 4개다. 구현 담당 3명을 먼저 실행하고, 완료된 자리에 검증 담당을 투입한다. 모든 에이전트는 같은 작업 트리를 공유하므로 파일 소유권을 지킨다.

| 역할 | 책임 | 기본 소유 경로 |
|---|---|---|
| 메인 | 공통 규격, 실행 진입점, 서버 연결, 통합, 문서 | `shiftlink/mes/contracts.py`, `shiftlink/mes/__main__.py`, `shiftlink/mes/server.py`, 개발 문서 |
| 시뮬레이션 | 시간·상태 전이·소재 흐름·센서 생성·이상 전파 | `shiftlink/mes/engine.py`, `shiftlink/mes/scenarios/`, 엔진 테스트 |
| MES 화면 | 2D 맵·설비 상세·추이·알람·시연 제어 | `shiftlink/mes/web/`, UI 테스트 |
| 데이터·연동 | 기준정보 로더·SQLite·조회·내보내기·관측 어댑터 | `shiftlink/mes/storage.py`, `shiftlink/mes/adapters.py`, `shiftlink/mes/catalog.py`, 데이터 테스트 |
| 통합 검증 | 계약·재현성·이상 전파·누수·화면 검증 | `tests/test_mes_integration.py`, 검증 보고서 |

경로는 제안이다. 메인이 기존 코드 확인 후 확정하고 공유한다. 공용 파일과 의존성 파일은 메인만 수정한다. 다른 담당 파일 수정이 필요하면 메인에게 변경 요구를 전달한다. 검증 담당은 실패 재현과 테스트를 제공하고 수정은 소유 담당에게 맡긴다.

## 4. 메인이 먼저 확정할 최소 계약

병렬 구현 전에 `contracts.py`와 동일 규격의 정상·이상 샘플을 작성한다.

| 데이터 | 필수 내용 |
|---|---|
| Run | run_id, seed, 시작 시각, tick 간격, 기준정보·시나리오 버전, split, is_synthetic |
| Snapshot | run_id, sequence, simulated_at, line_id, 라인 모드, 설비·구간 상태, 코일 위치, 측정값, 활성 알람 |
| EquipmentState | equipment_id, 운전 상태, 이상 수준, 대기·정지 사유 |
| Measurement | equipment_id, signal, value, unit, observed_at, 데이터 품질 |
| Alarm | alarm_id, code, equipment_id, severity, raised_at, acknowledged_at, cleared_at |
| RuntimeEvent | run_id, sequence, occurred_at, event_type, 관련 설비, 당시 관측 내용 |
| GroundTruth | run_id, 실제 주입 원인·시점, 기대 영향·조치; 평가 전용 저장 |

- 운전 상태와 이상 수준을 분리한다. 정상 설비가 하류 정체로 대기할 수 있다.
- 소재 부족, 하류 정체, 자체 고장, 계획정지를 구분한다.
- `scenario_id`는 모의 운전 시나리오, 기존 `scenario=S1/S2/S3`는 사용자 지원 시나리오다. 서로 다른 필드로 둔다.
- 새 런타임 이벤트를 기존 `EV-0000` 형식의 Event와 혼용하지 않는다. 변환은 명시적 어댑터에서 수행한다.
- `simulated_at`은 고정 시작 시각과 tick에서 계산한다. 실시간 기록 시각은 별도 필드로 둔다.
- 복합 식별자 `(run_id, sequence)`로 순서·중복을 관리한다.
- 정상 범위·임계값·변화율·단위는 설정에 두고 가상 값임을 명시한다.

## 5. 실행 구조

초기안은 기존 Python 환경, SQLite, 정적 HTML/CSS/JavaScript를 사용하는 단일 로컬 실행 프로세스다. 기존 웹 구조가 발견되면 우선 재사용한다. 웹 전송은 상태 조회 폴링으로 시작하며 필요한 최소 서버 방식을 메인이 선택한다.

- 시뮬레이션 계산 기본 간격은 가상 시간 1초다.
- 엔진은 브라우저 접속 수와 관계없이 한 번만 진행한다. 조회 API는 상태를 변경하지 않는다.
- 배속은 실제 대기 간격을 바꾼다. 동일 seed·입력·가상 실행 시간에서는 동일한 결과를 만든다.
- 조작 명령은 시작, 일시정지, 재개, 초기화, 배속 변경, 시나리오 선택, 복구 진행으로 제한한다.
- 초기화는 새 run을 만들고 기존 기록을 보존한다.
- 화면은 서버 상태를 표시하고 엔진과 별도로 난수 센서값을 생성하지 않는다.
- 재생은 기록을 읽어 표시한다. 재생 중 실시간 엔진과 상태를 섞지 않는다.
- 기본 바인딩은 localhost로 한다.

논리 인터페이스: 기준정보 조회, 현재 상태 조회, sequence 이후 이벤트 조회, 실행 제어, 실행 목록·기록 조회, 내보내기. 경로·요청·응답·오류 형식은 메인이 공통 계약으로 작성한다.

## 6. 담당별 작업 지시

### 시뮬레이션 담당에게 전달

> 공통 계약을 바탕으로 결정적 시뮬레이션 엔진을 구현한다. 정상 → 징후 → 이상 → 복구 → 재가동 → 안정화 흐름을 지원한다. 소재는 설정된 이송 경로를 따르고 정체·대기 영향은 연결 관계를 따라 전파한다. 센서값은 기준값·부하·시나리오 변화·작은 잡음으로 계산한다. 알람 지속시간과 해제 조건을 적용한다. 엔진은 UI·DB에 의존하지 않으며 snapshot과 events를 반환한다. 재현성, 정지 중 이동 금지, 소재 수량 보존, 용량 초과 금지, 복구 전이 테스트를 작성한다.

### MES 화면 담당에게 전달

> 공통 샘플 데이터로 2D MES 화면을 구현한다. 상단 요약, 중앙 라인 맵, 유틸리티 연결, 우측 설비 상세·센서 추이, 하단 알람·이벤트, 시연 제어를 제공한다. 정상·주의·고장·대기 상태는 색과 문구를 함께 사용한다. 코일 이동은 서버의 위치를 기준으로 보간한다. 조회 실패·오래된 데이터·일시정지를 명시하고 연결이 끊겼을 때 계속 정상인 것처럼 애니메이션하지 않는다. 조작 실패를 사용자에게 표시한다. 작은 화면에서도 상세 정보에 접근할 수 있도록 한다.

### 데이터·연동 담당에게 전달

> 기존 기준정보의 ID와 관계를 보존하는 로더, SQLite 저장, 조회, 기록 재생용 조회, JSONL/CSV 내보내기를 구현한다. 같은 tick의 스냅샷·이벤트는 일관되게 저장하고 중복 기록을 막는다. ShiftLink에 as_of 시점까지의 관측 데이터만 제공하는 어댑터를 작성한다. 원인 정답·미래 결과는 별도 평가 저장소에 두며 일반 API와 내보내기에서 제외한다. 기존 Event 변환이 필요하면 평가용 변환으로 분리한다. 단위·참조 무결성·내보내기 재읽기·미래 누수 방지 테스트를 작성한다.

### 통합 검증 담당에게 전달

> 정상 가동, 구동부 이상, 출측 정체, 공통 유압 이상, 복구·재가동을 실행해 화면·API·DB가 같은 상태를 표현하는지 검증한다. 두 브라우저 접속 시 엔진이 두 배로 진행하지 않는지, 배속과 재시작 후 재현되는지, 관측 API에 원인 정답과 미래 정보가 노출되지 않는지 확인한다. 실패는 재현 절차·기대값·실제값·소유 담당과 함께 보고한다. 실제 브라우저로 조작·차트·알람·재생을 확인하고 확인하지 못한 항목은 명시한다.

## 7. ShiftLink 목적별 생성 데이터

| 사용 목적 | 제공 데이터 | 생성 기준 |
|---|---|---|
| S1 신입 지원 | 설비 식별·역할·현재 상태·신호 단위·최근 알람 | 기준정보와 현재 관측값을 연결 |
| S2 문제 해결 | 이상 전후 센서 추이·상하류 상태·알람 순서·이미 수행한 모의 조치 | 실제 발생 시각 순으로 생성; 원인 정답은 제외 |
| S3 인수인계 | 교대 구간 사건·미해제 알람·조치 이력·복구 후 관찰 상태·미해결 항목 | 교대 경계와 as_of 기준으로 집계 |
| 평가 | 주입 원인·기대 영향·기대 조치·결과 | 별도 정답 데이터; 일반 조회와 격리 |

조치 기록에는 수행 시각과 모의 조치임을 표시한다. 알람 해제만으로 문제 해결을 확정하지 않으며 복구 후 관찰 상태를 남긴다. 실제 베테랑 노하우·검수된 지식카드를 센서 데이터만으로 생성했다고 주장하지 않는다.

기존 sealed 사건과 그 변형을 시연·개발 데이터로 사용하지 않는다. 시연 시나리오는 독립적으로 작성한다. 한 원형에서 나온 변형 실행을 kb/dev/sealed에 나누어 넣지 않는다. 기본 시연 출력은 dev로 두고 정식 데이터 분할·봉인은 별도 절차로 유지한다.

## 8. 진행 순서와 완료 조건

1. 메인이 기준 상태와 공통 계약·샘플·파일 소유권을 확정한다.
2. 세 구현 담당이 병렬 작업한다. 각 담당은 변경 파일·검증 결과·계약 변경 요청을 메인에게 전달한다.
3. 정상 가동 한 경로를 먼저 엔진 → 저장 → API → 화면까지 연결한다.
4. 이상 3종과 복구 흐름, 기록 재생·내보내기를 연결한다.
5. 검증 담당이 통합 검증하고 메인이 수정 사항을 통합한다.
6. 실행 명령, 시연 순서, 데이터 위치, 가상 가정, 검증 결과를 문서화한다.

완료 체크리스트:

- [ ] 한 명령으로 로컬 서버와 화면을 사용할 수 있다.
- [ ] 정상·이상·복구가 화면과 저장 데이터에 일치한다.
- [ ] 자체 고장과 영향받은 정상 설비의 대기가 구분된다.
- [ ] 정지 구간에서 코일이 이동하지 않고 처리량이 임의 증가하지 않는다.
- [ ] 같은 seed·시작 시각·입력으로 같은 가상 결과가 나온다.
- [ ] 기록 재생과 JSONL/CSV 내보내기를 확인했다.
- [ ] S1/S2/S3용 관측 데이터 예시와 평가용 정답을 분리했다.
- [ ] as_of 이후 정보와 sealed 데이터가 일반 조회에 섞이지 않는다.
- [ ] 기존 테스트와 추가한 관련 테스트가 통과한다.
- [ ] 실제 브라우저에서 상태 표시·제어·오류 표시를 확인했다.

예상 실행 진입점은 `python -m shiftlink.mes`다. 이는 구현 목표이며 현재 동작하는 명령이라는 뜻은 아니다. 최종 문서에는 실제 확인된 실행·검증 명령만 적는다. 생성 DB와 대량 데이터는 Git에 포함하지 않고 작은 검증 fixture와 생성 설정만 관리한다.
