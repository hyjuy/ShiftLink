# D15 사전 등록 — 정상 학습 생성 경로만 바꾸기

2026-10-21. 사용자 요청: 다음 실험 계속 진행. D12 forest 및 D14 빠른 해제 후보가 이미 보류됐으므로 반복하지 않는다. D11–D13에서 확인한 정상 생성 경로의 차이를 다음 변수로 선택한다. search-first 연구자와 별도 데이터 감사자가 설계·재현을 읽기 전용으로 검토했다.

## 질문과 고정 조건

고정된 설비별 Isolation Forest에서 정상 학습 창의 출처를 pattern v4에서 independent v7로 바꾸면, 새로운 v7 정상 입력의 경보가 줄어드는가? 생성기·센서 카탈로그·운영 코드·기존 산출물은 바꾸지 않는다. 이는 실제 물리 관계를 바로잡거나 현장 성능을 입증하는 실험이 아니다.

- 기준 통계: 기존 pattern v4 train의 평균/scale와 D12의 63/69개 위치 마스크를 두 모델에 똑같이 사용한다. 총 69개는 10대 설비의 서로 다른 측정 위치 합계다.
- 모델: 현재값·8프레임 평균/표준편차/기울기, IF 200 trees, max_samples=min(256,N), seed20261020, n_jobs1, contamination=auto. 임계값 .65 고정. 재탐색·앙상블·RF·PCA 추가 없음.
- 기존 전체 run에서 먼저 창을 만든 후 8개 프레임 모두 faults=[]인 창만 학습한다. intensity0도 고장 라벨이 있으면 제외한다. 정상 선택은 합성 정답에 의존한다.
- 두 출처의 설비별 정상 창 수 중 작은 수 N을 양쪽에서 동일하게 뽑는다. 고정 salt `mes-training-source-20261021`와 (설비,run,sequence)의 SHA256 순으로 N개를 뽑고 원래 시간 순서를 복원한다. N<100, 빈 채널, 차원 불일치, 비유한 입력은 중단한다. 선택 키·해시·run별 수를 저장한다. 중첩 창 N개를 독립 고장 N건으로 표현하지 않는다.
- 전처리는 고정하고 IF의 적합 입력 출처만 바꾼다. N이 작아 v4도 일부 추출하면 기존 D12 적합과 다른 **수량을 맞춘 대조군**이라고 표시한다.
- 비교 기준: 같은 v4 정상 통계의 EWMA3, robust z6. 기존 임계값을 새 결과로 바꾸지 않는다.

## 새 자료와 봉인

`build_mes_fault_dataset.py`를 그대로 사용해 independent v7 seed1371, 각 분할 8run × 300초, hazard .003, warmup60의 full1.0/weak.2를 만든다. seed1371..1394가 기존 manifest와 겹치면 중단하고 이 사전 기록을 수정하기 전 다른 시드를 고르지 않는다. v7 .2는 임의 스트레스이며 v6 .2는 계속 무효다.

새 full의 **train만** aligned 학습에 사용하고, 새 full/weak의 validation만 평가한다. pattern train과 새 학습/검증의 run/seed는 분리하며 full/weak는 일정·키·정상 측정값이 같은 짝이다. 기존 generator가 test 파일 행도 생성하는 사실을 기록한다. test 분할은 생성되지만 읽거나 채점하지 않는다. 매니페스트의 시험 집계 메타데이터는 읽는다. 이번 실험만으로 새 최종 시험이나 배포를 승인하지 않는다.

## 검증과 판정

1. 현재 코드로 기존 v7 사실 재생을 확인한다. 새 v7도 replay_validation의 factual 동등성 및 고장 전 twin 동등성을 통과해야 한다. 코드/카탈로그/입력 해시를 남긴다.
2. 일차 진단 지표: 새 validation에서 8개 모두 faults=[]인 창과 최초 주입 전 창의 IF 경보 설비·프레임. full/weak 정상 창이 같은지 확인하고 중복 증거로 세지 않는다. 정상 current 속도–전류 상관, std8 중앙값도 출처별로 보고하되 이것 하나를 인과 원인으로 단정하지 않는다.
   8개 모두 faults=[]여도 더 오래된 고장이 코일/상태에 남을 수 있다. 최초 주입 전 결과를 따로 보고, 고장 후 창에서만 개선되면 순수 정상 분포의 원인 규명으로 표현하지 않는다.
3. 기존 strict source score를 그대로 유지한다. 사건 탐지·미탐·false 시작·오진 합집합 초·설비초·성공건 p95와 설비/유형별 악화를 나란히 보고한다. IF가 원인/유형을 출력한다고 주장하지 않는다.
4. 진단 가설은 matched v4 대비 v7 학습 IF의 정상 창 경보 설비·프레임이 엄격히 줄어들면 이 고정 파이프라인에서 지지된 것으로 기록한다. 감소해도 고장 탐지 성능 개선이나 배포 승격은 별개다. 양팔 정상 창 경보가 모두 0이면 바닥 효과로 판정 불가다.
5. 연구 후보 통과는 양팔 모두 기존 gate_failures로 matched v4 IF와 EWMA3 대비 탐지·false 시작·오진 시간·p95·설비/유형별 악화가 없고, 적합/관측 보류/비유한 점수 문제가 없으며, matched v4 IF 대비 탐지 증가 또는 오진 설비초 감소가 하나 이상 있어야 한다. robust z6은 동일 표에 보조 기준으로 제시한다. 실패하면 보류하고 재튜닝하지 않는다.

테스트를 먼저 실패시킨 뒤 새 비교 스크립트를 구현한다. 관련 회귀·새 코드 coverage와 독립 결과 검토를 기록한다. 정상 running 단일 모드·합성 지문·정답 기반 정상 선택·짧은 시간·창 자기상관·반복 연구 선택의 한계는 유지한다.

## 실행 전 정정 — 공유 작업 폴더의 동시 변경

모델 점수 계산 전, 기존 pattern의 config_id 검사에서 중단됐다. 실행 도중 다른 작업이 engine.py(시료 관측 시각), signal_dynamics.py(60초 캐시), signal_semantics.py(시료 설명)를 바꿨다. 새 구성 `23e0e6b3aa6f073857d48e81fd7430068ee40ca2f0cfe77147bae37741a0b036`과 기존 구성 `3713bf5f3e0f9ef808ff264ea1fa12dee6ded2b97ac4b549816c275c7f568900`을 섞지 않는다. config_id는 생성기 난수 nonce에도 들어간다.

기존 DB의 구성 payload를 읽기 전용으로 복원해 해시를 확인했다. 구성 차이는 5개 수동 시료의 applicability 문구뿐이지만 실제 시료 생성 동작도 별도로 바뀌었다. 처음 만든 `mes-fault-coherent-v7-seed1371-20261021`, `mes-fault-weak-v7-seed1371-20261021`는 **구성 불일치로 미평가**이며 보존한다.

운영 작업 파일은 수정하지 않는다. `output/mes-training-source-runtime-20261021/`에 관련 Python 소스와 카탈로그를 복사하고, 위 3개 파일만 Git HEAD의 이전 수집 동작으로 고정한다. 나머지 기존 연구 코드와 작업 중 random_factory는 복사 시점의 해시를 고정한다. 이 별도 프로세스에서 기존 구성 해시와 기존 v7 factual replay를 다시 확인한 뒤, 동일 시드·조건의 새 폴더 `mes-fault-coherent-v7-seed1371-frozen-20261021`, `mes-fault-weak-v7-seed1371-frozen-20261021`를 생성한다. 코드 스냅숏 provenance를 보존한다. 학습/채점 설계·임계값·판정은 그대로다. 미평가 생성 시드 재사용이며 결과를 보고 시드를 고른 것이 아니다.
