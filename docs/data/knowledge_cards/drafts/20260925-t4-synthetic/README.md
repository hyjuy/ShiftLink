## D. 보완 대기와 개선 의견

현장 근거 기준에서는 25건 모두 보완 대기다. 기존 원문 후보 Q01–Q08의 부족 자료도 [기존 보고서](../20260925-t4-evidence-review/review.md)에 유지한다. 아래는 개발용 검토에서 남은 의견이며 점수에 반영되어 있다.

- M03 (synthetic_boundary_review, minor): 연락담당의 회신은 그 역할의 정보 수신만 확인하며 고지 대상 인원 전체가 인지했다는 뜻은 아니라는 문장을 보완하면 대상 범위의 오독을 더 줄일 수 있다. 현재도 전원 고지 완료나 착수 승인을 주장하지는 않는다.
- M07 (synthetic_boundary_review, minor): unresolved_handling의 '인계 미완료 또는 해당 항목 보완 요청'을 정보 수신 확인 상태와 질문 답변 대기 상태로 나누면 좋다. 답변이 아직 없어도 그 미확인 상태를 정확히 인수한 경우를 구분할 수 있다.
- M08 (synthetic_boundary_review, minor): '결측이 채워지지 않았으면 인계 미완료' 대신 결측 상태의 수신 확인과 계측정보 보완 대기를 별도로 적으면 제목·방법의 '미확인 상태 그대로 인계' 목적이 더 잘 드러난다. 현재 문구는 보수적인 미완료 처리이므로 안전한 사실 경계를 침해하지 않는다.
- M08 (harness_review, minor): 결측 상태를 정확히 인수했다는 확인과 결측 데이터 보완 완료를 별도 상태로 나누면, 결측값이 채워지기 전 정보 전달까지 무조건 미완료가 되는 해석을 줄일 수 있다.
- M10 (synthetic_boundary_review, minor): 시각 출처의 장치·작성자뿐 아니라 원문에 표시된 시간대나 시각 기준의 존재 여부도 확인 항목에 명시하면 서로 다른 기준 문제를 더 구체적으로 다룰 수 있다. 원문에 없는 시간대·보정값은 계속 미확인으로 유지해야 한다.
- M13 (synthetic_boundary_review, minor): 충돌 내용을 미해결로 정확히 받았다는 확인과 충돌 사실의 해결 여부를 분리하면 좋다. 현재 '불일치가 해소되지 않았으면 인계 미완료 또는 보완 요청'은 보수적이지만 이 방법의 미해결 상태 보존 목적과 완료 기준이 다소 모호하다.
- M13 (harness_review, minor): 불일치를 그대로 인수한 전달 확인과 원문 간 분쟁 해결을 별도 상태로 명시하면 인계 미완료 또는 항목 보완 요청이라는 양자택일 표현이 명확해진다.
- M14 (method_design_review, minor): M18과 선택하기 쉽도록 이미 의뢰되어 회신을 추적하는 항목은 M18, 새 질문의 접수 범위 확인은 M14라는 적용 경계를 카드 본문에 더 직접 적을 여지가 있다.
- M15 (method_design_review, minor): 다수 제한 기록이 있을 때 어느 기록을 인계 중인지 식별할 단위를 예시 양식에 명시하면 원기록 참조·범위 대조가 더 분명해진다.
- M16 (method_design_review, minor): acknowledgement의 '승인 또는 미승인으로 단정한 회신'은 '확인된 기록 근거 없이 단정한 회신'으로 한정하고, 새 증빙 회신은 원문 확인 대상으로 연결한다고 적으면 확인 요청 이후의 흐름도 일관된다.
- M17 (method_design_review, minor): 식별자 미부여 보고가 여러 개면 전체 식별자 회신만으로 대조하기 어려우므로 원문 위치 등 기존 입력으로 구별 가능한 참조를 회신하도록 구체화할 여지가 있다.
- M18 (method_design_review, minor): 회신 기록의 부재가 확인된 미회신인지, 단지 인계 자료에 회신 기록이 빠진 것인지 구분하는 입력 상태를 추가하면 대기 의뢰와 기록 공백을 혼동하지 않는다.
- M20 (method_design_review, minor): 접근불가와 미확보를 이미 구분하므로, 실제 입력이 있을 경우 접근불가의 기록상 사유도 전달할 수 있게 하면 자료 확보 요청의 구체성이 높아진다.
- M21 (method_design_review, minor): 역할 확인 요청을 받는 주체와 최종 정보 수신 주체의 회신을 단계별로 구분하고, 실제 역할 확인 기록이 입력되기 전에는 전환하지 않는다는 조건을 좀 더 직접 적을 여지가 있다.
- M22 (method_design_review, minor): 대체 경로를 확인하는 실제 운영 입력이 없으므로 현장 절차로는 아직 실행할 수 없다. 현재 점수는 그 선택을 미확정으로 남긴 개발용 프로토콜의 품질만 평가한다.
- M24 (method_design_review, minor): 제목의 '이전 진술의 재참조를 막기'는 '이전 진술의 정정 상태를 확인하기'처럼 기록으로 확인 가능한 범위로 좁히면 본문과 일치한다. 현 문안은 후속 재사용 방지 자체를 검증하지 않는다.

## E. 목표 대비 수량과 추가 자료

- 합성 개발 초안: 25/25건 통과, 부족 0건.
- 원문만으로 검증된 지식카드: 0/25건, 부족 25건. 확인된 실제 사건: 0건.
- 추가 확보: 현장의 실제 인계 규정·양식과 적용 범위, 수신 역할과 채널, 전달 시점, 항목별 확인 응답·미응답 처리 기록, 승인권과 수신 확인의 구분, 비식별화된 송수신 원문 및 원문 접근·판본 기록. 각 방법에 해당하는 자료로 필드별 합성 제안을 검증·교체해야 한다.
- 관리값은 [배치 정책](batch-policy.json)과 [실행 원장](manifest.json)에 산출 근거를 기록했다. ID는 조사한 파일 범위의 미사용 번호이며 전역 발급 승인이 아니다. 버전은 정책·명세 해시, provenance는 실제 실행 입력·시각이다. 운영 등록부·분할표·DB는 수정하지 않았다.
