## 코드·데이터 고정

관련 Python 소스와 카탈로그를 `output/mes-diagnostic-runtime-20261021/`에 복사하고 복사 전후 해시가 같은지 검사한다. 이번에는 이전 수집 방식을 복구하지 않고 현재 동작을 그대로 고정한다. 구성 ID만으로 코드 고정을 대신하지 않는다. manifest, 코드, 카탈로그, 사용한 데이터 prefix의 해시를 보존한다.

비교 기준은 EWMA alpha.4/threshold3, robust z6, 설비별 IF200trees/seed20261020/threshold.65다. 평균·scale·95%관측률 마스크·8프레임 IF 특징은 새 full train에서만 적합한다. 모든 8프레임에 faults=[]인 정상 창을 사용하며 정답 기반 정상 선택의 한계를 표시한다. 현재 입력은68개 위치가 예상되지만 관측률로 확인하고, event를 억지로 채우지 않는다. 임계값 검색이나 RF/PCA 추가는 없다. 이전63개 자료와 직접 성능 차이를 주장하지 않는다.

## 원인·반응·시간 문맥

기존 strict source score()와 에피소드 매칭은 수정하지 않는다. replay_validation으로 factual 재현과 최초 고장 전 twin 동일성을 먼저 확인한다. no_faults twin은 모든 주입을 제거한 생성기 개입이며 단일 고장의 물리 원인을 증명하지 않는다.

factual와 no_faults를 위치키로 연결하고 valid_values의 최신/good/유한/정확한 단위 값만 비교한다. primary response는 **직렬화된 유효 숫자가 정확히 다른 것**이다. 공학적 중요도 임계값으로 부르지 않고, 최대 절대/학습 scale 대비 차이와 valid-key 차이를 함께 기록한다. timestamp/quality만 다른 전체 record 비교를 반응 정답으로 쓰지 않는다.

각 경보 설비·시간을 다음 우선순위로 한 번만 분류한다.

1. 비교 불가: 공통 유효 숫자가 없거나, 공통 숫자는 같지만 유효 채널 집합이 다름.
2. 원인 활성: 로컬 주입 intensity>0.
3. 로컬 episode off: 로컬 라벨은 있지만 intensity0.
4. 로컬 종료 후: 실제로 관측된 로컬 episode의 exclusive end로부터0..7초.
5. 다른 원인 활성 중 반응: 위 조건이 아니고 remote intensity>0이며 유효 숫자 차이가 있음.
6. 남은 twin 차이: 숫자 차이는 있지만 위 조건이 아님.
7. twin 숫자 동일 배경: 공통 값이 있고 유효 집합/숫자가 같으며 위 조건이 아님.

비교 불가를 먼저 분류해도 strict source-positive/wrong을 각 항목에 교차 집계한다. 모든 항목 합은 전체 경보 설비초, wrong 합은 기존 scorer의 오진 설비초, wrong 합집합 시간은 scorer의 오진 초와 같아야 한다. 원인/영향 설비/간헐 off를 이유로 과거 점수를 깎아 주지 않는다. 최초 주입 전, 운전 상태/코일 수 차이와 valid-set 차이는 별도 flag다.

같은 full/weak의 run/time/주입 일정과 최초 주입 전 측정 동일성을 검사한다. 주입 이후 정상 라벨만으로 두 팔의 상태/측정이 같다고 강제하지 않고 차이를 보고한다. 영향 반응 coverage는 사건 재현율이 아닌 설비·시간 coverage로 표시한다.

## 조건부 D17 — 신호 방향을 보존하는 EWMA 하나

D16의 진단용 trace에서 abs(EMA(z))와 EMA(abs(z))의 차이를 조사한다. 현재 식은 편차를 먼저 양수로 바꿔 누적한다. 동일 alpha.4/threshold3에서 signed 방식을 쓰면 삼각부등식에 따라 후보 경보는 기준 경보의 프레임별 부분집합이어야 한다. 이는 구현 불변식이지 안전성 보장이 아니다. 방향 반전 고장의 지연과 경보 분절/중복 증가 반례를 먼저 테스트한다.

한 팔이라도 이런 차이에 의존하는 strict wrong 시간이 기존 wrong 시간의 **10% 이상**이면 D17 후보 하나를 같은 개발 검증에서 평가한다. 10%는 연구 우선순위용 임의 기준이다. 미만이면 관련 없는 모델을 추가하지 않고 D16 평가 개선으로 마친다. 관측/라벨/twin은 예측에 넣지 않는다.

D17은 기존 safety_failures(원인 탐지·시작·오진·전체/설비/유형 p95), 개별 기존 탐지 사건의 손실/지연 증가0, twin 반응 경보 coverage 감소0를 모두 요구한다. 탐지 증가 또는 strict wrong 설비초 감소가 하나 이상 있어야 한다. 실패하면 보류하고 새 튜닝을 하지 않는다. 통과한 경우에만 동일 고정 모델/통계로 새 seed3371..3394의 validation을 한 번 확인한다. 이 확인도 합성 개발 확인이며 현장 적용 승인이 아니다. 원본 test는 읽지 않는다.

테스트 RED/GREEN, 데이터·설계·결과의 독립 검토, 집단 손실과 비용을 남긴다. 다른 작업의 변경은 보존하고 운영 배포는 하지 않는다.
