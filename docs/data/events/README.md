# 냉간코일 공장 내 오류·고장 및 조치 사건

이 폴더는 **냉간 철강 코일 공정과 해당 공장 내부 설비에서 발생한 오류·고장에 대해 관측, 조치, 결과를 연결한 Event**를 보관한다. 현재 이 기준으로 확인된 실제 사건은 0건이다. 자료를 확보하지 않은 상태에서 실제 사건이나 복구 조치를 생성하지 않는다.

## 포함·제외 기준

- 포함: 냉간코일 공장 내 생산·가공·권취 및 관련 설비의 오류, 품질 이상, 정지, 고장 진단·정비·복구 사례. 공장·공정과 대상 설비의 관계를 원문에서 확인해야 한다.
- 외부 운송, 화물차 상하차, 배송·출하 물류 사례는 제외한다. 단순히 코일을 취급하거나 공장 안에서 발생했다는 이유로 포함하지 않는다.
- 라인 내부 공급·이송설비는 냉간코일 생산 공정의 구성 설비임이 확인되고, 해당 오류와 실제 조치가 기록된 경우에만 검토한다. 프로젝트에 없는 코일카·권취기 등을 임의로 CV/RT에 매핑하지 않는다.
- 구리 열간압연 등 재료·공정이 다른 유사 사례는 제외한다.
- 사고 경위·피해·예방 권고만 있고 실제 오류 대응 조치를 확인하지 못한 보고서는 [안전 참고자료](../../sources/safety/public_incidents/README.md)로 분리한다.
- 일반 매뉴얼의 고장 대책은 사건 기록과 다르다. 실제 수행 기록 없이 매뉴얼 권고를 해당 사건의 수행 조치로 바꾸지 않는다.

## 사건에 필요한 내용

| 내용 | 현재 Event에 기록하는 위치 | 작성 기준 |
|---|---|---|
| 공장·공정·설비와 작업 상황 | `timeline`, `equipment` | 대상 범위를 확인하고 설비 분류 근거는 출처 메타데이터에 기록 |
| 오류·증상·알람·관측값 | `timeline`, `measurements` | 코드·단위·발생 순서는 원문 그대로, 없는 수치 생성 금지 |
| 원인 확인 과정과 결론 | `timeline`, `true_cause` | 관측·추정·확정을 구분. 미확정이면 미확정임을 명시 |
| 실제 수행한 조치와 순서 | `timeline` | 실패하거나 위험했던 시도도 사실로 구분해 기록 |
| 검증된 적절한 대응 조치 | `true_actions` | 실제 했다는 이유만으로 정답 조치로 채택하지 않음. 수행 근거와 적절성 검토 필요 |
| 조치 후 상태·확인 결과·미해결 사항 | `timeline`, 해당 시 `restart_attempts` | 성공·실패·부분 복구·확인 불가를 구분. 성공을 강제하지 않음 |
| 출처·판본·절·계보·검토 상태 | 사건 묶음의 별도 `manifest.json` | 각 사건과 source_id/위치 연결, 원문 검토·분할 확인 |

새 스키마 필드를 이번 정리에서 추가하지 않는다. Event에 없는 독립적인 결과 필드는 `timeline`에 명시적으로 기록한다. 정답 조치를 검증하지 못했다면 `true_actions=[]`의 의미를 출처 메타데이터에 적고, 완성된 조치 학습·평가 자료로 사용하지 않는다. 출처 후보와 미완성 사건은 먼저 조사·검토 자료로 관리한다.

## 작성·채택 순서

1. 냉간코일 공장 내 오류 및 **실제 대응 기록**이 있는 원문을 확보한다. 정비 이력, 고장 분석 보고서, 조치 후 확인 기록을 우선한다.
2. 사용 범위와 출처를 검토하고, 해당 원문 계보의 그룹·split을 확정한다.
3. 오류 → 확인 과정 → 수행 조치 → 결과가 연결된 Event를 작성한다.
4. 스키마 검사와 별도로 공정 적합성·수행 사실·조치 적절성·결과 근거를 검수한다.
5. 검증 결과는 입력 / 기대 결과 / 실제 결과 / 수정 필요 사항으로 기록한다. 불명확한 업무 규칙은 별도 미결 항목으로 남긴다.

실패 사례도 포함할 수 있으나 실패 시도와 검증된 정답 조치는 분리한다. 안전 참고자료에서 제시한 예방 대책을 성공한 복구 결과로 바꾸지 않는다. 합성 사건이 필요하면 합성임을 명시하고 기존 `../scenarios/` 자료와 구분한다. sealed 사건은 개발·생성 입력으로 사용하지 않는다.

## 기존 자료 재분류 (2026-09-22)

EV-0101~EV-0105는 모두 실제 조치의 검증 근거가 부족해 안전 참고자료로 이동했다. 원래 Event JSON·출처 URL·ID·분할 값은 보존했다. 사건 데이터에서 제외한 것이며 사고 내용을 삭제하거나 정상 복구 사례로 변경한 것이 아니다.
