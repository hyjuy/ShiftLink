# 현재 시나리오와 프로젝트 기준 재검토

검토일: 2026-09-30. 대상: 현재 활성 기본 구성의 77개 시나리오와 기존 MES·카드 계약.

## 결론

기본 구성은 **정상 포함 기존 9개 + 독립 센서 시연 46개 + 증상 조합 시연 22개 = 77개**다. 22개 증상 시나리오는 15개 관측 패턴을 설비별로 적용한 것이다. 여기서 등록·확정된 런타임 목록은 실제 고장 진단 규칙의 전문가 승인이나 KB 등록 승인을 뜻하지 않는다.

77개 모두 선택 → 3 tick 관측 → 명시적 주입값 확인 → 필요한 모의 조치 → 정상 복귀를 실행했다. 복귀 후 알람과 증상 후보가 사라지는 것도 확인했다. 검토에서 발견한 코드·문서 불일치는 아래와 같이 수정했다. 수정 후 전체 테스트 541개가 통과했으며, 독립 검토에서 추가 필수 수정은 발견하지 못했다.

## 유지한 경계

- [원문·분할 계약](../data/policies/source-and-split-contract.md)의 승인·계보·split 규칙은 변경하지 않았다. 신규 증상 22개는 대응표의 `unlinked`이며 기존 승인 카드에 조건을 자동 부착하지 않았다.
- 증상 후보는 관측값·단위·품질·시각으로 판단한다. 시나리오 ID·주입 원인·알람 정답을 판정 입력으로 사용하지 않는다. `confirmed=False`, `threshold_basis=synthetic_config`를 유지한다.
- 가상 수치·3회 관측 설정은 논문에서 검증한 고장 임계값이나 실설비 진단 성능이 아니다. RT 승강 구조, 센서 설치 위치, 원시 파형, 수요·부하 조건이 아직 미확정이다.
- 기존 `pdp_trip`의 55 A·트립 1 동시값은 합성 채널 테스트로 유지한다. 실제 차단 후 전류로 해석하지 않으며 신규 증상 시연은 트립 전 전류 상승과 트립 후 0 A를 분리한다.
- `symptom_diagnostics`는 현재 상태 API에서 계산한다. 저장 Snapshot·과거 재생·관측 어댑터·내보내기에 후보가 자동 저장되는 기능은 구현하지 않았다. 이 차이는 공통 계약에 명시했다.
- 사용자 구성의 단위 변경 자체와 필수 신호 삭제를 일괄 차단하는 정책은 추가하지 않았다. 변경된 단위·효과값·카드 조건과 필수 관측 계약은 구성 적용 전 별도 검토해야 한다. MES → 모델 답변 연결과 평가용 공개 상태 판정 함수도 업무 분장상의 별도 작업이다.

Python 3.10과 기존 프로젝트 의존성으로 **541 passed in 39.28s**. 지정 변경 모듈 합계 **92%**: symptoms 96%, configuration 94%, storage 94%, card_adapter 88%, server 88%. 전체 프로젝트 커버리지·원격 CI 결과가 아니다. C tracer 미설치로 coverage의 Python tracer를 사용했다. 측정 파일: `artifacts/scenario-criteria.coverage`.

시나리오·가이드 예시 확인: `python artifacts/check-scenario-criteria.py` — 77개 주입값·정상 복귀 통과, CV-02 제거 구성 유효, 압력 단위 변환 구성 유효(14500–16500 kPa), 미지원 capability fixture는 예상대로 거부됐다. 이 재현 스크립트는 ignored artifacts에 있다.

독립 검토: 정책 에이전트가 bool 유효값·목록·승인 및 분할 경계를 대조했다. 런타임 에이전트가 77개 복귀를 별도 실행하고 구성 적용 실패 후 재시작 문제를 재현했다. 수정 후 런타임 에이전트의 criteria·storage·server 테스트 29개와 가이드 예시 재실행이 통과했다. 정책 에이전트의 criteria·symptom 테스트 41개도 통과했으며, bool 2의 후보 근거 배제·구성 거부·문서 충돌 해소를 재확인했다. 기존의 관련 없는 미커밋 작업과 안전 자료는 이 변경에 포함하지 않았다.
