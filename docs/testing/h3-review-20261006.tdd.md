# H3 리뷰 반영 검증 (2026-10-06)

Claude 리뷰의 A·B·C에서 검증할 동작을 도출했다. 실제 장비 등록이나 클라우드 접속은 실행하지 않았다.

## 보장할 동작

운영자는 업로더 실패를 JSON 로그에서 확인하되 접속 정보가 로그에 남지 않아야 한다. 일시적인 클라우드·SQLite 오류 후 다음 전송 주기에 재시도할 수 있어야 한다. MES와 업로더가 같은 파일 DB에 접근해도 이미 저장된 인계·질의가 유지돼야 한다. MES는 Ollama 시작을 요청하면서 업로더와 정지·장애 생명주기를 결합하지 않아야 한다.

## C·공백 경로 결과

`tests/test_deploy_services.py`가 스크립트를 공백이 있는 임시 저장소에 복사하고 WSL bash에서 `DRY_RUN=1`로 실행한다. Ollama Wants, 생명주기 결합 의존성 부재, 동일 기본 DB, 공백 환경 파일 경로를 확인한다. 추가로 생성된 두 unit을 `systemd-analyze verify --man=no`에 전달해 실제 파서가 처리하는지 검증한다. 의존성 stub이나 실제 서비스 등록은 사용하지 않았다.

- 초기 RED: `2 failed in 0.82s` (Ollama Wants 누락 및 리뷰에 따른 WorkingDirectory 인용 기대). 체크포인트 `f17cd88`.
- 권고 정정: 실제 systemd 파서에서는 WorkingDirectory 큰따옴표가 경로 문자로 남아 `path is not absolute`로 실패했다. 테스트 기대를 기존 비인용 형식으로 바로잡았다. EnvironmentFile은 인용했다.
- GREEN: `$env:PYTHONPATH='.test-deps'; python -m pytest tests/test_deploy_services.py -q` → `3 passed in 5.95s`. Windows sandbox의 subprocess 핸들 오류 때문에 WSL을 사용하는 검증은 승인된 sandbox 밖 실행으로 수행했다.

이는 unit 생성·파싱 검증이며 실제 서비스 시작 및 모델 준비를 보장하지 않는다.

최종 서비스·업로더·저장소·대사 결합 시험:

```powershell
$env:PYTHONPATH = '.test-deps'
python -m pytest tests/test_deploy_services.py tests/test_mes_uploader.py tests/test_mes_storage.py tests/test_check_upload_recon.py -q --basetemp=tmp/h3-final-pytest
```

승인된 sandbox 밖 실행에서 `21 passed in 10.10s`. `git diff --check`도 H3 변경 파일 대상으로 통과했다.
