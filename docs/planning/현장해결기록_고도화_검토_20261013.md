# 현장 해결 기록 → 카드 초안: 고도화 검토 (2026-10-13)

대상: PR #268(현장 해결 기록 → 검수 대기 카드 초안). 검증 기록: [field-resolution-card-draft.tdd.md](../testing/field-resolution-card-draft.tdd.md)

검토 방법: 서브에이전트 3개가 코드만 읽고 독립 검토했다. 관점은 ① 코드 견고성, ② 지식 품질·검색·승격 경로, ③ 현장 운영·안전·데이터 거버넌스다.
그 뒤 주요 주장을 직접 확인했다.
- **재현**: 실행해서 확인한 것.
- **코드 확인**: 해당 줄을 읽어서 맞는 것을 확인한 것.
- **제안**: 설계 의견. 검증하지 않음.

크기는 S(반나절 이하), M(1~2일), L(그 이상)이다.

## 결론

지금 초안은 "현장 경험 메모가 붙은 카드 초안"이다. 원인을 말하는 질문에는 검색이 잘 걸린다. 시험 승격 때 판정기도 통과했다. 하지만 아래 이유로 그대로 승격하면 안 된다.

1. 서버가 해결 확인 근거를 클라이언트에서 받는다(재현).
2. 답에 단계 일부가 빠진다(코드 확인).
3. 안전 근거·중복 검사·승격 게이트가 없다.

**먼저 할 것은 P1 6개다.**
- 서버 쪽 결함 3개: 근거 신뢰, 시간대 오류, 저장 원자성
- 답 렌더: 단계가 잘리는 문제
- PDA 문구: "확인 불가"를 "아직 이상"으로 표시하는 문제
- 승격 전 필수 검수 항목 정의

검수 탭 구현은 그다음이다.

### 승격 기준 초안 (6번, 합의용)
- 안전 표현(차단기·재가동·커버·인터록 등)이 있는 카드는 사람이 채워야 한다.
  - `safety_flag`와 `safety_basis`
  - `safety_review`: 승인자, 역할, 검토일, 유효기한, 근거 등급. 스키마는 `agent/schemas.py`에 이미 있다.
  - 이 카드는 **안전 담당만 승인**한다.
- 모든 단계에 결과가 있어야 하고, 필요하면 중단 조건을 쓴다.
- 부품(`component`, `mes_component_code`)과 시나리오를 지정한다. 지금은 "HPU-01"과 S1 기본값이다.
- MES로 확인된 해결이 2건 이상이고 반대 근거가 없어야 한다(현재 `ready`). 이 조건을 만족하지 않으면 운영자가 사유를 남기고 예외 승인한다.
- 기존 카드와 중복 검사를 통과해야 한다(P2-1).

## 이미 확인해서 문제없던 것
- 같은 인계 재전송: `save_handover`의 중복 무시와 `card_draft_records`의 기본키로 초안이 두 번 생기지 않는다.
- 초안은 검색·PDA에 나가지 않는다. 시험 승격 전 실측에서 "해당 지식 없음"이 유지됐다.
- 업로드 보류: 실장비에서 해결 기록 인계 7건이 업로더 여러 주기 동안 `pending`으로 남았다.
