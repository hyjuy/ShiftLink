생성자(Claude Code)가 작성한 **대조·정정 기록**이다. **판정은 들어 있지 않다.**
분장 문서 8단계의 "생성자 본인 검수 금지"에 따라 판정은 최재영이 [`review.md`](review.md)에 적는다.

`G1`~`G7`은 이 배치의 기준이 아니다. 계획 문서의 `G1`~`G3`는 날짜 마일스톤(9/23·10/1·10/2)이고 `G4`~`G7`은 개별 정의가 저장소에 없다. 지난 배치 판정문에 쓰인 `G` 코드는 별개 체계이며 정의 문서가 없다.

## 0. 근거를 읽는 두 가지 방식

카드는 기록의 요약이 아니라 기록에서 도출한 처방이다. "근거 있음"에는 두 유형이 있고, 둘 중 하나만 있어도 7.1의 "근거와 함께 표시"를 채운다.

| 유형 | 뜻 | 예 |
|---|---|---|
| **A. 실행 사례** | 누군가 실제로 그렇게 했다 | `AR-0336` "00:30 공급원 HPU-01 압력 152 bar 확인 — 정상이었다" → K-1107 |
| **B. 문제 사례** | 안 해서 문제가 생겼다 | `AR-0330` "공급원 HPU-01 쪽인지 텐셔너 자체인지 가리지 못했다" → K-1107 |

B형이면 처방 문구가 기록에 그대로 없어도 정당하다. 둘 다 없는 경우만 근거 없음이다.

## 3. 검수 판정 (2026-09-29)

근거가 다른 카드에 **완전 포함**된 두 건에 대한 판정이다. 판정 내용은 각 카드의 `confidence_basis`에도 남겼다.

### 3.1 K-1111(흡수) → K-1103에 흡수 (판정)

근거 3건(`EV-0304`·`EV-0308`·`EV-0311`)이 K-1103의 근거 5건에 모두 포함되어 있었다.

| | 흡수 전 K-1103 | K-1111(흡수) | 흡수 후 K-1103 |
|---|---|---|---|
| 제목 | 정지·재기동 방지 상태와 운전 복귀 조건·승인 주체 | 작업 제한 상태와 대기 사유 | …승인 주체**·대기 사유** |
| `component` | 정지·재기동 방지 상태 | 작업 제한 상태 | 정지·재기동 방지 상태**와 작업 제한** |
| `required_context` | 5개 | 4개 | **6개** |
| `safety_flag` | true | false | true |
| 근거 | 5건 | 3건 | **5건** (늘지 않음 — 이미 포함) |

옮긴 것은 K-1111(흡수)의 고유 항목 하나뿐이다.

> "정비가 교대 안에 끝나지 않았으면 무엇을 기다리는지(부품 입고·담당자 도착·이력 조회)와 예상 시점"

겹치던 두 항목("제한이 풀리는 조건", "제한을 푸는 승인 주체")은 K-1103에 이미 있어 옮기지 않았다. `know_how`·`rationale`·`generalization_scope`도 대기 사유를 포함하도록 고쳤고, 대기 사유가 사건마다 달랐던 것(EV-0304 부품·오일 미준비 / EV-0308 담당자 미도착 / EV-0311 부품 입고 대기)을 rationale에 명시했다.

**부수 효과**: K-1103(`true`)과 K-1111(흡수)(`false`)의 `safety_flag` 불일치가 함께 해소됐다. 대기 사유가 안전 카드 안으로 들어가 등급이 하나로 통일됐다.

이때 생긴 결번 `S11`은 §3.2의 재배치로 메웠다.

### 3.2 K-1112 → K-1111로 재배치 후 유지 (판정)

근거 2건(`EV-0310`·`EV-0317`)이 K-1108의 근거 3건에 모두 포함되지만 **별도 카드로 유지**한다.

유지가 정해진 뒤, K-1111이 K-1103에 흡수되어 생긴 결번을 없애기 위해 **K-1112를 K-1111(slot S11)로 재배치**했다. 커밋 전이고 `accepted`가 아니어서 외부 참조가 없는 시점에 수행했다. 카드 본문에도 재배치 사실을 남겼다.

| | K-1108 | K-1111(구 K-1112) |
|---|---|---|
| 제목 | 추정과 관측을 구분해 적고 단정하지 말아야 할 이유를 함께 넘긴다 | 눈으로만 본 관측은 수치가 없다는 사실을 적고 다음 조에 계측 방법을 지정해 요청한다 |
| 처방 | 구분해서 **적어라** | 다음 조에 **재도록 요청하라** |

이 카드의 고유 기여는 "다음 조가 잴 대상과 방법을 지정해 요청"이고 K-1108에는 이 처방이 없다. 근거는 `AR-0334` "가능하면 동작 시간을 재서 기록해 달라, 내가 눈으로만 봐서 수치가 없다".

근거 포함 관계는 `confidence_basis`에 사실대로 남겼다.

## 4. acknowledgement — 기록 보강으로 해결 (2026-09-29)

### 4.1 문제였던 것

11장 모두 "받는 사람이 … 되짚어 말한다"류였고 그 관행이 기록에 없었다. 스키마가 빈 값을 거부하는 필수 필드(`NonBlank`)라 지시서 예시("복창·서명")를 참고해 생성자가 작성한 값이었다. **기록 → 카드 체인이 이 필드 한 칸에서 끊겨 있었다.**

| 검색어 | 보강 전 |
|---|---|
| 복창 / 되짚 / 되물 / 서명 / 날인 / 수신 확인 | **0회** |
| 알겠 / 이해했 / 확인했다고 / 답했 | **0회** |
| (대조) 정비 담당 29회 · 기록 23회 · 확인 215회 | 검색은 정상 |

`확인` 215회는 전부 **보내는 사람이 설비를 확인한 것**이라 근거가 되지 않는다. 받는 쪽 확인 행위와 구분해야 한다.

### 4.2 왜 외부 문서가 아니라 기록 보강인가

세 갈래를 검토했다.

| 길 | 판단 |
|---|---|
| ① 외부 문서 확보 | **기각.** OSHA 29 CFR 1910.147(f)(4) 원문을 확인한 결과 "orderly transfer"까지만 요구하고 확인 형태는 사업장에 위임한다. KOSHA GUIDE P-172-2021(PSM 운전 규범)은 공식 경로에서 원문을 받지 못했다. 게다가 지침은 "권고"라 필드가 "이렇게 한다"에서 "이렇게 하는 것이 좋다"로 바뀌고, 다른 필드가 전부 합성 기록 기반인데 이 필드만 문헌 기반이 되어 근거 계통이 섞인다 |
| ② 카드만 다양한 표현으로 | **기각.** 표현은 다양해지지만 근거 부재는 그대로다. 7.1 미충족 |
| ③ **기록 보강 후 재추출** | **채택.** 지시서가 정한 "요령은 기록에서 나온다"는 체인을 복원한다. 기록이 합성이므로 보강도 합성이며 새 원칙을 들이는 게 아니다 |

확인할 실제 현장이 이 저장소 안에 없다는 점도 근거다. 기준정보 `_meta`가 `"all_numbers_are": "[가상 값]"`, `"is_synthetic": true`이고 페르소나도 "실존 인물과 무관한 가칭"이다. `docs/design/pda_ui/review/review_round_N_현장작업자.md`는 실제 인터뷰가 아니라 `ui_rubric.md` 기반 관점별 채점 문서다.

### 4.3 보강 설계

**대상 9건**은 계산으로 정했다 — 카드 11장이 각각 근거 2건 이상을 갖는 최소 집합이다. 근거가 2건뿐인 세 카드(K-1107·K-1110·K-1111)가 그 2건을 반드시 요구해 `EV-0304`·`EV-0310`·`EV-0315`·`EV-0317`·`EV-0318`·`EV-0320` 6건이 고정되고, 나머지 카드를 덮는 데 `EV-0305`·`EV-0307`·`EV-0312` 3건이 더 필요했다.

**방식**은 `seeds/personas_v0.1.yaml`의 `handover_style`에서 도출했다. 생성자가 임의로 정하지 않았다.

| 사건 | 페르소나 | 방식 | 넣은 장면 |
|---|---|---|---|
| EV-0304 | V-13 | 정비 기록 기재 | 인수 정비 담당이 전원 차단·재기동 방지 상태를 현장 확인, 오더에 이름·시각(22:05) |
| EV-0305 | V-13 | 정비 기록 기재 | 정지·재가동 보류 상태를 인수 기재(06:10), 시험 운전 안 했음도 기재 |
| EV-0317 | V-13 | 정비 기록 기재 | 공압 소견·드레인 결과를 읽고 확인 기재(14:05) |
| EV-0312 | V-12 | 체크리스트 | 교체 부품·압력값·재확인 시각 3항목에 인수 확인 표시(22:05) |
| EV-0315 | V-12 | 체크리스트 | 다음 조 확인 4항목에 인수 표시(06:05), 담당 범위 되물음 |
| **EV-0320** | V-12 | **확인 실패** | 체크리스트 확인은 했으나 **서식에 감압 항목이 없어** 확인 대상에서 빠짐 |
| EV-0307 | V-11 | 구두 | "필터는 원인 아님"을 짚어 주자 되물었고 답함(14:05) |
| EV-0318 | V-11 | 구두 | 공급원 정상을 짚어 주자 담당 범위를 되물음(06:05) |
| **EV-0310** | V-11 | **구두, 시각 미기재** | 구두로 넘겼고 알겠다고 했으나 **확인 시각을 안 적음** (V-11의 `omission_risk` 반영) |

**나머지 11건은 건드리지 않았다.** 모든 인계에 확인이 있으면 비현실적이고, 45%만 있어야 "확인이 있는 인계와 없는 인계"를 견줄 수 있다.

### 4.4 결과 — 결함 사례가 처방으로 이어졌다

기록에 넣은 두 실패가 카드에 반영됐다. A형(실행 사례)과 B형(문제 사례)이 둘 다 생겼다.

| 기록의 실패 | 카드의 처방 |
|---|---|
| EV-0320: 서식에 감압 항목이 없어 확인해도 놓침 | **K-1110**: "인계 서식에 감압 여부 항목이 없으면 확인을 해도 빠지므로, 서식에 그 항목이 있는지부터 본다" |
| EV-0310: 구두로 넘겨 확인 시각이 안 남음 | **K-1105·K-1108·K-1111**: "구두로만 넘기면 확인 시각이 남지 않으므로 확인 시각을 함께 적는다" |

각 카드의 `confidence_basis`에 **어느 사건의 어떤 방식에서 나왔는지** 적었다. `know_how` 본문에 확인 행위가 있던 K-1101·K-1103도 근거에 맞춰 함께 고쳤다(K-1103은 근거가 문서 방식이므로 "되짚어 말한다"를 "정비 오더에 인수 기재"로 교체).

### 4.5 검수자가 볼 것 — 새로 생긴 항목

생성자가 기록에 없던 장면을 넣었으므로 **"보강한 기록이 억지스럽지 않은가"**가 검수 항목이 됐다. 자기충족적 근거(카드에 맞춰 기록을 지어내는 것)를 막으려 둔 장치는 이렇다.

- 방식을 페르소나 정의(`handover_style`)에서 도출하고 생성자가 고르지 않음
- 대상 9건을 "카드가 근거 2건을 갖는 최소 집합"으로 계산해 정함
- 확인이 **없는** 11건과 **실패한** 2건(EV-0320·EV-0310)을 남겨 전부 성공 사례가 되지 않게 함
- 배정을 `plan.py`에 넣어 시드로 고정(재실행 바이트 동일), 평가용 사건 배정 0건을 `assert`로 강제

검증 결과: `verify.py` 전부 통과 · `card_lint` 0건 · dev 오염 0건 · 페르소나 정의 불일치 0건.

## 5. equipment 전 카드 COMMON

`shiftlink/rag/retrieval.py`가 `COMMON`을 이렇게 다룬다.

```python
303:  if card.equipment not in equipment_codes and card.equipment != "COMMON":   # 제외 조건
339:  if c.safety_flag and (c.equipment in equipment_codes or c.equipment == "COMMON")
```

- 303행 때문에 11장이 HPU·GR·RT·CV **어느 질의에도 후보로 올라온다.** 설비 필터가 걸러주지 않는다
- 339행 때문에 `safety_flag`인 K-1103·K-1110은 **모든 설비 질의에서 선두 노출**된다(7.1 "일반 top-k 밖이어도 선두 노출")

인계 요령이 설비 무관인 것은 사실이므로 `COMMON`이 틀린 값은 아니다. "이 두 장이 모든 질의 상단에 떠도 되는가"가 설계 판단 사항이다.
