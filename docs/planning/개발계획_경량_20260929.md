## 1. 목표 — 한 줄

**10/26 발표에서 "카메라로 설비 인식 → Jetson LLM이 카드 근거로 답변 → 인계 저장(로컬) → 클라우드 DB 업로드"를 한 번에 시연한다.**

```
[카메라 → 설비 4클래스 분류] --클래스명만--> [Jetson: 검색 + LLM 답변]
                                                   │
                                       [로컬 SQLite 인계 저장] --업로드--> [클라우드 DB (Aiven MySQL)]
```

- 카메라 쪽 출력은 **클래스 이름(`HPU` / `GR` / `RT` / `CV`)과 신뢰도**로 고정한다. 어떤 장치에서 분류하든 Jetson 입력은 같다.
- Jetson 추론·검색·인계 저장은 네트워크 없이 동작한다. 클라우드 업로드는 연결될 때 밀린 것을 올린다.

### 카메라 방식 후보 (1주차에 결정)

| 안 | 구성 | 장점 | 부담 |
|---|---|---|---|
| A. 라즈베리파이 분리 (현재 유력) | 웹캠 → 라즈베리파이에서 CNN → 클래스명만 Jetson으로 | Jetson 메모리(LLM)와 분리됨 | 장치 1대 추가, 장치 간 통신 필요 |
| B. Jetson 직결 | USB 웹캠 → Jetson에서 CNN → 같은 장치의 LLM 입력 | 장치·통신 없음 | 8GB 메모리를 LLM과 나눠 씀 (플랜 B 측정 때 여유 적었음) |

두 안 모두 CNN 학습(사전학습 모델 전이학습)과 촬영 데이터는 같으니, 결정 전에도 데이터 수집·학습은 시작할 수 있다.

**촬영 대상 (9/29 확정)**: 설비 4종마다 실물을 대신할 객체(박스 등)를 하나씩 정해 팀이 직접 촬영한다.

일정: 개발 완료 **10/16**, 10/19~23 예비·발표 준비, **10/26 발표**.

## 2. 반드시 지키는 것 (이것만)

| 구분 | 내용 |
|---|---|
| 외부 필수 | Jetson 사용 · 카메라 사용 · **클라우드 DB** 사용 |
| 보안 | 공개 저장소라서 `.env`·API 키·재배포 권한 없는 PDF 원문은 커밋하지 않는다 |

## 3. 없애거나 줄이는 것

| 기존 | 변경 |

| 문헌별 승인 범위·원문 해시·검토자 기록 | 출처 URL·페이지만 |
| LLM judge, 계열 분리, 판정 일치율 20건 게이트 | 사람 샘플 검수 + 스키마 검사. judge(Solar Pro 4)는 시간 나면 참고용 |

| 봉인·해시 봉인·1회 채점 절차 | 평가셋 30건을 개발용과 분리해 두기만 한다. 해시 봉인 없음 |

| 15W 고정, B/C 동일 조건 비교, p95 20건 측정 규약 | 데모 설정 하나로 20건 돌려 p95만 기록 |
| N-3 outbox 세부 규약(허용 목록·충돌 보류·부분 실패 시험 등) | 로컬 SQLite 저장 → 미전송 표시 → 연결 시 클라우드 DB로 업로드, 같은 ID 중복 무시. 테이블은 통합본 §4.11의 7개(`db/aiven_schema.sql`, 9/29 생성 완료) |
| PDA 브라우저 QR 카메라 설계(C-056·C-057 포함) | 폐기. 웹캠 + CNN 4클래스 분류로 대체 (장치는 1절 후보 중 선택) |
| SFT (기준선 3) | **진행은 확정(9/29).** 방식·시점은 그때 결정 (Qwen2.5-3B LoRA 안) |
| 제약 대장 200개 규칙 | 참고 자료 |
