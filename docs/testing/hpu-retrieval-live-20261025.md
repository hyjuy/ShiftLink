# HPU 실제 모델 비교: 운영 적용 보류

검증일: 2026-10-25 (Asia/Seoul). 시작 HEAD `e25a46d739d1f22b6c7041ae341dd84c30a7f147`.
결론: **관계 보완 효과는 일부 표현에서 확인했지만, 운영 적용은 보류하고 기본 off를 유지한다.**
운영 코드·서비스 설정·업무 DB·KB·검색 인덱스는 수정하지 않았다.

## 실제로 실행한 범위

- Jetson에서 실행 중인 `embeddinggemma:300m`, `exaone-sft-judge`, `exaone-rag-mes-ck176`을 사용했다.
  운영 답변 모델은 ck106 기본값과 달라 실제 ck176 설정에 맞췄다. 다운로드·서비스 재시작은 하지 않았다.
- 운영 인덱스를 로컬 검증 폴더로 읽기 전용 복사했다. 실제 순위·벡터·모델 출력을 대체하거나
  의도적으로 카드 순위를 낮추지 않았다. 로컬 전처리에서 임시 SSH 터널로 Jetson 모델 API를 호출했다.
- 원문·수치 검수의 근거가 알려진 합성 근무일지 **1건/현장 카드 1개**를 별도 임시 DB에 작성하고
  심사→검수→실제 임베딩 게시→실제 judge를 통과한 인용 witness를 만들었다.
  실측 설비나 운영 작업자의 실제 일지 분포를 평가한 것은 아니다.
- 원래 평가군은 [대표 질문 16개](../../tests/fixtures/hpu_retrieval_live_cases.json)를 실행 전에
  `bef0a81`에 고정했다. 질문별 2회, 실행 순서를 교차한 **32쌍**이다.
  펌프 무압·소음/기포·필터 차압 질문은 KB `K-1001`, `K-1004`, `K-1201/1202`에서 도출했다.
- 결과를 본 뒤 구성한 [표현 진단 4개](../../tests/fixtures/hpu_retrieval_live_diagnostics.json)는
  실행 전에 `5b80fdc`에 별도 고정했다. **8쌍의 탐색 평가**이며 원래 32쌍의 성적을 바꾸지 않는다.
- 수용 범위·검색 풀·청크/토큰 예산·judge·보류·이력 원문 필터·생성 검사는 기존 코드 그대로다.
  S30h 운영 사본과 로컬 파일은 모듈 설명문만 다르고 실행 AST가 같았다. generate/evidence_score/
  field_history/knowledge_graph·KB·카탈로그 해시도 확인했다.

모델 digest와 인덱스 SHA256은 [집계 JSON](hpu-retrieval-live-20261025-summary.json)에 보존했다.
모델의 답변 온도는 기존 설정인 0이다.

## 확인된 문제와 해석

1. **이력 조회 분류 누락.** `history-observation`의 “압력 정상 범위 복귀와 재발 여부를 확인한
   기록만 보여줘”는 알려진 원문을 묻지만 `is_history_question`이 false였다.
   두 경로 모두 보류했고 관계 보완은 수용 범위 밖이었다. 후속 원문 표현은 true로 분류되어 인용이 회복됐다.
2. **미기록 시간 조건 무시.** `missing-217`은 원문에 없는 217분 기록만 요청했으나 false로 분류되어
   일반 생성 경로로 갔다. 두 번씩 137분 기록과 현재 MES를 섞어 답했고 보류하지 않았다.
   217분이라는 거짓 수치를 생성한 것은 아니지만, 요청한 조건에 맞지 않는 카드 인용/보류 누락이다.
   원래 기대값과 실패 2건을 수정하거나 제외하지 않았다. HPU 보완 전후 공통 문제다.
3. **정적 이력 fallback의 범위 미확인.** 자산 교체·반려 대조에서는 금지된 현장 카드가 제거됐지만
   정적 인계에서 “131 bar, 16:35, 미회복”을 대신 답했다. 137분 원문 요청의 조건 일치나
   자산 판본을 보증하지 못한다. 이 대조는 독립 파이프라인 직접 호출이므로 서비스 계층의
   incident↔asset 검증을 포함한 실제 `/api/query` 누출로 확정하지 않는다.
   새 관계 오연결 0건을 전체 정적 검색의 오연결 0건으로 확대해서는 안 된다.
4. **지연·재현성 한계.** 실제 보완이 일어난 탐색 평가의 추가 지연은 사전에 둔 잠정 +1초/평균,
   p95 +10% 기준을 넘었다. 이 기준은 공식 운영 SLO가 아니다. 2회 반복/합성 카드 1개로는
   공유 모델 부하·캐시·PC 스케줄링 영향을 분리하거나 운영 PDA p95를 추정하기 어렵다.

현재 작업 질문은 관계 실험을 적용하지 않았다. 정비 허용을 과거 관찰만으로 승인하지 않는 답변과
무압·기포·차압 질문의 인용 카드는 원문으로 확인했다. 이것은 전문가의 설비 안전성 검수를 대체하지 않는다.

## 운영 판단과 다음 게이트

**운영 전환/배포 없음. 기본 off 유지.** 원래 평가군에서는 추가 이득이 없고 공통 보류 문제가 남았다.
탐색군의 실제 인용 회복은 유효한 후속 실험 근거지만 채택 근거로는 부족하다.

다음 순서는 (1) 두 분류 누락과 시간 조건 실패를 독립 회귀로 보존하고 기존 현재/과거 경계와 함께 수정 검증,
(2) 정적 인계도 자산·사건·수치 조건을 검증하고 서비스 API까지 범위 대조,
(3) 여러 검수 카드·다른 사건·다른 자산을 포함한 승인 실자료와 별도 고정 질문군으로 재시험,
(4) 실제 후보가 추가되는 질문을 충분히 확보해 반복·동시 부하·PDA 종단 지연 및 공식 SLO를 검증하는 것이다.
이번 요청에서는 기존 질의·검색·답변 보존을 위해 이 문제들을 수정하지 않았다.
