# 장비별 합성 T4 지식카드 확장 · 2026-09-26

기존 공통 25개를 보존하고 **장비별 카드 20개를 추가했다. 현재 합계 45개**다. 25개를 목표나 상한으로 두지 않았다. 장비별 후보 38개 중 저자 검토에서 12개, 교차 검토에서 6개를 제외·통합했다. 남긴 카드마다 장비의 계측 의미·연결 관계·부품 또는 관측 범위 때문에 필요한 인계 확인 방법을 기록했다. 이 수량은 모든 현장 상황을 망라했다는 뜻이 아니다.

모든 신규 카드는 **T4 / draft / L0 / dev**다. 합성 구성과 합성 인계 방법이며 사람 승인·현장 검증·운영 KB 채택을 기록하지 않았다. 기존 25개도 개발 초안이고, 과거 카드의 미해결/수신확인 표현 개선 과제는 이번 신규 카드 검증으로 해결됐다고 간주하지 않는다.

## 생성·검토에서 달라진 내용

원본 후보와 제외 이력을 보존했다. [원본 HPU/GR/PDP](candidate-specs-hpu-gr.json), [원본 RT/CV/CAU](candidate-specs-rt-cv.json), [제외 후보 18개](excluded-candidates.json), [검토 반영 결정](review-decisions.json)을 대조할 수 있다.

- RT-03 방법을 GR-04 방법(K-0036)에 통합하고 RT-03 장비를 관련 범위로 연결했다.
- RT-06 방법을 HPU-01 방법(K-0037)에 통합하고 RT·CV 수요처를 관련 범위로 연결했다.
- HPU-04, RT-07, CV-05, CAU-02는 기존 공통/장비 방법의 변형·조합이라 독립 카드에서 제외했다.
- HPU-03의 유온 기록 존재 단정, GR-04의 대응 문서 미확인 고정을 입력 상태에 따라 조건화했다.
- PDP-02 송수신 역할을 분리하고 PDP-03 하류 RT/CV 관계 참조를 보완했다.

검토자 3명은 저자 간 교차 검토 2명과 카드 작성에 참여하지 않은 독립 검토자 1명이다. 원래 26개에 대한 리뷰는 원본 snapshot 해시와 연결된다. 수정 후 20개 전체의 최신 검토는 [review-final.json](review-final.json)이며 모두 pass다. 검토자 간 중복 기준 차이와 최종 통합 선택도 숨기지 않았다. AI 문서 검토이며 사람이 한 안전 검토나 효과성 점수가 아니다.

## 구조·연결 검증

[validation.json](validation.json): 스키마 20/20, T4 필수 5필드 누락/공백 거부 200/200, dev 적재 차단 20/20, draft/L0 제외 20/20. 카드와 명세 일치, 카탈로그 참조 해소, 장비 ID·유형·적용 인스턴스, 관리값·원본 해시를 검증했다. 기존 공통 25개와 신규 20개 사이의 990쌍을 완전 일치/문자 유사도로 검사하고 의미 중복은 별도 AI 검토로 판단했다. 전체 운영 KB의 의미 중복 검사를 했다는 뜻은 아니다.

인계 방법 5필드의 직접 원문 지지는 신규 20개 모두 0/5다. confidence=0은 이전 합성 배치와 같은 개발용 정의(직접 원문 지지 필드 수/5)이며 품질·효과·운영 신뢰도 점수가 아니다. 장비 카탈로그는 가상 구성의 근거일 뿐 인계 방법 효과의 증거가 아니다. 새 시나리오·모의 응답은 실제 사건 참조로 등록하지 않았다.

## 실제 송수신 파일럿 결과

[항목별 결과 보고서](pilot-results.md) · [독립 판정 원장](pilot-judgment.json) · [경계 사례의 별도 판정](pilot-adjudication.json) · [입력·출력 검사](pilot-audit.json).

HPU/GR/RT/CV 각 1개 상황에서 새 송신자·수신자 컨텍스트를 사용했다. 조건별로 네 상황을 묶어 실행한 송신 3회·수신 3회이며, 4개 짝지은 상황 × 3조건의 결과 12건이다. 수신자는 카드나 평가 정답을 직접 보지 않고 실제 송신 메시지만 받았다.

| 조건 | 필수 사실 보존 | 미확인 보존 | 승인 오류 | 완료 오판 | 입력 밖 수신자 주장 | 후속 요청 단위 |
|---|---:|---:|---:|---:|---:|---:|
| 카드 없음 | 24/24 | 12/12 | 0 | 0 | 0 | 27 |
| 일반 5항목 체크리스트 | 24/24 | 12/12 | 0 | 0 | 0 | 19 |
| 장비 카드 실행 필드 발췌 | 24/24 | 12/12 | 0 | 0 | 1 (민감도 0~1) | 37 |

세 조건에서 필수 항목 보존이 같으므로 **이 파일럿은 카드의 추가효과를 입증하지 못했다.** 후속 요청은 독립적으로 답할 수 있는 필드·대상별 단위로 분해한 값이며 대화 턴 수나 비용이 아니다. 요청이 적거나 많다는 이유만으로 더 좋다고 해석하지 않는다.

경계 사례는 카드 조건 HPU 수신문의 “RT-02·RT-03의 말단 클램프 압력”이다. 실제 전달문은 RT-02만 클램프라고 했고 RT-03은 압력이라고 했다. 독립 심판은 입력 밖 측정 대상 명칭의 배정을 1건으로 셌다. 별도 검토자는 부정형 대체금지 문장에 있는 전제라는 점에서 ambiguous로 판정했다. 두 판단과 엄격 1/대안 0 민감도를 보존한다. 비공개 자료를 실제로 읽었다는 증거나 카드의 인과적 결함으로 해석하지 않는다.

ExpeL에서 가져온 경험 비교에 따라 “수치뿐 아니라 측정 대상 명칭도 실제 전달 범위에 한정한다”는 개선 후보를 남겼다. 나머지 상황에는 실패 대비 개선 근거가 없고 이 경계 사례도 원인 단계가 확정되지 않아 이번 실행 뒤 카드를 자동 수정하지 않았다. 후보 작성 단계의 검토 수정과 실행 경험에 의한 효과 개선을 구분한다.

단발 4상황, 조건 내 배치 호출, 같은 계열 AI 판정, 이미 잘 구조화된 원장, 요청 길이만 통제한 예산이라는 한계가 있다. 모든 신규 카드의 효과·PDP/CAU 효과·현장 효과를 측정한 것이 아니다. 프로토콜의 “카드 전문” 표현과 실제 발췌 노출의 차이, 중첩 실행 순서도 [편차 기록](pilot-deviations.json)에 공개했다. 원래 동결 입력·프로토콜은 결과에 맞춰 바꾸지 않았다.

## 재검증과 재생성

프로젝트 루트에서:

```powershell
python docs/data/knowledge_cards/drafts/20260926-t4-equipment/verify.py
python docs/data/knowledge_cards/drafts/20260926-t4-equipment/pilot.py audit
```

검증은 결과 JSON을 다시 쓴다. `build.py`는 명세가 실제로 바뀔 때만 사용하며 수정 후에는 내용 재검토와 최신 해시 확인이 필요하다. 파일럿 입력은 `freeze`가 덮어쓰기를 거부하도록 했다. 이미 실행한 입력·출력은 보존하고 새 실험은 별도 배치로 만든다. 식별자는 명시된 카드 JSON 조사 범위에서만 충돌을 검사했으며 전역 DB ID 발급 인증이 아니다.
