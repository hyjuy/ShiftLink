# v11: Timestral 제거 후보의 불량 측정 후 고착 재통지 수정 결과

판정: 이번에 확인한 불량 측정 뒤 고착 이력 재구축을 정상 회복으로 오인하는 결함은 별도 v11에서 수정했다. 기존 문제 재생·회귀·고정 후 새 품질 스트레스 평가에서 첫 탐지와 지연을 유지하며 중복을 제거했다. 정상 오통지2건과 비매칭 통지는 남으므로 전체 경보 품질이나 현장 운영 가능성을 입증한 것은 아니다. Pi 배포·운영 경보 연결은 하지 않았다.

## 원인과 최소 수정

v10b 기준 후보는 EQ-0006 `rt_motor_current` 고착[376,434)에서391초 첫 통지 후406초 `quality=bad`가 들어오면,16개 고착 이력을 다시 쌓는 동안5개 낮은 판정을 정상 회복으로 셌다. 다른 센서가 유효하다는 이유로 경보를 만든 센서까지 회복했다고 간주해422초에 같은 고착을 다시 통지했다.

원본을 수정하지 않고 `scripts/mes_causal_v11.py`를 추가했다.

- `:6 flat_evidence`: 고착 증거를 **고착 / 관측된 변화 / 불명확**으로 구분한다. 불량 샘플이나 이력 부족은 정상 증거가 아니다. 유효 관측의 변화가 허용오차를 넘으면 일부 결측 이력이 남아도 non-flat임을 증명한다.
- `:20 predict`: 기존 공정 점수와 임계값을 그대로 쓰고 고착 판정의 유효성만 별도로 만든다.
- `:34 notifications`, 특히`:45`: 해당 경보에 기여한 공정·고착 채널을 추적한다. **그 채널들이 판정 가능하고 이상 증거가 없는 경우에만 정상 회복5회를 센다.** 관계없는 다른 센서의 정상값으로 회복을 확정하지 않는다.

단순히16개 이력이 채워질 때까지 회복을 전부 막는 수정은, 불량 직후5개의 실제 변화 샘플 뒤 발생한 가까운 새 고착을 놓쳤다. 이를 실패 회귀로 확인하고 관측된 변화에 의한 회복을 허용했다. 실제 회복·다음 고장 통지는 유지하고 불명확한 재구축만 정상으로 세지 않는 수정이다.

기준 v10b의 no_timestral 설정은 그대로다: 입력63채널, 기존 정상 통계·임계값, median5, EWMA.4, q.98×1.5, 공정 지속4, 고착16, 정상 회복5,64프레임 준비. 모델 로딩·학습·임계 재선택은 하지 않았다.

## 기존 문제와 개발 확인

기존 소비된36건에서 모델 없는 기준 경로의 모든 통지 행이 기존 저장된 no_timestral 예측과 정확히 같음을 확인했다. 수정 후36/36·정상0건·p9518초를 유지하며 중복1→0, 해당 사건의 통지 `[391,422]→[391]`을 확인했다. 모든 사건 첫 통지 시각도 같다. 이 재생은 원인 확인용이며 새 평가와 합치지 않았다.

새 개발12건도 기준/수정 모두12/12·정상0/2688초·p9521초, 중복4→0이었다. 이 결과와 회귀를 확인한 후 후보 소스·고정 설정·자료·보호 파일을 잠그고 그 뒤 새 test를 처음 생성했다. 새 시험 결과로 코드를 바꾸지 않았다. [사전 명세](mes-causal-v11-prereg-20261023.md), [TDD 근거](../testing/mes-causal-v11-20261023.tdd.md).

## 새 미사용 품질 불량 강화 평가

동일한 새36사건과 무고장 대조 실행으로 비교했다. 기존 후보도 이 입력에 다시 적용했다. 고착 중 시작+25초의 단발 bad를 명시적으로 넣었으므로, 예전36건의 중복1과 아래 새36건의 기준 중복12를 직접 전후 성능으로 비교하면 안 된다.

사건별 첫 통지 지연은 **36건 모두 정확히 같다.** 단순히 첫 통지를 늦추거나 고장을 놓쳐 중복이 줄어든 것이 아니다. 종류별 friction6/6, leak6/6, sensor_stuck12/12, cooling_loss6/6, blockage6/6도 같다. 이 종류는 사후 장부 기준이며 고장 종류를 진단하는 분류 성능이 아니다.

중복은 활성 개입 구간 안의 추가 통지를 세는 지표다. 구간 밖 잔류 통지는 비매칭으로 잡히므로 이를 함께 공개했다. 수정 후보의 비매칭17건 중 정상 전용/paired 무고장 실행에서2건이 있고, 나머지는 고장 실행의 비근원 설비·잔류 구간 등을 포함한다. 하류 반응과 오류를 이 집계만으로 확정할 수 없으며 모든 사용자 통지가 적절하다는 증거가 아니다.

정상 노출11648초는 **약3.24시간의 합성 시간**이다. 두 후보 모두 관측 오통지율0.6181/line-hour다. 독립 정상 포아송 가정의 단측95%상한은1.9458/시간이므로, 실제 오통지율≤1/시간을 입증했다고 설명하지 않는다. 합성 시계열의 시간 의존성과 현장 분포에 대한 보장도 아니다.

## 공정한 비교·감사

새 개발은10실행·6seed group·5120프레임·12사건, 새 시험은26실행·14seed group·23296프레임·36사건이다. fault/control만 의도적으로 같은 seed를 공유한다. 역할별 run/group/seed/nonce는 분리했고 이전 v10b 역할과도 겹치지 않는다.16개 paired prefix에서 첫 개입 전 관측이 같다.

고착 중 단발 bad는 fault/control 모두 동일한 대상·시각에 적용했다. 개발+시험 합계32개 강제 bad 지점을 확인했고, 자연113주기 bad도 유지했다. detector는 장부나 품질 스트레스 일정을 읽지 않고 현재 센서값·품질만 처리한다. 이는 고착과 불량 관측의 상호작용을 강화한 조건이며 현장 고장 분포를 대표하지 않는다.

69채널·단위·순서·config_id·유한값·bool·1초 시각·순번을 확인했다. 입력63채널 설정은 기준 파일과 완전히 같다. 시험의 eligible21632프레임 중 공통 수집 반복284프레임, 정상 nominal11648초 중 반복155초다. 반복과 겹친2사건도36건 분모에 남겼다. 정상 통지 분모에서 품질 반복 시간을 빼지 않았다.

보호498파일과 고정511파일의 해시가 유지됐다. 원본 stage5와 v8/v9/v10/v10b 코드·모델·산출물·이전 결과 문서를 보존했다. Timestral·Torch가 로드되지 않았음을 별도 CLI 실행에서 확인했다. 새3모듈 문장186/186=100%이며 branch coverage는 측정하지 않았다. 커버리지는 미검증 상황까지 정확하다는 보장이 아니다.

회귀는 새11개와 기존52개, 총63개 PASS다. 단발·반복·장기 결측, 공정 경보 근거 채널 불량, 관계없는 센서 불량, 공통 반복, reset, 정상 충격, 실제 회복 뒤 가까운 새 고착을 포함한다. 기존 v10b의 실패 재현 스크립트는 원본 보존을 위해 그대로 남으며, 수정 검사는 별도 v11을 대상으로 한다.

## 범위와 남은 한계

이 수정에서 명시한 통과 기준(중복0·배경 제외 탐지 저하 없음·첫 통지 지연 악화 없음·정상 통지 증가 없음)은 새 시험에서 모두 충족했다. 전체 경보의 정밀도·실제 고장 원인 진단·현장 일반화까지 완료한 것은 아니다.

정상 오통지2건과 비매칭 통지는 후속 분석 대상이다. A/B 동역학·작성자·측정 의미·고장 종류를 공유한다. 누설은 EQ1, 고착은 정확한 반복값을 쓰는 조건이다. noisy stuck·부분 고착·저분해능·실측 자료·장기 네트워크 단절·재시작 후 동일 에피소드 유지·Pi 자원 및 끝단 지연은 미검증이다. reset은 새 에피소드로 처리하는 기존 규칙을 유지했다.

p95는 탐지 성공 사건의 개입 시각 기준 합성 시간이며 실제 처리·대기·통신·PDA 화면 시간을 포함하지 않는다. Pi 배포와 운영 경보 연결은 수행하지 않았다.
