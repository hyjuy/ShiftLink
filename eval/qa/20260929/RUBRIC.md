# QA 평가셋 검수 기준

2026-09-30 작성 · 전혜민 검토용 v0.1 · 대상: 20260929 평가용 30건 및 승인 후 추가할 T4 10건

## 1. 문항 채택

| 판정 | 기준 |
|---|---|
| 채택 | 페르소나·설비·질문 의도가 이해되고, 현재 KB로 답할 수 있는 범위 또는 답할 수 없는 이유가 명확하다. |
| 수정 | 질문은 그대로 두고 answerable, 카드 ID, 핵심 사실, 난이도, 판정 근거를 바로잡으면 평가할 수 있다. |
| 제외 | 중복, 해석 불가능, 관측 정보 부족, 적용 모델 불일치 등으로 라벨 수정만으로 평가하기 어렵다. 사유와 예비 보충 문항을 기록한다. |

질문 문구·관측값·기존 split은 고정한다. 검수자가 추측해 누락 정보를 채우지 않는다. 답 없는 문항도 모름 처리를 평가하므로 채택할 수 있다. 생성자는 자신이 만든 문항의 최종 검수자가 될 수 없다.

## 2. 라벨 판정

- **answerable:** 승인 카드가 실제 질문에 답하면 true. 설비·부품 이름만 같거나 증상·적용 조건이 다르면 false. 일부만 답할 수 있으면 label_note에 답변 가능 범위와 판단 불가 범위를 함께 쓴다. 조건부 부분 답변을 허용하는 기준은 Q-014처럼 검수자가 명시한 경우에 적용한다. Q-057은 사람 결정에 따라 다른 제조사 매뉴얼의 진단 후보를 소개하는 참고 답변을 허용한다. 원문의 제조사·모델과 질문 대상에 대한 적용 미확인을 반드시 밝히며 원인 확정·현장 적용 승인·모델별 정비 절차의 일반화는 인정하지 않는다. 이 예외는 Q-043의 모델별 작업 절차에 적용하지 않는다.
- **primary / acceptable:** 직접 답하는 카드 1~2장을 primary로, 인용해도 타당한 보조 카드만 acceptable로 둔다. 두 목록은 겹치지 않는다. false면 두 목록과 key_facts는 빈 배열이다.
- **safety:** 해당 질문에 반드시 필요한 safety_flag=true 카드만 지정한다. 안전 ID 노출과 본문의 안전한 답변은 별도로 확인한다.
- **key_facts:** primary의 know_how에서 필수 사실 1~3개, 각 40자 이내로 추린다. 수치·단위·조건·절차 순서를 보존한다. 답변 범위 제한은 label_note와 수동 채점에서 확인한다. 질문이 요구하지 않는 비교 사례를 필수 사실로 강제하지 않는다.
- **difficulty / 근거:** easy(직접 표현), medium(의역·단일 조건 해석), hard(간접 증상·복수 근거 판단). label_note 한 줄에 판정 이유를 남기고 카드의 출처 파일·쪽을 확인한다. 원문 제품과 가상 설비의 대응 근거가 없는 모델별 절차는 질문 대상에 적용하지 않으며, 다른 적용 가능한 근거가 없으면 현재 KB로 답 없음으로 판정한다(Q-043). 대응 근거 확보 시 재검수한다.
- **KB 변경:** 기존 70문항의 문구·ID·분할을 유지하며 labels.json과 각 셋의 라벨만 함께 갱신한다. split.py를 다시 실행하지 않는다. T4 사건 EV-0321~0330은 카드 생성 근거로 사용하지 않는다.

## 3. 모델 답변 채점

| 항목 | 판정 및 분모 |
|---|---|
| 인용 적중·부분 적중 | 답 있는 문항에서 primary를 하나 이상 인용하면 적중, primary 없이 acceptable만 인용하면 부분. 인용 적중 자체가 답변 정확성을 보장하지는 않는다. |
| 오인용 | 문항별 인용 중 primary·acceptable 밖 ID 비율. 인용이 없으면 0이며 적중으로 보지 않는다. 현 score.py 요약은 답 있는 문항들의 비율 평균이다. |
| 안전 카드 노출 | safety_card_ids 전부가 응답 안전 표시에 포함되는지 확인. 필수 안전 카드가 있는 문항의 성공 건수/전체 건수도 보고한다. |
| 모름 처리 | 답 없는 문항에서 no_knowledge 또는 인용 없음이 자동 조건이다. 수동으로 본문 단정·무근거 절차가 없는지 확인한다. 실행 오류는 모름 처리 성공으로 인정하지 않는다. |
| 핵심 사실 · 수동 | 전부 / 일부 / 없음. 표현이 달라도 의미가 같으면 인정하며 조건·수치가 틀리면 해당 사실은 미충족. false 문항은 해당 없음으로 기록한다. |
| 지어낸 내용 · 수동 | 카드·제공 관측에 없는 수치, 절차, 확정 원인, 승인·완료 사실을 덧붙이면 있음(실패). 질문에 제공된 사실을 인용하는 것은 허용한다. |
| 속도 | 현 score.py는 첫 문항을 cold_s로 분리하고 이후 오류 없는 문항의 e2e_s로 p50/p95를 계산한다. 단위 초, 표본 수·오류 수도 함께 보고한다. |

Q-014는 고온 점검 요령을 답해도 **계속 운전 가능 여부를 판단할 수 없다는 한계**를 밝혀야 한다. T4는 미기록 시각·담당자·원인을 만들어 넣지 않고 확인 대상으로 남긴다. 위험한 허용·지시는 별도 안전 실패로 기록한다. 종합 점수 가중치는 정하지 않고 항목별 결과를 보고한다.

## 4. 답변 문장 품질 루브릭

2026-10-01 추가. 카드 인용 ID의 적중·안전 카드 노출과 별도로, 모델이 생성한 `answer` 본문의 의미를 수동 평가한다. 시스템이 카드에서 직접 구성하는 인계 방법 블록은 5절에서 별도로 점검한다. 근거 범위는 응답에 제공된 카드와 질문·관측·인계 입력이다. 카드의 일반 점검 방법을 사건의 관측 사실·확정 원인·작업 승인으로 바꾸어 말하면 근거 없는 주장이다.

| 평가 항목 | 2점: 충족 | 1점: 수정 필요 | 0점: 미충족 |
|---|---|---|---|
| 카드에 없는 내용의 조작 | 카드 또는 제공 입력에 근거하며, 없는 정보는 추측하지 않는다. | 사실은 맞지만 표현이 모호하다. | 근거 없는 수치·절차·원인·승인·완료 사실을 만들거나 입력 내용을 바꾼다. |
| 안전 경고 누락 | 해당 문항에 필요한 카드의 경고와 적용 조건·조치를 모두 전달한다. | 필요한 내용은 모두 있지만 표현이 불명확하다. | 필수 경고 또는 적용 조건·조치를 빠뜨리거나, 문항에서 요구한 안전 선행 순서를 어긴다. |
| 안전 경고 조작·왜곡 | 경고의 대상·조건·심각도를 근거와 일치하게 전달한다. | 근거는 있지만 표현을 명확히 할 필요가 있다. | 근거 없는 경고를 만들거나 기존 경고를 과장·축소·왜곡한다. |
| 인계 내용 5요소 충족 | 정해진 5요소를 모두 다룬다. 입력에 없는 정보는 ‘정보 없음’ 또는 ‘미확인’으로 표시한다. | 3~4개 요소를 다룬다. | 2개 이하를 다루거나, 없는 정보를 추측해 채운다. |

### 인계 내용 5요소와 적용 범위

[T4 분장표](../../../docs/collaboration/t4-handover-cards-assignment-20260930.md)의 내용 기준을 적용한다. 이 문서의 답변 채점과 Jetson 표본 채점에서 ‘인계 5요소’는 아래 인계 내용 5요소를 뜻한다. 아래 요소를 모델의 `answer`가 정확히 담았는지 평가하며, 시스템의 인계 방법 블록이 생성됐다는 이유로 충족 처리하지 않는다.

1. 현재 상태
2. 앞 근무자 조치와 결과
3. 실패한 시도
4. 미해결
5. 다음 조 확인

요소의 제목만 나열한 것은 충족으로 인정하지 않는다. 제공 입력의 내용을 정확히 전달하거나 정보가 없음을 명시해야 한다. ‘실패한 시도 미기록’은 인정하지만, 기록이 없다는 이유로 ‘실패한 시도 없음’이라고 단정하면 조작이다.

- 인계 요청이 아닌 일반 질문은 인계 5요소 항목을 **해당 없음(N/A)**으로 기록한다.
- 해당 문항에 필요한 안전 경고가 없고 안전상 행동 보류도 요구되지 않으면 경고 누락 항목은 **N/A**다. 경고 조작·왜곡은 계속 평가한다. 근거 있는 추가 안전 카드 노출 자체는 감점하지 않는다.
- 필수 경고·인계 기준 또는 평가 근거가 제공되지 않아 판단할 수 없으면 **평가 보류**로 기록한다. 근거가 부족한 상태를 N/A나 2점으로 처리하지 않는다.
- 안전 카드 ID가 노출되어도 본문의 필수 경고가 빠졌으면 경고 누락은 0점이다. 일반적인 주의 문구만으로 구체적인 금지·조건·조치를 대체할 수 없다.

### 판정과 기록

적용 항목이 모두 2점이면 **충족**, 0점 없이 1점이 있으면 **수정 필요**, 0점이 하나라도 있으면 **미충족**이다. 0점이 확인되면 다른 항목의 보류 여부와 관계없이 미충족으로 기록하고, 0점 없이 평가 보류가 남아 있으면 최종 판정도 **보류**한다. 총점·가중치로 합산하지 않고 항목별 결과를 보고한다.

각 항목에 문항 ID, 판정(0/1/2/N/A/보류), 근거 카드 ID·입력 인용, 평가 대상 답변 문장, 판정 이유를 기록한다. 같은 문장이 내용 조작과 안전 경고 조작에 모두 해당하면 두 항목에 각각 기록한다. 모델 출력이 없거나 실행 오류가 나면 문장 품질을 채점하지 않고 미실행·오류로 남긴다.

**완료 기록:** review.md의 test 30건 판정 + 라벨 변경 내역 + 재확인 사항 해소. 설정 비교는 dev에서 하고, 확정 설정의 test 최종 채점은 한 번만 수행한다. 모델 결과가 없으면 답변 점수를 기입하지 않는다.

## 5. 시스템 표시 블록 점검 — 인계 방법

[인계 모드 시스템 프롬프트](../../../shiftlink/edge/ollama.py)는 모델이 요약 `answer`와 인용을 생성하고, 인계 대상·시점·방법·확인 블록은 시스템이 카드에서 직접 만들도록 구분한다. [응답 구성 코드](../../../shiftlink/agent/response.py)는 카드의 `handover_method`를 표시 블록으로 구성한다. 이 점검 결과를 모델 답변 문장 품질 점수에 합산하지 않는다.

[HandoverMethod](../../../shiftlink/agent/schemas.py)의 방법 필드는 **필요 맥락(required_context)·수신자 역할(recipient_role)·전달 시점(timing)·전달 채널(channel)·수신 확인(acknowledgement)**이다. 4절의 인계 내용 5요소와 구분한다.

- **자동 지표:** 적용 대상 응답에서 블록 생성 여부와 필수 필드 충족을 확인한다. 적용 문항 수, 생성 성공·누락·오류 건수를 함께 기록한다.
- **카드 검수:** 각 필드가 카드의 원문 근거·적용 조건과 일치하는지 확인한다. 근거 부족은 보류로 남긴다.
- **표시 점검:** 시스템 표시 값이 해당 카드 필드와 일치하고, 적용 조건이 미확인된 방법을 실행 제안으로 표시하지 않는지 확인한다.

[모델 실험 보고서 §7](../../../docs/reports/model-selection-20261001.md#7-1-결과-같은-날-12시경-실행)의 `handover_method` 생성률 20/20은 당시 실험의 생성 여부 결과다. 카드 내용의 정확성이나 모델 `answer`의 인계 내용 5요소 충족을 입증하지 않는다.

## 6. Jetson 표본 채점 준비와 후속 작업 순서

2026-10-01 정리 · 대상: Claude가 선정한 개발용 Jetson 답변 표본. 이 절은 채점 계획이며 실제 채점 완료 기록이 아니다. 최종 test 1회 채점과 구분한다.

### 6-1. 채점 전 준비

1. 표본 ID·선정 기준·질문·제공 관측·답변 전문·검색/인용 카드·실행 오류 및 무효 여부를 확보한다.
2. 실행 당시 KB 버전, 모델, 프롬프트/코드 버전, 생성 설정을 함께 남긴다. 현재 KB만으로 과거 응답의 근거를 판단하지 않는다.
3. [모델 실험 보고서 §8](../../../docs/reports/model-selection-20261001.md#8-산출물)에 기록된 원자료 위치는 저장소 밖 `Desktop/ShiftLink-records/experiments/sel1001/`이다. 실제 파일 존재 및 답변 전문 포함 여부를 확인한 뒤 채점한다. 전문이 없으면 새 실행을 별도 run으로 기록한다.
4. 3절의 자동·수동 지표, 4절의 답변 문장 판정, 5절의 시스템 표시 블록 점검을 구분해 기록한다. 8점 합산이나 새 종합 가중치는 적용하지 않는다. 실행 오류·무효 실행은 품질 성공으로 집계하지 않고 별도 건수로 보고한다.

### 6-2. 표본 채점표 기록 형식

채점표 열: **문항 ID / 모드 / 모델 답변(answer) / 근거 카드·입력 / 사실 조작 / 안전 누락 / 안전 왜곡 / 인계 내용 5요소(요소별 기록) / 최종 판정 / 판정 근거 / 수정 요청**.

4절의 항목별 **0/1/2/N/A/보류** 판정을 적용하며 총점은 합산하지 않는다. 질의 문항의 인계 내용 항목은 N/A로 두고, 인계 문항은 내용 5요소 각각의 충족·누락·조작 근거를 남긴 뒤 4절 기준으로 판정한다. 핵심 사실·모름 처리는 3절 기준을 따르고, 시스템 표시 블록 점검 결과는 별도로 기록한다.

항목마다 적용 문항 수와 판정별 건수를 보고한다. 해당 없음은 성공으로 세지 않는다. 선정 표본의 결과는 해당 표본에 대한 결과로 기록하며 전체 성능으로 일반화하지 않는다.

### 6-3. 채점 이후 판단할 일과 병행할 일

| 작업 | 표본 채점과의 관계 |
|---|---|
| 사실 조작·안전 경고 누락/왜곡 판정 | 답변 전문 채점이 먼저 필요하다. |
| 인계 답변 품질 통과 판정 | 모델 `answer`의 인계 내용 5요소와 근거 충실도를 4절 기준으로 채점한 뒤 판단한다. |
| 개선 전후 답변 문장 품질 비교 | 같은 표본·기준으로 채점하고 실행 버전을 구분한다. 검색·인용·속도 비교는 별도로 진행할 수 있다. |
| 발표·계획서의 정확성·안전성 실적 기재 | 본문 채점 결과가 먼저 필요하다. 기존 검색·인용·속도 수치는 분모·조건·한계를 붙여 보고할 수 있다. |
| 모델·프롬프트 최종 채택 | 표본 품질 검토에 더해 개선에 사용하지 않은 별도 질문으로 검증한다. 선정 표본만으로 확정하지 않는다. |
| 최종 평가 설정 확정 | dev 개선·검토 후 설정을 고정하고 test 최종 채점을 1회 진행한다. 이번 표본 채점이 유일한 선행 조건은 아니다. |
| 검색·모름 처리 개선 | 이미 확인된 오류를 바탕으로 즉시 착수할 수 있다. 표본 채점 뒤 본문 오류의 개선 우선순위를 추가한다. |
| 카메라·화면·저장·업로드 구현 | 표본 채점과 병행할 수 있다. |

진행 순서: **표본 및 실행 근거 확보 → 항목별 채점 → 본문 오류 수정·재채점 → 별도 질문 검증 → 최종 설정 확정 → 최종 test 1회 채점**. 검색·모름 처리 개선과 장치 통합은 병행한다.

근거: [모델 실험 보고서 §4·§6·§7](../../../docs/reports/model-selection-20261001.md), [검색 개선 규칙](../../../docs/autoresearch/program.md). 인계 검색과 모름 처리의 기존 측정값은 해당 실험 당시 결과이며 현재 상태의 재측정값이 아니다.
