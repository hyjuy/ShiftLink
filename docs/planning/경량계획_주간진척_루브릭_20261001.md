# 경량 계획 주간 진척 루브릭

기준 문서: [`개발계획_경량_20260929.md`](개발계획_경량_20260929.md) 5절(주차별 끝)·6절(10/16 완료 판정).  
쓰는 법: 매주 금요일에 항목마다 0·1·2를 적고, 2점에는 증거 경로를 한 줄 붙인다. 증거가 없으면 2점을 주지 않는다.

이전에 말한 약 45%는 이 표로 계산한 값이 아니다. 그 숫자는 주차를 40·35·25로 어림한 판단이다. 앞으로의 진척률은 아래 식만 쓴다.

## 점수

각 항목은 0, 1, 2만 준다.

| 점수 | 뜻 |
|---|---|
| 0 | 끝 문장을 만족하는 결과도, 그 결과로 가는 실행 가능한 코드·데이터도 없다 |
| 1 | 코드·데이터·초안은 있으나, 그 항목의 끝 문장을 만족하는 실행 증거가 없다 |
| 2 | 끝 문장을 만족하는 실행 증거가 있다. 경로·명령·화면·수치 중 하나를 적는다 |

한 주의 진척률 = 그 주 항목 점수 합 ÷ (항목 수 × 2).  
전체 진척률 = (1주차 + 2주차 + 3주차) ÷ 3.

주는 서로 같은 비중이다. 항목 수가 달라도 주 점수를 먼저 비율로 바꾸므로, 항목이 많은 주가 전체를 끌어올리지 않는다.

6절 완료 판정 7개는 전체 진척률에 더하지 않는다. 개발 완료는 전체 진척률이 아니라, 그 7개가 모두 2점일 때만 말한다. 1·2주차가 100%여도 게이트가 비어 있으면 완료가 아니다.

## 1주차 (9/29~10/2) — 끝까지 한 번 이어 붙이기

| ID | 끝 | 2점 증거 | 1점 |
|---|---|---|---|
| W1-1 | 질의 1건이 카드 근거로 답한다 | 질의 1건의 질문, 설비, 인용 카드 ID, 답 문장이 남음 | 파이프라인은 연결됐으나 그 실행 기록이 없음 |
| W1-2 | KB 카드 30장 이상 accepted | `kb_cards.json`에 accepted·kb·L1이 30장 이상 | 30장 이상이 draft이거나 통합 목록 밖에 있음 |
| W1-3 | 사진이 클래스명으로 나온다 (PC여도 됨) | 클래스 6개 중 사진 1장 이상이 클래스명으로 출력된 기록. 장수·정확도는 2주차 | 학습 코드만 있고 사진→클래스명 출력이 없음 |
| W1-4 | DB 접속이 확인된다 | `.env`로 Aiven 접속이 된 기록. 비밀값은 적지 않음 | 스키마만 있고 접속 확인이 없음 |
| W1-5 | 평가셋 파일 1개 | 개발용과 분리된 평가셋 파일이 있음 | 문항은 있으나 개발용과 분리되지 않음 |

## 2주차 (10/5~10/8) — 연결과 인계 저장

| ID | 끝 | 2점 증거 | 1점 |

| W2-5 | 1차 결과의 실패 목록이 있다 | 실패 문항 ID와 이유가 있는 목록 | 점수만 있고 실패 목록이 없음 |

| W3-6 | README와 실행 가이드로 다시 돌릴 수 있다 | 장비 주소, 모델, 시작·종료 명령이 저장소에 있음. 비밀값 없음 | 일부 명령만 있음 |

## 완료 게이트 (10/16, 진척률에 더하지 않음)

모두 2점일 때만 개발 완료다.

| ID | 끝 | 2점 |
|---|---|---|
| G1 | 카메라 클래스명이 Jetson에 들어가 그 설비 기준으로 답한다 (10/7 결정: 카메라 = Unity 작업자 시점 PDA 영상, 웹캠은 얼굴 로그인 전용) | W2-1과 같은 종류의 증거. 화면이 Jetson 답이다 |
| G2 | 답에 근거 카드 ID가 있고, 해당 안전 카드가 맨 앞에 나온다 | 안전 카드가 있는 질의 1건의 화면 또는 로그 |
| G3 | 인계가 로컬에 있고 재시작 후에도 남는다 | 저장, 프로세스 재시작, 같은 인계가 다시 보임 |
| G4 | 인계가 클라우드에 있고, 끊김 복구 후에도 누락·중복이 없다 | W2-4와 W3-3이 모두 2점 |
| G5 | CNN 6클래스 정확도를 발표 자료에 넣을 수 있다 | W3-2가 2점 |
| G6 | 평가셋 30건 점수와 p95를 발표 자료에 넣을 수 있다 | W3-4와 W3-1이 모두 2점 |
| G7 | 데모 영상이 있다 | W3-5의 본 영상 |
