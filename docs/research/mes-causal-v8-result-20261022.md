# 인과 합성 MES v8 — 재학습과 최초 미사용 시험 결과

판정: 새 자료 생성·정상 추가학습·고정 후 네 시험군 비교는 완료했다. 현재 후보는 정상 전용 자료에서도 통지가 많고 Timestral 추가 이득을 입증하지 못했다. 운영 통지·PDA 연결·Pi 배포는 보류한다. 원본 stage5, 이전 체크포인트와 55건 결과는 보존했다.

## 무엇을 변경했는가

사용자 요청을 [사전 실행 명세](mes-causal-v8-prereg-20261022.md)로 재작성했다. 기존 운영 MES를 바꾸지 않고, localhost의 별도 센서 MES를 실행하여 HTTP로 1초 간격 합성 프레임을 수집했다. 가속된 합성 시간이며 실제 장비 운전 시간이 아니다. A는 1차 관성 기반 상태식, B는 별도 2차 수요·비선형 저장/모터 상태식으로 구현했다. 두 생성기는 기존 탐지기의 PATTERNS·고장 목표값을 읽지 않는다. 새 채점기는 생성기 코드를 import하지 않고 개입 장부 시각을 사용한다.

공정 고장은 내부 상태에 개입해 압력·유량, 전류·진동·느린 온도, HPU 공급에서 RT 클램프까지의 지연 반응을 만든다. 센서 bias/stuck은 측정 출력 한 개만 바꾸고 공정 상태와 다른 측정에 전파하지 않는다. 이는 생성한 자료의 정성적 가정이며, 모델이 인과 그래프나 고장 종류를 학습했다는 뜻은 아니다. 40°C 조건화 점도 시료·수동 형상에 운전 온도 인과식을 강제하지 않았다.

자료 감사에서 최초 생성본의 연속 bool·지나치게 깨끗한 정상값, 두 번째 생성본의 계측 의미 오류를 교정했다. 초기 data/, data-v2/, 중단한 특징 추출 training/은 삭제하지 않았다. 최종은 data-v3/와 run-final/이다. 교정은 최종 학습·시험 결과를 보기 전에 끝냈다.

## 분할과 학습

총 44개 실행·15,616프레임이다. fit 8, selection 4, calibration 4, development 4, 시험 4군 각각 6개 실행을 분리했다. run·seed·nonce는 역할 간 중복이 없고 프레임을 무작위 분할하지 않았다. 1,077,504개 측정 위치나 중첩 창을 독립 표본 수로 세지 않는다. 시험은 총 60개 개입 사건이며 군마다 정상 전용 실행 1개와 고장 실행 5개(사건 15개)다.

69신호 계약 중 fit의 가동·최신·good 관측 비율로 63개를 선정했다. 30초 수동 관측 5개와 unavailable 이벤트 신호 1개를 제외했다. 기존 68입력 후보와 호환된다고 가정하지 않는다. 모든 비교법에 같은 채널·64프레임 준비·정지 후 재준비·품질 조건을 적용했다.

원본 공개 Timestral 체크포인트에서 backbone을 동결하고 예측 헤드 1,880,064개 파라미터를 5 epochs 학습했다. 정상 fit 창 256개, 정상 selection 창 128개를 사용해 epoch 5를 선택했다. selection loss는 0.168879817 → 0.167828329 (0.623% 감소)다. 이는 고장 탐지율 개선의 증거가 아니다. 테스트 자료를 읽어 모델을 고르지 않았다.

새 model.safetensors SHA-256: `3c98f0352b76158b629e1549385e9cde6592e8216999c97957a65ff43b7e2752`. 정상 calibration 1,024개 창의 .995 분위수(최소 1)로 방법별 임계값을 고정했다. 고장 정답 기반 탐색 예산은 모두 0이다. 기존 결합·통지 정책은 과거 개발에서 선택된 값을 재사용하므로 역사적인 전체 개발 비용까지 동일한 비교는 아니다. Timestral 제거 대조는 결합 정책에서 모델 수치만 중립화한 것이다.

정상 오통지는 고장이 전혀 없는 실행의 공통 준비 이후 시간에서만 집계했다. 개입 후 잔류 반응·정상적인 하류 반응을 곧바로 현장 오경보로 세지 않았다. 전체 unmatched 통지와 표시 상태 지표는 evaluation/*-result.json에 별도로 남겼다. 정상 노출은 총 21분20초뿐이며 같은 시뮬레이션 가정에 묶여 있으므로 현장 오경보율을 추정하기에는 부족하다.

사건 구간의 같은 설비 통지 매칭은 그 개입이 통지를 유발했다는 인과적 귀속을 증명하지 않는다. 배경 통지가 많으면 우연한 일치도 탐지로 집계될 수 있다. 같은 seed의 무개입 대조를 모든 시험 실행에 붙여 네 방법을 끝까지 재추론하는 시험은 수행하지 않았다. 단일 센서 비전파·공정 지연의 반사실 검사는 생성기 단위 검증이며 탐지기의 인과 귀속 검증을 대체하지 않는다.

원본 55건의 p95는 관측 가능 onset 기준이고 이번 p95는 개입 시각 기준이다. 자료·입력·채점 기준이 다르므로 이전 6초와 이번 수치로 전후 개선량을 계산하지 않는다. 추론 대기·통신·화면 표시를 포함한 끝단 p95도 아니다.

같은 .995 정상 보정 예산이 결합 정책까지 포함한 최종 오통지율의 동등성을 보장하지 않는다. 탐지 수만으로 방법의 절대 우열을 선언하지 않는다. 제거 대조의 탐지 증가와 오통지 변화는 함께 봐야 하며, 동일 오통지율에서의 우위는 이번 고정 단일 운전점 시험으로 입증하지 않았다. 원본 미학습 Timestral을 같은 새 시험에 적용한 대조는 없으므로 추가학습 자체의 고장 탐지 효과도 분리해 주장하지 않는다.

## 검증·보존

새 단위/HTTP 검사와 기존 guarded 회귀 26개, 추가 품질·준비 경계 검사 3개를 통과했다. 단위+추가 경계+실제 평가 E2E의 새 6개 모듈 문장 커버리지는 89.94%다. [TDD 기록](../testing/mes-causal-v8-20261022.tdd.md)에 실패·교정 체크포인트와 명령을 기록했다. 실제 정상 학습은 별도 완료 실행으로 확인했으며 커버리지를 위해 재학습하지 않았다.

고정 파일 38개와 원본·기존 결과 71개의 해시가 평가 후에도 동일하다. 전체 8개 역할에서 신호·단위·유한값·bool·config_id·1초 시각 연속·run/seed/nonce 분리와 데이터/장부 해시를 추가 감사했다. 후보 잠금 SHA-256은 `da1815db273751df00a78875b73ff72026a6749398dce5225113bc015805632a`다.

네 시험군의 저장 예측은 각각 1,844 × 63 × 3이며 비유한값·분위수 순서 역전은 모두 0개다. fit의 비상수 채널 사이에 완전 복제는 없었다. 상수 채널은 breaker_trip, gr_oil_leak 2개, unavailable인 rt_lift_delay로 별도 기록했다. 고착 센서는 결합 후보가 10건 중 1건만 매칭해 특히 취약했다.

새 프로세스의 체크포인트 로딩 후 정상 창 3개에서 공식 forecast와 특징 재구성을 비교했다. rtol=1e-5, atol=1e-5 기준 통과, 최대 절대 차이 0.00025177001953125다. 정확히 0이라고 주장하지 않는다.

## 해석과 남은 검증

데이터 분석 측면에서는 순환 검증 위험을 줄인 새 자료·계측 의미 감사·정상 학습·후보 고정·동역학/기전 분리 시험으로 기존 정책의 약점을 확인했다. 정상 예측 loss 감소가 탐지 개선을 뜻하지 않으며 현재 후보의 운영 적합성은 입증되지 않았다.

A/B는 코드·식은 다르지만 카탈로그·정성적 인과 가정·작성자를 공유한다. 외부 독립 검증, 보정된 물리 시뮬레이터, 실제 장비 일반화는 아니다. 미사용 기전도 작성자·단위 테스트까지 블라인드였다는 뜻이 아니다. 미모델링 채널은 독립 관측 잡음을 사용하며 전체 69신호의 물리를 구현하지 않았다. 정상 충격 잡음 빈도·고장 강도는 현장 추정치가 아니다.

군마다 사건 15개·정상 실행 1개로 표본이 작고 모든 설비·기전을 균등하게 지원하지 않는다. 사건 시작은 고정 시각(95/165/240 또는 95/100/240)이고 품질 저하 일정도 공유한다. 새 시험의 5초 간격 사건은 서로 다른 원인 설비를 사용한다. 같은 설비에서 가까운 새 고장 첫 통지는 기존 guarded 회귀에서 검증하며, 이번 60건 전체가 그 조건을 검증한 것은 아니다.

이 네 시험군은 이제 사용된 평가셋이다. 다음 개선은 정상 통지 예산과 단순 대조를 먼저 정한 새 개발 버전에서 진행하고, 현재 시험군을 다시 미사용이라고 부르지 않아야 한다. Timestral의 필요성도 다시 검토해야 한다. 이후 실측 정상·고장 자료 또는 외부 작성 생성기로 검증하고, Pi 실기 부하·끝단 지연을 확인한 뒤에만 운영 연결 여부를 판단한다. 이번 작업에서는 Pi 설치·서비스 변경·실제 사용자 경보 활성화를 수행하지 않았다.
