# 배치 C 독립 검토 기준

검토자: 생성자와 다른 Codex 서브에이전트. 기준일: 2026-09-30.
`eval/`은 읽지 않는다. 생성된 카드·KB 기록·가이드·현재 스키마·MES 신호사전·로컬 PDF 실제 페이지를 대조한다.

## 판정 규칙

| 검사 | 통과 근거 | 수정 또는 보류 근거 |
| --- | --- | --- |
| 구성 | T2 10장(HPU 3/CV 3/RT 2/GR 2), T6 9장(정비 4/비정상 3/정상 2) | 누락, ID 충돌, 유형만 바꾼 동일 카드 |
| 출처 일치 | 원문 파일 존재, PDF 실제 1기준 페이지·절·버전과 주장 직접 일치 | 원문 없는 조치·원인·숫자, 인쇄/PDF 페이지 혼동, 문서명 오류 |
| T2 분기 | 조건에 따라 확인 방향이나 조치가 달라지고 본문에 대안 분기가 있음 | 조건은 적용 범위일 뿐이고 조치는 동일, 상태만으로 원인 확정 |
| MES | 단일 설비에 실제 존재하는 `*_state`, `unit=null`, 상태는 검색 후보 분류 | 다른 설비 신호 AND 결합, 숫자를 제조사 기준으로 취급, quality 누락을 정상으로 처리 |
| RT | 반송·클램프 범위, 원문 구조와 가상 구조 미확정 표시 | 코일카 시저 리프트/RT-02 승강 동일성 가정, 승강 복구 처방 확정 |
| 중복 | K-1007 점도 2000 cSt 및 K-1029 옥외·수분 기준과 구별 | 기존 점도·수분 카드의 단순 재표현 |
| T6 반복 | KB 15개 기록 중 카드별 같은 요령/실패를 지지하는 서로 다른 사건 최소 2개 | dev 사건 인용, 사건 ID만 2개이고 동일 주장을 실제로 지지하지 않음 |
| 실패 기록 | attempt action/result와 출처 사건 일치, 같은 restart_type 또는 unknown | 기록 없는 실패 이유 창작, failure_reason null일 때 not_recorded 누락 |
| 합성 한계 | 합성 기록임을 명시, 근거의 범위를 생성된 사례로 제한 | 현장 관찰이나 인과 검증으로 표현, 합성을 실증 정확도 근거로 표현 |
| 안전 | 매뉴얼 작업 전제·보호장치 유지, 재기동 허가와 출처 한계 명시 | 인터록 우회·반복 리셋·접근/정비를 검색 상태만으로 허용 |
| 추적성 | seed/slot, 고정 prompt sha256, 사건/아티팩트 연결, 수정 전후 별도 기록 | 프롬프트 해시 재작성, 검토로 accepted/L1 승격 |
| 보류 상태 | draft/L0/confidence=0.0, 사람 검토 필요 | 기계 검토를 사람 승인으로 표현 |

## 알려진 적용 제한

- `rt_motor_current`는 RT-03(EQ-0008)에만 있고 `rt_lift_delay`는 RT-02(EQ-0007)에만 있다. 한 설치 위치에서 두 상태를 AND로 묶을 수 없다.
- `cv_speed`의 low는 정상 정지에서도 발생한다. 운전 상태 확인을 전제로 하며 이 신호 단독으로 고장을 판단하지 않는다.
- MES 정상 범위는 제조사 임계값과 무관하다. 유온 low로 점도 2000 cSt 초과를 추론하지 않는다.
- 작업가이드의 예시 방향은 확정 조치가 아니다. 원문 부족 슬롯은 이유와 잔여 제한을 명시하거나 근거 있는 반송·클램프 범위의 슬롯으로 수정한다.

## 산출물

1. `review_round1.md`: 카드별 원문 실제 페이지, 일치 여부, 판정근거, 수정 필요 항목.
2. 생성 종료 확인 후 독립 검토자가 카드와 필요한 근거 연결을 수정한다. 생성 프롬프트/해시는 보존한다.
3. `review_round2.md`: 수정 전후, 재검토 결과, 남은 적용 제한. 필요하면 `review_changes.json`으로 변경 전후 필드와 근거를 기록한다.
4. 최종 검증은 KnowledgeCard 스키마, 개수·분포, provenance 원문/사건 연결, KB/dev 인용 분리, prompt 해시, 최소 관련 검증 명령으로 수행한다.
