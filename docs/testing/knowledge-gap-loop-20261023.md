# 원질문에서 근무일지 지식카드 재사용 검증 (2026-10-23)

## 구현

PDA의 기존 근무일지 작성 버튼은 질문 ID·발생시각을 가진 구조화 입력 기록을 열며 조치·관찰 결과는 빈 상태로 작업자가 작성한다. 같은 질문에서 반복해서 열어도 기존 기록을 덮어쓰거나 복제하지 않는다.

구조화 근무일지 후보가 이미 검증된 `query_id`의 원질문·출처를 보존한다. 관리자 화면에서 연결된 질문과 현장 조치를 함께 검토한다. 승인 → 검수 통과 → 임베딩 게시 후 기존 조건·judge를 거쳐 답변한다. 검토 승인만으로 게시하지 않고, 동일 질문이라는 이유로 답변을 캐시하거나 판정을 우회하지 않는다.

서버는 최종 잠금에서 게시 ticket·내용 해시를 확인하고 실제 인용한 현장 카드만 `cited_cards`로 반환·저장한다. PDA는 이 답변의 인용 ID·설비에 맞는 카드 원문을 표시한다. 초기 정적 카드 목록, 센서값 및 AI 알림 처리는 유지한다. 원래 일지·후보 원문·이전 답변을 갱신하지 않는다.

Pi에 누락된 기존 검토 HTML/JS의 게시 상태 기능을 맞춘다. 공통 `/static/style.css` 경로를 PDA 프록시의 정적 허용 목록에 추가하고 기존 저장소의 스타일 파일을 제공한다. 새 디자인·CSS 작성은 포함하지 않는다.

## 로컬 검증

- PDA 질문→일지 시작 경로: 실제 Pi에서 기존 버튼이 질문 ID와 구조화 입력을 누락함을 재현했다. 새 브라우저 회귀는 빈 조치·미확인 정상 운전 상태, 질문 ID, 중복 방지를 검사한다. 로컬 실제 Chrome 4개 검사 통과.
- 원질문 연결 누락: 동일 질문 회귀 2개가 `query_id` 누락으로 실패한 뒤 수정 후 통과.
- 동적 카드 표시 누락: `cited_cards` 부재로 Python 2개와 PDA CJS가 실패한 뒤 수정 후 통과.
- Pi 공통 스타일: HTTP 404 회귀를 확인하고 수정 후 통과.
- 게시·이력·현재 판단·근무일지 회귀 1,460개 통과. 실제 로컬 Chrome HTTP 검토 포함. 이 그룹의 검색 임베딩·judge·답변은 fixture다.
- 최종 PDA 프록시·Unity 카메라·AI 분석 서비스·동일 질문 검사 33개 통과.
- PDA sensor display, network boot, Unity link, symptom rank, query 계약 CJS 통과. 확장 CJS 수집은 27개 통과했으나 main에서도 같은 오류인 3개(옛 문구 기대 2개·필수 발생시각 누락 fixture 1개)와 Node Playwright 모듈 누락 4개는 미통과로 남겼다. 별도 이름의 Node 브라우저 파일도 이 환경의 모듈 누락으로 실행하지 못했다. 해당 항목을 통과로 계산하거나 무관한 UI/테스트를 수정하지 않았다. 실제 Chrome/Pi Chromium 검증은 Python Playwright로 별도 수행했다. 게시 무결성 검사 `ok: true` (문법·메타데이터이며 의미 정확도 점수가 아님).

## 실제 장비 격리 검증

Jetson `/tmp/shiftlink-knowledge-gap-20261023`는 운영 패키지의 기기 내부 복사본에 수정 파일만 적용했다. 운영의 온톨로지 query/publication/S30h 코드는 유지한다. 별도 SQLite·별도 계정을 만들고 초기 검색 view는 빈 카드·청크로 구성했다. 기존 모델을 사용했으며 다운로드하지 않았다. 운영 DB와 인덱스에 검증 카드를 쓰지 않았다.

Pi는 운영 PDA HTML·CSS를 복사한 별도 8083 프록시와 별도 Chromium 프로필을 사용했다. 실제 Pi Chromium을 SSH CDP로 제어해 관리자 검토와 PDA 로그인·설비 선택·질문 입력·근거 펼치기를 확인했다.

질문: `압력 표시가 요동칠 때 어떤 순서로 점검하나요?`

1. 처음에는 `no_applicable_card`, 인용 없음.
2. 질문 ID를 가진 구조화 근무일지 저장. 검토 전과 승인만 된 상태에서는 여전히 인용 없음.
3. 검수 후 실제 embeddinggemma 768차원으로 게시.
4. 같은 문자열 질문에서 실제 EXAONE judge 확률 0.9211·0.9914, `confident` 경로, `K-7001` 인용 답변. 실제 ck176 답변에 필터 오염 확인 → 교체 → 압력 요동 해소 확인이 반영됨.
5. 보완 요청 후 검색 제외와 동일 질문의 근거 없음 확인.
6. 재검토·검수 후 Pi PDA에서 직접 같은 질문을 입력했다. 부팅 시 정적 목록에 없는 `K-7001`이 답변 근거 상세에 표시되고 원문 조치·결과를 확인했다.
7. 이전 답변의 근거 없음 상태, 원본 일지 질문 ID, 원본 draft 상태, 게시 accepted 상태 및 단계 원문 보존을 DB에서 대조했다.
8. 스타일 의존성 복구 후 검토 화면 1280·390 폭에서 가로 넘침·페이지 오류·HTTP 오류 없음.

첫 번째 별도 일지는 스트레이너 정비만 기록해 질문의 압력 요동 증상 근거가 부족했다. 게시·검색 후보까지는 연결됐지만 실제 judge 확률 0.0343·0.0011로 거부됐다. 이 자료를 실패 기록으로 보존하고 제외했으며, 증상과 조치 결과가 명시된 별도 사례의 성공과 구분한다. 전체 운영 정확도·검색 precision/recall 또는 모든 동일 질문의 답변을 보장하는 시험이 아니다.
