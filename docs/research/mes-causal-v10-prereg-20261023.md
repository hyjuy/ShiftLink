# v10 누설·정상 오통지 원인 수정 사전 명세

v9 누설 6건과 정상 통지 2건은 이미 본 원인 분석 자료다. 신규 성능 주장에 재사용하지 않는다. 원본·v8·v9 소스와 결과를 해시로 보존하고 새 v10 출력 경로만 쓴다. Pi·PDA·운영 MES·실사용자 경보는 변경하지 않는다.

## 원인과 수정 가설

EQ1의 EWMA 임계값 13.893731, TS 임계값 23.240467을 누설 6건은 한 번도 넘지 못했다. 정상 보정 hpu_pump_current의 tick139 순간값을 140~151에 복제한 acquisition hold가 EQ1 공통 문턱을 높였다. 정상 control 두 건의 tick146 통지도 진동 순간값의 같은 복제로 발생했다. 지속 시간만 줄여서는 해결하지 못한다.

채널별 signed 편차의 과거 중앙값→signed EWMA→절댓값→채널별 정상 quantile→설비 any 집계로 센서 간 보정 오염을 막는다. 새 정상 fit/calibration을 사용한다. normally variable 유효 채널 최소 4개 중 80% 이상이 직전값과 정확히 같으면 전체 수집 반복 상태로 기록한다. 이 구간은 새 공정 증거로 누적하지 않는다. 단일 센서의 낮은 plateau를 임의 삭제하지 않는다. 단일 고착 16프레임 경로는 유지한다. 측정 품질·시각이 계약상 불량이면 입력하지 않는다.

평가 생성 전 검토에서 hold 후 width9/flat16 이력 재구축 대기가 정상 회복으로 잘못 계산되어 같은 고장 재통지가 생기는 회귀를 확인했다. 최초 개발 실행을 명시 중지하고 완료된 checkpoint/자료/예측 구간을 보존했다. 재구축 대기 16개 새 관측 전에는 활성 통지 상태를 정상 회복으로 재무장하지 않는다. 이 동안 새 이상 증거에 따른 시작 자체는 막지 않는다. 개발 선택·후보 잠금·시험 생성 전 수정이다. 재개는 동일 입력·모델 해시의 예측 구간만 재사용하며 기존 파일을 덮어쓰지 않는다.

## 고정 비교·선택

모델 추가학습은 하지 않는다. v9 checkpoint(efc0e5839767c88a83f121f66b2c6b16260f867cef8992a1b6b2055ab3502351)를 고정한다. 이번 원인은 보정·수집 처리이며 재학습을 개선 원인으로 섞지 않는다.

동일 입력에서 full(강건 EWMA+TS+고착), no_timestral(강건 EWMA+고착), timestral(TS+고착), persistence(직전값 오차+고착), no_flat(강건 EWMA)를 비교한다. TS/직전값 오차도 같은 중앙값과 채널별 보정을 적용한다. 방법별 width 5/9 × q .98/.995 × patience 4/8의 8개 설정을 독립 선택한다. full에서 TS만 제거한 동일 설정 대조도 저장한다. frozen v9도 같은 자료로 비교한다.

추가 고정 대조 gate_only(새 정상 통계+global gate+기존 abs EWMA+설비 보정), gate_channel(같은 점수+채널 보정)은 no_timestral에서 고른 q/patience를 그대로 사용한다. 두 대조는 별도 탐색하지 않으며 새 정상 통계·NaN 초기화 등도 바뀌므로 각 차이를 특정 한 요소의 순수 인과 효과로 주장하지 않는다.

선택: 개발 정상 관측 오통지율 ≤1/line-hour 우선, 통과 후보 중 paired background 제외 매칭 최대, 중복 최소, 10초 내 배경 제외 매칭 최대, 단순 설정 순. 목표 실패 시 최저 정상 통지율 우선의 사전 fallback을 사용하고 실패로 표시한다. 누설 사건을 따로 가중하지 않는다.

## 신규 자료와 경계

기존 A/B 동역학과 69채널 관측 계약 유지, 입력은 정상 fit 가용성 기준 63채널. 새 seed 영역 1001000 이후, role/group/run/nonce disjoint; fault/control만 동일 seed와 정상 잡음을 의도적으로 공유한다.

- fit: A/B 각 4회 ×384초, 정상만.
- calibration: A/B 각 2회 ×384초, 정상만.
- development: A/B 각 3그룹 ×512초, index0 정상, 나머지 fault/control 쌍(12사건).
- test: A/B 각 7그룹 ×512초, index0 정상, 나머지 fault/control 쌍(36사건).

기존 friction/cooling_loss, leak/blockage, sensor_stuck 종류를 사용하되 새 실행으로 평가한다. 고장 시작 100/230/370 ±12초, 길이32~60초, 세기 .5~2.5. 공통 정상 acquisition hold는 시작140~180, 길이6~14초로 바꾼다. 동일한 RNG draw를 모든 역할에 적용해 fault/control의 hold는 동일하다. 고장 검출기에 이 시점·고장명·세기를 주입하지 않는다. A/B 모두 개발에서 사용하므로 새로운 동역학 독립 검증이라 부르지 않는다.

## 잠금·채점·판정

새 test를 생성하기 전에 소스·체크포인트·통계·임계값·선택결과·사전 명세·보호파일·개발 자료를 SHA-256 잠금한다. 시험 예측을 먼저 저장하고 그 뒤 장부를 열어 채점한다. 시험 결과로 설정을 고치지 않는다. 기존·새 평가를 섞어 98.2% 등의 전후 비교를 하지 않는다.

전체/종류별 매칭, paired background 제외 매칭, 중복, 정상 오통지 수/line-hour, 전체 사건 중10초 내 탐지율, 성공 건 조건부 injection p95를 보고한다. 전체 가동/64초 warmup 이후 정상 노출을 오통지 분모로 쓰고, hold 제외 시간·유효 시간도 별도 공개한다. hold에 겹친 고장도 전체 사건 분모에서 빼지 않는다. 정상0건이면 포아송 가정 단측95%상한 -ln(.05)/정상시간을 함께 표시하고 현장 보장이라 해석하지 않는다.

새 시험에서 누설·오통지가 개선되고 고착 회귀가 없는지 확인한다. TS 포함이 제거보다 실제 고장·오통지·지연 이득을 보일 때만 추가 효과를 인정한다. 동등하면 필요성 미입증으로 판정한다. 합성 A/B·작성자·고장 종류 공유, exact hold 및 exact stuck, 센서 분해능·noisy stuck·동시 고장·실측 일반화·장비 추론·끝단 지연은 한계다. 정상 관계 회귀 모델은 이번 최소 수정에 추가하지 않는다.
