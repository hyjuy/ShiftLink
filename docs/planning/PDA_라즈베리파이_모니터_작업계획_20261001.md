# PDA 단말 작업계획 — Jetson + 라즈베리파이 + 모니터 (2026-10-01)

> 상태: **로컬 초안 — 팀 공유 전.**
> 근거: [`개발계획_경량_20260929.md`](개발계획_경량_20260929.md) 1절 카메라 방식 **A안(라즈베리파이 분리) 채택**.
> 브라우저 QR 카메라 설계(`PDA_카메라_설비식별_고도화.md`, C-056·C-057)는 경량 계획 3절에서 폐기됨. 이 문서는 그 대체안의 구현 작업만 다룬다.

## 1. 구성

```
[USB 웹캠] → [라즈베리파이]
               ├ 카메라 프로세스: 프레임 → CNN 6클래스 → {class, conf}
               │      └ HTTP POST ──────────────┐
               └ 모니터: Chromium 키오스크 ──────┤  LAN
                                                ▼
                                    [Jetson (headless)]
                                     shiftlink.mes 서버 + 에이전트 + Ollama
                                     로컬 SQLite 인계 → (연결 시) Aiven 업로드
```

- 원본 이미지는 라즈베리파이 밖으로 나가지 않는다. Jetson으로는 **클래스명(`HPU`/`GR`/`RT`/`CV`/`CAU`/`PDP`)과 신뢰도만** 보낸다(경량 계획 1절).
- 모니터 화면은 Jetson이 서빙하는 PDA 웹 화면이다. 브라우저가 카메라를 쓰지 않으므로 HTTPS가 필요 없다.
- 통신은 **HTTP**로 한다. 서버가 이미 표준 라이브러리 `ThreadingHTTPServer`이므로 MQTT 브로커를 추가하지 않는다.
- Jetson은 GUI 없이 운영해 8GB 메모리를 LLM에 남긴다.

## 2. 작업 목록

### A. 하드웨어·OS

| # | 작업 | 끝 |
|---|---|---|
| A1 | 라즈베리파이 모델·메모리 확인(4/5, RAM), Raspberry Pi OS Desktop 64bit 설치 | 부팅·SSH 접속 |
| A2 | USB 웹캠·모니터 연결, `ls /dev/video*`, OpenCV로 프레임 캡처 | 사진 1장 저장 |
| A3 | Jetson `sudo systemctl set-default multi-user.target`(headless) | 재부팅 후 `tegrastats` 여유 메모리 기록 |
| A4 | 라즈베리파이 ↔ Jetson 같은 LAN, 고정 IP 또는 호스트명 | 서로 `ping` |

### B. 데이터·CNN (경량 계획 1주차 허재원 항목)

| # | 작업 | 끝 |
|---|---|---|
| B1 | 대체 객체 6종 결정(설비 1종당 박스 등 1개, `CAU`·`PDP` 추가분 포함) | 객체·클래스 대응표 |
| B2 | **라즈베리파이에 연결한 데모용 웹캠으로** 촬영. 클래스당 100장, 각도·거리·조명 변화 | `HPU/GR/RT/CV/CAU/PDP` 폴더 6개 |
| B3 | PC에서 사전학습 MobileNetV3-Small 전이학습 1차, 검증 정확도 기록 | 사진 → 클래스명 출력(PC) |
| B4 | ONNX로 내보내 라즈베리파이 `onnxruntime`에서 실행, 1프레임 분류 시간 측정 | 파이에서 클래스명 출력 |
| B5 | "배경/없음" 처리: 신뢰도 임계값(조정 가능 값으로 둠) 미만이면 전송 안 함, 연속 N프레임 같은 클래스일 때만 확정 | 손 흔들어도 오인식 전송 없음 |

> 촬영 원본 사진은 용량·저작권 문제가 없어도 저장소에 커밋하지 않는다. 학습된 모델 파일 보관 위치는 별도로 정한다.

### C. 서버 코드 (`shiftlink/mes/`)

| # | 작업 | 끝 |
|---|---|---|
| C1 | `__main__.py`에 `--host` 인자 추가(현재 `127.0.0.1` 고정이라 파이에서 접속 불가). Jetson에서는 `--host 0.0.0.0` | 파이에서 `curl http://<jetson>:8000/api/state` |
| C2 | `POST /api/equipment/scan` — 본문 `{class, conf, device_id, ts}`, 클래스명 → `eq_id` 매핑 | 파이 POST → 서버 기록 |
| C3 | `GET /api/equipment/scan/recent?limit=5` — 화면이 폴링해 최신 인식 결과 표시 | 화면에 인식 설비 표시 |
| C4 | `pda.html`·`pda.js`를 `shiftlink/mes/web/`으로 옮기고 정적 화이트리스트 등록, 데이터 fetch 경로 수정 | `http://<jetson>:8000/pda.html` 열림 |
| C5 | 에이전트 질의 API(`POST /api/query`) — `FixedPipeline` 호출. 현재 `runSearch()`는 로컬 순위+sleep 가짜 | 화면 질문 → Jetson LLM 답변 |
| C6 | PDA 화면 scan 단계 교체: 브라우저 카메라·QR 대신 "웹캠 앞에 객체를 놓으세요" + C3 폴링 결과 표시, 수동 선택은 유지 | 객체를 비추면 ctx 화면으로 넘어감 |

> C1~C3·C5에서 새로 생기는 엔드포인트·필드명은 같은 변경 안에서 `docs/collaboration/naming_registry/registry.md`에 등록한다. C5는 유현준(파이프라인 담당)과 맞춘다.

### D. 라즈베리파이 단말 코드

| # | 작업 | 끝 |
|---|---|---|
| D1 | 카메라 루프 스크립트: 캡처 → B4 모델 → B5 확정 → C2 POST. 전송 실패 시 다음 확정 때 재시도(인계가 아니라 버려도 되는 값) | 객체 → Jetson 기록 |
| D2 | systemd 서비스로 D1 자동 시작 | 재부팅 후 동작 |
| D3 | Chromium 키오스크 자동 시작 `chromium --kiosk http://<jetson>:8000/pda.html` | 부팅하면 PDA 화면 |
| D4 | 화면 방향 결정: 현재 UI는 세로 모바일 기준 → 모니터 세로 회전 또는 가운데 고정 | 버튼 잘림 없음 |
| D5 | 입력 장치: 터치 모니터면 그대로, 아니면 마우스 | 전체 흐름 조작 가능 |

### E. Jetson 운영

| # | 작업 | 끝 |
|---|---|---|
| E1 | `python -m shiftlink.mes --host 0.0.0.0` systemd 서비스 등록(Ollama는 기존 서비스) | 재부팅 후 자동 기동 |
| E2 | E2E 측정: 객체 인식 → 답변까지 20건 p95, 분류 정확도(클래스별) | 경량 계획 3주차 수치 |

## 3. 오늘 계획 (10/1)

1주차 마감이 내일(10/2)이고, 이 주의 완료 기준은 "사진 → 클래스명 출력(PC에서라도), DB 접속 확인"이다. 오늘은 **촬영과 학습 1차까지**를 목표로 한다. 서버 코드(C)는 2주차로 미룬다.

| 시간 | 작업 | 끝 |
|---|---|---|
| 오전 1 | 결정 기록: A안 채택, 통신 HTTP를 경량 계획 7절 "합의가 필요한 것"에 공유 | 팀 채널 공지 |
| 오전 2 | A1·A2 라즈베리파이 설치, 웹캠·모니터 연결, 캡처 확인 | 사진 1장 |
| 오전 3 | B1 대체 객체 6종 확정 | 대응표 |
| 오후 1 | B2 촬영(파이 웹캠 + 간단한 캡처 스크립트, 키 누르면 해당 클래스 폴더에 저장) | 클래스당 100장(총 600장) |
| 오후 2 | B3 PC 전이학습 1차 | 검증 정확도, 사진 → 클래스명 |
| 오후 3 | A4 파이 ↔ Jetson 네트워크 확인, A3 Jetson headless 전환 후 메모리 기록 | `ping`, 여유 메모리 수치 |
| 마무리 | Aiven 접속 정보 `.env` 입력·접속 확인(`scripts/check_env.py`) | DB 접속 확인 |

**내일(10/2)**: B4(파이에서 ONNX 실행·분류 시간), 남으면 C1(`--host`)과 D1 초안.
**막히면**: 촬영이 밀리면 클래스당 50장으로 1차 학습부터 돌리고, 정확도를 보고 추가 촬영한다.
