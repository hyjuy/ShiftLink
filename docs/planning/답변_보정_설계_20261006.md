# 답변 문장 보정 설계 — 코드가 사실·금지 문장을 직접 쓴다 (2026-10-06)

> **권장안(코드 보정) 기준 초안.** 작성: Claude(fork) · 기준: origin/main `212417a`
> 10/6 결정 기록(메모)에 "코드 보정을 먼저(10/12까지), SFT는 병행 준비"가 있어 이 방향과 같다. SFT는 이 문서 범위 밖이다.

## 요약

1. 답변 미충족 34건 중 인계(t4) 8건을 뺀 질의 쪽 26건을 유형별로 나눠 보면, **코드가 직접 쓰거나 막을 수 있는 것이 19건**(측정값 5, 금지·순서 5, 필수 안전 단계 누락 5, 운전/정지 2, 분기 뒤집기 2)이고 나머지 7건은 모델이 근거 없이 지어낸 문장이다.
2. 설계는 **네 층(L1~L4)**이다. 모델 답은 짧은 요약으로 두고, 코드가 ① 측정 사실 줄 ② 무측정 단정 차단 ③ 카드의 금지·정지 문장 선행 ④ 카드 근거 없는 문장 제거를 덧붙인다. 모델 호출은 늘지 않는다.
3. **측정은 Jetson 없이 재생(replay)으로 한다.** 저장된 모델 답에 보정을 입히고, 바뀐 문장만 다시 채점한다. 층마다 따로 채택·기각한다. 블라인드 셋은 확인용 1회만, `qa_test.json`은 열지 않는다.
4. **주의: 평가 입력과 시연 입력이 다르다.** 평가 질문은 관측값 0~2개, 시연 경로는 34개다(H1 리뷰 참조). 보정이 시연 경로에서도 맞는지 확인하는 Jetson 입회 시험을 따로 둔다.

## 2. 설계: 네 층

원칙: **모델은 요약만, 사실·금지는 코드가 쓴다.** 보정은 검증기가 아니라 **후처리**다(응답을 거절하지 않고 문장을 합성). 그래서 재시도가 생기지 않는다.

최종 `answer` = `[L1 측정 사실] + [L3 선행 안전 문장] + [모델 요약(L2·L4 통과분)]`. `answer`는 계속 문자열이라 응답 스키마·PDA는 그대로다.

### L1. 측정 사실 줄 (코드 생성)

- 입력: `tool_results["observation_facts"]`(`signal·label·value·unit·state·normal_min·normal_max`, `retrieval.py:404-429`).
- 출력 예: `현재 유압 압력 154.8 bar — 정상 범위 145–165 안.`
- 규칙:
  - 인용 카드의 `conditions`가 가리키는 신호(`*_state`)만 최대 3줄. 조건이 없으면 상태가 정상 범위 밖인 신호만.
  - 관측값이 하나도 없으면 한 줄: `입력된 측정값이 없습니다. 카드의 기준값은 참고이며 현재 상태를 뜻하지 않습니다.`
  - 카드가 `condition_status = "reference"`(기준값 질문, #177)이면: `기준값 질문이라 현재 측정값과 비교하지 않았습니다.`
- 목표 유형: ① (측정이 없는데 있는 것처럼), ④ (방향을 코드가 말해 준다).
- 문장 틀은 `observation_fact_block`(`ollama.py:200-225`)의 표현을 재사용한다(같은 판정 문구).

### L2. 무측정 단정 차단 (후처리 필터)

- 대상: 모델 요약 문장 중 **측정이 없는데** 방향·상태 단정을 하는 문장.
- 조건: (관측값 없음 또는 해당 신호의 `observation_fact` 없음) **그리고** 문장에 `초과|넘|벗어|미만|높|낮` 같은 방향어 + 수치 또는 신호 라벨이 있음 → 문장 제거.
- 제거 후 요약이 비면 대체 문장: `측정값이 없어 판단할 수 없습니다. 카드 기준: {카드 know_how 첫 문장}`.
- **기존 #163 가드와 다른 점**: #163은 `states and all(state == "normal")`일 때만 동작한다(`response.py:331-332`). 관측값이 **없을 때**(S-02·S-16·Q-002)는 아무 것도 하지 않아서 이 층이 메운다.
- 목표 유형: ① (5건 중 관측값이 없던 쪽), ③의 일부("계속 돌려도 된다" 같은 문장은 L3가 막는다).

### L3. 카드의 금지·정지 문장 선행

- 입력(구조화된 것만, 문장을 생성하지 않고 **카드 필드를 그대로 옮긴다**):
  - T3 카드: `type_payload.steps[*].preconditions` 중 금지문, `stop_conditions` 첫 항목 (T3 19장 모두 `stop_conditions`가 있음).
  - 안전 카드(`safety_flag`, 53장): `safety_basis` 첫 문장.
  - 인용 카드가 아닌 **적용 가능한 안전 카드**는 `ranked_cards`에서 검증됨(`condition_status == "verified"`)·`safety_flag`인 것만 최대 1장.
- 출력 예: `먼저: 플랫폼 아래로 들어가지 않는다. 속도 퓨즈는 분리하지 않는다. (K-1021)`
- 길이: 최대 2문장. 안전 공지 블록(`render_response`가 맨 앞에 출력)과 겹치지 않게 **카드 ID와 한 줄 요약만** 쓴다.
- 목표 유형: ⑤ (정지·감압·잠금이 답에서 빠짐, 5건), ② (금지 조치, 5건), ③ (운전/정지, 2건).
- 한계: **구조화된 금지 문구가 없는 카드**(T1 19장 · T2 14장 · T6 9장 중 안전 카드가 아닌 것)는 이 층이 아무것도 못 한다. 그 카드의 금지는 `know_how` 줄글에만 있다.

### L4. 카드 근거 없는 문장 제거 (실험 층, 조건부)

- 규칙: 모델 요약의 각 문장이 인용 카드 본문·질문·측정값과 **내용어 어간(2글자)이 일정 비율 이상 겹쳐야** 남긴다. 못 넘는 문장은 제거, 모두 제거되면 카드 첫 단계(`steps[0].action` 또는 `know_how` 첫 문장)로 대체.
- 비율(임계)은 **dev 셋에서만** 정하고 측정 전에 고정한다.
- 목표 유형: ⑥ (지어낸 원인·절차, 7건), ④ (뒤집힌 분기, 일부).
- **위험이 크다**: 검색에서 2글자 어간 비교는 흔한 어간이 겹쳐 dev가 21→18로 떨어졌다(X1 실험, `bench/experiments.tsv`). 같은 문제가 여기서도 생길 수 있다. 그래서 L4는 **L1~L3를 먼저 채택하고 남은 문항으로 판단**하며, 기각해도 설계 전체가 무너지지 않는다.

## 4. 사전 등록 (측정 전에 고정)

### 4.1 설계·측정 셋 (개발용, 조정에 사용 가능)

| 셋 | 질의 모드 답 | 출처 |
|---|---|---|

| sanity | 20 | 같은 폴더 |

| t4(인계) | 13 | 보정을 **적용하지 않고** 그대로인지만 확인 |

기준선(위 57건): **충족 29 · 수정 2 · 미충족 26.** guards1002 문장 기준과 같은 파일을 쓴다.

### 4.2 방법: 재생(replay)

- 저장된 `answer·cited`에 `compose_answer`를 입혀 새 문장을 만든다(`tool_results`는 모델 없이 `FixedPipeline._run_tools`로 다시 만든다, 검색은 결정적).
- 바뀐 문장만 **같은 루브릭으로 다시 채점**한다(guards1002 방식). 채점은 내가 하지 않고 **Cursor**가 한다(자기 변경을 자기가 채점하지 않음).
- Jetson이 필요 없다. 문장이 모델 출력 + 결정적 후처리이기 때문이다.

### 4.3 채택 기준 (층마다 따로 적용, 이 순서대로 L1 → L2 → L3 → L4 누적)

| 구분 | 기준 |
|---|---|
| **채택** | 그 층이 겨냥한 유형의 미충족이 줄고, 아래 모두를 만족: ① 질의 57건의 미충족이 누적 **18 이하**(기준선 26에서 −8 이상) ② 기준선에서 충족이던 29건 중 **28건 이상 유지**(하락 1건까지, 사유 기록) ③ sanity 충족 **17 이상**(카드 문장에서 만든 셋이라 가장 민감) |
| **기각(그 층만)** | 충족 → 미충족이 **2건 이상**이거나, sanity 충족이 17 미만 |
| **즉시 기각(전체)** | 새로 만든 수치·절차 1건이라도, 카드에 없는 금지·안전 문장 1건이라도, 답이 비거나 ID만 남은 것 1건이라도 |
| 부가 | 답 길이 상한·PDA 가독성은 전혜민 검토(M3)로 확인. 길어져서 읽기 어려우면 L3를 1문장으로 줄이는 쪽으로만 조정 |

- 상한 추정(측정 전 값): L1~L3가 전부 맞으면 미충족 26 → **약 11~13**. 이 값은 목표가 아니라 상한이다. L4는 여기에 최대 수 건을 더 줄일 뿐 확신이 없다.
- 임계 같은 숫자는 **L4 어간 겹침 비율 하나뿐**이고 dev에서만 정해 고정한다. 정한 뒤에는 바꾸지 않는다.

| 셋 | 쓰는 이유 | 통과 기준 |
|---|---|---|
| 블라인드 2차(BN) | 처음 보는 현장 질문 | 이전에 충족인 답이 충족을 유지, 미충족 수가 늘지 않음 |
| 블라인드 3차(B3) · T6 · cjy · 신입 후속(NH) | 같음 | 같음 |

- 블라인드·T6는 **채택 근거가 아니다.** 결과가 나빠도 그 셋에 맞춰 고치지 않는다.
- `eval/qa/20260929/qa_test.json`은 열지 않는다. 10/14 최종 1회는 동결한 구성으로만 한다.

### 4.5 시연 경로 확인 (Jetson 입회 1회)

보정이 시연 입력(34개 관측값, 자연어 질문)에서도 맞는지 본다. 시연 설비 3개(HPU·GR·CV) × 3질문 = 9건을 `/api/query`로 호출해: 답이 한글 문장인지, L1이 실제 MES 값과 일치하는지, L3가 카드 문장과 일치하는지, p95가 6초를 넘지 않는지(#184 기준 LLM p95 5.79초) 확인한다. 이 시험은 **H1 리뷰의 프롬프트 과대 문제를 고친 뒤**에 한다.

## 7. 이 설계가 하지 않는 것

- 모델 교체·프롬프트 개선·SFT. 이 층들은 "모델이 틀려도 사실 문장은 맞게"를 목표로 하고, 모델이 요약을 잘 쓰게 만들지는 않는다.
- 인계 모드(t4) 문장. 10/6 결정으로 시연은 메모 구조화다.
- 답 없음 판정. 판정기(#166)가 맡는다.
- 검색 개선. 이미 한계에 도달했다고 결정했다.
