# 배치 C 통합 전 정책·출처·분할 검증

검증일: 2026-09-30. 판정: **통합 승인 보류**. 배치 자체의 스키마·개수 검증과 전프로젝트 출처·분할 계약의 준수는 별도이다. 카드와 기존 데이터는 수정하지 않았다.

## 확인 범위

`docs/data/policies/source-and-split-contract.md`, `docs/guides/card-generation.md`, `seeds/source_registry.json`, `splits/prototype_split.json`, 배치 C의 계획·프롬프트·카드·관측 투영을 대조했다. 원장은 코드가 Artifact 투영과 ID만 비교하도록 사용했다. dev 사건의 원인·정답은 출력하거나 카드 작성에 사용하지 않았다. dev Artifact 텍스트는 중복 검증에서만 프로그램으로 비교하고 의미내용을 출력하지 않았다. `eval/` 및 sealed/holdout 의미내용은 읽지 않았다.

## P1 — KB와 dev에 같은 합성 기록이 존재

계약 58행은 동일 원문 재서술과 같은 원형에서 수치·설비명만 바꾼 사례를 같은 누출 연결 그룹으로 묶도록 한다. 배치 단계 A 프롬프트 4행과 `event_plan.json`은 EV-0401~0415를 kb, EV-0416~0420을 dev로 고정했지만 그룹 계보를 등록하지 않았다.

`records/kb_artifacts.json`과 `records/dev_artifacts.json`의 `text`를 정확 비교하면 다음 **8쌍의 work_note가 완전히 동일**하다.

최소 조치: 이 dev 5건을 독립 평가자료로 사용하지 않도록 보류한다. 원문·합성 템플릿의 실제 계보로 그룹을 확정하고 외부 배정표에 등록한 뒤 계약의 기존 배정 우선·SHA256 규칙에 따라 재분할한다. KB15/dev5를 맞추기 위해 그룹 ID나 기존 배정을 바꾸면 안 된다. 필요하면 독립 원형으로 평가 기록을 새로 설계한다. 계보 확정·배정 승인은 사람 판단이 필요하다.

## P1 — 출처 등록·발췌 승인과 공식 생성 preflight 불일치

계약 34행과 생성 가이드 8·17·36행은 기준 `source_id`, `approved_for_draft`, 검토된 `approved_scope`, 발췌문 해시 및 사건의 `group_id/reference_ids`를 요구한다. `shiftlink/data/generation.py:117~130`은 미등록 그룹·미승인 출처를 실제로 거절한다.

배치 카드의 출처는 **PDF 7개와 사건/Artifact ID 45개, 총 52개**다. 이 52개 `source_id`는 모두 현재 `seeds/source_registry.json`의 기준 ID에 없다. PDF는 로컬에 존재하지만 등록·발췌 승인을 대신하지 않는다. 기존 SD-002의 HY29-0035 문서를 HY29-0022와 같은 문서로 간주하거나, M-02 웹 자료를 26867443.pdf와 임의로 합쳐서는 안 된다.

PDF 목록:

- MAN-C-012.pdf
- 100980172-Logical-Troubleshooting-in-Hydraulic-Systems.pdf
- Convey-All-TroubleshootingGuide.pdf
- conveyor-manual-0323-en.pdf
- 1110_Roller_conveyor_EN_TNr_1131919_V1.0.pdf
- 26867443.pdf
- HY29-0022-UK.pdf

`cards.json:40` 등의 출처 필드는 파일명이며, `verify.py:39,65~66`은 PDF 파일명이나 배치 Event/Artifact의 존재만 확인한다. 레지스트리 승인·발췌 해시·허용 주장·제외 범위를 검사하지 않는다. `plan.json`과 `event_plan.json`에는 `group_id`도 없고 `splits/prototype_split.json`에는 배치 C의 신규 그룹 등록이 없다. 따라서 공식 생성 절차와 동등한 검증을 통과했다고 말할 수 없다.

최소 조치: 실제 판본·원문 식별 후 기준 출처 ID를 등록하고, 사용한 절·발췌문 해시·허용 주장·제외 범위·검토자·검토일을 승인 기록으로 남긴다. 사건 근거에는 앞 절의 그룹 계보를 연결한다. 필요하면 카드 `source_id`를 기준 ID로 매핑하되 locator에는 파일명·쪽을 보존한다. 발췌·출처 승인을 AI가 임의로 확정하지 않는다. 자동으로 보완 가능한 부분은 미등록/미승인 출처를 실패 또는 보류로 보고하는 검증이다.

## P2 — 서로 다른 사건 ID만으로 독립 반복 근거를 세고 있음

KB work_note 안에서도 다음 6쌍은 정확히 같은 텍스트다: EV-0403/0404, EV-0405/0406, EV-0407/0408, EV-0409/0410, EV-0411/0412, EV-0413/0414. T6 검증은 사건 ID 2개 이상을 확인하나, 실제 독립 경험 2건을 입증하지 않는다. 이는 README의 합성 템플릿 반복 한계와 일치한다.

최소 조치: 카드 검수에서 합성 반복을 실제 경험 근거로 승격하지 않는다. 독립 반복 근거가 필요하면 다른 관측과 경과가 있는 사건 기록을 추가하거나 해당 카드를 보류한다. 같은 문장이라는 이유만으로 두 사건이 반드시 동일한 실제 사건이라고 단정하지는 않는다. 현재 자료에는 합성 계보가 부족하므로 독립성을 인정할 근거가 없다.

## 가이드와 계약 사이의 충돌

배치 업무 가이드 공통 원칙 6은 카드에 파일명·쪽을 쓰도록 하고 단계 A는 KB15/평가5 고정 개수를 요구한다. 전프로젝트 계약은 기준 출처 ID/검토 승인과 사건별 개수가 아닌 누출 그룹 분할을 요구한다. 계약 7행은 이전 설계의 분할 제안과 충돌하면 계약이 우선한다고 명시한다. 배치 업무 가이드를 충족한 결과만으로 계약 준수를 선언하지 않는다. 파일명은 locator에 유지하면서 기준 ID를 연결할 수 있으나, 15/5는 독립 그룹 분할 결과를 보고 추가 자료로 충족해야 한다.

## 통과한 검사와 한계

- 카드에서 인용한 사건/Artifact 45개는 모두 KB 투영에 존재한다. dev 직접 인용은 없다.
- KB Event 투영에는 `true_cause`, `true_actions`, `cards_expected`가 없다.
- KB/dev Artifact 분리 파일은 통합 Artifact의 각 split 필터 결과와 일치한다.
- 프롬프트 인덱스 3개의 SHA256이 실제 파일과 일치한다.
- 인용 PDF 7개는 모두 로컬에 존재한다. 내용의 전체 적합성·권한은 이 검사로 확정하지 않는다.
- 배치 C를 제외한 `docs/data` JSON 156개에서 `timeline`이 있는 Event 또는 `text`가 있는 Artifact의 정의 ID를 검사했다. EV-0401~0420/AR-0401~0440 정의 충돌은 없다. eval/·sealed/holdout·sources/reference는 제외했으므로 그 제외 영역까지 전역 무충돌이라고 주장하지 않는다.

## 재현

표준 라이브러리 Python으로 JSON을 읽고, `a['text'] == b['text']`를 비교했다. 정규화 검사는 `(EV|AR|AT|K)-\\d{4}` ID를 고정 표기로 치환한 뒤 모든 `\\d+`를 `N`으로 치환했다. 출력은 매칭 ID·개수뿐이며 dev 의미내용·정답은 출력하지 않았다. 출처는 카드 `provenance.sources[].source_id` 집합과 레지스트리 `sources[].source_id` 집합의 차집합으로 검사했다. 프롬프트는 원본 바이트의 SHA256으로 확인했다.

판정 근거가 해소되기 전에는 `draft/L0`를 유지한다. 위 보류는 사람의 카드 내용 검수와 별도로, 통합 전 출처·계보 계약을 먼저 충족하기 위한 것이다.
