## 감점 내역

### B1 안전 카드 최상단 고정 (-5 / 8)
- 근거: `pda.js:1107`, `pda.js:685-704`. 결과 화면의 안전 관문은 서버 `safety_notices`와 인용·미확인 카드 중 `safety_flag` 카드만으로 만든다. 같은 줄에서 계산한 `rankCards(S.eq).safety`(로컬 kb 안전 카드)는 `local.actions/excluded`만 쓰이고 `safety`는 버려진다. 서버가 안전 카드를 빠뜨리면 결과 화면에는 관문이 아예 없다(`pda.js:896`의 `if (r.safety.length)`). 반면 질의(`pda.js:782`)·대기(`pda.js:1070`) 화면은 로컬 안전 카드를 보인다. (-2)
- 왜 문제인가: 조치 버튼 「이 조치 시도」가 있는 화면만 안전 관문이 서버 응답에 달려 있다. 서버가 빠뜨려도 막아 줄 로컬 대조가 없다. 서버 쪽 고정 반환(`shiftlink/rag/retrieval.py:492-507`)을 믿는 것일 뿐 화면 쪽에는 방어가 없다.
- 근거: `pda.js:710`에서 T4는 고정 안전 카드에서 빠진다. 인계 확인(`pda.js:1120-1165`)과 인계 작성(`pda.html:496-514`, `pda.js:1188-1214`) 화면에는 안전 관문이 없다. kb에는 `safety_flag=true`인 T4 카드 K-1103(정지·재기동 방지 상태 인계, OSHA 1910.147(f)(4), `kb_cards.json:2326-2340`)이 있는데, 화면 어디에도 최상단으로 고정되는 경로가 없다. (-2)
- 왜 문제인가: 루브릭은 "카드 유형과 무관하게 최상단"이다. 재기동 방지 상태를 인계할 때 적용되는 안전 카드가 바로 그 인계 화면에 나오지 않는다.
- 근거: `pda.html:433-439`, `pda.js:1076`. 대기 화면은 진행 단계 블록 아래에 안전 카드를 놓는다. `safetyEl(c, false)`라서 관문 띠(sticky)와 관문 문구 `.gate`가 없다. (-1)
- 왜 문제인가: 결과를 기다리는 동안에는 안전 카드가 화면 최상단이 아니고, 스크롤하면 고정되지도 않는다.

## 감점하지 않은 것 중 위험 신호
- 실측 필요(A4): 홈 화면 주 행동 「설비 스캔」이 두 `.grow` 사이 중앙에 놓인다(`pda.html:324-327`). 하단 40% 안에 들어오는지 브라우저 실측이 필요하다.
- 실측 필요(A1·B1): `#alert` 띠가 최대 3행+α로 pane 위를 차지한다(`pda.html:146-154`, `pda.js:1405-1421`). 작은 화면에서 질의 화면 sticky 안전 띠와 카드가 얼마나 밀리는지 실측이 필요하다.
- `#alert`가 안전 관문과 같은 색 토큰(`--safety-bg`, `--safety-edge`)과 「⚠」를 써서(`pda.html:146`, `pda.js:1410`) 모든 화면에서 안전 관문보다 위에 놓인다. 고장 알림이 안전 관문으로 오인되거나, 반대로 관문이 알림처럼 무시될 위험이 있다.
- 질의·대기 화면의 안전 카드는 원본 카드라 `stop_conditions`가 붙지 않는다(`pda.js:782`, `1070`). `safetyEl`은 `know_how`만 보이고 T3 안전 카드의 단계별 멈춤 조건은 보이지 않는다(`pda.js:753-760`). 멈춤 조건은 결과 화면에서 서버 공지가 있을 때만 나온다(`pda.js:689`).
- `safety-bar`의 건수에 「설비 불일치」로 가린 카드도 들어간다(`pda.js:772`, `673`). 실제 지켜야 할 안전 조건 수와 다르게 읽힐 수 있다.
- 대기 취소 뒤 같은 설비로 다시 검색하면 `waitAbort`가 초기화되어(`pda.js:1081`) 먼저 보낸 질의의 응답이 뒤늦게 결과 화면을 덮을 수 있다(`pda.js:1062`). 설비는 같지만 질문이 다른 응답일 수 있다.
- 안전 관문은 표시일 뿐 확인 동작이 없다. 「이 조치 시도」가 관문 확인 없이 바로 눌린다(`pda.js:883-889`).
