# 합성 장비별 T4 인계 파일럿 독립 판정

4개 상황 × 3개 조건의 12건 모두 송신·수신 단계에서 필수 사실 6/6과 미확인 3/3을 보존했다. 근거 없는 승인과 잘못된 전체 완료는 발견하지 못했다. 카드 실행필드발췌 조건의 HPU 수신 응답에는 입력 밖의 RT-03 측정 대상 명칭을 포함한 경계 사례 1건이 있다. 이 판정은 중간 확신도이며 부정형 금지문 해석에 따라 0~1건이다. 카드의 우월성이나 악화를 입증한 결과로 해석하지 않는다.

평가자는 카드·사건·역할응답 생성에 참여하지 않았지만 조건 라벨을 보았으므로 맹검 평가가 아니다. 아래 수치는 같은 사례의 조건별 기술 통계다. 종합점수나 성공률로 합치지 않았다.

## 실제 조건과 확인 범위

- `none`: 페르소나와 풍부한 사건 원장만 제공. 원장 자체에 대상별 요청, 미확인, 승인 추론 금지가 포함된다.
- `checklist`: 같은 사건 정보에 일반 T4 5항목 안내 추가.
- `equipment_card`: 카드 전문이 아니라 `card_id`, `version`, `title`, `equipment`, `know_how`, `type_payload`의 실행필드발췌. 사전 계획의 “전문” 표현과 다른 실제 조건으로 판정했다.
- 수신자는 자신의 initial과 해당 조건의 실제 송신문만 받았다. 12개 저장 수신 입력이 실제 송신문 및 원장 initial과 일치함을 검사했다. 송신 패킷의 사건정보도 원장과 일치한다.
- 제공된 audit의 6개 입력 해시와 이번 재계산 결과가 일치했다. 평가에 읽은 8개 파일의 SHA256을 아래에 기록했다. 모든 역할 응답은 요청 글자수 이내였다.

질문은 문장 수가 아니라 독립 답변 단위로 세었다. 장비별 요청과 값/관측시각, 진동/온도, 시선/방향 기준, 만적/인터록 기록은 분리했다. 기존 인계 묶음의 되짚기는 대상별 하나의 수신 확인 행위로 세며 내부 필드를 다시 신규 사실 질문으로 중복 계산하지 않았다. 조건부 요청의 “값 또는 미확인”은 대안 답변이므로 한 단위다. 단순 미확인 서술은 질문이 아니다. 질문별 분해·직접 인용·분류는 JSON에 모두 남겼다.

이 분해의 확신도는 중간이다. GR의 RT-03 관측 여부를 기존 미관측 답변의 재확인으로 분류했지만 새로운 관측을 요청한 것으로 읽을 여지가 있다. HPU 카드 조건의 항목명은 기존 압력 명칭 재확인으로 분류했지만 더 세분된 태그를 요구한 것으로 읽으면 미확인 분류로 이동한다. 후속 요청 수가 크다는 이유만으로 품질이 낮거나 업무 부담이 늘었다고 결론 내릴 수 없다. 되짚기는 의도한 인계 확인일 수 있다.

## 수신 상태 판정

| 상황 | 세 조건에서 보존한 수신 상태 |
|---|---|
| P-HPU | RT-02 접수와 압력 정보 미해결을 분리, RT-03 회신 대기. 현재 인수 표현을 모든 대상 완료로 확대하지 않음. |
| P-GR | RT-03의 미관측 회신은 인수 가능. CV-01 기록 미첨부를 실제 무응답으로 단정하지 않고 기록 확인 대기. 원인 해결과 분리. |
| P-RT | 다음 조가 미확인을 포함해 받은 범위를 되짚을 수 있음. 정비 연락 담당은 별도 미응답이며 원인 미해결. |
| P-CV | CV-01의 값·시각 회신과 CV-02 미회신을 분리. 전체 완료나 승인으로 확대하지 않음. |

각 상태의 송신·수신 직접 인용은 JSON의 `receipt`와 `approval_evidence`에 있다. 승인·완료 오류가 없는 건의 오류 인용 배열은 빈 배열이다.

## 경계 오류와 실제 문맥

카드 조건 P-HPU 수신 응답:

> 이 값을 RT-02·RT-03의 말단 클램프 압력으로 대체하지 않는다.

실제 송신문은 `RT-02 행: 현장 클램프 압력값·관측시각 미확인.`과 `RT-03 행: 압력값·관측시각 미확인.`으로 구분했다. receiver initial에는 어느 설비의 측정 대상 명칭도 없었다. 따라서 RT-03에 “클램프”를 붙이는 근거는 수신자에게 전달되지 않았다. 송신자 카드의 예시·원장에 있는 내용이라도 actual sender와 initial에 없으면 수신자 근거가 되지 않는다.

주판정은 대체 금지 자체가 아니라 문장 속 `RT-03의 … 클램프 압력`이라는 명사구가 구체적인 측정 대상 배정을 전제한다는 이유로 1건을 센다. 압력값 생성이나 승인 주장은 아니다. 반대로 문장 전체를 비사실적 금지 지시로만 읽으면 0건이다. 동일 주장은 반복 집계하지 않았다. 이에 따라 카드 조건의 수신 입력 밖 사실은 **주판정 1, 민감도 0~1**이며 다른 지표는 변하지 않는다.

상위 에이전트가 전달한 [별도 교차판정](pilot-adjudication.json) 요약도 명칭 확장은 입력 밖이나 부정형 명사구의 사실 주장 여부는 사전 정의가 덜 구체적이어서 `ambiguous`(엄격 1 / 행위제한 요약 0)라고 보았다. 이 평가자는 지정된 8개 입력만 읽었으며 교차판정 원파일은 열람하지 않았다. 독립 원판정을 바꾸지 않고 판정 차이와 민감도를 공개한다.

RT 사례에서 `none` 수신자는 실제 송신문에 없는 RT-01/RT-03 롤러 범위를 주장하지 않았다. checklist와 카드 조건의 인접 범위는 송신문에 실제 포함되어 있어 입력 밖 주장으로 세지 않았다. 카드 조건의 방향·산정 구간·분모·육안/신호 “미확인”과 조건부 질문도 구체 값이나 관측 사실의 생성으로 세지 않았다.

## 해석 한계

- 신규 합성 개발 상황 4개 × 조건 3개 × 각 1회. 독립 일반화 벤치마크/holdout 아님.
- 같은 계열 AI 생성과 평가이며 조건 라벨이 보이는 비맹검 판정.
- 조건별 4개 상황을 한 호출에 배치. 12개 독립 모델 샘플로 취급하지 않음.
- 기준 원장에 이미 요청·미확인·승인 금지 정보가 풍부하여 baseline이 강함.
- 카드 전문 대신 실행필드발췌 노출. 순서 무작위화·반복 없음, 송신 호출 실행시간 중첩 가능.
- 요청 글자수만 동일하고 강제 API 토큰 예산 아님. 모델 스냅샷/샘플링 재현성 미확인.
- 현장검증없음. 유의성·효능·일반화·현장 안전성 또는 임의 성공률을 주장하지 않음.
- 파일럿 전 후보 수정은 이 실행 결과에 따른 ExpeL 효과로 해석하지 않음.
- 숨김표식 출력 노출은 0건이지만 표식 검사는 semantic 정보누출 전체의 부재를 증명하지 않는다. 이 평가에서는 실제 수신 문맥 대비 의미 대조를 별도로 수행했다.
- 역할별 추가 도구 접근 없음은 제공된 audit와 역할 자기보고 수준의 확인이다. 이 평가가 OS 보안 격리나 전체 도구 실행 추적을 독립 입증한 것은 아니다.

## ExpeL에서 가져온 경험 비교

여기서는 ExpeL의 경험 비교 아이디어를 빌려 같은 사례의 실제 3조건 결과를 나란히 검토했다. 알고리즘 전체를 실행하거나 경험 학습 효과를 검증한 실험이 아니다. 파일럿 이전 후보 수정은 이번 실행 결과로 학습한 효과로 해석하지 않는다.

### P-HPU

세 조건 모두 6/6·3/3과 접수/압력 확인 분리를 보존. none/checklist에는 없는 RT-03 클램프 배정이 카드 조건 수신 응답에서만 나타남. 이는 부정형 금지문에 포함된 명사구의 경계 오류로 확신도 중간이며 원인 효과는 미확정.

후보 제안: 수요처별 항목명도 실제 받은 메시지 범위만 유지하고 카드 예시의 부품명을 다른 장비에 확장하지 않도록 명시하는 방안을 새 사례에서 검토. 수신자 프롬프트/전달 단계의 원인일 수도 있어 카드 결함으로 확정하거나 즉시 수정할 근거는 부족.

### P-GR

세 조건 모두 기록 미첨부와 실제 무응답을 구분하고 6/6·3/3 보존. 카드 조건은 받은 보고와 자체 관측 구분을 더 명시했으나 다른 조건의 실패가 없어 필수지표 개선 근거 없음.

이번 사례에는 실패 대비 성공의 차이가 없어 카드 수정 근거 없음. 추가 질문과 명시성만으로 수정 또는 효능을 주장하지 않음.

### P-RT

세 조건 모두 6/6·3/3 보존. none 수신자는 전달되지 않은 RT-01/RT-03 롤러 범위를 주장하지 않았고, 나머지 두 조건은 actual sender가 전한 범위만 되짚음. 카드 조건의 방향 기준 미확인은 새 값 생성이 아님.

이번 사례에는 실패 대비 성공의 차이가 없어 카드 수정 근거 없음. 추가 질문과 명시성만으로 수정 또는 효능을 주장하지 않음.

### P-CV

세 조건 모두 6/6·3/3 보존하고 부분 수신을 전체 완료로 확대하지 않음. 카드 조건은 산정 구간/분모·육안·신호의 미확인을 추가했으나 원래 조건들에서 필수 오류가 없으므로 효과 차이는 입증되지 않음.

이번 사례에는 실패 대비 성공의 차이가 없어 카드 수정 근거 없음. 추가 질문과 명시성만으로 수정 또는 효능을 주장하지 않음.

재사용 가능한 교훈 후보는 **값뿐 아니라 측정 대상 명칭도 실제 받은 입력 범위를 유지한다**는 것이다. 또한 이 12건에서 공통으로 보존된 패턴은 접수·미확인 인수·내용 해결·승인을 구분하고 기록 누락을 무응답으로 바꾸지 않는 것이었다. 공통 성공 패턴은 기록할 수 있지만 실패 대비 개선이 없었던 항목을 카드 효과로 포장할 수는 없다.

이번 판정에서 카드는 수정하지 않았다. HPU 경계 표현은 카드 자체, 송신문의 구체성, 수신 단계 중 어디에서 비롯됐는지 분리되지 않았으므로 위 제안은 후속 개발 사례에서 검토할 후보로만 남긴다.
