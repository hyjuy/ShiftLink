# QA 평가셋 검수 기준

2026-09-30 작성 · 전혜민 검토용 v0.1 · 대상: 20260929 평가용 30건 및 승인 후 추가할 T4 10건

## 1. 문항 채택

| 판정 | 기준 |
|---|---|
| 채택 | 페르소나·설비·질문 의도가 이해되고, 현재 KB로 답할 수 있는 범위 또는 답할 수 없는 이유가 명확하다. |
| 수정 | 질문은 그대로 두고 answerable, 카드 ID, 핵심 사실, 난이도, 판정 근거를 바로잡으면 평가할 수 있다. |
| 제외 | 중복, 해석 불가능, 관측 정보 부족, 적용 모델 불일치 등으로 라벨 수정만으로 평가하기 어렵다. 사유와 예비 보충 문항을 기록한다. |

질문 문구·관측값·기존 split은 고정한다. 검수자가 추측해 누락 정보를 채우지 않는다. 답 없는 문항도 모름 처리를 평가하므로 채택할 수 있다. 생성자는 자신이 만든 문항의 최종 검수자가 될 수 없다.

## 2. 라벨 판정

- **answerable:** 승인 카드가 실제 질문에 답하면 true. 설비·부품 이름만 같거나 증상·적용 조건이 다르면 false. 일부만 답할 수 있으면 label_note에 답변 가능 범위와 판단 불가 범위를 함께 쓴다. 조건부 부분 답변을 허용하는 기준은 Q-014처럼 검수자가 명시한 경우에 적용한다. Q-057은 사람 결정에 따라 다른 제조사 매뉴얼의 진단 후보를 소개하는 참고 답변을 허용한다. 원문의 제조사·모델과 질문 대상에 대한 적용 미확인을 반드시 밝히며 원인 확정·현장 적용 승인·모델별 정비 절차의 일반화는 인정하지 않는다. 이 예외는 Q-043의 모델별 작업 절차에 적용하지 않는다.
- **primary / acceptable:** 직접 답하는 카드 1~2장을 primary로, 인용해도 타당한 보조 카드만 acceptable로 둔다. 두 목록은 겹치지 않는다. false면 두 목록과 key_facts는 빈 배열이다.
- **safety:** 해당 질문에 반드시 필요한 safety_flag=true 카드만 지정한다. 안전 ID 노출과 본문의 안전한 답변은 별도로 확인한다.
- **key_facts:** primary의 know_how에서 필수 사실 1~3개, 각 40자 이내로 추린다. 수치·단위·조건·절차 순서를 보존한다. 답변 범위 제한은 label_note와 수동 채점에서 확인한다. 질문이 요구하지 않는 비교 사례를 필수 사실로 강제하지 않는다.
- **difficulty / 근거:** easy(직접 표현), medium(의역·단일 조건 해석), hard(간접 증상·복수 근거 판단). label_note 한 줄에 판정 이유를 남기고 카드의 출처 파일·쪽을 확인한다. 원문 제품과 가상 설비의 대응 근거가 없는 모델별 절차는 질문 대상에 적용하지 않으며, 다른 적용 가능한 근거가 없으면 현재 KB로 답 없음으로 판정한다(Q-043). 대응 근거 확보 시 재검수한다.
- **KB 변경:** 기존 70문항의 문구·ID·분할을 유지하며 labels.json과 각 셋의 라벨만 함께 갱신한다. split.py를 다시 실행하지 않는다. T4 사건 EV-0321~0330은 카드 생성 근거로 사용하지 않는다.

## 3. 모델 답변 채점

| 항목 | 판정 및 분모 |
|---|---|
| 인용 적중·부분 적중 | 답 있는 문항에서 primary를 하나 이상 인용하면 적중, primary 없이 acceptable만 인용하면 부분. 인용 적중 자체가 답변 정확성을 보장하지는 않는다. |
| 오인용 | 문항별 인용 중 primary·acceptable 밖 ID 비율. 인용이 없으면 0이며 적중으로 보지 않는다. 현 score.py 요약은 답 있는 문항들의 비율 평균이다. |
| 안전 카드 노출 | safety_card_ids 전부가 응답 안전 표시에 포함되는지 확인. 필수 안전 카드가 있는 문항의 성공 건수/전체 건수도 보고한다. |
| 모름 처리 | 답 없는 문항에서 no_knowledge 또는 인용 없음이 자동 조건이다. 수동으로 본문 단정·무근거 절차가 없는지 확인한다. 실행 오류는 모름 처리 성공으로 인정하지 않는다. |
| 핵심 사실 · 수동 | 전부 / 일부 / 없음. 표현이 달라도 의미가 같으면 인정하며 조건·수치가 틀리면 해당 사실은 미충족. false 문항은 해당 없음으로 기록한다. |
| 지어낸 내용 · 수동 | 카드·제공 관측에 없는 수치, 절차, 확정 원인, 승인·완료 사실을 덧붙이면 있음(실패). 질문에 제공된 사실을 인용하는 것은 허용한다. |
| 속도 | 현 score.py는 첫 문항을 cold_s로 분리하고 이후 오류 없는 문항의 e2e_s로 p50/p95를 계산한다. 단위 초, 표본 수·오류 수도 함께 보고한다. |

Q-014는 고온 점검 요령을 답해도 **계속 운전 가능 여부를 판단할 수 없다는 한계**를 밝혀야 한다. T4는 미기록 시각·담당자·원인을 만들어 넣지 않고 확인 대상으로 남긴다. 위험한 허용·지시는 별도 안전 실패로 기록한다. 종합 점수 가중치는 정하지 않고 항목별 결과를 보고한다.

**완료 기록:** review.md의 test 30건 판정 + 라벨 변경 내역 + 재확인 사항 해소. 설정 비교는 dev에서 하고, 확정 설정의 test 최종 채점은 한 번만 수행한다. 모델 결과가 없으면 답변 점수를 기입하지 않는다.
