## 권장 작업 순서와 완료 기준

### 1. 기존 COMMON 카드의 상태 표현 정합화 — 먼저 수행

대상은 공통 카드 M07/M08/M13을 우선으로 하고, 같은 검토에서 지적된 M16/M18도 확인한다. 기존 [명세 M01~M13](../data/knowledge_cards/drafts/20260925-t4-synthetic/specs-01-13.json), [명세 M14~M25](../data/knowledge_cards/drafts/20260925-t4-synthetic/specs-14-25.json), 카드 전문과 연결 대본을 함께 대조한다.

| 대상 | 필요한 수정·확인 | 완료 판정 예시 |
|---|---|---|
| M07/M08/M13 | 수신 확인과 결측·충돌 정보의 해결을 분리 | “값 미확인/기록 충돌”을 정확히 되짚으면 해당 정보의 수신 확인은 가능하고 내용은 미해결로 유지 |
| M16 | 새 증빙 도착을 기존 상태와 구분 | 새 기록의 존재·범위·판본을 확인 대상으로 연결하되 자동으로 작업 승인으로 바꾸지 않음 |
| M18 | 명시적 무응답과 응답 기록 미첨부를 구분 | 실제 무응답은 회신 대기, 기록 미첨부는 회신 여부 확인 대기로 각각 표시 |

방법 명세·know_how·acknowledgement·미완료 처리·대본 사이에 같은 원칙이 적용되는지 확인한다. 수신 확인, 내용 해결, 현장 확인, 작업·운전·재가동 승인은 계속 분리한다. 단순 문장 수정만으로 과거 점수나 효과 검증을 승계하지 않는다.

**산출물:** 수정 전후와 수정 이유, 카드 버전/원본 연결, 변경한 내용에 대한 작성자 아닌 검토, 관련 스키마·참조 검증 결과. 기존 기록은 보존하고 후속 버전의 별도 산출물 폴더에서 작업하는 것을 기본으로 한다.

**완료 기준:** 미확인 인수, 충돌 인수, 일부 회신, 명시적 무응답, 기록 미첨부, 새 증빙 도착의 각 사례에서 수신 상태와 해결·승인 상태를 혼동하지 않는다. 변경 카드와 참조 대본을 실제 읽고 재검토했으며 검증 대상 해시가 현재 파일과 일치한다.

### 2. 후속 비교 실험의 원장·지표·입력 범위를 실행 전에 고정

현재 원장에는 요청 방식과 주의사항이 풍부해서 세 조건 모두 필수 항목을 보존했다. 다음 실험은 덜 정리된 합성 원자료에서 시작하되 특정 조건을 실패시키려고 정답이나 난도를 사후 변경하지 않는다. 사실 원장과 역할별 관측은 고정하고, 전달 방법 안내는 조건별 지원 입력으로 분리한다.

- HPU/GR/RT/CV 외 PDP/CAU도 포함하는 범위표를 만든다. 한 장비군 대표 사례의 결과를 그 장비군 모든 카드의 효과로 확대하지 않는다.
- 같은 태그의 다른 장비, 관측시각·단위 누락, 원문 충돌, 일부 회신, 응답 기록 미첨부, 자료 밖 측정 대상 명칭 추가처럼 서로 다른 실패 요인을 구분한다.
- `카드 없음 / 일반 5항목 체크리스트 / 선택 T4 카드`를 유지하고 카드 선택·노출 필드를 명시한다. 카드 전문인지 실행 필드 발췌인지 실제 입력과 문서를 일치시킨다.
- 상황 수·상황별 반복 수·조건 순서·길이/토큰 예산·중단 및 부적격 기준을 정해 기록한다. 설정이 노출되지 않으면 모른다고 명시한다. 개별 상황·역할마다 새 컨텍스트를 기본으로 하고 묶음 호출을 택하면 이유와 한계를 남긴다.
- 정답·평가 원장·예시 회신/F8을 역할 입력에서 제외한다. 기존 sealed/holdout은 열람하거나 생성 재료로 사용하지 않는다.
- 필수 사실과 미확인 항목을 가능한 한 개별 판정 단위로 나눈다. 승인 오류·완료 오판·수신 입력 밖 주장·후속 요청은 별도 지표로 유지한다.
- P-HPU의 “RT-03 클램프”처럼 부정형 문장 안의 대상 전제도 입력 밖 주장으로 셀지 실행 전에 정의한다. 오류와 정상 대조 예시를 함께 만들고 애매한 판정의 처리 규칙을 정한다.
- 질문은 새 정보 요청과 수신 확인용 되짚기를 분리한다. 문장 수·독립 답변 항목 수·대화 턴 수를 혼용하지 않는다.

**산출물:** 새 실험 계획, 합성 사실 원장, 장비/카드/실패 요인 범위표, 역할별 입력, 평가 기준, 실행 전 독립 설계 검토, 동결 해시.

**완료 기준:** 역할이 볼 수 있는 정보와 평가자가 볼 수 있는 정보가 실제 입력 파일에서 분리되고, 모든 조건이 같은 사건 사실·평가 기준을 사용한다. 계획과 실행 입력이 일치한 뒤 실행을 시작한다. 운영 DB·split 정책 변경은 필요하지 않다.

### 3. 격리 송수신 실행과 독립 판정

송신자는 자기 관측과 조건별 지원만 받고, 수신자는 자기 초기 정보와 실제 전달문만 받는다. 컨텍스트 분리는 `fork_turns=none` 등 실제 사용할 수단으로 기록한다. 자기 packet 읽기 이외 도구 접근을 금지하는 경우에도 OS 수준 차단이라고 주장하지 않는다. 추가 도구 접근·예산 초과·응답 누락은 조용히 재시도해 지우지 말고 실행 로그에 남긴다.

작성자가 아닌 판정자는 고정 원장과 실제 송수신 입력·응답을 대조한다. 가능한 경우 조건명은 판정자에게 가리고, 문체로 조건을 추정할 수 있다는 한계는 남긴다. 경계 사례는 별도 검토자가 먼저 독립 판단하고, 이견을 보존한 뒤 처리한다.

**산출물:** 실제 입력·발화 원문, 역할/모델 설정과 실행 식별자, 편차 기록, 입력·출력 해시, 항목별 근거 판정, 상황별 짝지은 비교표, 질문 유형별 집계.

**완료 기준:** 계획한 실행이 완료됐거나 빠진 실행과 이유가 모두 기록돼 있다. 합계는 항목별 판정에서 재계산 가능하고 정답 비노출 검사는 실제 packet을 대상으로 한다. 차이가 없거나 카드 조건이 나쁘면 그대로 보고한다. 카드 개선 효과를 얻어야만 실험이 완료되는 것은 아니다.

### 4. 실행 경험에서 개선하고, 개선에 쓰지 않은 새 상황으로 평가

ExpeL에서 가져온 경험 비교를 적용하되, 실제 실패·성공 발화와 입력을 먼저 보존한다. 실패 원인이 카드 내용, 송신문 누락, 수신자 추론, 평가 기준 중 어디에 있는지 구분하고 최소한의 수정 후보를 만든다. 현재 “측정 대상 명칭도 전달 범위에 한정”은 후보이며 특정 카드 결함으로 확정하지 않았다.

카드를 고쳤다면 변경 이유와 실제 실행 ID를 연결하고, 변경 전후 버전과 검토를 보존한다. 생성·개선에 쓰지 않은 새 합성 상황으로 다시 비교한다. 장비명·숫자·문체만 바꾼 파생 상황은 같은 사건 그룹으로 취급하며 일반화 평가용 독립 상황으로 세지 않는다. 원래 상황 재실행은 회귀 확인이고 별도 상황 평가는 일반화 확인으로 구분한다.

**산출물:** 경험 비교·수정/미수정 결정, 필요시 개정 카드와 독립 검토, 별도 평가 상황의 계보·결과.

**완료 기준:** 수정했다면 관련 실패와 수정의 연결 근거 및 별도 평가 결과가 있다. 수정 근거가 부족하면 미수정 이유가 있다. 실패를 삭제하거나 평가 정답을 바꿔 개선으로 만들지 않는다. 추가 카드도 필요한 새 방법이 확인될 때만 만들며 25개나 45개를 목표·상한으로 삼지 않는다.

### 5. 장비별 운영 검색 연결 — 연구 작업과 별도 후속 단계

현재 `equipment-map.json`은 개발 적용표다. 생산 검색은 인스턴스 sidecar를 강제하지 않으며 PDP/CAU 유형도 현재 enum 밖이다. 장비 연결표가 있다는 이유로 실제 자동 배치가 끝났다고 쓰지 않는다.

운영 적용을 진행하는 별도 작업에서는 [검색 구현](../../shiftlink/rag/retrieval.py)과 스키마를 확인하고, 공통 방법·장비 유형·개별 인스턴스·관련 장비의 선택 규칙부터 설계한다. PDP/CAU를 COMMON에 유지하며 적용 범위를 필터링할지, 명시적인 유형 확장이 필요한지 현재 호출 경로와 호환성을 근거로 정한다. 이 문서는 어느 구현안을 이미 확정한 것이 아니다.

**완료 기준:** 특정 장비의 카드가 무관한 장비에 노출되지 않고 공통 카드가 의도대로 검색되며 dev/sealed·draft/L0 차단이 유지된다. 장비 관계에 이름이 등장한다는 이유만으로 모든 관련 카드가 자동 적용되지 않는다. 출처·사람 검토·카드 채택 계약은 별도로 충족하며 이번 연구 산출물을 자동 승격하지 않는다.

## 재개·파일 변경 시 주의

- 새 작업 시작 시 `git status --short`를 확인한다. 이번 확인 시 두 핸드오프와 기존/신규 산출물 폴더가 untracked였고 커밋·푸시는 하지 않았다. 기존 파일을 정리 대상으로 삭제하거나 모든 변경을 일괄 처리하지 않는다.
- 새 카드 현재 버전은 `synthetic-f7c3411308f7`이다. 기존 25개와 신규20개는 서로 다른 배치이며 카드 ID에는 제외 후보 때문에 빈 번호가 있다. 번호를 연속으로 만들려고 다시 할당하지 않는다.
- `build.py`는 필요 없이 재실행하지 않는다. 기존 공통 배치 생성·검증기는 25개 및 특정 경로를 가정하는 부분이 있으므로 새 버전에 그대로 실행하기 전에 입력/출력을 확인한다.
- 기존 공통 카드 파일을 바꾸면 장비 배치 manifest/review의 원본 카드 해시와 기존 대본의 연결 검증에도 영향이 있다. 기록을 보존하려면 별도 버전에 원본 경로·해시·수정 계보를 명시한다. 단지 해시를 최신 값으로 바꿔 과거 검토를 새 검토처럼 만들지 않는다.
- `candidate-specs-*.json`은 원본26개와 과거 리뷰를 연결하는 snapshot이다. 현재 채택20개로 덮어쓰지 않는다. 기존 `pilot-*` 입력·출력·프로토콜도 결과에 맞춰 변경하지 않는다.
- 평가 지표는 별도 메타데이터로 두고 기존 confidence 의미를 바꾸지 않는다. 이전94.9점은 기존 카드의 문서 설계 점수이며 새 카드나 실행 효과 점수로 재사용하지 않는다.
- 합성 연구를 계속한다는 사용자 목적을 유지한다. 실제 현장 자료 확보를 이번 합성 개발의 필수 종착점으로 되돌리지 않는다. 합성 내부 타당성·실행 결과·현장 검증은 별개로 보고한다.
