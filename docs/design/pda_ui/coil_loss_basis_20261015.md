# 정지 손실을 코일 개수로 — 표준 생산 속도 근거 (2026-10-15)

대시보드 정지 손실 칸은 "이번 주 원인 설비 때문에 못 만든 코일 수"를 보인다.
값은 카탈로그 `docs/data/reference/00_plant_and_relations.json`의 `production_lines[0].production_standard`에 두고,
`shiftlink/mes/analytics.py`(`coils_per_hour`, `summary`)가 계산한다. 모두 **가상 값**이며 아래 공개 자료를 근거로 현실 범위에 맞췄다.

## 1. 왜 코일 개수인가

| 기준 | 장점 | 한계 |
|---|---|---|
| 정지 횟수 | 얼마나 자주 서나 | 1분 트립과 2시간 정지가 같은 1회. 반복 증상 칸이 이미 횟수를 본다 |
| 정지 시간(분) | 원래 측정값 | 설비마다 무게가 다르다. 이전 방식(직접 + 대기 설비 수 × 시간)은 직렬 라인에서 같은 시간을 여러 번 셌다(HPU-01 97분 → "485분") |
| **못 만든 코일(개)** | 공장 언어 그대로. 원인 설비끼리 바로 비교. 출측이 멈춘 시간을 한 번만 센다 | 표준 생산 속도라는 가정이 필요 → 아래 근거 |

화면(정지 손실 칸):
- 맨 위 한 줄: 왼쪽 "생산 1,749 / 계획 1,800개", 오른쪽 "손실 51개 · 2.8%"(계획 대비).
- 링 두 개: ① 생산 링 100% = 계획 생산량(회색 생산 + 끝부분 손실, 가운데 "97.2% 생산") ② 손실 링 100% = 이번 주 손실(설비별 몫, 설비 종류 색, 가운데 "51개 손실"). 오른쪽에 계획·생산·손실(계획 대비 %).
- (10/15 갱신) 두 그래프는 SVG 하나에 같은 중심 높이로 나란히 — 왼쪽 작은 생산 링(반지름 38), 오른쪽 큰 손실 도넛(반지름 52), 굵기는 반지름의 약 0.4로 맞춤. 요약(계획·생산 / 손실)은 그래프 위 한 줄. 손실 도넛은 조각 바깥에 설비 코드·못 만든 코일 수를 직접 단다("HPU-01 17"). 라벨은 조각 가운데 각도 바깥, 같은 쪽 라벨은 16px 이상 떨어지게 민다(`lossDonut`).
- 손실 링 조각은 6개까지: 손실 상위 5대는 설비 종류 색, 6번째부터는 회색 '기타' 한 조각(작은 조각은 각도로 구별되지 않는다). 설비 줄 왼쪽 표지도 같은 규칙.
- 링은 화면 읽기용 요약을 단다(`role=img`, 예: "손실 51개 중 HPU-01 17개, …, 기타 4개"). 보이는 숫자는 오른쪽 요약과 아래 설비 줄.
- 범례(링 아래): 색 표지 + "HPU-01 17개 · 0.9%"(못 만든 코일 · 계획 대비 %). 손실 링은 설비 몫을 크게 보이고, 숫자는 계획 대비로 읽는다.
- 설비 줄: 같은 색 왼쪽 표지 · 못 만든 코일 N개 · "MTBF 223시간 · MTTR 53분 · 정지 97분"(MTBF·MTTR은 4주 기준, 계획 대비 %는 위 요약에만). 손실이 없는 설비는 맨 아래 "정지 없음 · …" 한 줄.
- 모든 %는 계획 생산량 대비다(손실 중 몫으로 보이지 않는다).

## 2. 계산

```
표준 생산 속도(개/h) = 연간 능력(t) ÷ 연간 유효 가동 시간(h) ÷ 평균 코일 중량(t)
                     = 1,500,000 ÷ 7,000 ÷ 20 ≈ 10.7개/h (약 5.6분에 1개)
설비별 손실(개)      = 이번 주(7일) 그 설비 사건의 정지 시간(h) × 10.7   — 라인을 세운 설비만
이번 주 계획(개)     = 계획 가동 168 h × 10.7 ≈ 1,800개
이번 주 생산(개)     = 계획 − 손실
```

- **라인을 세웠나**: 원인 설비가 라인 경로(RT-01 → RT-02 → RT-03 → CV-01)이거나, 구동·유압·공압·전원·인터록 관계를 여러 단계 따라가 경로 설비에 닿으면 라인 정지(`_halts_line`). 지금 카탈로그에서는 PDP-01 → GR/HPU → 경로처럼 모든 설비가 경로에 닿는다. 분기(CV-02)만 세우는 설비가 생기면 손실 0, "라인 영향 없음".
- **직렬 라인**: 몇 대가 같이 기다려도 출측이 멈춘 시간은 한 번 → 대기 설비 수를 곱하지 않는다.
- **시뮬레이터 실제 출측 수를 쓰지 않는 이유**: 모의 MES는 Unity 시연 축척(이송 구간 4.8 m)이라 분당 6개가 나온다(30분 180개 실측). 현실 범위와 맞지 않아 표준 속도로 환산한다.

## 4. 합성 이력 기준 값

이번 주 계획 1,800개 → 손실 51개(2.8%), 생산 1,749개. HPU-01 17개(정지 97분) · RT-02 9개(51분) · CV-01 7개(41분) · CAU-01 7개(39분) · GR-02 6개(33분) · RT-03 4개(23분). 나머지 4대(PDP-01·GR-01·RT-01·CV-02)는 이번 주 정지 없음.
`tests/test_mes_analytics.py`가 대조한다. 실제 공장의 비계획 정지 손실은 보통 이보다 크다 — 합성 이력은 4주 사건 32건(설비 10대)만 심었다.

## 5. 한계와 다음

- **감속 손실**: 임시 조치로 라인 속도를 낮춘 시간(예: 96 → 80 m/min)은 정지가 아니라 세지 않는다. 지금 실행 사건은 속도 센서(`rt_speed`·`cv_speed`)로 ∫(표준 − 실제)/표준 을 셀 수 있지만 저장 이력에는 속도 기록이 없다.
- **겹치는 정지**: 서로 다른 원인이 같은 시간에 라인을 세우면 두 번 센다(지금 이력에는 겹침 없음). 생기면 라인 정지 구간을 합집합으로 바꾼다.
- **제품별 속도**: 제품(CR-A08·CR-B12)마다 두께·폭이 달라 속도가 다르지만 한 값으로 둔다.
- 실제 공장에 붙일 때는 이 세 값 대신 MES의 표준 사이클 타임(제품별)·생산 계획을 쓴다.

- (10/15 갱신) 생산 링과 손실 도넛은 같은 크기(반지름 52, 굵기 22). 요약은 그래프 위 표(계획 · 생산 | 손실 · 손실률, 값 20px). 홈 '현재 설비 상황'에도 같은 생산 링을 작게(64px) 둔다 — 사용자 결정.
