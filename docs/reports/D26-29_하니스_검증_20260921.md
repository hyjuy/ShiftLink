## 2. 필수 안전·무결성 조건 (100% 항목)

- 안전 카드 top-k 밖 독립 조회: `search_safety_cards` 전수 조회 + 병합 시 card_id 중복 0, 안전 선두. 병합 전 원본을 `tool_results["safety_cards"]`로 보존해 독립 감사 가능.
- 조건 불일치·exclusions 오적용 0건(결정적 매칭, 관측 부재는 `condition_status="unverified"`로 보수적 포함).
- 검토 대기(needs_review) → accepted 자동 편입 0건. 변환 카드 status는 무조건 draft. 근거·단계·인계 방법 자동 창작 0건.
- 정답 유출: 카나리 토큰(평가용 qqz7-, KB용 zzk9-)이 적재 KB·렌더 텍스트에 나타나는지 검사, 유출 0건. dev/sealed split 카드는 적재 시 ValueError.
- 실패 이유 미상·유형 미상은 None/unknown 그대로 보존(렌더 시 "미상" 표기, 데이터는 불변).
- 모델 호출: 기본 1회, 검증 실패 시에만 1회 재시도, 재실패는 review_queue(저장 차단).

## 3. 실행 성능 (대체 환경 측정)

- 측정 환경: **개발 PC(Windows 11, Python 3.10)**. Jetson 15W 측정 아님 — 15W 수치로 주장하지 않는다.
- dev 스위트(46케이스, 파이프라인 E2E 포함) 전체 실행 약 0.4초, 관련 pytest 112건 1.4초.
- LLM 호출 0회(결정적 스텁), 토큰·비용 0, 재시도 발생 0. 실제 모델·임베딩 연결 후 p50/p95·RAM은 재측정 필요(N-4/N-5 미결).

## 4. 반복 루프 기록

| 반복 | 실패 | 원인 분류 | 조치 | 결과 |
|---|---|---|---|---|
| 1 | schemas evidence_ids 형식 검사 누락 | 스키마(계약 이탈) | 메인이 패턴 검증 추가 | 22건 통과 |
| 2 | 파이프라인: safety_cards 원본 미보존, 재시도 미구현 | 응답/파이프라인(계약 이탈) | 메인이 보존 키·1회 재시도 추가 | 79건 통과 |
| 3 | 하니스 A·F 항상 not_implemented | 평가기 | C가 실평가기 구현(기대값 불변) | dev 46/46 |
| 4 | holdout 13건 실패 | **전부 fixture 형식 결함**(fixture_cards 부재, 부분 카드 dict, split="holdout" 비허용값, 설비 인스턴스 ID) | C가 형식만 보완, 기대값·의도·카나리 불변 | holdout 20/20 |
| 5 | report.json git_rev="unknown" | 평가기(경로 버그) | 메인이 cwd 수정 | rev 기록됨 |

- 평가기 수정 사유는 위와 같이 기록했고, 수정 전 점수(holdout 0/6)는 형식 결함 포함 수치라 수정 후와 직접 비교 불가.
- **holdout 노출 기록**: 반복 4에서 메인·C가 holdout 내용을 형식 수리 목적으로 열람했다. 제품 코드는 holdout 분석으로 변경하지 않아 과적합은 없으나, 엄격한 독립성 기준으로는 본 holdout을 "형식 수리 이력 있음"으로 표시한다. 이후 제품 튜닝에 holdout 실패를 사용하게 되면 규칙대로 dev로 전환하고 새 holdout을 만든다. 기존 봉인셋(docs/data/ 카나리 파일)은 튜닝에 사용하지 않았다.
