# ShiftLink Unity 제조 공정 시연

현재 모의 MES 장비 전체와 코일 이송 공정을 표현하는 첫 단계다. 장비 외형·크기·배치는 시연용이며 실제 장비를 재현한 CAD 모델이 아니다. 압연 본체는 현재 MES 데이터 범위에 포함되지 않는다.

## 실행

1. Unity Hub에서 실제 Editor를 설치한다. 프로젝트 기준 버전은 2021.3.17f1이며 Built-in Render Pipeline을 사용한다. 다른 버전에서 열 경우 복사본으로 확인한다. 현재 PC에는 해당 버전의 설치 목록만 있고 Unity.exe가 없다.
2. 저장소 루트에서 기준정보를 내보낸다.

   ```powershell
   python -B scripts/export_unity_mes.py
   ```

   실행 중인 MES의 활성 구성을 사용할 때는 다음 명령으로 내보낸다. 연결 실패 시 오프라인 목록으로 자동 대체하지 않는다.

   ```powershell
   python -B scripts/export_unity_mes.py --mes-url http://127.0.0.1:8000
   ```

3. Unity Hub의 Add로 이 폴더를 등록하고 연다. 처음 불러올 때 Unity가 기본 설정과 .meta 파일을 생성한다.
4. 메뉴에서 **ShiftLink → Create Manufacturing Scene**을 선택한다. 저장되지 않은 기존 장면이 있으면 Unity 저장 확인에 따라 처리한다.
5. MES를 실행한다. 기존 데이터베이스 대신 별도의 시연용 DB를 지정할 수 있다.

   ```powershell
   python -m shiftlink.mes --port 8000 --db mes_data/unity-demo.sqlite3
   ```

6. Play를 누른다. WASD 이동, Q/E 높이, 마우스 오른쪽 버튼 시선 변경, Shift 빠른 이동, 왼쪽 클릭 장비 정보 선택이다. 장면의 MesSceneBootstrap Inspector에서 mesBaseUrl을 변경할 수 있다.
7. MES 웹 화면에서 공정을 시작하거나 고장 시나리오를 적용한다. Unity는 /api/state를 읽어서 상태와 코일 위치를 표시한다. 서버 연결 실패나 config_id 불일치 시 상태를 회색으로 표시하고 코일을 숨긴다.
8. MES 구성이 바뀌면 Play를 중단하고 --mes-url로 다시 내보낸 후 재시작한다.

장비 클릭은 장면 정보를 선택하는 기능이다. AI 이미지 인식 결과가 아니다. 장비 라벨·상태등·관계선은 학습 데이터 촬영 단계에서 제외해야 한다.

## 기준 장비와 공정

기본 카탈로그 DS-v1.0, 라인 LN-0001의 장비 10대와 유형 6종을 사용한다. 실행 MES의 구성이 변경되면 활성 구성 API가 우선이다.

| 구역 | 장비 |
|---|---|
| 입측 | GR-01(EQ-0004), RT-01(EQ-0006) |
| 중앙 | RT-02(EQ-0007) |
| 출측 | GR-02(EQ-0005), RT-03(EQ-0008), CV-01(EQ-0009), CV-02(EQ-0010) |
| 유틸리티 | HPU-01(EQ-0001), PDP-01(EQ-0002), CAU-01(EQ-0003) |

주경로는 RT-01 → RT-02 → RT-03 → CV-01, 스크랩 분기는 RT-03 → CV-02다. 분기 관계는 표시하지만 현재 MES 엔진은 코일을 주경로로만 이동시킨다. 구동·공급 관계도 선으로 표시한다. 좌표는 구역별 실제 배치도가 아니라 경로와 관계를 읽기 위한 임시 배치다. 새 유형은 기본 모형으로 표시한다.

## 팀과 첫 주 일정

| 담당 | 첫 작업 | 완료 기준 |
|---|---|---|
| MES·공정 | 전체 장비·주경로·분기 확인, 활성 구성 내보내기 | API의 ID와 Unity 입력의 ID가 일치 |
| Unity | 유형별 간단한 모형, 카메라 이동, MES 상태·코일 위치 표현 | 전체 장비 누락 없이 시연 장면 실행 |
| 통합·검증 | 연결 오류·구성 변경 처리, 시연 절차 | 실제 Editor 실행 및 MES 연동 점검 |

1~2일차: 설치·공정 공간·장비 모형. 3~4일차: 자동 촬영과 가림을 고려한 정답 라벨. 5일차: 장비 6종 탐지 모델 학습. 6일차: 별도 장면 평가와 보완. 7일차: PDA 연동과 리허설.

학습용 자동 촬영·정답 라벨 생성, AI 학습·추론, PDA 영상 전달은 다음 단계이며 이번 초기 구현에 포함되지 않았다. 실제 장비 인식 성능은 실제 사진으로 별도 검증한다. 같은 유형의 개별 장비 ID는 이미지 인식만으로 확정하지 않는다.

## 검증

```powershell
python -B -m unittest tests.test_unity_mes_export -v
```

현재 검증은 내보내기 도구와 실제 MES HTTP API 연동에 한정된다. Unity Editor가 없어 C# 컴파일, 장면 렌더링, 조작, Unity에서의 상태 조회는 아직 실행 검증하지 못했다.
