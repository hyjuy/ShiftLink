시연 파이프라인 (2026-10-02)

작성: 최재영·Claude · 상태: 초안, 팀 공유용 근거: 개발계획_경량_20260929.md 1절(A안 라즈베리파이 분리), PDA_라즈베리파이_모니터_작업계획_20261001.md, 경량계획_주간진척_루브릭_20261001.md 발표 목표: 카메라로 설비 인식 → Jetson LLM이 카드 근거로 답변 → 인계 로컬 저장 → 클라우드 DB 업로드를 한 번에 시연한다.

1. 장비와 역할

장비 역할 돌리는 것
라즈베리파이 4 Model B (4 GB) + 모니터 + 키보드·마우스 + USB 웹캠 PDA 단말 Chromium 키오스크(PDA·MES 화면), 카메라 루프(CNN 6클래스 분류)
Jetson Orin Nano Super (7.6 GB, 15 W, headless) 현장 엣지 서버 MES 서버 + 데이터 생성기, 검색·에이전트, ollama(exaone 2.4B), 로컬 SQLite
Aiven MySQL 클라우드 DB 인계 기록, 질의 기록, 피드백 (오프라인이어도 현장은 동작)
노트북 (선택) 다음 조·관리자 화면, 비상 시 MES 대체 서버 브라우저

2. MES와 데이터 생성기 위치 → Jetson

라즈베리파이 4 (4 GB) Jetson Orin Nano (7.6 GB)
이미 하는 일 Chromium 키오스크(0.6~0.9 GB, CPU 많이 씀) + 웹캠 + CNN 연속 추론(CPU 1~2코어) exaone(GPU). 10/2 측정 중 여유 메모리 3.1~3.5 GB, CPU 여유
MES 서버 + 생성기를 얹으면 메모리는 되지만 CPU 4코어를 화면·CNN·생성기가 나눠 실시간 그래프와 인식이 함께 느려짐 표준 라이브러리 HTTP 서버 + 생성기 + SQLite ≈ 0.1~0.2 GB, 여유 3 GB 안
역할 작업자가 쓰는 단말 설비 데이터 + 지식 + LLM이 모인 엣지 서버
  • 데이터 생성기는 MES 서버 안의 엔진(shiftlink/mes/engine.py)이므로 MES와 같은 프로세스로 돌린다.
  • Jetson은 GUI 없이 운영한다(작업계획 A3). 메모리 0.5~1 GB를 더 확보한다.
  • 비상 대안: 시연 중 Jetson 여유 메모리가 1 GB 아래면 노트북에서 python -m shiftlink.mes --host 0.0.0.0로 MES만 옮긴다. 화면 주소만 바꾸고 코드는 그대로다.

한 번의 질의 순서

단계 어디서 무엇
1 라즈베리파이 작업자가 설비(대체 객체) 앞에 선다. 웹캠 CNN이 GR을 확정해 POST /api/equipment/scan
2 PDA 화면 최근 인식 결과를 폴링해 그 설비 화면으로 바뀐다
3 PDA 화면 (MES) 그 설비의 운전/정지/알람 상태와 실시간 센서값을 본다
4 PDA 화면 키보드로 질문 입력 (예: "갈리는 소리가 나요") → POST /api/query
5 Jetson 서버 최근 인식 설비 + MES 현재 센서값을 자동으로 붙여 FixedPipeline 호출
6 Jetson 검색 → 안전 카드 → exaone 답변 (p95 약 5초)
7 PDA 화면 안전 공지 → 답변 → 근거 카드 순서로 표시
8 PDA 화면 → Jetson 인계 메모 작성 → POST /api/handover → 로컬 저장 → 연결되면 Aiven 업로드
  • 5단계가 핵심: 10/2 최종 측정에서 "1위 카드 조건 미확인으로 확인 대상 카드로 끝남"(Q-021·H-011·H-017)은 질문에 값이 없어서였다. 시연에서는 MES 생성기의 현재 값이 들어가므로 T2 카드 조건이 실제로 판정된다(예: 장력 low → K-1204).
  • 통신은 HTTP만 쓴다. 서버가 이미 ThreadingHTTPServer이므로 MQTT 브로커를 추가하지 않는다.

4. 클라우드 DB 활용 (Aiven, db/aiven_schema.sql에 표가 이미 있음)

우선 쓰임 올리는 것 시연 장면 루브릭
1 인계 기록 보관 (handover_record·handover_item) 인계 메모, 인용 카드, 설비, 작성 시각. 인계 ID로 같은 ID는 한 번만 저장 랜선을 뽑고 인계 2건 작성 → 다시 꽂으면 자동 업로드, 클라우드에 정확히 2건 G3·G4, W2-4, W3-3
2 교대 간 공유 (1과 같음) 노트북 = "다음 조 관리자 화면"이 클라우드 인계 목록을 읽음 —
3 질의·답변 기록 (pipeline_run·eval_result) 질문, 설비, 인용 카드, 해당 지식 없음 여부, 응답 시간, 모델·KB 버전 발표 자료의 p95·성공률을 클라우드 기록에서 집계 W3-1
4 현장 피드백 (human_review) 답변마다 "도움됨 / 틀림" 틀림이 쌓인 카드 = 다음 카드 개선 목록 —
5 설비 이벤트 요약 알람·정지 이벤트만 관리자 화면 "오늘 GR-01 정지 2회" —

올리지 않는 것: 웹캠 이미지(파이 밖으로 안 나감), 원시 센서 스트림(양이 많고 현장 데이터), LLM 호출(현장 오프라인 원칙).

시연 메시지: 인터넷이 끊겨도 현장은 돌고, 연결되면 기록이 빠짐없이 올라간다.

5. 새로 만들 것 (2주차 10/5~10/8)

# 일 담당 크기 루브릭
1 POST /api/query: 최근 인식 설비·현재 센서값을 붙여 FixedPipeline 호출 Claude 반나절 W2-1, G1, G2
2 PDA 화면의 가짜 검색(runSearch)을 /api/query 호출로 교체, 응답 렌더 Cursor 반나절 W2-1
3 POST /api/handover + 로컬 SQLite outbox + Aiven 업로더(재시도, 같은 ID 중복 방지) Claude 하루 W2-4, G3, G4
4 노트북용 "다음 조" 인계 목록 화면(클라우드 읽기 전용) Cursor 반나절 —
5 질의 기록 업로드(pipeline_run) Claude 2시간 W3-1
6 라즈베리파이 카메라 루프·키오스크·systemd (작업계획 D1~D3) 허재원 진행 중 W2-3

새 엔드포인트·필드명은 같은 변경 안에서 docs/collaboration/naming_registry/registry.md에 등록한다.
