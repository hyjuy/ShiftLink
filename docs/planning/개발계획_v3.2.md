## 9. 운영 규칙

- **스탠드업**: 매일 오전 10분. 어제 한 일, 오늘 할 일, 막힌 것, **게이트까지 남은 양**을 말한다.
- **PR**
  - 작게 올리고, 리뷰는 24시간 안에 한다.
  - 스키마·도구 인터페이스 변경은 유현준이 반드시 리뷰한다(`docs/guides/branching.md`).
  - 머지는 squash merge로 한다.
- **브랜치·태그**
  - 브랜치: `feat/*`, `fix/*`, `chore/*`. 동결 이후에는 `hotfix/*`만 쓴다.
  - 태그: `v0.1-week1`, `v0.2-week2`, `v0.3-week3`, `data-v1.0-sealed`, `v0.5-eval`, `v1.0`
- **Jetson 점유**
  - 🔒 예약 시간대에만 독점한다.
  - 공용 실행본 `~/shiftlink`는 `git pull` 전용이다(커밋 금지). 개인 작업은 `~/work/<이름>/`에서 한다.
  - 평소 개발은 PC에서 같은 모델 digest로 한다.
- **실험 규칙 (autoresearch 원칙 차용)**
  - 실험 1회당 고정 시간 예산을 둔다.
  - 단일 주 지표는 구조화 출력 성공률이다(보조 지표 p95·온도).
  - 한 번에 한 변수만 바꾼다(모델·양자화·프롬프트·`num_ctx`·전력 모드 중 하나).
  - keep/discard 판정을 `experiments.tsv`에 추가만 한다.
  - **봉인셋은 반복 루프에 절대 넣지 않는다.**
- **결정 로그**: 노션에 결정·근거·결정자·날짜로 한 줄씩 남긴다. 게이트 미달 시 조치도 여기에 기록한다.
- **안전·등급 표기**
  - MVP 최고 등급은 L1이다.
  - 팀 검수와 서브에이전트 판정은 L2로 표기하지 않는다.
  - 데모 화면에 "실제 작업지시 아님"을 상시 표시한다.

| 가상환경 (`.venv`) | 프로젝트마다 파이썬 패키지를 따로 설치하는 폴더 |

| `.env.example` | `.env`에 들어갈 키 이름만 적은 견본(값 없음) |
| `check_env.py` | 버전·패키지·연결 상태를 한 번에 확인하는 점검 스크립트 |
| 스모크 테스트 | "켜지기는 하는가"만 빠르게 보는 최소한의 시험 |
| pytest | 파이썬 테스트 실행 도구 |
| SSH 키 | 비밀번호 대신 쓰는 접속용 열쇠 한 쌍. 공개키는 Jetson에, 개인키는 내 PC에 둔다 |
| VSCode Remote-SSH | 내 PC의 VSCode로 Jetson 파일을 편집·실행하는 기능. Jetson에 서버 프로세스가 떠서 메모리를 쓴다 |

**Jetson·추론**

| 용어 | 뜻 |
|---|---|
| L4T | Linux for Tegra. JetPack에 포함된 Jetson용 리눅스. 이 버전으로 JetPack 버전을 확인한다 |
| CUDA / TensorRT | NVIDIA GPU 연산 라이브러리 / 추론 최적화 라이브러리 |
| nvpmodel / tegrastats | 전력 모드를 조회·변경하는 명령 / 온도·메모리 사용량을 출력하는 명령 |
| GPU 오프로드 | 모델 연산을 GPU로 넘기는 것. `ollama ps`에 "100% GPU"로 표시되어야 한다 |
| GUI 끔 (`multi-user.target`) | 데스크톱 화면 없이 부팅하는 설정. 메모리를 아낄 수 있다 |
| 모델 태그 / digest | Ollama 모델의 이름표 / 모델 파일의 고유 지문. 태그가 같아도 digest가 다르면 다른 파일이다 |
| `models.lock` | 팀이 쓰는 모델의 태그·digest와 Ollama 버전을 적어 두는 파일 |
| 첫 토큰 지연 (TTFT) | 요청 후 첫 글자가 나올 때까지의 시간. 전체 응답 시간과 따로 잰다 |
| `OLLAMA_NUM_PARALLEL` | Ollama가 동시에 처리하는 요청 수. 1이면 하나씩 처리한다 |
| 점유 규칙 | Jetson 1대를 여럿이 쓸 때 측정 시간대를 예약해 서로 방해하지 않게 하는 규칙 |
| sentence-transformers / ONNX | 임베딩 모델을 실행하는 라이브러리 / 여러 런타임에서 돌릴 수 있게 바꾼 모델 형식 |
| 커뮤니티 변환본 | 원 개발자가 아닌 사람이 GGUF 등으로 바꿔 올린 모델. 원본과 결과가 같은지 확인해야 한다 |
| 코사인 유사도 | 두 벡터가 같은 방향을 가리키는 정도(1에 가까울수록 같음). 변환본 검증에 쓴다 |

**데이터·실험**

| 용어 | 뜻 |
|---|---|
| autoresearch 방식 | karpathy/autoresearch의 실험 원칙. 고정 시간 예산 안에서 한 번에 하나만 바꿔 실행하고, 단일 지표로 keep/discard를 판정해 로그에 쌓는다 |
| 고정 시간 예산 | 모든 실험에 같은 시간만 쓰게 해서 결과를 공정하게 비교하는 규칙 |
| keep / discard | 지표가 나아진 변경은 남기고, 아니면 버리는 판정 |
| `experiments.tsv` | 실험 설정·지표·판정을 한 줄씩 추가하는 기록표 |
| 평가 대상 버전 고정 | 채점 전에 코드·프롬프트·모델을 고정해 "채점하면서 고치기"를 막는 절차(`v0.5-eval`) |
| judge–사람 일치율 | AI 심사 결과가 사람 판정과 같은 비율. judge를 믿어도 되는지 재는 값 |
| 안전 서브에이전트 | 안전관리자 페르소나를 준 별도 AI 검토자. 사람 검수를 대신하지 않으며 L2(전문가 승인)로 표기하지 않는다 |
| outbox | 보낼 기록을 로컬에 먼저 쌓아 두는 대기열. 네트워크가 끊겨도 기록이 사라지지 않는다 |
| 배치 업로드 | 쌓아 둔 기록을 정해진 주기에 한꺼번에 올리는 방식(여기서는 하루 1회) |
| 멱등 업로드 | 같은 기록을 여러 번 올려도 한 번 올린 것과 결과가 같도록 만든 방식. 실패 후 다시 시도해도 안전하다 |
