## 감점 내역

### A1 터치 타깃 (-2 / 8)
- 근거: `pda.html:146` `#alert` 아래쪽 여백은 `padding:4px 0`와 `border-bottom:2px`이고, 그 바로 아래가 화면 appbar의 `← 이전`(`pda.html:50`, 48px)이다. 스캔·직접 선택·설비 변경 확인 화면에서는 `#ctx`가 숨겨지므로(`pda.js:129`) 고장 알림 행(`.alrow`, `pda.html:148`)과 `← 이전` 버튼 사이가 약 6px이다.
- 왜 문제인가: 간격 기준 8dp에 못 미친다. 장갑 낀 손으로 `← 이전`을 누르다가 고장 알림 행을 누르면 설비 변경 확인 화면으로 넘어간다.
- 근거: `pda.html:481` `#hoPending`(`button.outbox-note`, `margin:0`, `pda.html:93`)이 appbar 바로 아래 붙어 있다. appbar는 최소 높이 50px에 `.ic` 48px를 가운데 맞춤하고 1px 테두리를 둔다(`pda.html:47-50`). 그래서 `← 이전`·`⌂ 홈`과의 간격이 약 2px이다.
- 왜 문제인가: 인계 확인 화면에서 뒤로 가려다 업로드 대기 화면이 열린다. 업로드 대기 건이 있을 때만 나타나지만, 실제로 생기는 상태다.

### A2 대비 (-2 / 7)
- 근거: 실제로 쓰이는 글자색·배경색 쌍을 계산했다. `.card .body` `#AEB9C4` / `#161B22` = 약 8.7:1, `.why.no` `#FF8A3D` / `#161B22` = 약 7.4:1, `.safety .basis` `#FFC9C5` / `#3A0F0D` = 약 11.5:1로 모두 7:1을 넘는다. 그런데도 조치 본문(know_how)이 회색이다. 근거는 `pda.html:184`(`.card .body{color:var(--tx-2)}`), T3 단계 목록 `pda.html:203-204`, 시도 기록 값 `pda.html:237`(`.try .fld .v{color:var(--tx-2)}`)이다.
- 왜 문제인가: 루브릭은 회색 사용 자체를 감점한다. 작업자가 실제로 따라 할 행동 문장이 흰색(`--tx`)이 아니라 회색이어서, 햇빛·오염 화면에서 가장 먼저 읽기 어려워진다.
- 근거: `pda.html:172` `.safety .basis`가 11.5px, 기본 굵기, 파스텔 분홍 `#FFC9C5`다. `pda.html:241` `.t4 .k`는 10.5px, `pda.html:169` `.safety .kid`와 `pda.html:198` `.pill`은 11px다.
- 왜 문제인가: 조문 번호(안전 근거)가 화면에서 가장 작은 축의 글씨로 나온다. 파스텔에 얇은 소형 글씨이므로 감점 대상이다.

### A4 엄지 도달 (-2 / 5)
- 근거: `pda.html:146-153`, `pda.js:1426-1435`. 고장 알림 띠의 각 행이 `<button>`이고 화면 맨 위(`#app` 첫 영역, `pda.html:300`)에 있다. 누르면 설비 변경 확인 화면으로 넘어간다(`pda.js:1434`).
- 왜 문제인가: 루브릭은 "상단은 표시 전용"이다. 한 손 엄지로는 가장 닿기 어려운 곳에 누르는 요소를 두었다.
- 근거: `pda.html:404-424`. 주 행동인 `검색`(`#doSearch`, `pda.html:423`)이 스크롤 영역 `.pane`(`overflow-y:auto`, `pda.html:55`)의 맨 끝 자식이다. 그 위로 증상 목록(행당 56px + 간격 8px, 설비 카드 수만큼), 관측값 목록, 입력 줄이 쌓인다. 인계 작성의 `저장`(`pda.html:510`)도 같은 구조다(`pda.html:497-511`).
- 왜 문제인가: 증상을 고른 직후 검색 버튼이 화면 밖에 있을 수 있다. 하단 고정이 아니라서 매번 끝까지 쓸어내려야 하고, 버튼이 아래 있다는 표시도 없다.

### C3 실패 후 다음 동선 (-1 / 4)
- 근거: `pda.js:904-909`, `pda.js:967-979`. `이 조치 시도` 버튼 하나를 누르는 즉시 `failure_reason: '조치 후에도 증상이 유지됨'`인 실패 기록이 생기고 시도 기록 화면으로 넘어간다. "효과 있음" 선택지가 없다. `.try.solved` 스타일(`pda.html:231`)은 정의만 있고 어디서도 쓰이지 않는다. 기록을 되돌리는 동작도 없다.
- 왜 문제인가: 버튼 문구는 "시도"인데 실제로는 "실패 기록"이다. 장갑을 낀 손으로 잘못 누르면 하지도 않은 조치가 실패로 남고, 그 기록이 인계 맥락에 그대로 들어간다(`pda.js:1210-1212`, `pda.js:1360`). 조치가 성공했을 때 끝내는 경로도 없다.

- **실측 필요 — 작업 선택 화면.** `pda.html:376-380`에서 버튼 4개와 라벨이 하단에 쌓여 있다. 맨 위의 `증상 질의`(주 행동)가 하단 40% 경계 밖으로 밀리는지 재야 한다.
- **실측 필요 — 안전 덩어리 안 스크롤.** `pda.html:161-162`에서 `.safety-stack`은 `max-height:50vh; overflow-y:auto`인데 넘친다는 표시(그라데이션, "더 있음" 문구)가 코드에 없다. 터치 기기는 스크롤바가 숨겨지므로, 안전 카드가 길거나 여러 장이면 아래쪽 `근거 —` 줄(`pda.js:788`)이 상자 안에서 잘려도 작업자가 모를 수 있다. 바깥 pane 스크롤과 안쪽 스크롤이 겹쳐서, 장갑 낀 손으로 쓸면 어느 쪽이 움직일지도 예측하기 어렵다. - **화면 밀림 — 누르려던 버튼이 움직인다.** `pda.js:1422`에서 3초 감시(`pda.js:1388`) 중 고장이 생기면 `#alert`가 숨김에서 표시로 바뀐다. 이 띠는 모든 화면 위에 흐름으로 끼어 있어(`pda.html:300`) 아래 버튼 전체가 한꺼번에 아래로 밀린다. 증상 목록도 MES 상황이 바뀌면 다시 정렬된다(`pda.js:357`). 누르는 순간에 순서가 바뀌면 다른 증상이 선택된다. 루브릭 A1 문면(크기·간격)에 정확히 맞는 항목이 없어 점수에는 넣지 않았지만, 오조작 위험은 이번 라운드에서 가장 크다.
