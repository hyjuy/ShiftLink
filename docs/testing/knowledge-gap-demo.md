# 지식 공백 채우기 시연 시나리오 (2026-10-15)

카드에 없던 상황이 현장 조치 기록으로 카드 초안이 되고, 승인된 뒤 다음 교대의 질문에 답하기까지를 보여 준다.
화면은 PDA 질의·조치 기록과 대시보드 **지식 공백** 칸(지식 없음 → 카드 초안 → 검수 대기 → 승인 → 카드로 답).
지식 공백 칸은 합성 이력 없이 MES DB에 쌓인 실제 기록만 센다(정의: `docs/design/pda_ui/dashboard_analytics_20261014.md` 1절).

자동 리허설: `tests/test_knowledge_gap_rehearsal.py`가 아래 장면 1~7을 같은 입력으로 서버 함수에 돌려 단계마다 숫자를 확인한다.
판정 모델은 쓰지 않는다(장면 1~4는 검색 후보 카드가 없어 판정 없이 '해당 지식 없음', 장면 6은 판정을 '답 가능'으로 고정).
실제 판정 모델의 판단은 Jetson에서 확인한다 — 장면 1~4의 질문은 10/13 Jetson에서 '해당 지식 없음', 장면 6은 10/13 Jetson에서
K-7000 단계별 답을 확인했다(`docs/testing/field-resolution-card-draft.tdd.md` 4.2·8절).

## 준비

1. MES DB 테스트 데이터 비우기 → 지식 공백 칸이 모두 0. (Jetson: `field-resolution-card-draft.tdd.md` 8절 준비 1)
2. 지난 시연에서 승격한 카드가 남지 않게 `python scripts/field_card_promote.py restore`(Jetson은 `--remote jetson@100.115.59.4`)를 한 번 실행한다. 되돌릴 것이 없으면 아무것도 하지 않는다.
3. 장면마다 MES "주요 고장 → 유압유 과열"로 새로 시작한다(앞 장면의 복구 상태가 남지 않게).

조치 입력은 `field-resolution-card-draft.tdd.md` 7.2 상황지 A1·A2·B와 같다. 'MES 단계 3 + 재가동' = PDA 조치 기록의
MES 단계 칩 셋(유면·냉각·밸브 점검 → 냉각 성능 복구 → 유온·공급 정상 확인)과 재가동 칩을 차례로 완료(재가동 잠금 응답 '해당 없음').

## 주의

- 장면 5의 K-7000은 장면 2·3으로 MES 확인 해결 2건이 모여 승격 권장 상태라 `--force`가 필요 없다. 장면 3을 건너뛰거나 "현장에서 본 것"을 짧게 적으면(기록 빈약) 승격 권장이 아니어서 `--force`가 필요하다.
- 장면 5 로컬(노트북)은 `promote K-7000 --yes`만으로 카드 묶음에 들어가지만, **MES 서버를 다시 띄워야** 질의가 새 카드를 찾는다(질의 파이프라인은 시작할 때 카드 묶음을 읽는다). `--remote`는 Jetson MES 서비스를 다시 띄운다. 대시보드의 '승인' 숫자는 다시 띄우지 않아도 바로 바뀐다.
- 시연 뒤 `python scripts/field_card_promote.py restore`(Jetson은 `--remote …`)로 카드 묶음을 되돌린다. 되돌리면 '승인'·'카드로 답'은 0으로 돌아가고, 초안·질의 기록은 DB에 남는다.
- 장면 3의 근거 묶음, 장면 4의 별도 초안은 원인 비교로 정해진다(`field-resolution-card-draft.tdd.md` 7.3). 원인을 다르게 적으면(예: "팬 고장") 새 초안이 될 수 있다 — 원인 칩을 쓰면 안전하다.
- 지식 없음 질의는 **질의할 때마다** 센다. 리허설 중 같은 질문을 여러 번 하면 숫자가 대본보다 커진다.
