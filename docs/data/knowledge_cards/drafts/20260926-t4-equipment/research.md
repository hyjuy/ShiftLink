# 장비별 T4 합성 카드: 연구 적용과 검증 기준

검토일: 2026-09-26 (Asia/Seoul). 생성 대상: `HPU`, `GR`, `RT`, `CV`, 카탈로그의 `PDP`, `CAU`까지 여섯 장비군의 합성 인계 방법. `PDP`와 `CAU`는 기존 스키마 열거값 정책에 따라 카드의 `equipment`를 `COMMON`으로 두고 `equipment-map` 보조 자료에서 적용 인스턴스를 지정한다. 파일럿은 `HPU`, `GR`, `RT`, `CV` 네 장비군만 대상으로 하며 `PDP`·`CAU` 효과를 검증하지 않는다. 기존 `COMMON` 25건을 장비명만 바꿔 복제하지 않고 장비별 정보 대상·관측 맥락·전달 경계가 다른 방법을 추가한다. 카드 수의 상한은 25건으로 두지 않는다. 수량은 후보 검토 결과이며 충분성이나 효과의 지표가 아니다.

이 문서는 논문 원문 재확인과 이번 작업의 실행 기준이다. 아래 여섯 연구는 제조업 T4 카드의 정확성·안전성·현장 효과를 입증한 연구가 아니다. 논문의 일부 아이디어를 이 프로젝트에 옮기는 것이며 원 실험의 재현이나 모델 학습을 수행했다는 뜻이 아니다. 실행 여부·카드 수·검증 결과는 같은 폴더의 실제 산출물과 검증 보고서로 확인한다. 계획을 완료 기록으로 사용하지 않는다.

## 2. 생성 절차와 종료 기준

1. 기존 COMMON 카드와 프로젝트 장비 열거값을 기준으로 장비별 전달 실패 후보를 넓힌다. 장비 상태의 진단·조작 절차가 아니라 그 상태를 정확히 인계하는 방법을 만든다.
2. 페르소나에 장비 사실을 넣지 않는다. 페르소나는 생략 경향·표현 방식·되묻는 관점만 정하고 관측은 합성 상황 원장에 둔다.
3. 후보별로 장비, 적용 상황, 필요한 정보, 정보공백, 송신자, 수신자, 전달 시점, 채널, 수신 확인을 명세한다. `required_context`, `recipient_role`, `timing`, `channel`, `acknowledgement` 다섯 스키마 필드로 대응한다.
4. 모순을 제거한다. 미관측 값을 정상으로 바꾸거나, 문서가 없다는 사실을 미실시 확정으로 바꾸거나, 직급으로 승인권을 추론하거나, 읽음 표시로 업무 인수를 확정하면 수정 또는 탈락한다.
5. 장비명·위치·말투를 지운 뒤 기존 카드와 비교한다. 핵심 정보 관계와 수신 확인 방법이 같다면 별도 방법으로 채택하지 않는다. 같은 정보 묶음의 관측시각만 다른 경우도 단일 방법으로 합친다.
6. 채택 이유와 탈락 이유를 모두 남기고 작성자가 아닌 에이전트가 장비 적합성·T4 적합성·미확인 보존·의미 중복을 검토한다. 인계 완료, 정보 해결, 작업 승인을 별개 상태로 유지한다.
7. 장비별로 서로 다른 전달 문제를 설명할 수 있고, 남은 후보가 중복·부적절하다는 근거가 있을 때 이번 배치를 마친다. 이는 열린 확장 기준이며 모든 현장 상황을 망라했다는 선언이 아니다.

합성 상황에서 정한 숫자·문서번호·시간은 실제 설치장비 기준이나 허용치로 일반화하지 않는다. 정비·차단·재가동 수행법을 새로 만들지 않는다. 장비별 카드도 개발 초안이며 사람 승인·실제 사건 근거·운영 채택을 만들어 기록하지 않는다.

## 3. 정보가 분리된 파일럿 프로토콜

이번 소규모 시험은 네 장비 각각 한 상황, 동일 상황의 세 조건으로 구성한다. 총 12개 실행 결과는 12개의 독립 상황 표본이 아니라 **4개의 짝지은 상황**이다. 한 번의 초기 인계와 수신 결과만 실행한다면 이를 단일 전달 시험이라고 부르며 다회차 대화 실험으로 표시하지 않는다.

| 조건 | 송신자에게 추가되는 지원 | 수신자 입력 |
|---|---|---|
| 카드 없음 | 공통 과업 지시만 | 자기 초기 정보와 해당 실행의 송신 발화 |
| 일반 체크리스트 | 무엇을 / 누구에게 / 언제 / 어떤 채널로 / 어떻게 수신 확인할지의 일반 5필드 | 자기 초기 정보와 해당 실행의 송신 발화 |
| 장비 T4 | 해당 장비의 선택된 카드 전문 | 자기 초기 정보와 해당 실행의 송신 발화 |

카드 효과를 송신 지원의 차이로 해석하기 위해 기본적으로 수신자는 조건 카드나 조건명을 받지 않는다. 다르게 실행한다면 변경된 노출 조건을 기록한다. 장비 T4에는 평가 상황의 숨은 값·정답·예시 회신을 넣지 않는다.

실행 전에 다음을 고정한다.

- 상황 원장의 확인 사실, 실제로 알 수 없는 항목, 최초 정보 접근 주체, 정보 전달 의무와 승인 상태. 시험 후 사실을 바꾸어 실패를 성공으로 만들지 않는다.
- 세 조건의 공통 과업 지시, 수신자의 역할·초기 지식, 응답 형식, 턴 수·분량·도구 사용 제한. 조건 간 차이는 지원 자료로 제한한다.
- 모델 식별자와 설정. 플랫폼이 모델·temperature·토큰 한도를 제공하지 않으면 `unavailable`로 기록하며 동일 설정을 계측 확인했다고 쓰지 않는다.
- 카드·원장·역할별 입력의 해시, 실행 ID, 조건 순서, 성공 판정 기준. 진행 중 기준을 바꾸면 새 프로토콜 버전으로 분리한다.

송신자는 자기에게 보이는 원장 투영만 받으며 수신자는 자기 투영과 실제 발화만 받는다. 두 역할 모두 전체 원장·기존 F8 모의 응답·평가 정답·다른 조건의 결과·기존 대본을 보지 않는다. 서로 다른 조건과 상황은 새 컨텍스트로 실행한다. 전체 대화를 한 에이전트가 작성해 놓고 역할명만 붙이는 방식은 격리 실행에 해당하지 않는다.

서브에이전트가 저장소 도구를 가진다면 단순 역할 프롬프트는 파일 접근 권한 격리가 아니다. 도구 사용 없이 전달된 입력만 처리하도록 제한하고, 가능한 도구 호출 기록을 확인한다. 기술적으로 접근을 차단하지 못한 경우 **컨텍스트 격리·도구 미사용 기반**이라고 정확히 기록한다. 실입력 로그에 정답·비공개 사실이 섞이면 해당 실행은 제외하고 이유를 보존한다.

## 4. 평가와 보고

평가자는 전체 원장과 실제 입력·출력만 받아 판정하며 해당 카드를 작성하거나 역할 응답을 생성한 에이전트와 분리한다. 조건명은 판정 전에 가리는 것이 원칙이다. 발화 내용으로 조건을 추측할 가능성은 남으므로 완전 맹검이라고 주장하지 않는다. 가능한 항목은 기계 검사하고 의미 판단은 별도 AI 판정으로 기록한다.

| 항목 | 분모·판정 기준 |
|---|---|
| 필수 정보 보존 | 실행 전 지정한 필수 사실 중 수신자가 정확히 재현한 수 / 필수 사실 수. 누락·값 오류·시각/대상 오류를 각각 남김 |
| 미확인 보존 | 지정된 미확인 항목을 미확인으로 유지한 수 / 지정된 미확인 항목 수. 분모가 0이면 N/A |
| 근거 없는 사실 생성 | 역할 입력과 이전 발화로 지지되지 않는 구체 주장 수. 우연히 원장과 일치해도 근거 없음으로 기록 |
| 잘못된 승인 추론 | 단순 수신·문서·정비 상태를 작업/운전/재가동 허가로 전환한 건수. 무발생은 실제 안전 검증을 뜻하지 않음 |
| 상태 혼동 | 수신 확인 / 정보 해결 / 작업 승인 중 서로 다른 상태를 합쳐 완료로 처리한 건수 |
| 수신 확인 적합성 | 필요한 식별·미확인·남은 요청을 되짚는지 발화 인용과 함께 판정. 단순 “확인했습니다”와 구분 |
| 재질문·소요 | 실제 턴 수와 재질문 수. 단일 전달 시험은 후속 해결 시간을 측정하지 않았다고 기록 |

각 상황에서 장비 T4와 카드 없음, 장비 T4와 일반 체크리스트의 항목별 차이를 나란히 보고한다. 원자료 수와 분모, 4상황별 차이, 개선/동률/악화 개수를 우선한다. 임의의 종합 품질점수나 4개 표본으로 정밀한 효과 추정·유의성을 제시하지 않는다. 같은 원장에서 나온 필드들을 독립 표본으로 취급하지 않는다.

독립 AI 검토는 사람 평가의 대체 증명이 아니다. 이 파일럿은 역할 입력 격리와 판정 가능성을 확인하고 다음 개선 후보를 찾는 개발 시험이다. 네 장비의 모든 카드 효과, 다른 모델·채널·페르소나 조합, 실제 작업자 행동으로 일반화하지 않는다. 작성·수정에 활용한 상황은 이후 평가용 독립 상황으로 재사용하지 않는다.

## 5. ExpeL 적용 완료의 조건

실행 기록을 읽은 뒤 같은 상황에서 어떤 필수 정보가 전달·누락되었는지 비교한다. 차이가 없다면 “차이 없음”을 남기며 실패나 개선을 만들어내지 않는다. 차이가 관찰되면 재사용 가능한 이유를 가설로 적고 카드 수정·유지·삭제 중 하나를 선택한다. 카드 수정은 필수 조건이 아니지만 **수정하지 않은 경우 수정 적용 완료라고 기록하지 않는다.**

경험 기록에는 비교한 실행 ID, 실제 발화 인용, 실패 유형, 통찰, 카드 변경 여부, 변경한 필드, 다른 상황에도 적용할 수 있는 이유, 검증하지 못한 범위를 포함한다. 수정한 카드의 동일 상황 재시험은 회귀 확인일 뿐 일반화 시험이 아니다. 별도 새 상황 재시험이 없으면 ExpeL에서 착안한 경험 비교·수정까지만 수행한 것으로 보고한다.

## 6. 논문 적용 증거 점검표

다음은 완료 판정 조건이다. 실제 산출물과 연결하기 전에는 체크 완료로 해석하지 않는다.

- [ ] 후보 전체 원장에 채택·탈락·이유가 있고 최종 개수에 맞춰 역으로 후보를 꾸미지 않았다.
- [ ] 여섯 생성 대상 장비군과 V-11~V-13의 관점·상황·채널 분포 및 적용 빈틈을 기록했다. 네 장비군 파일럿의 범위와 구분했다.
- [ ] 단계별 조건과 모순 제거 내역을 남겼으며 실제 모델 호출 단계 수를 과장하지 않았다.
- [ ] 기존 COMMON 카드와 새 카드 간 방법 차이와 의미 중복 검토를 기록했다.
- [ ] 채택된 모든 카드가 실제 T4 스키마 검사와 작성자 외 내용 검토를 거쳤다.
- [ ] 파일럿 원장·프로토콜·성공 기준·카드 해시가 실행 전에 고정되었다.
- [ ] 역할별 실입력·실출력·전달 순서와 사용 가능한 실행 설정을 보존했다.
- [ ] F8·평가 정답·비공개 정보·다른 조건의 결과가 역할 입력에 없음을 확인했다.
- [ ] 독립 판정에 근거 발화·항목별 수/분모·이견·한계가 있다.
- [ ] 결과가 없는 연구 방법은 미실행, 정적 검토는 정적 검토로 표기했다.
- [ ] ExpeL 관련 주장은 실제 실행 비교와 실제 카드 변경 범위에 한정했다.
- [ ] 문서 설계·합성 파일럿·사람 평가·현장 검증을 서로 다른 상태로 보고했다.
