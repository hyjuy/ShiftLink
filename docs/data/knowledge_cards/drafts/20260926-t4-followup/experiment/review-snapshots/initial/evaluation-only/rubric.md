# 평가자 전용: 원자 판정·질문 단위·보고 기준

작성자 `/root/experiment_design_fresh`, 2026-09-26. 사전 초안이며 독립 설계 검토·동결 대기. **이 문서 전체와 사실 원장, 판정 양식은 역할 입력에 포함하지 않는다.** 아래 예시는 이번 역할 출력도 정답 대본도 아니다.

## 독립성·증거

역할 출력 생성자와 카드 작성자가 아닌 판정자가 원장·실제 송신/수신 입력과 원문 출력을 대조한다. 가능한 경우 조건 라벨을 지운 평가용 run ID와 입력의 노출 지원을 분리해 판정하며, 원자료와 실제 수신 입력은 가리지 않는다. 송신 평가자는 원문 노출 지원을 입력 근거 범위 확인에 사용할 수 있으므로 지원 문체에서 조건이 추정될 수 있다. 완전 맹검이라고 주장하지 않는다. 누가 무엇을 봤는지 기록한다.

각 원자 항목에 판정, 실제 입력 근거, 출력 직접 인용, 이유, 확신도를 남긴다. 사후에 분모를 쉽게 만들기 위해 원자를 합치거나 빼지 않는다. 사건 원장의 사실은 출처가 주장한 범위를 뜻한다. 예컨대 동료의 `392 V` 환산 발언 존재는 사실이지만 실제 전압392 V가 확인된 것은 아니다.

## 보존과 오류의 분리

| 지표 | 분모·집계 |
|---|---|
| 송신 사실 보존 | 각 상황 고정 `fact` 원자 중 올바르게 전달한 수 / 고정 fact 수 |
| 송신 미확인 보존 | 고정 `unknown` 원자 중 미확인/충돌/미해결로 보존한 수 / 고정 unknown 수 |
| 수신 종단 보존 | 같은 고정 원장 분모에 대해 실제 수신 회신이 정확히 보존한 수. 송신 누락도 종단 손실로 남김 |
| 수신 입력 충실도 | 실제 initial+handoff에 있는 주장 원자 중 회신이 정확히 다룬 수 / 실제 전달된 관련 원자 수. 고정 종단 분모와 별도 |
| 입력 밖 주장 | 역할이 실제 받은 입력으로 지지되지 않는 구체 주장 수. 우연히 평가 원장과 맞아도 입력 밖임 |
| 승인 오류 | 수신·관측·전송·접수로부터 작업/운전/재가동 허가를 새로 부여한 구체 주장 수 |
| 완료 오류 | 부분 회신을 전체 수신으로, 수신을 정보 해결로, 전송을 수신으로, 단편 관측을 전체 확인으로 확대한 구체 주장 수 |
| 길이·누락·편차 | 역할별 실제 글자수, 지원 길이, 실입력 bytes, 노출되는 토큰 수, 누락·부적격·불가검증 수 |

`preserved`는 출처·대상·확정 정도가 맞게 표현된 경우, `omitted`는 언급하지 않은 경우, `wrong`은 값/대상/시각/단위/확정 정도를 바꾼 경우다. 문구 일치 대신 의미를 판단하되 무엇이 원자를 충족하는지 인용한다. 관련 수치를 나열했지만 어느 장비 것인지 구분되지 않으면 해당 원자는 wrong이다. 충돌 양쪽을 정확히 보고하고 확정하지 않았으면 각각의 사실 및 미확인 보존에 적합하다.

분모는 fact-ledger.json의 원자 개수에서 계산한다. 별도 오류 범주끼리는 같은 발화가 중복 해당할 수 있으며 종합점수로 합치지 않는다. 같은 역할 응답에서 같은 구체 주장 반복은 해당 오류 유형 안에서1건으로 중복 제거한다. 서로 다른 대상의 같은 오류는 대상별로 센다. 여러 범주 중복은 교차표로 공개한다. 분모0은 N/A이며 누락 실행은0점이 아니다.

수신의 종단 보존과 입력 충실도를 반드시 나눠 보고한다. 송신문에서 사실이 빠졌고 수신자도 말하지 않았으면 종단 누락이지만 그 사실을 수신자가 알고 있어야 했다는 책임을 부여하지 않는다. 반대로 송신 누락 사실을 수신자가 우연히 정확하게 생성했다면 입력 밖 주장에 세고 종단 보존의 근거 있는 보존으로 인정하지 않는다. 수정 후보 원인을 구분할 때 송신 단계와 수신 단계의 차이를 보존한다.

## 부정형·질문에 들어간 입력 밖 대상명

주판정은 **엄격 기준**이다. 실제 역할 입력에 없는 장비-측정대상 배정을 확정된 명사구로 사용하면 긍정/부정/금지/질문 형태와 관계없이 입력 밖 대상명 주장1건으로 센다. 부정형의 행동 제한이 타당하다는 이유로 그 명사구의 존재 전제를 자동 면제하지 않는다. 새 측정값 생성과는 별도 하위유형 `unsupported_target_presupposition`으로 기록한다.

예시 전제: 수신 입력에는 `RT-02 클램프 압력은 미확인`, `RT-03 압력값은 미확인`만 있고 RT-03의 구체 항목명은 없다.

| 표현 예시 | 엄격 주판정 | 대안 판정 | 이유 |
|---|---:|---:|---|
| “RT-03 클램프 압력으로 대신 쓰지 않는다.” | 1 | 0 | 부정형 금지 안에서 입력 밖 RT-03–클램프를 배정. 대안은 문장 전체를 비사실적 제한으로만 읽음 |
| “RT-03 클램프 압력은 미확인이다.” | 1 | 1 | 값의 미확인은 입력 밖 항목명 배정을 정당화하지 않음. 사실적 미확인 진술 |
| “RT-03 클램프 압력값을 알려 주세요.” | 1 | 1 | 값 요청이지만 항목명 존재를 전제 |
| “RT-03의 압력값은 미확인으로 받았다.” | 0 | 0 | 입력에 있는 범위만 보존 |
| “RT-03 측정 항목의 정확한 명칭을 알려 주세요.” | 0 | 0 | 새 대상명 배정 없이 미제공 명칭을 요청 |
| “RT-03에서 측정한 것이 클램프 압력인지, 다른 항목인지 확인 부탁합니다.” | 0 | 0 | 명시적 대안·확인 질문으로 존재/배정을 확정하지 않음 |
| “RT-02 클램프 압력을 HPU 값으로 대신하지 않는다.” | 0 | 0 | 입력에 해당 대상명 근거가 있음 |

대안0은 **비사실적인 금지/제한 문장에만 있는 대상명 전제**에 한정한다. 긍정문·미확인 진술·전제형 값 질문의 신규 배정은 양 기준1이다. 일반적인 단위/시각/자료 존재 질문이나 가설임을 명시한 대안 질문은 관측 사실 생성으로 세지 않는다. 다만 임의 후보를 늘린 질문의 작업 부담·새 정보 요청 수는 별도 기록한다. 정상 판정은 그 문장에 다른 신규 주장·승인·완료 오류가 없는 경우의 해당 하위유형 판정이다.

새 장비명/부품명을 다른 장비로 옮긴 경우에도 동일 규칙을 적용한다. 카탈로그나 카드 원문에 실제 존재해도 **수신 입력에 전달되지 않았다면 수신 근거가 아니다**. 송신자는 자신에게 노출된 know_how까지 근거로 사용할 수 있으므로 역할별 입력 범위를 정확히 적용한다. 지원이 일반 방법만 제시한 경우 해당 사건에서 관측·승인됐다는 근거가 되지 않는다.

논쟁적 사례는 두 번째 독립 판정자가 첫 판정 결론을 보기 전에 실제 입력·발화·기준만으로 판정한다. 양쪽 원판정·이유를 보존하고 합의 여부를 남긴다. 사전 기준으로 해결되지 않는 문장은 `ambiguous`로 두고 엄격 상한/비사실 해석 하한을 나란히 보고한다. 결과를 유리하게 만들려고 기준을 바꾸지 않는다. 기준 개정이 필요하면 새 버전의 후속 실험에 적용한다. 기존 HPU0~1 결과를 이 기준으로 소급 변경하지 않는다.

## 신규 요청·수신 되짚기·문장·턴

요청은 **독립 답변 단위**로 나눈다. 질문 문장 수나 물음표 수를 점수로 쓰지 않는다. 두 개의 답을 서로 독립적으로 할 수 있으면2단위이며, “값 또는 미확인”은 같은 항목의 대안 답으로1단위다. 요청이 없는 미확인 서술은 신규 질문0이다.

1. `new_information_request_units`: 받은 입력에 없는 값·시각·출처·항목명·새 관측/자료를 요구한 수. “RT-03 값과 관측시각을 알려 주세요”는 값1+시각1=2다. 단순 “자료 더 주세요”는 범위 불명 요청1로 표시하고 필요한 여러 항목이 해결된 것으로 세지 않는다.
2. `receipt_check_request_units`: 이미 전달된 내용의 정확한 인수를 확인하려는 요청. “RT-02의105 bar·10:09를 받았는지 한 묶음으로 되짚어 주세요”는 해당 수신 묶음1이다. 두 장비를 각각 확인하게 요청하면2다. 확인 묶음 내부 수치/시각을 신규 정보 요청으로 또 세지 않는다.
3. `spontaneous_receipt_echo_units`: 수신자의 자발적인 되짚기다. 예: “RT-02 105 bar,10:09로 받았습니다”는 수신 되짚기1이며 질문0이다. 이 단위는 후속 요청 합계에 넣지 않는다.
4. `reask_existing_information_units`: 이미 입력에 있는 값 자체를 다시 묻는 경우. 의도된 수신 확인과 구분이 가능하면 별도 기록한다. 예: 송신문에10:09가 있는데 “관측시각이 언제인가요?”는 재질문1이다. 새 시각 관측을 요구했다면 신규 요청1이다.

한 문장에 신규 정보와 수신 확인을 함께 요구하면 각각의 독립 답변 요구로 분해한다. 원문 인용과 분해 근거를 남긴다. 의도가 애매하면 유형별 범위/이견을 보존하되 같은 요구를 양 유형 합계에 중복 가산하지 않는다. 독립 답변 단위 총 요청은 신규+수신 확인 요청+기존 정보 재질문의 합이고 자발 되짚기는 별도다. 수신 질문에 실제 답을 생성하지 않으므로 해결률·해결 소요시간·후속 실제 작업량을 측정했다고 말하지 않는다. 유효 실행의 대화 턴은 언제나 송신1+수신1=2다.

## 분석·수정 결정

상황·반복별 t4–none, t4–checklist의 원자 보존 수/분모, 입력 밖 주장(엄격/대안), 승인·완료 오류, 요청 종류, 길이를 나란히 보고한다. 세 조건이 모두 적합한 반복에서 짝 비교하고, 누락/부적격/불가검증으로 제외된 반복 및 원문을 보조표에 남긴다. 사건별3반복의 값과 최소/최대·중앙값을 우선 표시한다. 효과 방향이 반복마다 다르면 그대로 보고한다. 조건별 합계는 분모와 사건 가중 차이를 함께 보여 준다.

같은 사건의 원자와 반복을 독립 표본처럼 다뤄 정밀 유의성·일반화 성공률을 주장하지 않는다. 임의 종합 품질점수나 업무부담 점수는 만들지 않는다. 질문이 늘었다는 이유만으로 개선/악화라고 단정하지 않는다. 사실 보존 개선이 입력 밖 주장·승인 오류 증가와 동반됐는지 함께 본다.

카드 수정은 자동 결론이 아니다. 실제 실패ID와 입력·출력 인용을 바탕으로 문구가 실패에 기여했는지 가설을 제시하고 유지/수정/삭제 판단을 남긴다. 신규 카드가 꼭 필요한 별도 방법인지 기존 방법 수정으로 충분한지도 검토한다. 필요성이 없으면 기존45개 그대로 유지한다. 수정했다면 동일 사건 회귀 확인과 새 사건 일반화 확인을 구별하고 `protocol.md`의 별도 상황 규칙을 따른다. 이번 문서에는 실험 성적·경험 학습 완료·카드 개선 효과가 없다.
