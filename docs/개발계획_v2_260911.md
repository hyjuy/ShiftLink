### 2.1 팀 표준 개발환경

| 항목 | 표준 | 이유·비고 |
|---|---|---|
| Python | **3.10.x** | Jetson이 3.10.12다. PC가 3.11 이상이면 3.10에 없는 기능(`tomllib` 등)을 모르고 쓰게 된다 |
| 가상환경 | 리포 루트 `.venv` | Windows `py -3.10 -m venv .venv` / Linux·macOS `python3.10 -m venv .venv` |
| 패키지 | `requirements.txt`, 전부 `==`로 고정 | 4.4 스택 + `sqlite-vec==0.1.9`(Jetson aarch64·Windows·macOS 휠 제공 확인) |
| 추론 런타임 | Ollama, 전원 같은 버전 | Ollama 버전과 모델 digest를 `models.lock`에 기록 |
| 모델 태그 | B `qwen2.5:3b-instruct-q4_K_M` / A `qwen2.5:7b-instruct-q4_K_M` / C `exaone3.5:2.4b-instruct-q4_K_M` | Ollama 공식 태그로 확인했다. 4.3의 플랜 C "Q4_K_S/Q4_0"은 공식 태그에 없다(→ N-6) |
| 줄바꿈 | `.gitattributes`로 LF 통일 | Windows에서 CRLF 변환 경고가 이미 났다. PC에서 Jetson으로 복사한 스크립트가 깨지는 것을 막는다 |
| 비밀정보 | `.env` 커밋 금지, `.env.example`에는 키 이름만 | **리포가 공개(public)** 상태다 |
| 원격 개발 | VSCode Remote-SSH + 개인 SSH 키 | 비밀번호 로그인 대신 키를 등록한다 |
| 리포 구조 | `shiftlink/`(`data`·`agent`·`rag`·`edge`) + `eval/`·`tests/`·`scripts/` | `python -m shiftlink.data` 실행 경로와 맞춘다. 9/11 초기 구성(`src/pipeline` 등)은 Day 1에 정정한다 |

## 6. 용어 사전

> `kb/dev/sealed`, K-01 필드, T1~T5, RAG·SFT·LoRA, Recall@k·p95, jtop, 양자화 같은 기존 용어는 「ShiftLink 고도화 문서 — 용어 사전」과 같은 뜻으로 썼다. 아래에는 이 계획서에 새로 나온 용어만 정리했다.

**일정·운영**

| 용어 | 뜻 |
|---|---|
| 크리티컬 패스 | 하나라도 늦으면 종료일 전체가 밀리는 작업 사슬 |
| 버퍼 | 지연을 흡수하려고 비워 둔 시간 |
| 마일스톤 | 반드시 지나야 하는 확인 지점(스키마 동결, 봉인, 동결 등) |
| 완료 기준 (DoD) | Definition of Done. "끝났다"고 말할 수 있는, 확인 가능한 조건 |
| 타임박스 | 결과와 상관없이 정한 시간이 되면 멈추고 결론을 내는 방식 |
| 스파이크 | 결정을 내리려고 짧게 해 보는 기술 검증 실험 |
| 스탠드업 | 매일 짧게 하는 진행 공유 회의 |
| 결정 로그 | 결정·근거·결정자·날짜를 한 줄씩 쌓는 기록 |
| 스키마 동결 | 데이터 형식을 고정해 이후 생성분을 다시 만들지 않게 하는 것 |
| 핫픽스 | 동결 후 치명 결함만 예외로 고치는 수정 |
| 사후 채점 (post-hoc) | 결과를 본 뒤 고치고 다시 매긴 점수. 1차 점수와 섞으면 성능이 부풀려진다 |
| 과적합 | 특정 평가 데이터에만 맞춰져서 새 데이터에서는 성능이 떨어지는 현상 |

**Jetson·추론**

| 용어 | 뜻 |
|---|---|
| L4T | Linux for Tegra. JetPack에 포함된 Jetson용 리눅스. 이 버전으로 JetPack 버전을 확인한다 |
| CUDA / TensorRT | NVIDIA GPU 연산 라이브러리 / 추론 최적화 라이브러리 |
| nvpmodel / tegrastats | 전력 모드를 조회·변경하는 명령 / 온도·메모리 사용량을 출력하는 명령 |
| GPU 오프로드 | 모델 연산을 GPU로 넘기는 것. `ollama ps`에 "100% GPU"로 표시되어야 한다 |
| GUI 끔 (`multi-user.target`) | 데스크톱 화면 없이 부팅하는 설정. 메모리를 아낄 수 있다 |
| 모델 태그 / digest | Ollama 모델의 이름표 / 모델 파일의 고유 지문. 태그가 같아도 digest가 다르면 다른 파일이다 |
| `models.lock` | 팀이 쓰는 모델의 태그·digest와 Ollama 버전을 적어 두는 파일 |
| 첫 토큰 지연 (TTFT) | 요청 후 첫 글자가 나올 때까지의 시간. 전체 응답 시간과 따로 잰다 |
| `OLLAMA_NUM_PARALLEL` | Ollama가 동시에 처리하는 요청 수. 1이면 하나씩 처리한다 |
| 점유 규칙 | Jetson 1대를 여럿이 쓸 때 측정 시간대를 예약해 서로 방해하지 않게 하는 규칙 |
| sentence-transformers / ONNX | 임베딩 모델을 실행하는 라이브러리 / 여러 런타임에서 돌릴 수 있게 바꾼 모델 형식 |
| 커뮤니티 변환본 | 원 개발자가 아닌 사람이 GGUF 등으로 바꿔 올린 모델. 원본과 결과가 같은지 확인해야 한다 |
| 코사인 유사도 | 두 벡터가 같은 방향을 가리키는 정도(1에 가까울수록 같음). 변환본 검증에 쓴다 |

**데이터·실험**

| 용어 | 뜻 |
|---|---|
| autoresearch 방식 | karpathy/autoresearch의 실험 원칙. 고정 시간 예산 안에서 한 번에 하나만 바꿔 실행하고, 단일 지표로 keep/discard를 판정해 로그에 쌓는다 |
| 고정 시간 예산 | 모든 실험에 같은 시간만 쓰게 해서 결과를 공정하게 비교하는 규칙 |
| keep / discard | 지표가 나아진 변경은 남기고, 아니면 버리는 판정 |
| `experiments.tsv` | 실험 설정·지표·판정을 한 줄씩 추가하는 기록표 |
| 평가 대상 버전 고정 | 채점 전에 코드·프롬프트·모델을 고정해 "채점하면서 고치기"를 막는 절차(`v0.5-eval`) |
| judge–사람 일치율 | AI 심사 결과가 사람 판정과 같은 비율. judge를 믿어도 되는지 재는 값 |
| 안전 서브에이전트 | 안전관리자 페르소나를 준 별도 AI 검토자. 사람 검수를 대신하지 않으며 L2(전문가 승인)로 표기하지 않는다 |
| 배치 업로드 | 쌓아 둔 기록을 정해진 주기에 한꺼번에 올리는 방식(여기서는 하루 1회) |
| 멱등 업로드 | 같은 기록을 여러 번 올려도 한 번 올린 것과 결과가 같도록 만든 방식. 실패 후 다시 시도해도 안전하다 |
