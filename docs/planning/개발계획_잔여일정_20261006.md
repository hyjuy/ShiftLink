### 10/14 test 30 채점 절차 (사전 등록 대상)

**결정(10/6)**: 두 구성을 모두 채점하고, 시연은 hybrid로 간다. 같은 test 셋을 두 번 쓰므로 아래 규칙을 **10/8까지 `ShiftLink-records/experiments/test30_1014/PREREG_test30.md`에 적고 전원 합의한 뒤에만** 실행한다.

| 구성 | 환경변수 | `--model` |
|---|---|---|
| E1(추출형) + SFT 판정기 | `SHIFTLINK_ANSWER_MODE=extract`, `SHIFTLINK_JUDGE_MODEL=exaone-sft-judge` | `exaone3.5:2.4b-instruct-q4_K_M` (extract에서는 호출되지 않음) |
| hybrid + SFT 판정기 | `SHIFTLINK_ANSWER_MODE=hybrid`, `SHIFTLINK_JUDGE_MODEL=exaone-sft-judge` | `exaone-sft-answer` |

```bash
SHIFTLINK_ANSWER_MODE=extract SHIFTLINK_JUDGE_MODEL=exaone-sft-judge python eval/qa/score.py eval/qa/20260929/qa_test.json \
  --host http://127.0.0.1:11435 --model exaone3.5:2.4b-instruct-q4_K_M --judge-strict --out eval/results/qa_test_final_extract.json
SHIFTLINK_ANSWER_MODE=hybrid SHIFTLINK_JUDGE_MODEL=exaone-sft-judge python eval/qa/score.py eval/qa/20260929/qa_test.json \
  --host http://127.0.0.1:11435 --model exaone-sft-answer --judge-strict --out eval/results/qa_test_final_hybrid.json
```

사전 등록할 규칙:
1. 두 구성의 결과를 **모두, 나란히** 보고한다. 점수를 본 뒤 구성을 바꾸거나 "더 좋은 쪽만" 고르지 않는다.
2. **시연 구성은 hybrid로 고정**한다. 결과가 어느 쪽이 높아도 바꾸지 않는다(사전 결정).
3. 같은 커밋, 같은 `qa_test.json`, 같은 Jetson 설정(문맥 4096, 데스크톱 끔)으로 구성당 **1회**만 실행한다. 잠금 파일은 구성별로 둔다: `FINAL_DONE.test30.extract.txt`, `FINAL_DONE.test30.hybrid.txt`(기존 `FINAL_DONE.*`처럼 `ShiftLink-records`에 수동으로 만든다. `score.py`가 강제하지는 않는다).
4. 실행이 `--judge-strict`로 `.INVALID`가 되면(판정 모델 오류·터널 끊김 등 **인프라 문제**) 점수를 해석하기 전에 원인을 고치고 같은 구성을 다시 실행한다. 잠금 파일은 유효한 실행 뒤에만 만든다. 점수를 본 뒤의 재실행은 허용하지 않는다.
5. 사람이 `qa_test.json`을 열지 않는다. 결과는 고치지 않고 실패 문항 분류만 기록한다.
6. 두 구성을 드라이런할 때는 test 30이 아니라 dev 셋 3건을 쓴다(10/7). 목적은 `config` 기록이 올바른지 확인하는 것이다.

두 구성의 결과가 갈릴 때의 해석(예: hybrid가 낮음)은 보고서에 그대로 적고 시연 구성은 바꾸지 않는다. 근거가 얇은 hybrid(합산 26문항 개선, 새 문항에서는 변별 없음)를 test 30으로 처음 단독 평가하는 셈이므로, 발표에서는 "사전 등록한 두 구성 모두 보고"로 설명한다.
