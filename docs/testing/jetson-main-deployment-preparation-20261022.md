## C5를 보존하는 롤백

후속 롤백이 필요하면 새 작업 승인을 받아 수행한다. C3 비상 복귀 스크립트는 색인·모델·C5 설정을 바꾸므로 이번 배포만 취소하는 용도로 호출하지 않는다.

1. 사용자 쓰기와 업로더를 통제하고 MES·업로더의 정지를 확인한다. 실패 시점 코드·로그·DB/WAL/SHM은 분석용으로 별도 보존한다.
2. 이번 새 `code-before.tar`의 기존 12개 파일을 정확한 경로·권한으로 복원한다. 신규 publication.py는 격리해 배포 전 부재 상태를 복원한다. 변경 모듈의 새 pycache도 필요한 범위에서 격리한다. server 또는 query만 단독으로 되돌리지 않는다. 배포 전 기록의 해시와 대조한다.
3. DB 복원이 필요한지 먼저 결정한다. 새 코드가 DB를 열기 전 실패했다면 불필요하게 DB를 덮어쓰지 않는다. 검증 구간에서 복원할 경우 실패 DB/WAL/SHM을 함께 보존한 뒤 검증된 백업의 새 복구 사본을 준비하고 소유자·권한·무결성을 확인한다. 과거 WAL을 복구 DB에 다시 적용하지 않는다.
4. **이번에는 사용자 쓰기와 외부 업로드가 이미 재개됐다.** 과거 DB를 즉시 덮어쓰지 않는다. 현재 DB의 일관된 사본부터 만들고 이후 업무 기록·질의·심사·outbox 및 외부 업로드 식별자를 대조해 이관·재처리 계획을 정한다. 숫자를 맞추려고 이력을 삭제하지 않는다.
5. 영구 설정은 이번 배포에서 바꾸지 않았다. 예상 밖 차이가 있으면 보호 백업과 비교해 해당 차이만 복구한다. 변경하지 않은 계정·C5 설정·색인·모델은 덮어쓰지 않는다.
6. 이전 MES의 API·질의·인용·센서·86개 카드와 후보 상태를 확인하고 업로더 및 사용자 쓰기를 마지막에 재개한다.
