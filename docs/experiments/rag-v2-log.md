### 4단계 결론 (10/13)
- 후보 A — **bge-m3 · 700 · 레인(w=0.25)**: 원문 근거 찾기 최고(.532), R@1 .537. v2의 목적(카드에 없는 원문 근거)에 맞음. Jetson에 1.2GB 모델 추가.
- 후보 B — **embeddinggemma · 700 · dense**: 상위권 최고(R@5 .756, R@10 .837), 모델 0.6GB로 Jetson에 가장 가벼움. 원문 근거는 .325.
- 2-모델 레인은 단일 bge-m3 레인보다 낫지 않음 → 기각.
- 남은 확인: Jetson에서 질문 임베딩 지연·메모리(A·B), Chroma ARM 설치. 이후 5단계(생성)에서 A·B를 같은 질문으로 비교해 최종 선택.

### 4단계 요약 — 실험에서 알게 된 것 (10/13, 사용자 확인)
1. 모델마다 강점이 다르다. qwen3와 gemma는 한국어 카드를 잘 찾지만 영어 원문은 못 찾는다(qwen3 원문 R@10 .12). bge-m3는 원문을 가장 잘 찾는다. 한국어 미세조정 모델 KURE는 bge-m3보다 전반적으로 낮다.
2. 청크 크기는 700이 가장 좋다(250 < 450 < 700). 쪽 경계를 넘지 않게 잘라 700은 사실상 한 쪽 단위다.
3. BM25 비중을 낮추면 R@1은 오르지만 원문 근거 비율은 dense만 쓸 때보다 낮다. 그래서 카드와 원문을 따로 찾는 레인 방식을 만들었고, 원문 근거 비율 .532로 가장 높았다.
4. 2-모델 레인(카드 gemma·qwen3 / 원문 bge-m3)은 bge-m3 단일 레인보다 낫지 않아 기각했다.
5. 설비 필터는 유지한다. 빼면 모든 지표가 떨어진다.
6. 벡터 DB(Chroma)는 numpy와 결과가 99.9% 같다. 질의 14ms, 재시작 후 유지, 문서 단위 삭제 정확.
7. 유사도 점수로는 "답 없음"을 가를 수 없다. 거절은 생성 단계의 판정기가 맡는다.

**실험 설계**
- 출력 JSON 순서를 `{insufficient_evidence, answer, citations}`로 바꾼다. 라벨과 분할은 같고 직렬화 순서만 다르다(619/68, assert로 확인). 판단 토큰 확률이 답 텍스트의 영향을 받지 않게 하기 위해서다.
- 재학습은 어제와 같은 하이퍼파라미터·seed로 하고, 체크포인트를 스텝 59·68·78·88·98·107·117(1.5~3.0 epoch)에 저장한다.
  - 1.5~2.75 epoch 체크포인트는 3 epoch 코사인 일정의 중간 지점이라, 학습률이 덜 줄어든 상태다.

  1. 정답 종류 분포가 반대다. 학습 쌍의 양성은 매뉴얼 471(62%) · 카드 286(38%)인데, 개발 셋 정답 조각은 카드 76%다. 판정기(v1)는 카드 중심 데이터로 학습됐다.
  2. 학습 프롬프트에 이벤트 조각이 0개다. 개발 셋 검색에는 이벤트 조각이 섞인다(틀린 1위 중 이벤트 8, 판정기 5).
  3. hard negative(판정기 P < 0.1)는 판정기도 이미 아니라고 아는 쉬운 음성이다. 헷갈리는 카드 대 매뉴얼 경쟁을 겨냥하지 못했다. B의 질문 안 순위 손실도 효과가 없었다.
  4. 양성 = 답에 인용된 조각이라, 관련 있지만 인용되지 않은 조각이 음성으로 학습된다(라벨 잡음).
  5. 기반 모델이 영어 전용(decider-2b)이다. 음성이 압도적으로 많아 확률이 0 근처로 몰렸다(p(yes) 중앙값 0.013, 80%가 0.1 미만). 그래서 lo가 0.045로 불안정하다. 다만 이것은 1위 실패의 직접 원인은 아니다.
- 다음에 한다면: 학습 쌍을 카드 정답 중심으로 다시 맞추고 이벤트 조각을 음성 후보에 넣는다. 같은 질문 안 카드 대 매뉴얼 쌍(판정기 0.3~0.7 구간, 사람 확인)을 hard negative로 쓴다. 검증 셋도 개발 셋 분포에 맞춘다. 시연(10/26)까지는 판정기(S30h)를 유지하고, decider는 발표 뒤 과제로 둔다.

### decider 학습 라벨 감사 — 작은 범위 (10/16, 오케스트레이터 TASK-006 1번, 분석만)
- 대상: SFT 학습 쌍 `sft2/c/rag_train` 846개 중 150개(`random.Random(1016)`), 프롬프트 조각 1,046개(전부 색인 조각과 본문 일치). 판정기 P(≥2)로 점수를 매겼다(10/16 GPU 박스, 1분 24초). **판정기는 정답이 아니라 선별 도구다**(개발 셋 조각 AUROC 0.816).

- 거짓 음성 후보(음성인데 P ≥ 0.7): 76개(음성의 8%)다. 그중 답 있는 쌍에 57개, 거절 라벨 쌍(조각 전부 음성)에 19개가 있다. 150쌍 중 46쌍(31%)에 이런 조각이 하나 이상 있다.
- 반대 방향도 있다. 양성 140개 중 40개(29%)는 판정기 P < 0.3이다. 인용됐지만 판정기는 관련 없다고 본다.
- 해석(가설): 라벨 잡음은 양방향으로 작지 않다. 다만 판정기 자체 오류와 섞여 있어 비율을 그대로 잡음률로 볼 수는 없다. 사람 확인용 시트를 만들었다: 거짓 음성 후보 30개(답 있는 쌍, 고정 표본), `ShiftLink-records/experiments/rag1013/sess1016/label_audit/audit_labels_review.tsv`. 사람 확인 결과로 실제 잡음률을 정한 뒤에 hard negative·분포 조정을 설계한다.
- **사람 판정(거짓 음성 후보 30개, 오케스트레이터 경유, `label_audit/human_verdicts.tsv`)**: 관련 있음 19, 없음 11(63%). 카드는 9개 중 8개(89%), 매뉴얼은 21개 중 11개(52%)가 관련 있음이다. 판정 기준은 "질문과 관련 있는가"이고 "답에 인용해야 하는가"가 아니다. 판정기 P ≥ 0.7인 음성만 골랐으므로 무작위 표본이 아니다.
  - 대략 추정(가설): 150쌍의 후보 57개에 63%를 곱하면 관련 있는데 음성으로 학습된 조각이 약 36개(음성 906개의 약 4%)다. 그중 카드 비율이 높다(89%). 관련 카드가 음성으로 학습되면 decider가 카드를 낮게 매기게 되므로, 진단 가설 1(카드 정답 문항을 놓침)과 같은 방향이다.
  - 라벨 기준 결정이 필요하다(팀). decider는 답 모델 앞에서 근거를 거르는 역할이고, 1단계 관문의 정답도 "질문 관련 페이지"(relevant_sources)다. 그래서 decider 라벨은 "인용"보다 "관련성"에 맞추는 쪽이 목적과 맞다(제안).
  - 약한 양성 시트(인용됐지만 판정기 P < 0.3, 답 있는 쌍 40개 중 30개, 고정 표본): `label_audit/audit_labels_weakpos_review.tsv`(카드 9, 매뉴얼 21).
- **사람 판정(약한 양성 30개, `label_audit/weakpos_verdicts_recovered.csv`)**: 인용됐지만 판정기 P < 0.3인 조각 중 관련 있음 21, 없음 9(70%)다. 카드는 9개 중 6개, 매뉴얼은 21개 중 15개가 관련 있다. 원본 CSV는 본문 줄바꿈 때문에 따옴표가 깨져 있었다. 오케스트레이터가 행 번호·쌍 ID 기준으로 복구했고, "relevent" 오타 21건을 relevant로 통일했다. 고정 표본이고 판정 기준은 질문 관련성이다.
  - 해석(가설): 판정기가 관련 없다고 본 조각의 70%가 실제로는 관련 있다. 특히 매뉴얼 페이지가 그렇다(15/21). 따라서 판정기 점수로 라벨을 자동 정정하면 안 된다. 같은 이유로 이번 hard negative 선별(판정기 P < 0.1)에도 관련 있는 매뉴얼 조각이 음성으로 섞였을 수 있다. B의 효과가 없었던 이유 후보에 추가한다.
  - 두 판정을 합친 정정 규칙은 라벨 기준(관련성 대 인용)을 팀이 정한 뒤에 설계한다.
- **관련성 기준 무작위 표본 60개(오케스트레이터 전달, `label_audit/random_relevance_60_revised.csv`)**: 150쌍의 조각 1,046개 중 `random.Random(1017)`로 판정기 점수와 무관하게 60개를 뽑아 사람이 관련성을 판정했다. 결과는 관련 26, 없음 34(43%)다. 카드는 26개 중 16개(62%), 매뉴얼은 34개 중 10개(29%)가 관련 있다. 수치는 PC에서 다시 계산해 일치를 확인했다.
