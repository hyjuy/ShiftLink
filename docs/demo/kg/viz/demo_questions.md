# ShiftLink 지식 그래프 시연 질문

이 화면은 카드의 분류·문서 판본·검수 전 증상 후보를 탐색하는 시연이다. 검색·답변 생성이나 GraphRAG를 실행하지 않는다. 작업 절차와 성능 향상을 설명하는 자료로 사용하지 않는다.

## 실행

저장소 루트 PowerShell에서:

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory docs/demo/kg
```

- 가짜 데이터: `http://127.0.0.1:8765/viz/?mock=1`
- 실제 파일: `http://127.0.0.1:8765/viz/`
- 가짜 데이터의 화면 자가 점검: `http://127.0.0.1:8765/viz/?mock=1&selftest=1`

실제 파일은 `../build/graph.json`에서 읽는다. 기본 주소가 실패하면 통합 상태와 HTTP 서버 위치를 확인한다. 가짜 데이터로 자동 전환하지 않는다. `file://`로 직접 열지 않는다.

## 가짜 데이터로 보여줄 순서 (약 4분)

상단에 **가짜 데이터**가 표시된 상태에서 시작한다. MOCK 식별자·인용·설명은 모두 화면 개발용이며 실제 카드·자산·매뉴얼 근거가 아니다.

| 순서 | 화면에서 확인할 질문 | 조작과 확인 지점 |
|---|---|---|
| 1 | HPU 카드는 어떤 설비·하위 분류와 연결되는가? | 노드 타입 `CardVersion`, 설비 분류 `HPU`를 선택한다. 목록에서 `가짜 카드 · 펌프 출구 압력 관측`을 선택한다. `ABOUT` 2개와 `HPU`, `주 베인펌프`를 확인한다. 실제 장착 관계로 설명하지 않는다. |
| 2 | 이 카드가 인용한 문서의 판본과 위치는 무엇인가? | 상세 영역의 `인용 locator`에서 문서 `MOCK-HPU-MANUAL`, 판본 `mock-2026/1`, `p. 12, Fig. 3`, `p. 13, Table 2`와 원본 인용 2건을 확인한다. `CITES` 이웃 버튼으로 문서를 선택하면 인용한 카드를 거꾸로 탐색할 수 있다. |
| 3 | 카드의 accepted는 새 증상 연결의 검수 완료인가? | 카드 상세의 `증상 연결 후보 · 검수 전`을 확인한다. `DESCRIBES_SYMPTOM` 이웃을 선택해 증상 정의와 `needs_review`를 확인한다. 후보가 없는 카드는 `증상 후보 연결 없음`으로 구분된다. 이웃이 필터 밖이면 필터가 초기화되며 선택한 노드가 목록에 나타난다. |
| 4 | 안전 카드와 원문 증상이 없는 카드는 어떻게 보이는가? | 필터를 초기화하고 `가짜 안전 카드 · 증상 연결 보류`를 선택한다. 안전·null 연결 보류 배지와 증상 관계가 없는 상태를 확인한다. 카드의 accepted 상태를 안전성·매핑 승인으로 해석하지 않는다. |
| 5 | 판본 없는 출처는 문서 판본으로 만들어지는가? | 같은 안전 카드에서 `판본 미지정 인용`과 `EV-MOCK-UNVERSIONED` 원문을 확인한다. 그 항목은 DocumentVersion·CITES로 만들지 않는다. 가짜 판본을 채워 넣지 않았음을 보여준다. |
| 6 | 장비 유형과 개별 장비는 어떻게 다른가? | 타입 `Asset`에서 `MOCK-HPU-01 (합성 장비)`를 선택한다. `INSTANCE_OF`, `DS-v1.0`, `from_catalog_default`, 합성 장비 배지를 확인한다. 실제 자산·현재 설치 이력을 확인한 자료가 아니며 AssetPart는 생성하지 않았음을 설명한다. |
| 7 | 원문 속성은 손실 없이 확인할 수 있는가? | HPU 관측 카드를 다시 선택해 `원문 속성 (props) 전체 보기`를 연다. card_id, version, symptom, provenance, mes_equipment_id를 확인한다. `display_literal`의 HTML 모양 문자열도 실행되지 않고 텍스트로 표시된다. |

목록은 Tab으로 진입하고 위·아래 방향키로 선택할 수 있다. 이웃 관계 버튼도 키보드로 선택한다. 이름/ID 찾기는 목록의 문자열 필터이며 자연어 질의나 의미 검색이 아니다. 이름 필터를 일치하지 않는 문자열로 설정해 빈 결과를 보여준 뒤 `필터 초기화`로 복원할 수 있다.

## 실제 파일 통합 후 보여줄 질문

짧은 발표에서는 위 단계를 세 질문으로 묶어도 된다. **문서 판본·locator 확인 → accepted와 검수 전의 차이 → 실제 현장 사건을 증명하는지 확인** 순서로 진행하면 각 주장에 대응하는 근거와 한계를 먼저 확인할 수 있다.

가짜 데이터 시연을 끝낸 뒤 `?mock=1`을 제거하고 기본 주소를 새로 연다. 실제 파일이라는 표시는 파일 경로의 구분이며 실제 현장 데이터라는 뜻이 아니다.

1. HPU의 실제 CardVersion을 선택했을 때 원본 카드의 설비·하위 분류·문서 판본·locator가 일치하는가?
2. 판본 미지정 원본 인용은 props와 별도 보류 안내에 남아 있는가?
3. 증상 후보 통합 후 비안전 카드에서만 `DESCRIBES_SYMPTOM`이 생기며 검수 전으로 표시되는가? 후보가 없는 현재 그래프는 `Symptom (0)`이 정상이다.
4. Asset은 합성 장비만 나타나며 실제 현장 자산·AssetPart·사건 기록을 추론하지 않는가?

화면에서 확인할 수 없는 검수 완료 여부·원인 진단·조치 효과·검색 성능은 답하지 않는다. 그래프 생성과 원본 보존 검증은 변환 담당자의 validation.json 및 인계 자료로 별도 확인한다.

## 파일 누락 오류 시연

build 파일을 옮기거나 삭제하지 않는다. 기존 서버와 다른 터미널에서 **viz 폴더만** 임시로 서비스한다.

```powershell
python -m http.server 8766 --bind 127.0.0.1 --directory docs/demo/kg/viz
```

`http://127.0.0.1:8766/`를 열면 실제 기본 상대 경로가 서버 범위 안에 없어 HTTP 404가 발생한다. 오류와 실행 안내를 확인하고 가짜 데이터가 자동 표시되지 않는 것을 보여준다. 시연 후 해당 터미널에서 Ctrl+C로 이 임시 서버를 종료한다.

## 발표 문장

> 카드의 설비 분류와 인용 문서 판본을 연결한 탐색 화면입니다. 증상 연결은 사람 검수 전 후보이고 장비는 합성 구성입니다. 실제 현장 자산과 부품 장착 이력은 확인하지 않았으며, GraphRAG와 성능 평가는 이번 시연 범위에 포함하지 않았습니다.
