## 1. 왜 하나

지금 검색은 **질문과 카드의 같은 단어 수**로 점수를 매긴다(제목·증상 2배, 1위 점수 < 5면 "해당 지식 없음"). 10/2 측정에서 이 방식의 한계가 그대로 드러났다.

| 증상 | 사례 | 원인 |
|---|---|---|
| 현장 말투로 물으면 카드를 못 찾음 | BN-004(압력 알람), BN-014, NH-007(잔류전하·접지 순서), BC-004(배전반 스파크), BL-007·BL-017 | 질문 단어와 카드 단어가 겹치지 않음 (스파크↔충전부·아크) |
| 답이 없어야 할 때 엉뚱한 카드가 1위 | 블라인드 2차 답 없음 6/19, dev 12/19 | 흔한 단어(설비명·"확인") 몇 개만 겹쳐도 점수가 기준선을 넘음 |
| 기준선 조정으로 해결 안 됨 | 10/1 실험: 기준 5→7→9로 올리면 답 있는 문항을 더 잃음 | 답 있음/없음의 1위 점수 분포가 겹침(dev 답 있음 5–13, 답 없음 1–12) |
| 인계 T4 검색 | H-012·H-017 (이슈 #147) | "소견·미해결" ↔ "추정·확정 못 함" |

목표: **뜻이 같은 표현을 찾고(재현율), 뜻이 먼 카드는 버리는(답 없음 판정) 검색**. 답변 문장 품질은 이 계획의 범위가 아니다(코드 규제·SFT가 담당).

## 3. 방법

### 3.1 카드 쪽 벡터 (오프라인, 카드가 바뀔 때만)
- 카드 1장 = 벡터 1개(제목 + 증상 + 부품), 그리고 본문(know_how) 벡터 1개. 두 벡터 중 높은 유사도를 쓴다(제목·증상 우선 원칙과 맞춤).
- T4 카드는 인계 모드에서 `required_context`·근거 사건 문장(evidence_text)도 별도 벡터로 둔다.
- 결과는 `kb_cards.json`과 같은 빌드에서 `kb_embeddings.json`(카드 ID → 벡터, 모델명·KB 해시 기록)으로 만든다. 카드 해시가 다르면 다시 만든다.

### 3.2 질문 쪽 (질의 1건마다 1회, 약 0.1초)
- 질문 문장을 그대로 임베딩한다. 설비 필터·조건 판정·T4 질의 제외 같은 기존 규칙은 그대로 둔다.

### 3.3 비교할 순위 방식

| ID | 방식 | 설명 |
|---|---|---|
| E0 | 현재 | 단어 겹침 점수 (기준선) |
| E1 | 임베딩만 | 코사인 유사도 순 |
| E2 | 혼합 | `α·정규화(단어 점수) + (1−α)·코사인`, α ∈ {0.2, 0.4, 0.6} |
| E3 | 임베딩 + 단어 재정렬 | 코사인 상위 k에서 단어 점수로 재정렬 |

### 3.4 답 없음 판정
- 1위 코사인이 기준 τ 미만이면 "해당 지식 없음". τ는 dev의 답 있음/없음 분포에서 정한다.
- 1위와 2위의 코사인 차이(여유)도 함께 본다(애매하면 확인 대상 카드로).

## 4. 평가

### 4.1 데이터 규칙
| 셋 | 용도 |
|---|---|
| dev 30, sanity 20 + reserve 10, t4 20, 개발용 블라인드 25, 신입 후속 10 | **조정에 사용** (α·τ 선택) |
| 블라인드 cjy 10 | 보고만 (조정 금지) |
| 블라인드 2차 25 | 최종 결과가 이미 기록됨. **조정에 쓰지 않고**, 채택 후 한 번만 다시 재서 개선 여부만 보고 |
| test 30 | 열지 않는다 (10/14 최종 채점) |

### 4.2 지표
- 주: 각 셋의 `route_score` (답 있음 1위 정답 + 답 없음 판정)
- 보조: 상위 5 안 정답(재현율), 답 있음/없음 따로, 질의당 지연(Jetson)

### 4.3 채택 기준 (keep / discard)
- **keep**: dev·sanity·t4·개발용 블라인드 합계가 E0보다 오르고, 어느 셋도 2문항 넘게 떨어지지 않는다.
- 답 없음 판정이 오르면서 답 있음이 떨어지는 교환은 셋별로 표에 남기고 재영이 판단한다.
- 지연: 질의당 검색 증가 0.3초 이내(Jetson 실측).
- 결과는 `bench/experiments.tsv`에 한 줄씩 남긴다.

## 6. 위험과 대비

| 위험 | 대비 |
|---|---|
| Jetson 메모리 부족(exaone + KURE + MES) | 임베딩 모델 `keep_alive`를 짧게, 안 되면 카드 벡터는 미리 계산·질문만 임베딩(이미 그 구조). 최악이면 bge-m3·더 작은 모델 비교 |
| 임베딩이 설비가 다른 카드를 올림 | 설비 필터는 그대로 먼저 건다 |
| dev에 맞춘 과적합 | 조정 셋 4개 합계로 고르고, 보고 전용 셋(BC·블라인드 2차)으로 일반화 확인 |
| 모델·카드가 바뀌면 벡터가 낡음 | 벡터 파일에 모델명·KB 해시 기록, CI에서 불일치 검사 |
| 카드 조건(T2) 판정과 충돌 | 조건 판정은 기존 코드 그대로, 임베딩은 순위만 바꾼다 |
